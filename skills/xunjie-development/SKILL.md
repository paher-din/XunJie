# XunJie 开发协作

面向协助开发者的编码 Agent。先辨认用户要使用已有工具、询问方案，还是实现新能力，再操作；工程建议与已经可运行的能力分别回答。

## 1. 确认可用入口

先读[工具状态与使用说明](../../docs/development-tooling.md#新-agent-的工具入口)，再核对当前 checkout 的实际入口、包脚本或帮助。该表集中维护命令、前置条件、平台限制与能力状态；本 Skill 不复制第二份命令目录。

如果文档描述的入口还不存在，明确说明缺少哪项能力，使用表中适合本次目标的现有入口，或在已授权的实现任务内补齐。完成条件是找到了实际可调用的入口，或给出有源码依据的缺口；不能把界面预览当成完整本地后端，也不能把 SSH 接通当成前端热更新已接线。

| 用户要做什么 | 阅读与判断 |
| --- | --- |
| 启动、停止、查看本地全栈环境 | [xj-dev README](../../tools/xj-dev/README.md)：已实现 doctor/up/status/down；每个工作树独立数据与端口；macOS 与 Windows 已实机验收，平台前置条件和验证范围见该 README |
| 切换本地与云端、联调云端 API、查看团队版本 | [模式切换](../../docs/development-tooling.md#切换本地与云端)：调用 `use`；从 JSON 核对固定入口、前后端来源、实际版本和数据归属。旧部署的版本 `not-exposed` 属于未验证；连接失败保留原模式 |

## 3. 执行并核对结果

用户只问原理或当前状态时，检查事实后回答即可。用户要求操作时，优先执行工具已经提供的确定性流程；上下文已有的成员授权和接入材料不要求重复提供。邀请和凭据从受限文件或工具的秘密输入读取，不写入仓库、命令参数或交接摘要。

操作前辨认当前工作树、数据环境和进程归属。失败时按工具报告处理对应阶段，保留已有数据与可用环境；只停止本工具拥有的进程。修改共享数据、切换数据起点和发布代码是不同操作，按用户本次目标选择。

工具说明与实际行为冲突时，以当前源码和执行证据判断可用性，修正相关说明；用户要求的目标仍以当前指令为准。更新命令或能力时，同步统一工具说明和命令帮助，Skill 只调整有变化的选择流程。

## 4. 回答开发者

先说明结果和当前可用状态，再给必要入口与后续动作。涉及环境时报告前端/后端来源、数据属于本地还是共享环境，以及执行或模型等能力是否实际可用；问题交接说明已生成、已上传、已恢复、已复现中的哪一步成立。

完成操作的依据是工具结果与相应检查，文档或计划本身不能作为成功证据。工程检查、浏览器验收和真实执行分别报告。使用指南的可读性检查不等于 Windows/macOS 安装、自动触发或连接已经验收。
