# 首次上手

首次准备时读取；已介绍但环境仍有缺项时只执行检查和准备段，跳过介绍段。本流程由 Agent 操作；成员无需找命令、复制长提示或手填连接配置。

## 先检查，再补缺项

1. 确认真实仓库、Git 状态、当前工作树及 `XJ_DEV_HOME`；保留他人改动。读取 CLI `--help` 后执行 `doctor --json` 和 `status --json`，检查运行时、依赖、已登记环境、所选模式及能力。`doctor` 会短暂探测工具目录可写性，不构造业务数据；新环境的 `status.ok: false` 不等于需要重置。
2. 查看当前环境记录的 enrollment 路径及已获准配置。若当前工作树没有登记，检查同一工具 home 的 `enrollment/registration.json`；不要据此断言成员未加入。当前身份读取 API 是 `tools/xj-dev/src/enrollment-client.mjs` 的 `readRegistration({ home })`，仅返回安全 ID、能力与私有文件路径，不能输出私钥、邀请正文或账号密码。已有记录只证明本机曾登记，在线权限仍以刷新及连接结果为准。随后查询[首引导状态](../../../docs/development-tooling.md#首引导状态)脚本，明确本次是否需要介绍；`introShown` 不参与就绪判断。
3. 仅有缺项时读取[平台前置条件](../../../tools/xj-dev/README.md#用法)，由 Agent 准备工具链与锁文件依赖；已有依赖复用。若要首次 `--here` 导入团队基线，先在两个工程按锁文件安装依赖，不用 `up` 绕过缺依赖，以免先播种内置数据而失去 `--here` 条件。其他首次启动可由 `up` 按需安装依赖；固定 Node 以 CLI 定位结果为准。系统确实要求本人确认时，只提示该项操作。
4. 按下节复用本人登记或通过 GitHub 接入；已有获准的私有 connection-v1 配置继续兼容。普通成员使用本人受限身份，Agent 准备连接材料，成员无需手填 SSH/CA 或提供管理员凭据。

只读提问不进入这些初始化步骤。已有配置或依赖也不等于首引导已完成；继续检查本次可用状态，首次仍须完成下面的介绍。

## GitHub 接入与身份续用

本节是接入契约；先核对当前 CLI `--help`、响应与服务实际支持情况。CLI 命令存在不代表云端已经部署。成员入口约定为：

```text
node tools/xj-dev/xj-dev.mjs login [--service FILE] [--wait-seconds N] [--mode local|cloud-api|cloud] [--no-start]
```

`N` 单次最多 60 秒。默认使用仓库内 `tools/xj-dev/team-service.json` 的公开可信服务 descriptor；仅明确使用另一个可信服务时传 `--service FILE`，无需成员创建私有邀请或填写连接配置。

- **同一 home 已有 registration**：复用原设备身份，通过 `refresh` 更新。当前工作树尚未绑定时，从前述安全注册结果取本人 `deviceFile`，执行 `refresh --device-file FILE` 绑定；不要求重复 GitHub 登录。仍以刷新与连接响应判断当前权限。
- **尚未登记**：由 Agent 执行 `login --no-start`，先登记再决定数据起点。收到 `authorization-required` 时，只向成员给出返回的 GitHub `verificationUri` 可点击链接与 `userCode`，说明“在 GitHub 网页确认即可，后续由 Agent 完成”；GitHub 密码或 token 由本人留在 GitHub，不进入聊天。
- **续办授权**：在同一 home/工作树执行 `login --wait-seconds 60 --no-start`，如曾指定服务与模式则沿用。按 CLI 返回的状态与间隔有限轮询；本轮仍待确认就保留事务、继续独立的本地准备，确认后续办。到期、拒绝或服务不可用时按实际响应恢复，不无限等待、不反复发起新授权。`--no-start` 成功只证明登记，不算环境就绪。
- **GitHub 用户尚未获批准**：只提示成员把自己的 GitHub 用户名告知维护者，获批准后续办；Agent 继续工具链、依赖及数据起点检查。普通成员不加载维护者管理说明，也不索要 owner SSH、管理员凭据或邀请附件。
- **明确维护兼容邀请接入时**：才读取[成员接入入口](../../../docs/development-access-operations.md#成员接入入口)，按实时帮助调用 `join`。GitHub 入口未提供、descriptor 缺失或远端未就绪时，交付可完成的本地准备与准确缺口，不自动退回索要邀请文件。

## 建立本地与获准连接

在已确认仓库根调用 `node tools/xj-dev/xj-dev.mjs ...`：

- **先决定数据起点，再启动。** 已有本地数据库、基线、凭据或环境状态一律复用，不能覆盖。当前工作树尚未初始化且采用团队固定起点时，先复用本人登记或 `login --no-start`，按[本轮推荐起点](../../../docs/development-tooling.md#本轮推荐起点)核对真实目录与收据，再执行 `baseline use NAME --team --version VERSION --here`，最后 `up` / `use local --json`。`--here` 不替换源码、不新建工作树，只首次导入本地数据；拒绝时保留现场，不通过 delete 再试。没有已发布/明确采用的团队起点时，本地内置起点以工具结果为准，不把它称为已采用团队基线。
- 有本人云端授权且获授 `page` 时，按上节完成登记/刷新，再验证 `use cloud --json` 与 `use cloud-api --json`；已有获准 connection-v1 继续兼容。每次核对页面/API 就绪、实际版本、数据目标和连接状态，不能用 SSH 成功代替应用验收。团队运行版本及基线选择需实时证据，不能从文档中的旧候选推断。
- `file:read`/`file:publish` 不包含页面或节点权限；file-only 成员仍可使用本地环境及获准文件操作，云端页面明确未授权。执行节点与模型服务按实际任务需要配置，缺少它们不阻止完成基础接入介绍。
- 浏览器访问前按[开发 CA 信任与精确撤销](../../../tools/xj-dev/README.md#开发-ca-的系统信任与精确撤销)完成本机信任和指纹读回；系统确认由本人完成。保持 HTTPS 校验，正常浏览器打开实际 `page.url`，用该环境私有账号材料验证获授角色的业务登录。密码不进入聊天、日志或 Git。本地展示按实际分配/课程关系选有任务的学生或有课程的教师，至少确认课程/任务列表，不机械取 `metadata.accounts` 首个同角色账号；空身份不等于基线丢数据，也不自动替成员制造业务数据；云端新受管学生可能尚无分配，按实际权限与列表说明。
- 首次验收可保留各模式独立入口；结束时按成员已表达的任务选择模式，没有偏好则回本地开发。切换不搬数据、不上传代码、不发布版本。`--no-start` 只登记，不计连接就绪。

失败保留同一 home、设备 key、已有数据和可用环境，按错误阶段修复；不靠重新授权、换 key 或重置掩盖故障。获准云服务暂不可用时，交付本地结果和准确缺口，恢复后只补该项，不重讲完整介绍。

## 主动介绍一次

准备完成后，用本次结果说明以下内容，给可直接打开的入口和自然语言用法，无需堆命令：

| 功能与适用场景 | 必须讲清的实际边界 |
| --- | --- |
| 本地完整开发：改业务、联调前后端、验证保存/提交/反馈 | 本工作树独立数据库和浏览器身份；重复启动沿用数据；当前可用角色以本地账号文件为准 |
| 本地前端连云端 API：调页面和热更新；云端版本：核对团队部署行为 | 两者写共享集成数据；云端页面不会包含本地未发布代码，所见版本以响应为准 |
| 固定基线：在一致数据起点开发；复现包：把问题现场交给同伴 | 首次未初始化工作树可用 `--here` 只导入数据，已有环境采用/复现恢复另建隔离副本；发布、上传、恢复、实际复现分别核对 |
| 节点运行与模型辅导 | 逐项报告 execution/models 的实际可用性及验证范围；页面就绪不代表能编译、仿真或调用模型 |
| 日常使用 | 可以直接说“启动开发”“本地页面连云端后端”“回本地”“把这个问题交给同伴”；停止保留数据，删除需明确目标 |

说明代码进 Git，数据库、密码、邀请、设备密钥和本机引导状态留在仓库外；共享集成数据不会自动同步回本地。真实编译/仿真、模型业务与教学效果未验证时直接说未验证。

介绍已实际展示后，调用 `node skills/xunjie-development/scripts/intro-state.mjs mark-shown --worktree <项目根>`，下次新会话查询同一受限 home 标记并跳过介绍。准备/连接失败且尚未介绍时不 mark；如果已解释现状及缺口，mark 只表示“说明已展示”，接入仍按真实失败阶段续做。完整时机见[首引导状态](../../../docs/development-tooling.md#首引导状态)。
