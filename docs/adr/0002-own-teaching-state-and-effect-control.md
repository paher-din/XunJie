# ADR 0002：掌握教学状态与执行控制，限制自研运行时范围

日期：2026-10-18。状态：初步工程决定，纳入 Wayfinder 重新评估。依据：Robert 对 Q8 的技术判断委托；L5 明确后续可以替换或推翻此前工程设计。本记录不表示用户逐项批准旧附件，也不表示已完成内核接入比较或运行验收。

2026-10-23 更新：本文下述 AI SDK Core 选型属于此前判断，已由 [三协议模型接入：第三方端点能力、适配与原生续接](https://github.com/paher-din/XunJie/issues/115) 的模型连接层决定替代：采用直接协议 SDK 加薄 adapter，依据与代价见 [实际端点评估](../references/2026-10-23-model-endpoint-assessment.md)。本文关于教学状态与执行控制的分工仍是总体架构候选；完整 Agent 内核由对应 Wayfinder 议题继续评估。

## 问题

学生作品不断变化，Agent 需要连续引导、调用工具并等待学生回应。实际输入、执行结果和学习证据不能只保存在模型消息里；但这个要求本身不足以证明必须自研完整 Agent 框架。

## 决定

循阶持有工作区事实、教学活动状态、执行意图、结果和学习证据。TeachingRuntime 首期只实现触发策略、上下文取证、一次有界运行及教学交付：TeachingEpisode 是数据，TeachingController 是触发与等待规则，RunDriver 组织有限的模型与工具步骤。

模型调用默认采用 AI SDK Core，通过 ModelPort 隔离 provider。先收齐并保存助手响应与工具意图，再经 ToolExecutor 检查和执行，记录结果后继续判断；发布教学动作前检查依据与教学策略。原生回放数据按实际路线保存，不只留可见文本。

Core 的工具 `execute` 可以省略，因此这条顺序有公开接口基础。选择它是因为当前有限流程可以直接组织，暂时不需要另一个通用会话/插件内核；不是因为领域状态自主天然排斥其他循环，也不是因为仓库已经安装它。[AI SDK 工具接口](https://ai-sdk.dev/docs/ai-sdk-core/tools-and-tool-calling)

Pi 的上下文准备与工具钩子使其成为可行备选；DeepSeek Harness 可复用更完整的插件与会话框架，同时增加集成其模型的工作。当前没有三个方案的接入原型或性能比较，不宣称 Core 的模型效果或性能更好。[源码核对与比较](../references/2026-10-18-architecture-checks.md#内核取舍的工程判断)

## 代价与停止扩张条件

循阶承担预算、取消、步骤记录、工具结果核实及恢复的必要实现。这不是只写一个 `while` 循环，但也不包含通用团队调度、终端会话、大型插件内核或事件溯源平台。

若后续需要大量队列、调度或恢复设施，应先在 RunDriver 边界比较接入现成循环的成本，再决定新增自研能力。换循环不改变作品权限、证据归属、工具意图或教学动作契约。

## 实现约束与验证

初期运行在模块化应用服务内，执行节点独立。课程工具与教学产物共用 UI 宿主、状态及选区/事件桥接；不为每个领域概念增加服务或数据库。

用一门课程的一条完整活动验证当前选择：取到相关输入、执行不重复、结果未知可核实、学生回应能继续教学。三协议与实际端点的高级能力、原生续接和取消分别验收。完整设计见[架构基线](../student-agent-architecture.md)。
