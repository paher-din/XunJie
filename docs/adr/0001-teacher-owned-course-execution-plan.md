# ADR 0001：教师发布课程运行方案，平台按设备执行

日期：2026-10-18。状态：产品原则已明确，工程契约纳入 Wayfinder 重评。依据：Robert 对 Q7 的产品决定；具体契约按 Q8 委托完成初步工程判断，L5 允许重新设计和替换；L7 澄清开发共享环境不决定产品部署。实现和跨平台验收尚未完成。

2026-10-23 更新：运行路线、跨课程生命周期及教师低门槛准备已由[本地优先执行决议](https://github.com/paher-din/XunJie/issues/114#issuecomment-6363162710)明确，本 ADR 保留此前取舍背景；具体答案以该决议为准，插件格式和总体架构继续在相应议题设计。

## 问题

课程工具可能运行在浏览器、本机组件或远端。把节点列表交给学生会把教学准备转化成部署选择；只在设计时写死某台机器，又无法适应真实设备差异。

## 决定

CoursePack 随课程发布版本化的 CourseExecutionPlan。能力包声明所需运行环境、版本、资源和权限；教师或教师 Agent 评估本地方案，只有本地不能满足时才配置必要的远端资源及适用条件。课程、包与方案保持版本关联。

平台在活动前检查实际设备，并在发布方案内匹配执行环境。缺少尚可安装的组件先引导准备，不自动转云；没有匹配路径时说明缺少的条件，由教师修订方案或完成环境准备。学生不选择节点。

本地显示与交互即时处理。学生手动运行先在本机持久绑定命令、输入及身份，再直接提交本地执行器，随后同步记录。应用服务上的 Agent 判断和面向教师的提交等待相关记录同步完成。Agent 发起的命令先保存意图，并由实际执行节点检查依据和权限。

每个任务固定原节点、节点代际、运行环境和输入。失联或结果未知先核实，不自动转到其他位置重跑。即使课程允许远端路径，也不能把任务恢复当作新任务调度。

## 代价与边界

需要环境检测、运行时版本检查以及统一的查询与结果契约。首条 ALU 采用浏览器 Worker 内 Icarus/WASM，不需要本机设备配对或 localhost 连接；未来确需本机组件的能力再验证配对、浏览器连接权限、通信与执行隔离，不能把这些成本默认加到全部课程。依赖准备和可修复故障由产品与 Agent 协助，教师不负责排查节点。

本地计算不保证源码不出机、完整离线教学或对学生电脑结果的防篡改证明。本轮不增加这些承诺。教师配置的是课程执行能力，平台交付方案仍负责应用服务、数据库和模型凭据的部署。

按 [L7](../student-agent-decisions.md#开发协作与产品运行边界l7)，当前云端共享数据和部分服务仅是尽量小的开发协作环境，用来减少成员设备、环境与数据差异导致的调试难以复现。开发共享基线与产品运行拓扑分别设计；当前环境不构成最终部署决定，也不锁定首版数据库或资源存储。教师设计运行方案、尽量学生本地执行的产品原则保持不变，工程契约与部署候选仍可重新设计或推翻。

开发复现需能对齐代码 commit、工具链与配置版本、相关数据/schema/seed 版本，记录输入、步骤与预期和实际结果，并避免成员测试数据和任务互相污染。具体隔离方式待设计，这些要求不表示已有实现，也不预选容器或分库。

## 被替换的建议

撤销“学生可以在本地组件与学校/云节点之间自行选择”。同时不采用“一遇本机问题就静默上云”，也不要求教师预先指定每位学生的物理节点。

## 验证

首条 ALU 已有 Mac 原生与浏览器功能小样本，来源和限制见[讨论与验证记录](../references/2026-10-23-local-execution-proposal.md)。可复现 WASM 构建、系统模块诊断修正、Windows/Edge、产品输入绑定/同步/恢复，以及教师工具准备体验仍待实施与验收。后续还需以不同类型工具验证有限作业、保持状态会话与非计算活动的边界；不能以 ALU 探针替代跨课程或教学效果验收。[执行位置研究](../references/2026-10-18-execution-topology-research.md)保留为早期比较背景。
