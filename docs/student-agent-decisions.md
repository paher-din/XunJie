## 最初 idea 中需要保留的产品原则

教师主导教学设计与最终判断；Agent 提供主动、引导式帮助，让学生参与思考；项目完成与知识掌握分开判断；个性化需要可持续维护的学习画像；课程工具与教学产物可复用。教师设计 Agent、教学分析 Agent 与跨学生案例库保留为产品方向，本轮不展开其实现。

I0 中的“零适配门槛”按 L8 拆成可验证的边界：教师可复用或借助 Agent 创建新工具，现有执行能力内的新依赖通过工具与环境装配接入；超出已有接口或执行能力的机制才需要适配。配置与检查应由产品和 Agent 协助，不能把“可配置”变成要求教师手写清单或自行集成。架构不能承诺自动理解所有外部工具或无需适配就支持任意系统能力。

## 本轮工程决定

| 编号 | 决定 | 依据与代价 |
| --- | --- | --- |
| P1 | 范围受限的自有 TeachingRuntime 是初步候选，掌握教学触发、取证、执行意图与交付；模型连接层原有 Core 选型已由[三协议模型接入议题](https://github.com/paher-din/XunJie/issues/115)替代，完整内核另议。 | 教学状态必须独立于模型会话，但这不自动要求自研完整内核。当前有限流程可直接组织，承担必要步骤与恢复；扩张前重新比较现成循环。见 [ADR 0002](adr/0002-own-teaching-state-and-effect-control.md)。 |
| P2 | CoursePack 选择能力包并携带课程运行方案；开发者与教师 Agent 产出的工具通过同一 Workspace SDK 接入。 | 教师定制能力不能依赖改写主前端；包声明环境需求，教师在设计阶段确定本地/远端策略，平台运行时检查与调度。 |
| P3 | 工作区事实、执行记录、学习证据、画像判断语义分开；使用一个工作区对象体系和一套持久化边界。 | 避免任务成功等于掌握，也避免 LiveWorkspace、ArtifactStore 和插件各维护一份交互状态。无需为这些概念分别部署数据库或服务。 |
| P4 | 受控教学组件与隔离自由页面共用 UI 宿主及状态/选区/事件契约。优先抽取 OpenIntelligentUI 的局部渲染能力。 | 课程工具是可复用定义，生成卡片是教学活动中的内容实例；不建设两套桥接。上游不成为状态恢复的权威，也不绑定其完整后端。 |
| P5 | 初期采用模块化应用服务与独立执行节点；工具本地优先，教师配置必要远端路径，学生只完成课程环境准备。 | 不按每个模块拆微服务。高频交互与手动本地实验直接执行，命令和输入先在本机持久绑定，再同步记录；云端判断与教师提交等待相关同步。见 [ADR 0001](adr/0001-teacher-owned-course-execution-plan.md)。 |

上述 P1—P5 记录 L4 阶段的工程判断，整体论证见[初步架构候选](student-agent-architecture.md)。L5 明确后续不仅验证这些方案，也重新比较和选择架构；它们不自动成为地图的不可变前提。协议端点互操作、浏览器/WASM 覆盖范围、本地组件安装形态及渲染器抽离仍是验证工作，不以文档判断代替实测。

## 第三轮决定与架构重评

**Q7 用户决定：运行方案由教师设计，优先本地。** 原提问把执行位置交给学生选择，不符合产品意图，现已撤销该建议。教师/教师 Agent 先评估本地环境能否满足课程；仅对无法满足的能力配置远端资源。学生按发布的课程方案使用，平台负责设备检测和方案内调度。

教师决定运行规则，不需要预先指定每位学生的物理节点。设备不符合要求时，平台引导环境准备；只有课程已配置相应远端替代路径时才能使用，不能静默把任务转上云或展示节点选择器。

**Q8 用户委托技术判断。** 用户没有对五条旧方案作统一批准，而是要求自行判断是否合适。本轮据此确定 P1—P5，修正教师运行方案、统一 UI/状态宿主、限制自研范围与本地交互路径；不再把 SDK 选择或整体技术结论留作等待用户勾选的事项。

当前研究见[执行位置研究](references/2026-10-18-execution-topology-research.md)。它证明相关机制有边界，不代表本项目已通过跨平台兼容或性能验收。

## 开发协作与产品运行边界（L7）

当前共享数据和部分服务的云端环境服务于团队开发复现，应保持尽量小的范围；它不决定产品的应用服务、执行节点或数据最终放在哪里，也不锁定首版数据库和资源存储。产品仍按 Q7 由教师设计课程运行方案、尽量学生本地执行。P1—P5 及部署组合继续作为可重新设计或推翻的工程候选。

开发复现需能对齐代码 commit、工具链与配置版本、相关数据/schema/seed 版本，并记录输入、复现步骤、预期与实际结果；共享环境还需避免成员测试数据和任务互相污染。这里只提出最小复现基线要求，具体隔离与交付方式待设计，不表示这些能力已经实现。运行位置与部署候选见[架构正文](student-agent-architecture.md#运行位置与部署组合)，课程运行原则见 [ADR 0001](adr/0001-teacher-owned-course-execution-plan.md)。

## 后续实施与验证

下一阶段通过 Wayfinder 逐项完成研究、讨论和设计，形成可实施的新架构与重构路线。下面既包含待验证机制，也包含需要重新审视的设计领域，不是只给现有方案补实现细节：

入口为 [学生端 Agent 与工作区重新设计：数字逻辑与部件设计先行](https://github.com/paher-din/XunJie/issues/112)。地图及其原生子议题、阻塞关系是后续工作状态的依据；同一主题可跨会话推进。建图阶段只发布，不认领或解决议题。

- 课程运行方案：按[已形成的执行决议](https://github.com/paher-din/XunJie/issues/114#issuecomment-6363162710)安排实施，验证 WASM 构建、目标设备矩阵、自动准备及恢复；工具接入和重构验收还须落实跨课程扩展与教师使用体验。
- 模型接入：固定版本与实际第三方端点，完成三协议、工具往返、原生续接与取消验证。
- 统一产物宿主：组件与自由页面共享状态/选区/事件，验证生成页面恢复与流式预览。
- 数据与迁移：独立确定首个产品部署组合的数据库和资源存储，不沿用开发共享环境作为既定选型；盘点实际需迁移的数据，离线与多端协同另立明确需求。
- 完整教学活动：从“数字逻辑与部件设计”确定具体活动、目标系统、实际端点与工具能力，重新设计实时编辑、引用、本地执行、IP 互动、学生回应、证据更新和教师提交，再选第二类工具检验通用性。
