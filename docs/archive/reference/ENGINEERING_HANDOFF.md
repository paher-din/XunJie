# 工程衔接说明

整理日期：2026-10-08（Asia/Shanghai）。本文件筛选此前 student-ide 0.6.0 与 Round 0 中对正式首版有用的契约和经验，团队可直接按本仓库文档开展设计与实现。正式数据模型、接口、权限和运行限额以 [TECH_DESIGN](../product/TECH_DESIGN.md) 为准，验收清单以 [MVP_SPEC](../product/MVP_SPEC.md) 为准。

## 复用范围与前提

| 已有经验 | 正式产品可以沿用什么 | 仍须实现或重新验收什么 |
| --- | --- | --- |
| Monaco 编辑、选区与草稿确认 | 当前对象、实例、版本、内容哈希和确认状态的语义 | 按团队 UI 接入；账号与课程范围、多个页面冲突、掉线恢复 |
| 文本事件、去重与回放 | 追加记录、确认序号、缺口、同名重建和历史定位 | 正式持久化、课程/Attempt 范围、权限裁剪、备份与恢复 |
| 按需语言与运行记录 | 工具链版本、源码快照、编译/执行分离、失败分类 | 受批准的首发语言配置和独立执行环境，不沿用宿主进程执行 |
| 编辑时静态诊断 | 分析已确认草稿、绑定版本、丢弃过期结果、区分环境失败 | 首发语言和实际 UI 的独立验收，隔离分析所需资源 |
| TeacherReview 与状态 revision | 纠正追加新版本、旧候选保留、下一次决策读取有效状态 | 真实教师身份、数据库事务、并发控制和待投递动作失效 |

此处迁入的是完整可读的语义和边界，旧插件实现并不是本仓库已经可导入的依赖。可以直接依据正式契约实现；如果后续选择迁用旧代码，再引入具体模块、依赖声明和必要测试，不以团队能够访问某台开发机为前提。

旧 MCP、Hook、loopback 服务和本地文件系统不是正式 Web 的认证或部署方案。教学内核不依赖 Codex，团队 UI 也无需迁用旧实验界面。

## 编辑与对象版本

- 代码求助、诊断、运行和提交都绑定文件实例、内容版本、哈希和作品快照。路径与行列号只在对应版本内解释，不能把当前路径或磁盘旧内容当作学生的未保存草稿。
- 同名文件回收后重建是新的实例；历史回放按实例和创建/回收事件判断当时状态，不只看当前的 `deleted` 字段。
- 代码范围使用一基 UTF-16 行列。增量编辑、中文和 emoji 的定位要核验；编译器字节偏移不能直接作为编辑器列号。
- 历史 `modelId` 表示文档实例，不是模型供应商版本；迁用引用时保留其来源含义，正式对象同时具有账号、课程和 Attempt 范围。
- 迟到的提示或诊断绑定旧对象时失效，不能用较新的接收时间覆盖较新的文档版本。

正式 ObjectRef 字段与校验关系见 TECH_DESIGN 第 4.1 节，团队按这一契约对接 UI。

## 记录确认与回放

学生编辑的本机草稿、服务端已确认作品和磁盘/持久化内容需要分别表达。界面只在服务端 ACK 后显示已同步；断线、重复发送、版本冲突和服务恢复要保留清楚的状态。

来源通道、原始操作、工具结果、模型解释和教师决定分别保存。编辑增量不是“一次按键”，日志内部连续也不能换算成真实学习过程全部覆盖。

暂停尝试、暂停过程采集和关闭主动提示是独立状态。采集关闭仍可保存必要作品并处理学生显式求助、运行和提交，但不能补传关闭期间的逐次编辑；缺口按时间区间保留。

原始事件追加保存，分析可以修订，历史不因新结论回写。账号切换、跨 Attempt 回放、多个页面与服务重启应在新产品中独立检查，不能把单机实验的日志保留结果当作这些能力已实现。

## 运行与语言环境

环境 smoke 验证只证明指定样例下工具链可用，不证明学生代码正确、课程目标通过或完整工程兼容。

可沿用的配置语义包括语言标识、扩展名、单文件/工程范围、实际工具链版本、批准的编译/执行步骤、源码采集范围和独立 smoke 样例。更新配置使旧验证失效；缺环境、工具链变化或启动失败与学生代码错误分别表达。

命令和参数由受信配置管理，参数单独传递，不接受学生或模型提供的任意 shell 字符串。环境变量按白名单提供，凭据不传入学生进程；注册环境不授权修改学生答案。

旧原型只将入口取自确认缓冲区，部分其他文件取自已保存磁盘，外部库也未完全冻结。正式多文件运行应绑定本次参与文件的不可变作品快照，并记录 runtime 配置版本与镜像 digest；不能因此宣称旧环境完全可复现。

编译、执行、课程检查和正式评价分别保存。编译失败不执行，退出码 0 和学生 stdout 中的 `passed` 不构成课程验收；可信验证器在学生进程之外判断，私有答案不提供给学生容器或辅导模型。

原 runner 是宿主进程，不能作为多人代码沙箱。正式首版仍按 TECH_DESIGN 第 8 节使用独立执行节点和受限作业容器，资源与超时限额按 MVP_SPEC，不能因旧实验可运行而回退到应用宿主执行。

## 编辑时诊断

可沿用的链路是：学生编辑 → 确认当前草稿 → 静态分析 → 检查对象版本 → 展示标记及问题信息。静态分析不执行学生答案，不修改作品，模型没有代学生触发运行或写代码的权限。

| 契约 | 必要含义 |
| --- | --- |
| 输入 | 获准文件、实例、版本、源码/来源集哈希和语言配置；命令不能由诊断请求任意指定 |
| 输出 | 文件、内容哈希、一基 UTF-16 范围、严重度、消息和来源；不以重复保存整份源码替代关联 |
| 状态 | 完成、需准备环境、未接入、不可用、超时、暂停、阻断、繁忙、过期分别表达；空列表不能掩盖检查未执行 |
| 时序 | 快速编辑、切文件、回收和同名重建后的旧结果不能覆盖新版本；历史结果可保留，当前结果失效 |
| 资源 | 分析限时、限输出、限并发，合并等待中的旧请求，不能无限拖延保存或学生显式运行 |

历史 0.6.0 曾覆盖 C/C++、Python、JavaScript/TypeScript、JSON、HTML/CSS；这不是要求首版同时交付全部语言。Python 当时仅 AST 语法，HTML 为基本结构检查，外部包类型、任意工程配置、完整 LSP、补全、符号跳转和调试未因此成为已实现能力。

旧自定义诊断器使用只读 JSON 输入 `{path, text, sources}`，输出为诊断数组或 `{diagnostics}`，位置使用一基 UTF-16 行列。若首版需要此适配方式，诊断器必须由维护者批准并验证，在受限环境中处理源码，不执行不可信课程脚本。

具体诊断方式随首发语言冻结。旧原型的进程数量、超时和页面宽度不是正式首版限额或 UI 布局要求，实际集成按当前规格验收。

## 教师纠正与历史版本

TeacherReview 指向被复核的状态版本、依据和帮助条件，追加新的有效 revision，保留原候选、反证和教师理由。状态更新与依赖失效需要同一业务事务，旧复核表单不能覆盖新决定。

下一次教学决策自动读取适用课程和目标的有效状态，并绑定 decisionEpoch；待展示动作基于已撤回的结论时取消或标记失效。上下文读到了新 revision 与教学支持确实适切是不同验收问题，不能要求每次话术变化来证明纠正生效。

来源通道、静态请求标记、教师转述与账号归属都不自动证明现实操作者身份。正式权限来自服务端会话、课程成员与资源范围，模型只能提出分析候选，不能造观察记录或写正式评价。

## 历史试验对开发的影响

Round 0 已于 2026-10-05 中止，状态为 `CANCELLED_BY_USER`。T0 用虚构角色和数据验证过对象关系、纠正保存和恢复；模拟使用构造情境，真实 T1 没有完成 A→教师纠正→B 的完整教学闭环。以下只作为工程风险线索，不认定学习效果。

| 历史发现 | 正式开发需要关注什么 |
| --- | --- |
| 服务、聊天、MCP 与项目范围曾需人工对齐 | 正常 UI 路径能明确当前用户、课程、作品与连接状态，不依赖维护者补目录上下文 |
| 自报完成、保存源码、编译与课程验收未闭合 | 提交固定快照，分别呈现运行、课程检查、解释和未知；未实际编译的版本不能记作已测得失败 |
| 编辑日志很多，但正式 TeachingAction 与展示回执不完整 | 应用直接保存教学消息原文及实际展示/取消回执，并关联后续作品与解释；不靠 Hook 或回忆补齐 |
| 状态全部 unknown 避免了过度推断，但没有证明画像有用 | 保留未知，同时说明已有证据、缺口和可用下一步；保守表达不等于教学价值已验证 |
| 部分提示没有给完整答案，仍可能提前提供关键策略 | 检查教学目的、支架程度、学生选择与后续表现，不只检查动作标签或完整答案是否出现 |
| 新 revision 可以自动读取，但不保证支持发生有效变化 | 数据/版本验收与真实教学语义验收分别进行 |

不恢复旧 Session B、补验、开跑包或旧服务。正式实现仍需完成 MVP 的工程和真实使用验收，历史通过数不计入新产品通过数。
