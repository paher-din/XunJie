# 产品研究依据

整理日期：2026-10-08（Asia/Shanghai）。本文件从此前研究中筛出影响当前首版的结论与限制，供团队直接查阅；不要求访问原研究工作空间。需求与范围以 [PRD](../product/PRD.md)、[MVP_SPEC](../product/MVP_SPEC.md) 为准，技术推荐以 [TECH_DESIGN](../product/TECH_DESIGN.md) 为准。

## 产品方向与三条能力线

产品的主线是教师与学生围绕真实项目展开工作。学生画像和过程记录帮助选择支持、解释表现和改进教学，不能成为强迫学生逐步接受测验的理由。

| 能力线 | 项目中的观察机会 | 不能替代它的指标 |
| --- | --- | --- |
| 学科知识与技能 | 解释概念、实施方法、预测结果、迁移到新条件 | 程序通过、作品完成或模型自报掌握率 |
| 项目能力 | 界定问题、选择路线、比较方案、试验修订、交付反思 | 编辑次数、在线时长或作品总分 |
| 人机协同与 AI 素养 | 合理提问和分工、核查建议、发现错误、调整协作 | 提示词长度、求助次数或建议采纳率 |

三条能力线与作品质量分别表达。教师按课程选择少量目标和观察方式，不要求每次互动覆盖全部能力，也不将缺少日志解释为学生能力不足。

首版聚焦高校 CS 课程、个人项目、一位教师和少量真实学生。独立 Web 应用与团队成员负责 Web UI 是已确认的方向；具体课程、语言、模型、后台技术版本和试点条件仍按产品文档冻结。

## 教师设计与反馈

教师与 Agent 在同一份蓝图上组织项目目标、资料、任务、证据、量规和帮助政策。模型提供可审阅的局部建议，教师确认活动版本；不能让现场辅导每轮重新生成任务或静默改变评价要求。

教师分析需要能够进入一次具体行动：查阅原文、纠正判断、提出反馈、允许修订、推荐资源或改进下一版项目。只展示汇总图表、日志数量和能力分数不足以说明教学价值。

个人状态纠正与课程设计变更分别处理。前者形成新的有效判断并影响后续支持，后者形成新的活动版本；二者都保留历史，不反向改写原始表现。

## 共同对象与交互连续性

学生的求助应绑定正在处理的项目、代码版本、运行结果或资料段落。Agent 所读对象与学生当前对象需要可核对，过期提示不能继续作为当前建议展示。

支持应保留学生的控制权：允许拒绝建议、停止生成、返回原任务、继续自主探索和恢复中断后的工作。缺少信息时可以保留未知或提出必要澄清，不默认把每次求助改成口试。

团队交付的 Web UI 承载这些行为。本研究不指定页面、导航、组件布局或前端框架；已有案例中的多栏界面、虚拟场景、白板和六屏原型不是首版必建清单。

## 研究证据与适用范围

以下沿用原研究在 2026-10-01 复核时的有限结论。本次整理未重新审查论文或验证外部产品当前版本。

| 可访问的一手来源 | 支持的有限判断 | 对本项目的限制 |
| --- | --- | --- |
| [Bastani 等作者公开论文](https://hamsabastani.github.io/education_llm.pdf) | 特定高中数学实验中，辅助下的练习表现与无辅助考试表现需要分别观察 | 不证明高校自主项目 Agent 必然提升学习，也不将练习完成作为独立掌握 |
| [Tutor CoPilot，作者 arXiv v2](https://arxiv.org/abs/2410.03017v2) | 辅助真人导师的研究为人机协作支持提供线索 | 研究对象与自主教学 Agent 不同，不直接外推成首版效果承诺 |
| [Kaliisa、Jivet、Prinsloo，2023](https://link.springer.com/article/10.1186/s41239-023-00394-6) | 教师看板中的觉察与可行动性需要分别考察 | 增加按钮或图表不代表已改善教学或减少教师工作 |

官方技术文档说明机制存在，源码阅读说明被阅读范围中的实现事实，模型模拟说明构造输入下的行为；这些均不能替代本项目的真实使用验收。多个团队报告引用同一论文仍只算一项原始研究，模型评阅与多个模型的一致意见也不是真人教学评价的替代品。

## 首版取舍

| 研究涉及的方向 | 当前取舍 | 重新考虑的条件 |
| --- | --- | --- |
| 学生画像与长期记忆 | 保存有来源、帮助条件、反证和未知的版本化主张；不直接用自由文本人物总结替代正式状态 | 现有明确检索和状态结构经固定样例证明不足 |
| BKT、深度知识追踪、在线策略训练 | 暂不纳入首版 | 有适合的数据、明确任务和可解释评估，且收益足以支持复杂度 |
| 多个自主 Agent、通用工作流平台 | 首版使用有界调用，业务状态与授权由应用负责 | 持久化分支或外部等待实际成为主要复杂度 |
| LMS 集成、团队协作、多学科场景、三维与语音课堂 | 暂不纳入首版 | 核心流程与试点需求证明需要，并先修订产品范围 |
| 独立模拟阶段、旧 Round 0 待办 | Round 0 已中止，不作为产品开发前置条件 | 只有新的明确研究指令才安排实验；正常工程与真实使用验证仍需执行 |

这些取舍来自当前产品文档，不将旧报告的 P0/P1、待办或建议实施顺序当作开发授权。
