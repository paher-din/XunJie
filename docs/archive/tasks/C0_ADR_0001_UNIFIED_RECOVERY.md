# C0 ADR-0001：统一恢复代际候选

日期：2026-10-09。状态：Q3～Q5 讨论决定已由项目负责人确认，具体共享契约待 A/B 会审；不授权代码、数据库变更或产品基线写入。

在 grill-with-docs 第 1 轮，项目负责人以“三项按推荐”确认以下方向：“是否把恢复代际作为全应用统一的候选方案，由 A 管恢复、C 接入记录与执行？”推荐内容原文：“统一处理。代价是恢复后旧页面和旧作业必须重新核对；仍需 A/B 会审。”

回退旧备份可能丢失应用侧的命令/作业记录，而独立执行节点仍已接受旧运行。选择统一候选而非各模块分别建立恢复边界，是为了让旧页面、作业完成和执行控制消息一致地重新核对；普通进程重启维持原代际，旧备份恢复创建新代际。

第 2 轮，项目负责人以“全部接受”确认 Q4：“恢复旧备份后，即使已证实旧作业尚未启动，也不自动续跑，是否接受？”推荐原文：“接受。原发起者核对恢复后的内容，再明确发起新操作；普通进程重启仍续取有效作业。”这项取舍保留重新发起的成本，避免旧备份恢复替发起者继续已过时的操作；不据此改变学生尝试状态或伪称未知运行已终止。

同轮确认 Q5：“长期账本只保存对账必要的作业事实、请求关联、摘要和结果引用，不额外长期复制学生源码与教学消息，是否接受？”推荐原文：“接受。正文由应用保存；回退后丢失的内容明确标为缺失，不能靠元数据补造。”选择最小事实账本而非冗余正文备份，是为了保持数据处理范围并避免双份正文的一致性负担；运行必需的临时数据和待交付结果不省略，具体保留/处理另按 D-03 落实。

账本关联、恢复代际的可靠登记/传播、执行启动与取消窗口、保留/资源参数和实际恢复验证仍需会审与实现证明，不能把本记录当作恢复问题已解决。
