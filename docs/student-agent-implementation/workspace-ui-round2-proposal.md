# 工作区与首页第二轮 UI 方案（待确认）

日期：2026-11-16。依据：本轮验收意见及两张截图、根目录 DESIGN.md、旧版 FileStrip 和首页实现、当前产品源码、@xunjie/ui。使用 Impeccable shape 流程，模式为 Operate。本文件只提出方案，不表示已实现；本轮未修改产品代码。

## 1. 方向与范围

沿用已确认的旧版视觉与交互：文件菜单管理项目文件，标签管理打开的视图；阅读工具未打开内容时提供可选材料；首页使用课程与任务的筛选和卡片体系。保留已验收的文件名反馈、空作品入口。Agent 相关部分仍按原团队边界暂缓。

参考入口：旧版 http://127.0.0.1:5601/；组件目录 http://127.0.0.1:5601/ui-catalog.html；当前产品 http://127.0.0.1:50453/。这些服务均为本机开发服务，旧版使用合成数据。

## 2. 左栏：统一“目标与材料”及文字层级

- 栏标题由“任务与资料”改为“目标与材料”，与顶部开关、阅读说明、无障碍名称一致。保留栏内收起按钮。
- 栏标题使用 DESIGN 的 17px/600 标题档；学习目标、任务要求、学习材料、我的 PDF 资料、我的个人笔记使用同一 17px/400 分区标题档，不再由浏览器默认 h3/h4 决定大小。
- 长篇目标与要求使用 15px 正文；文件行和紧凑操作使用 13px；版本、页数、限额等辅助信息使用 12px、muted。标题保留既有中文衬线，正文与控件使用系统字体。
- 分区统一节奏：20px 内容边距、24px 分区间距、12px 标题至内容间距；按既有 token 实现。标题与“添加”按钮同行，窄宽度时操作换行，长名称换行，不挤压按钮。
- 材料栏独立滚动；浅深主题使用相同层级和尺寸。目标、任务要求和个人材料不使用同等醒目的大标题争抢注意力。

## 3. 作品文件栏：迁移旧版 FileStrip 的交互

### 推荐结构

编辑器顶部恢复旧版的“文件 + 数量”按钮，右侧是已打开文件标签。取消本批新增的独立“新建文件”和“文件操作”两组常驻按钮；新建与管理回到文件菜单，空作品的直接新建按钮继续保留，并直接打开菜单中的命名框。

菜单中每行包含文件类型图标、完整文件名、当前选中状态、文件操作入口。底部为“新建文件”，点击后在菜单内原位命名。保持已验收的名称校验和就地反馈。

文件行操作推荐用三点菜单收纳“重命名”“删除”，减少每行多个文字按钮的噪声；打开文件与管理文件是平级控件，不在打开按钮中嵌套按钮。键盘可以独立到达操作入口。

### 操作定义

| 动作 | 预期行为 |
| --- | --- |
| 打开 | 打开对应稳定 objectId 的文件；已打开则激活已有标签；关闭菜单并将焦点交给编辑区 |
| 关闭标签 | 只关闭视图，不删除文件；关闭当前标签后选择相邻标签，最后一个关闭后显示“没有打开的文件”和“打开文件／新建文件”入口 |
| 新建 | 菜单内就地命名；Enter 创建、Escape 取消；成功打开新文件，失败保留名称及错误 |
| 重命名 | 当前文件行原位编辑，预填原名称；成功后菜单和标签同步变化，objectId、正文和引用身份保持；失败保留输入 |
| 删除 | 使用现有 ConfirmationDialog，明确具体文件名和从当前作品移除的影响；取消无改动；成功才移除文件及标签，失败保持正文与标签 |
| 导出备份 | 保留现有作品备份能力，放在文件菜单底部独立分组，可在未打开任何标签时使用 |

删除不能表述为“关闭标签”，也不能承诺目前没有的回收站恢复。旧 FileStrip 中的“回收／恢复／待确认”与旧作品生命周期、确认保存耦合；当前产品是 workspace.remove 和自动保存。本轮建议迁移其外观、菜单结构、命名与标签操作，使用真实的删除／重命名能力，不引入旧存储流程。

### 组件方案

直接以 `@xunjie/ui/workspace` 中的 FileStrip 为迁移对象，复用其文件图标、菜单行、命名布局和 FileTabs。当前 FileStrip 的公开参数仍强制要求旧 WorkspaceFile、回收状态与确认状态，不能以伪造 confirmed 或 lifecycle 接入。

建议在同一组件库内抽出不依赖旧文件生命周期的展示层（文件显示项、打开标签、命名、行操作插槽），让旧 FileStrip 和当前 ActivityWorkspace 共用；旧包装继续提供回收／恢复，当前调用方提供重命名／删除。业务保存和身份继续由当前 workspace 控制。同步补充目录示例，避免另造一份页面私有 FileStrip。

## 4. PDF 与个人笔记：阅读器首页显示材料列表

### 未打开材料时

保留“返回作品”和工具标题。将现有只有说明的区域改成“选择要阅读的 PDF／个人笔记”：标题、简短说明、真实材料列表；有内容时列表是主角，不放大插画或巨大空白。

PDF 分为“课程 PDF”和“我的 PDF”。课程组来自当前活动绑定版本的 PDF 材料元信息，即使尚未导入为 PdfDocument 也必须显示；个人组来自现有 pdf.documents。已导入课程 PDF 通过 courseSource 关联，避免在两个来源中重复出现。非 PDF 课程材料不混入此页。

PDF 行显示图标、名称、来源及真实可用的页数／处理状态，右侧“打开”。尚未导入的课程 PDF 不编造页数；点击沿用 pdf.openCourse(materialId)，已有文档沿用 pdf.openDocument(doc)。个人笔记行显示名称、当前版本和类型，沿用 personal.open(material)。不通过名称推断身份。

左栏继续承担目标查看、上传／添加、更新及移除；中央列表承担选择和阅读。同一 controller 提供数据及操作，不复制第二份状态。中央提供“添加 PDF／添加笔记”快捷入口时，应直接调用同一文件选择器或同一添加表单；表单只保留一个实例，不再要求用户先找侧栏。

### 阅读及切换

- 点击条目后在当前中央工具内加载并进入阅读；只因用户点击才打开材料，不自动打开第一份。
- 阅读工具栏增加“材料列表”入口，返回选择页后可以切换文件；“返回作品”继续回作品工具。两种返回含义分开。
- 页面先显示打开中的真实材料名称和就近反馈；失败显示原因与重试，保留列表返回入口，不能长时间只有空白。
- PDF 原有页码、页图、文字层、固定引用和个人笔记固定版本阅读保持；打开或选择材料不自动加入 Agent 上下文。
- 普通列表排除已移除笔记；通过历史引用定位已移除固定版本时，维持现有明确标记的历史阅读行为。本轮不借 UI 方案改变历史引用保留策略。

### 必须覆盖的状态

| 状态 | 展示与操作 |
| --- | --- |
| 正在加载列表 | 列表位置给出加载反馈，不提前显示“没有材料” |
| 已有材料 | 可打开的真实条目；长名称换行，来源和名称分层 |
| 空列表 | “还没有 PDF 资料／个人笔记”，提供添加操作；只读状态给出对应说明 |
| 读取列表失败 | 就近错误与重试，已有可用列表保持 |
| PDF 正在处理／处理失败 | 显示真实状态，沿现有查询与续办能力处理，不新建重复请求 |
| 权限受限 | 区分查看、上传、打开时读取所需权限，按现有实际契约禁用并说明；不以此次 UI 迁移扩大权限 |

共享列表展示在 @xunjie/ui 中提供紧凑条目和空／加载／错误展示；数据、上传、材料请求和阅读过程留在产品层。复用现有 Icon、Button、反馈组件及主题，不为本轮引入额外组件资源库。

## 5. 首页：采用旧版“课程与任务”的组织方式

### 结构

保留首页外壳、学习概览和学校／个人来源切换；下方统一为“课程与任务”区域。学校来源先显示现有 CourseTiles，再显示当前来源的活动卡片；个人来源直接显示活动卡片，删除当前将个人活动再次伪装为课程磁贴的重复展示。

活动区使用旧版布局：数量、左侧状态筛选、右侧搜索、下方两列卡片。窄桌面窗口按既有网格规则转为一列。保留既有悬停和焦点反馈，不新增动画体系。

### 真实字段适配

- 筛选项为“全部／进行中／已关闭”。不照搬演示中的未开始、已完成或逾期；已关闭不等于已完成。
- 搜索覆盖实际活动标题、目标／问题和所属课程名；作用于当前来源的活动列表。来源切换时重置筛选和搜索，避免新来源被旧条件遮蔽。
- 卡片显示状态、标题、实际目标或问题摘要、课程来源、动作。进行中使用“继续学习”，已关闭使用“查看活动”。标题不重复出现在说明中。
- 没有真实进度与截止时间时，保留卡片无进度布局，不画百分比、不加截止或完成徽标；createdAt 只可标为创建时间，不能冒充最近学习时间。
- 默认维持明确、稳定的创建时间排序，不宣称按最近使用排序。数量同时交代筛选结果，例如“3 / 8 个活动”。
- 无活动与无搜索结果使用不同文案；无搜索结果提供“清除筛选”。断网／读取失败不冒充空列表。

### 课程内浏览

复用 CourseBreadcrumb 展示“全部课程 / 课程名”。课程打开后的既有发布版本、领取及进入工作区流程继续保留；在课程区域展示该 courseId 的已有活动，并复用相同筛选和卡片。尚未领取的任务仍通过现有领取入口进入，不为了旧 UI 的“未开始”展示建立虚假活动。面包屑返回时恢复来源和列表位置，筛选切换不触发作品状态修改。

组件复用：HomeCourseRegion、HomeSectionHeading、CourseTiles、CourseBreadcrumb、TaskToolbar、LearningCardGrid、LearningTaskCard、HomeStatus；状态标签使用当前事实，进度缺失时使用 LearningTaskCard 无进度布局。当前 ProductHome 已使用其中一部分，此轮补齐信息组织与交互，无须重建首页。

## 6. 实施顺序与验收

建议分三批：①左栏及文件栏；②PDF／笔记列表与阅读切换；③首页课程与活动。每批实施前保存当时的实际页面截图，结束后在相同活动、主题、窗口尺寸与展开状态下保存对照。不能用旧版演示截图替代当前产品的修改前证据。

文件栏截图包括多文件菜单、重命名、删除确认、空作品、关闭全部标签；阅读页包括有材料未打开、阅读中、返回列表、无材料和错误；首页包括学校、个人、搜索筛选及无结果。浅深主题、1440px 与 1024px 桌面 Chrome 都要覆盖；使用隔离验证数据展示真实列表，不向用户实际作品填入演示内容。

工程检查按改动选择类型检查、相关组件测试和生产构建；交互回归重点验证关闭标签不删除、改名保持 objectId、删除失败保留内容、课程 PDF 未导入也可发现、材料打开不隐式引用、活动状态不被 UI 改写。浏览器结果和工程测试分开报告；本轮 UI 验收不证明教学效果。

确认点：建议采用“旧版文件栏 + 重命名／删除，当前不新增回收站”的行为；其余按本方案进入后续实现。
