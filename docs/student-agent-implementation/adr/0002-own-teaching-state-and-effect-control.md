# ADR 0002：自有持久 RunDriver 与独立的教学、模型和执行事实

建立：2026-10-18；修订：2026-10-27。状态：本轮长期目标架构的工程决定。依据：Robert 对技术判断的委托、各主题现行决议，以及负责人明确要求长期最终设计、实际问题发生后再修订的 L23。本工程决定已纳入[总体架构最终决议](https://github.com/paher-din/XunJie/issues/119#issuecomment-6443526782)；产品要求与工程取舍的来源分别保留，设计记录不表示实现或验收完成。

此前[覆盖审计](../references/2026-10-27-agent-design-coverage-audit.md)发现的 tool_use、Skills、MCP、plugin、提示词与上下文缺口，现已由[能力与质量契约](../references/2026-10-27-agent-capabilities-design.md)及[交互设计](../references/2026-10-27-agent-interaction-design.md)补齐，并完成具体能力表与完整请求走查。最新产品边界已有答复，组合设计继续使用本 ADR 的运行所有者；生产实现与验收由后续工作承接。

## 问题

学生在同一活动中会持续修改作品、调用课程组件、等待计算结果并暂停返回；Agent 也会多轮生成、验证和修订教学内容。运行必须跨进程重启和本机/学校/混合部署保持正确归属，不能凭模型消息推断工具已经执行，也不能用一次模型连接承载整个学习活动。

教学事实由循阶掌握，并不能单独证明必须自研调度。需要选择的是：完整原生响应、固定命令、实际回执、等待、取消和预算这些运行条件，由自有运行记录直接推进，还是整体委托框架的任务存储与调度。

## 决定

**长期采用自有持久 RunDriver。** 它负责一次已接收请求内的步骤推进、持久调度与恢复；不是临时循环，也不限制为少数模型步骤。模型连接使用已定的直接 `openai` / `@anthropic-ai/sdk` SDK 与薄 adapter，三协议原生续接按路线保存，SDK retry=0。

运行边界固定为：

- `RunStore` 持有运行、步骤、调用尝试引用、命令意图、等待、领取代际、取消和预算；与待发工作在所属存储内原子提交。
- `ModelGateway` 持有协议调用及完整原生结果。完整结果已可靠保存并关联步骤后，才能提交可执行工具意图。
- `ToolExecutor` 持有固定输入、实际执行状态与结果回执；在执行点复核权限和对象条件。结果未知先查原命令，不能换身份或节点重放。
- 教学协调持有触发、上下文取证与帮助投递规则；学习活动、工作区、证据和画像保留各自领域事实。RunDriver 不把这些对象纳入模型会话存储。

`waiting` 是逻辑 Run 的非终态，释放模型连接和内存处理者。匹配结果到达后核实等待、取消与预算，再继续原 Run；明确新建或排队处理的后继请求创建新 Run，普通 steering 继续当前 Run。取消后的晚结果保留实际事实，不复活运行。每个 Run 同时只有一个有效推进者，以领取代际和条件写入拒绝旧进程的新推进。

这一组语义同时用于可信本机进程与共享服务。跨组件通过稳定身份、持久结果引用和可查询回执衔接，不依赖跨服务数据库事务；部署变化不等于运行重试或数据迁移已经完成。完整契约见[总体运行与部署设计](../references/2026-10-27-overall-architecture-proposal.md#持久运行契约)。

## 依据与替代方案

选择自有 RunDriver 的长期收益是：运行阶段直接对应业务需要核对的原生结果、命令和回执，同机与跨机保持同一恢复规则，减少向框架特定消息、任务和重放模型的适配。选择同时意味着项目长期维护调度设施；没有证据证明它的总成本低于所有框架。

| 方案 | 已证实的价值 | 本轮取舍 |
| --- | --- | --- |
| Pi core | 内存循环、队列、异步屏障与独立实例取消 | 没有替代宿主的持久运行、等待与业务回执恢复；不加入另一套消息循环 |
| Pi durable 整体托管 | 检查点、任务恢复、去重、持久休眠与取消终态 | 可信替代方案，可省去相应自研设施，不必产生双重调度权威；原生记录关联、业务回执与外部事件接入尚未完整验证。本轮选择直接表达运行语义，未证明整体托管更贵 |
| DeepSeek Harness | 公开进程内单会话取消、会话日志、工具流水线与尾部修复 | 仍需业务续跑和长等待接入；本轮成功路径使用固定源码组合。取消能力不能由外层 SDK wire 限制否定 |

证据见[内核研究](../references/2026-10-27-agent-kernel-reuse-research.md)及其[可复现探针](../references/probes/2026-10-27-agent-kernel/README.md)。探针使用真实库或固定源码和假模型/工具，不能当成生产成本、并发或完整协议集成比较。

## 长期责任与演进

项目必须实现并维护持久阶段、原子待发记录、领取代际、未知结果查询、等待/唤醒、取消、预算预留/结算、并发边界和记录升级。多步生成与长等待均在当前设计范围，不按阶段推迟成为架构缺口。RunDriver 不扩张为没有实际用例的通用团队调度、终端会话或插件平台。

不预设以后换用 Pi、Harness 或其他框架。实际需求或运行证据表明现有边界不适用时，比较修改和替换，并明确数据、未结命令、等待与预算的迁移；不因已有自研而拒绝修订，也不因增加课程或模型步骤就自动换内核。

## 决策演变与验收边界

2026-10-18 的初步判断采用 AI SDK Core，并使用“首期有限运行”的表述；依据保留在[当时核对](../references/2026-10-18-architecture-checks.md#内核取舍的工程判断)与[原架构附件](../references/XunJie_Student_Agent_Architecture_2026-10-18.md)。2026-10-23 的[三协议决议](https://github.com/paher-din/XunJie/issues/115)已经替换调用层。2026-10-27 补充探针后，本次将完整持久 RunDriver 确定为长期工程设计，撤回将它描述为短期过渡方案的说法。

生产验收须覆盖真实原生续接、完整终态、权限变化、重复/未知回执、进程中断、等待取消、预算、部署组合及升级。现有探针仅提供部分接口与故障路径证据；目标运行环境、生产集成、浏览器和教学效果仍分别验收。存储产品与旧数据迁移由[重构迁移与验收](https://github.com/paher-din/XunJie/issues/120)承接，不改变本 ADR 的持久化与所有权要求。
