# ADR 0003：按运行职责组织入口，业务 module 随工作包深化

2026-10-29，Robert 确认采用本决定，并要求把分包责任落实到[实施总览](../student-agent-implementation-overview.md)与 WP01 规范及实施票。现有 `student` 已包含师生界面，`teaching` 同时容纳后端、公共契约和原生 runner；按身份命名不能表达实际运行职责。

采用师生共用的 `apps/web`、可组合的 `apps/server`，由 WP01 建立 `apps/local-runtime`，由 WP03 起按实际原生执行需要建立 `apps/execution-node`。后端业务先组织为内部 module；公共契约、产品运行和存储等有真实消费者或独立构建需要的内容才提取 package。六个逻辑部署单元保留各自事实所有权，同机合设不引入跨所有者事务；公开契约不反向依赖实现。

选择这条路线，是为了让职责、测试和后续部署集中在真实使用的 interface 上，同时避免把所有业务预先拆成独立 package/进程、增加构建和协调成本。师生身份通过页面与权限投影区分，不据此复制两套浏览器应用；以后出现实际独立分发需求再调整。

重构前只做目录、公开契约与构建规则的有限整理；工作区、课程执行、模型、Agent、教师路径和开发复现分别随所属 WP 完成新的 module、调用者接线与旧路径清理。全面预重构旧模型会重复消耗即将重建的逻辑，因此不设另一轮全仓结构重写或最后的统一重构包。具体归属与验收入口只在实施总览维护，本 ADR 记录取舍，不复制实时进度。
