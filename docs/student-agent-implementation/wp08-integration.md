## 组合后的行为

同一 Run 可保留明确选择的 Skill、渐进发现并加载的课程工具、原作品及实际读取的 PDF。普通换段、配置变化、换模型和压缩都经过共同装配，保留两类能力状态。摘要生成不附加 Skill 指导或 PDF 图片，也不启用工具；学习后继段再恢复获准内容、当前原意图、全部原操作与固定页图。重启读取原快照，不重跑原工具。

大结果的公共有界投影保留 PDF 已有的语义来源和继续读取入口；原 Command/SHA 始终指向完整 canonical JSON。语义摘录不能伪装成完整连续字节范围。新 Skill 命令使用共同嵌套范围；只对已发布 v1 Skill 命令保留精确的旧平面范围适配，读取仍复核主体、活动、Run、步骤和当前资格。原件续读还按原 Skill 身份、版本、摘要和当前资格检查每级祖先，读取前后均复核；即使另一 Skill 保留共享工具，已停用包也不能借此继续读取。已知资格拒绝归为明确失败，不形成未知效果等待。历史记录仍可按原权限核对。

对话公开读取把 Command 与 Wait 放在同一 PostgreSQL 语句的快照中，避免停止清理恰好提交时读到相互矛盾的旧结果与新 Wait。

## 两份已发布迁移 11

Skills 与压缩独立发布时都占用了 11。Skills 的原 SQL/版本保持 11；压缩的原导出与 SQL 保持不变，在最终注册表登记为 `{ version: 12, formerVersion: 11 }`。仅当旧尾项的名称、SQL checksum 与未变前缀完全一致时，provisioning 才事务性迁移该 ledger 身份，保留原 `applied_at`，只执行缺失 SQL 并更新 generation。其他名称、SQL、损坏前缀或混合历史均拒绝；`verifyBinding` 仍严格核对最终完整链。

恢复先校验并完成可信的原迁移链，再在写入/派发关闭状态升级。领域清单统一为 v3，精确兼容 #215 基础 v1、#220 基础加压缩 v1、#216 含历史结果资源的基础 v2、#217 基础加 Skills v2。旧行摘要只忽略后来追加且为默认值的 `capacity_rejected` 和 `compaction_id`；非默认事实不能被旧清单隐藏。即使旧清单只列部分历史资源，也验证全部保留资源字节。
