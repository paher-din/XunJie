## 同一逻辑 Run 与累计预算

在原物理调用结束且原工具配对/业务效果结清后，RunDriver 可将原 Run 持久暂停在 `model-switch-boundary`，切换完成后用同一 Run 的后继步骤进入新段；没有新建 Run 来绕过预算。规划和切换完成竞争时，在所属事务中重新核对 session 段，旧段的乐观规划不能获得新 attempt 预留。

按负责人确认的标准档，宿主配置 `TeachingRunLimits` 新增：

| 配置 | 默认上限 | 口径 |
| --- | --- | --- |
| `maxInputTokens` | 1,048,576 | Run 累计输入 token，按 1 Mi token 解释本轮的 1M |
| `maxOutputTokens` | 65,536 | Run 累计输出 token，按 64 Ki token 解释本轮的 64K |
| `maxCallMs` | 600,000 | 模型调用累计 10 分钟 |
| `hardDeadlineMs` | 86,400,000 | 自 Run 接受起的 24 小时绝对期限，包含工具/学生等待与停机 |

迁移 5 保存以上上限和绝对截止时间，接受 Run 时在同一 owner 事务固定。已有步骤/工具/并行度/Wait 上限继续保存；改宿主配置、切换来源/协议或重启不修改已接受 Run 的预算。显式“继续”沿现有产品契约创建新的关联 Run，区别于本票同一 Run 内自动推进及模型切换。

输入在调用前以配置的模型窗口作保守上界预留，不把字符数当成 token；缺少窗口无法安全预留则暂停。输出按剩余额度缩小本次请求上限；调用超时同时受剩余累计调用时间和硬期限约束。仅最终且已知的 token 用量释放对应预留，partial/unknown 仍持有上界，不能当零。调用时间用已持久保存的派发起点到确认物理结束的观测区间保守计入，包含回包/轮询和中断恢复延迟，不声称测得 GPU 时间；结果仍未知时保留整个调用时间预留。工具/学生等待不计入调用时间，但消耗硬期限。

所有新派发均复核硬期限；已接受但未派发的原 attempt 到期按原身份取消，真实回归确认 0 次 SDK 请求、原生 pending 为 false。Wait 的期限也不能越过 Run 截止时间。停止/到期后的原效果核对和清理仍保留原命令身份。

最终两个硬期限专项回归 2/2 通过：未派发 attempt 取消并释放原生 pending；已完成模型结果因观测回包延迟而越过截止时间时，保留原结果及 Run 引用，暂停后续派发，不重新生成。最终完整 typecheck、14 个浏览器公共契约导出检查、文档链接及 `git diff --check` 通过；付费密钥未出现在所有 tracked 差异和新交付文件中。
