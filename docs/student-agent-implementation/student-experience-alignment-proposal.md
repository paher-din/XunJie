# 学生学习全流程功能对齐与体验优化方案

日期：2026-11-14。阅读基线：`main@71a38e8f`。范围：课程/任务首页、工作区编辑与阅读、ALU 组件、求助与成果保留。本文为建议稿，不表示已批准或已实施。

## 0. 依据、结论强度和范围

依据：[实施总览](student-agent-implementation-overview.md)、[既有关闭票基线](student-flow-closed-issue-baseline.md)、WP02/03/04/07/08/09 的已关闭票及当前源码、根目录 [PRODUCT.md](../../PRODUCT.md)、[DESIGN.md](../../DESIGN.md)、[@xunjie/ui](../../packages/ui/README.md)。本轮不引用开放 issue，不增加尚未开展的画像、主动教学调度、教师创作/反馈或新课程能力。

“源码确认”表示调用或状态代码可直接支持该判断；“体验报告”来自本次用户实际使用，尚未在同一活动重新复现；“建议调整”表示原实现可能符合旧计划，但有合理的体验改进空间。此前浏览器标签已不存在，本轮未重建用户现场、未改产品、未跑浏览器或教学效果验收。不能把推测根因写成已复现缺陷。

Agent 区域由另一组并行开发：本方案仅保留待合流核查与设计建议，不先修改其会话、输入、回执或共享引用代码。其合并后按本方案补差，避免第二套会话/队列。

### 先纠正四项容易混淆的判断

1. **选区自动加入**是 #122 原设计：对话关闭时选区出现入口，点击后加入；对话打开时有效选区自动加入。当前 `DraftReferences`/来源适配仍实现此规则。用户反馈成立，但属于需要明确变更的旧交互，不应称未实现原要求。
2. **同名新对象**指 #151 / WP02 的“删除后同名重建”，不是允许两个现存文件占同一路径。`workFilesSchema` 同时要求 objectId 和 name 唯一。应改善命名反馈，并分别实测重复创建与删除重建。
3. **移除笔记保留旧版本可读**是 #219 的历史引用要求。问题是普通阅读没有退出、历史态与当前态混淆，不应删除旧引用依赖的原文。
4. **活动关闭不是完成或删除**。原 #149 支持建立、列出、关闭和重开；永久删除、级联清理不是既有验收要求。本轮建议把已有关闭/重开操作接到首页，不直接增加破坏性删除。

## 1. 功能：原预期、现状差异与修正

### F01 刷新活动列表不应结束当前工作位置〔建议优先 P1〕

- 原预期：#149/#150 可重开原活动；#151/#159 保护编辑、导航和恢复。列表刷新不是切换活动的用户意图。
- 源码现状：`ActivityPage` 的“刷新列表”调用 `LearningApp.refreshContext`；后者执行 `rememberActivity(null, nextKey)` 并清空活动/课程/材料缓存，解释了用户报告的跳回首页。
- 方案：拆分 `refreshIdentityContext`、`refreshActivityList`、`refreshCurrentActivity` 三种职责。工作区菜单移除含糊的“刷新列表”；若保留刷新动作则写“重新读取活动信息”，仅更新元数据，不清空 route/activity/材料选择、session 或编辑句柄。首页“刷新任务”只更新所属列表。
- 失败：保留现有内容与活动，显示可重试错误；只有确认身份/资格失效时进入原活动的受限状态，不静默返回首页或换主体。
- 验收：持续编辑时刷新、失败重试、前后退和双标签刷新，当前路由、作品、草稿、材料位置、Agent 原 session 均不丢；不重复领取/新建活动。

### F02 笔记/PDF 打开入口必须确定打开对象〔P1〕

- 原预期：#218/#219 支持真实资料阅读、固定引用和重开；没有要求每次先进入空阅读器再回材料栏选择。
- 源码现状：个人笔记 `reveal()` 仅切工具，不选择材料；PDF 也分别维护文档选择和阅读视图。用户从“打开阅读区”进入空页符合当前接线，但承诺与结果不匹配。
- 方案：统一“打开资料”决策：当前有效选中项 → 本活动最近有效阅读项 → 唯一可读项；若有多项且无选择，显示内联选择器，不任意挑第一项；无资料显示带“添加笔记/PDF”按钮的空态。点击某份资料直接选择并打开；重新挂载后按固定 materialId/documentId、版本、页码或位置恢复。
- 边界：只在本活动/原主体内恢复，不因同名替换；已移除/失权对象不能作为普通阅读的自动候选；定位历史引用走独立的历史读取入口。
- 验收：零/一/多资料、未选/已选/重开、读取失败、过期响应、空间切换；一次点击得到内容或明确选择，不出现死胡同空页。

### F03 笔记移除后的当前视图与历史引用分离〔P1〕

- 原预期：#219 移除后退出当前材料列表，但被引用的固定版本仍可读；#152 旧引用副本不消失。
- 源码现状：`PersonalMaterials.remove` 将当前 reading 的 material 更新为 removed，但保留正文；阅读区仍显示旧文本。`canQuote` 对 removedAt 为 false，而提示写“仍可阅读和引用”，存在表述歧义。
- 方案：移除回执确认后，若普通阅读对象匹配则清空 activeReading，关闭该材料编辑/引用入口，取消迟到读取，阅读器呈现“已移除该笔记”及“选择其他笔记”。不自动打开另一份材料。正在编辑时先保护正文，再完成移除；保护失败不卸载，操作未知时标“正在核对移除结果”，不假称成功。
- 历史路径：从旧问题引用进入时，以 `historical-reference` 只读模式显示固定旧版及“来源已移除”；保留旧引用定位与读取，不恢复到当前列表，不允许以当前可编辑笔记身份使用。是否允许重新引用旧版需按原 owner 的授权契约统一，提示与禁用条件必须一致。
- 验收：普通阅读/编辑/历史引用三种入口分别移除；丢回包、迟到读取、刷新、同名新笔记；当前视图退出且旧固定引用仍可解释。

### F04 文件创建、重命名和同名重建〔P1〕

- 原预期：#151 稳定对象、改名不换身份、删除后同名重建为新对象；现存路径唯一。
- 现状：当前统一 catch 显示“文件名、内容大小或重复路径”，没有精确指出失败条件。现存同名创建被拒绝本身不构成偏离。
- 方案：输入时检查空名称、非法/保留路径和现存重复；重复路径就近提示“已有 alu.sv”，提供“打开已有文件”与“使用 alu-2.sv 创建”建议，不能默认覆盖。重命名按 objectId 操作，已存在名称同样明确拒绝。
- 必验真实 gap：删除 A 后新建同路径 A2，A2.objectId 必须不同；旧引用/结果保持 A。若仍拒绝，检查已删除对象与可见路径校验、旧 pending 确认或墓碑处理，不放开重复现存路径来绕过。
- 原可靠工作区仍负责创建/删除/重命名，不在文件树另建保存权威；只读支架和组件内部状态不得被普通文件操作改写。

### F05 Markdown 阅读增强不能破坏引用〔P2，建议增强，不是缺陷〕

- 原预期：#219 交付 UTF-8 个人文本笔记，固定 materialId/version/sha256 和原文范围；未要求 Markdown 渲染。当前以 `TextReferenceSource` 展示原文符合该范围。
- 建议：增加“阅读 / 原文”切换，Markdown 作为同一原件的展示投影，编辑仍保留原字节；优先复用 `@xunjie/ui/chat` 的 Markdown 实现，并核对其当前安全边界，禁用原始 HTML、脚本与危险 URL；图片默认不自动请求任意外部地址。
- 关键约束：当前文本引用与定位依赖 `textContent === 原文` 和 UTF-16 范围，不能简单用渲染 HTML 替换。首版在阅读模式提供“切到原文引用”，原文模式保持现有精确引用；以后若需要直接引用渲染内容，再补可验证的源位置映射，不推断 DOM 偏移。
- 验收：标题、列表、代码块、链接、中文/换行/特殊字符；原文编辑不变、旧引用仍精确定位、渲染失败可回原文。来源范围校验不能放宽。

### F06 组件深色主题文字不可读〔P0：可用性阻断〕

- 原预期：#169/#159 的正式主题与可读性、#173 的真实组件使用，以及 DESIGN.md 的同角色深色 token。
- 现状证据：用户报告“本机连续计数”黑字。当前 `ComponentView` 会传 theme 并监听 data-theme；仓库 `state-accumulator/view*.html` 也读取 ink/canvas。不能未经复现就断言只是硬编码黑色，可能是已发布旧组件、初始化握手、变量缺失或主题更新未到达。
- 修正顺序：记录当前固定课程发布/组件版本/资源摘要；检查首次握手及切换主题的 `--ink/--canvas` 实际值与计算样式；按真实断点修复宿主或组件。给关键颜色建立正确的浅深回退，控件继承文字色；不能给全部 iframe 强制反色。
- 版本：固定组件资源不得原位覆盖。若组件内容需要改动，走新的组件版本和发布；旧活动问题需明确兼容宿主修复或受控修复路径，不自动重绑新版。
- 验收：首次即深色、浅→深→浅、跟随系统、重载、iframe 重建；正文/按钮/输入/禁用态可读，正文对比度以设计规范和 AA 为依据。ALU 仪器材质是 DESIGN.md 例外，不一并漂白。

### F07 接收记录顺序与事实来源〔Agent 组待合流，P1〕

- 原预期：#197 对话事件稳定有序；#153/#200 原请求和回执可核对，重读不重复、不倒退。
- 源码现状：`ActivityActions` 直接遍历 `state.items`；动作状态按保存项与追加项组合，并没有在展示层定义“实际接收顺序”。这能解释排序观感，但需用用户原请求复现，不能直接断言接收方乱序。
- 方案：分开“待发送”和“已接收历史”。前者按本机创建顺序稳定排列，后者按原接收 owner 的权威顺序；优先用已有 seq/回执顺序，若缺少则由原接收方补充稳定 acceptedSequence/acceptedAt，不用浏览器轮询完成时间代替。不同 owner 间不伪造严格全局因果顺序；缺证据的项留在待核对分组。
- 活跃对话按原 conversation seq 稳定合并，重试不生新记录，状态更新不使当前卡片来回跳。仅折叠投影，不删除历史事实。
- 验收：创建先后与接受先后相反、断网、重试、丢确认、重开、队列、迟到终态；未知显示未知。

### F08 首页管理已有活动状态〔P2〕

- 原预期：#149 已有 open/closed 生命周期及重开；closed 表示结束本次活动使用，不等于任务通过。
- 当前差异：已有状态操作主要位于工作区“活动”菜单，首页缺少便捷管理属于接入/体验改善，不需要新生命周期。
- 方案：首页活动项增加“更多 → 关闭活动/重新开始”；仍调用原 setStatus、沿原 requestId 核对回执，操作未知时保留记录并提示核对；多页面当前活动遵守保护与资格检查。显示“进行中/已关闭”，不新增“已掌握”“已交付”推断。
- 删除建议：本轮不引入永久删除或假装已删除的本地隐藏。关闭后可在筛选中查找、重开，满足整理需要。真正删除涉及作品/引用/执行/提交保留和在途任务，应另行明确范围后做独立设计，不能作为旧 issue gap 自动补入。

### F08 补充：删除活动专项设计（2026-11-16，待单独实施）

用户已确认本轮先接入关闭／重新开始，删除在本全流程方案中单独设计。下列是建议，不表示接口或验收已完成，也不作为旧关闭 issue 未实现的要求。

推荐将学生的“删除活动”定义为可恢复的删除标记：活动从默认列表移入“最近删除”，不级联销毁作品、笔记、引用、会话、实验证据或学校提交。永久清理是另一个明确动作，不能把关闭等同删除，也不能仅在一个浏览器 localStorage 隐藏后声称删除成功。

1. **所有权与授权**：学习数据所有者保存 deletion 标记、主体、时间和请求回执；本人且当前学校／个人绑定匹配才可操作。学校正式提交、教师评价和学习回执由各自所有者保留；学生删除入口不能撤销这些记录。
2. **删除前处理**：确认弹窗写明活动名、保留与恢复范围。已有工作区先保护草稿，核对未确认的保存、提交及材料请求；在途实验按现有关闭协议终止并确认。无法保护或终止时，不报告已删除，不丢弃待处理原请求。
3. **可恢复删除**：沿幂等 requestId 提交标记；成功后从默认首页／搜索移除，详情及旧链接显示“已删除，可恢复”，而不是 missing 或创建新活动。历史引用继续解析固定副本，恢复沿原 activityId、objectId 和所属空间，不复制一份新活动。
4. **恢复入口**：最近删除页可查原课程、删除时间及恢复；恢复前重新校验当前课程授权。课程已撤回、账号解绑或身份失效时保持数据，说明受限原因，不自动换绑或扩大权限。最近删除的保存时限必须由负责人另行确定；未确定前不显示倒计时承诺。
5. **永久清理**：本专项也不默认启用。需分别列出本机副本、学校记录、固定引用和执行证据的清理政策、保留义务及依赖检查，明确哪些能删、哪些仍保留；不能通过一次级联 SQL 绕过各数据所有者。
6. **验收**：覆盖双窗口、断网／回执丢失、重试原请求、未确认草稿、在途运行、学校提交已存在、解绑／重绑、历史链接与引用、恢复后身份不变；另验证任何失败不造成作品丢失。

需先确定删除保留期限、最近删除入口位置、在途请求处理和学校授权失效后的恢复策略，再新增契约、存储迁移、HTTP／学校客户端转发及 UI。当前版本继续以关闭、重开和筛选整理活动。

## 2. 用户体验：把学生的任务与系统机制分开

### X01 选区引用：推荐显式添加〔Agent 组待合流〕

旧规则符合 #122，但对复制、阅读和代码编辑的普通选区具有误加风险。建议改为：所有来源统一“选中 → 就地工具条 → 点击『加入问题』”；对话关闭时动作同时打开侧栏，已打开时只增加引用并保留焦点策略。键盘提供可访问的等价动作，快捷键在检查 Monaco/浏览器冲突后再定。

复制、查找替换、拖动选区、选全文都不自动增加。只有点击明确动作时冻结原范围和字节；引用卡显示来源、摘要、定位和移除。去重、旧副本、顺序和不自动发送规则不变。先不增加“自动引用”设置，避免用户承担配置成本。

这是旧交互的明确变更建议，实施前同步引用规范/相关测试，不把原来的自动加入测试简单删掉而无新行为覆盖。

### X02 发送方式移到发送动作旁〔Agent 组待合流〕

当前 `AgentInteraction` 的“本次发送方式”与编辑器/按钮分离，用户难预测点击结果。建议复用发送按钮分裂菜单：空闲显示“发送”；已有运行时主按钮显示当前方式“补充当前任务”或“排队发送”，旁边箭头切换。辅助说明分别为“用于当前运行的下一步”和“当前运行结束后处理”。

默认策略仍由原控制器决定，不为 UI 擅自改变 steering/queue 行为；点击时固定方式与输入、保护原请求。运行结束或变更时依据接收方实际状态裁决，不能显示一个方式却按另一个派发。中文组合输入与键盘发送共用同一路径。

### X03 发送反馈改为原问题就地状态〔Agent 组待合流〕

“已保留这次问题，可继续编辑；接收情况见下方记录”准确但像内部诊断，迫使学生跨区域确认。建议让原用户问题行直接承载状态：准备输入 → 等待接收 → 已接收/已排队 → 处理中/等待回应 → 已完成或明确异常；仅显示实际可证明的阶段。

本机保留未确认业务接收时写“问题已保留，正在等待接收”，不能直接写“发送成功”。常规成功不反复 toast；未知、取消待确认、失败和重试在原问题旁提供操作。旧完整回执记录保留到折叠“发送记录”，避免正文重复出现同一问题。

### X04 会话查找与历史折叠〔Agent 组待合流〕

先区分“跳到本活动以前的问题”和“切换不同会话”。本轮优先做当前工作区的问题目录：按真实用户输入生成简短目录，点击滚到对应原消息，当前问题高亮；长历史按已完成请求折叠，展开恢复位置，不折叠当前运行、待回应或待核对错误。

若使用已有普通 session 列表，沿用真实目录，支持既有标题/日期定位即可；不把一级个人 Agent 会话、课程工作区会话合并，不伪造新 session，也不增加跨课程全量内容搜索。资料和问题固定上下文保持原归属。切页/折叠不停止后台运行、不重发、不卸载可靠输入 owner。

### X05 文件操作使用熟悉的轻量 IDE 交互

当前“作品/文件/新建/改名”等操作分散且每次展示表单，增加认知负担。建议复用现有 FileStrip/FileTabs：上方打开文件标签；左侧“作品文件”列表；标题行“新建文件”，选中项更多菜单“重命名/删除/导出”。创建和改名就地编辑，Enter 确认、Escape 取消；错误紧邻文件名。删除前按现有数据保护规则处理，不加手动保存按钮。

首版只做文件列表和当前路径支持，不扩展目录树、任意依赖、终端、多光标协作等 IDE 范围。若当前没有多层路径产品需求，不为外观先造文件系统。

### X06 “活动”菜单回归活动本身

原设计依据：#149 的活动生命周期；#159 在既有外壳接入活动入口、导航和状态；WP02 的活动不等于学校连接。当前 `ActivityPage` 把状态、刷新、收纳页面及 `account` 插槽放在同一 Popover；`LearningApp` 将整段 schoolControls 传入，形成学校连接在活动菜单中的混杂。

建议菜单只保留“活动信息、关闭/重新开始、收纳的学习页面”等当前已有活动能力。学校连接留在已有账号菜单/设置的学校绑定流程，工作区只显示简短账号/课程归属。失联或资格问题在受影响内容处显示可点击的修复提示，不将完整认证表单常驻学习菜单。

“刷新”按 F01 处理。若真正意图是返回列表，则单独明确写“返回首页/活动列表”，走离开保护，不能借刷新偷偷导航。

## 3. UI：沿用现有产品，重排工作区层级

### V01 推荐布局

保留品牌、主导航、标题和现有中心工具容器，不新建平行学习页，不改 DESIGN.md 的字体、颜色和角色集。

```text
全局侧栏：主页 / 个人 Agent / 账号与设置
工作区顶栏：课程与任务 / 活动标题 / 材料开关 / Agent 开关 / 活动菜单
┌────────────────┬─────────────────────┬──────────────────┐
│ 任务与资料       │ 当前中心工具         │ 本活动 Agent      │
│ 目标与要求       │ 编辑器 / 笔记 / PDF  │ 对话正文与工具结果│
│ 作品文件         │ / ALU / 教学页面     │ 当前问题目录      │
│ 课程资料与笔记   │ 文件标签与局部工具栏  │ 引用 + 问题输入   │
└────────────────┴─────────────────────┴──────────────────┘
```

左栏只组织当前活动导航，不放学校认证、模型参数和运行账本。目标、作品文件、课程资料/个人笔记分组；展开规则依据当前任务，不按后台模块名堆叠。材料列表点击直接打开具体内容；只在空列表显示添加入口，不另外设置无对象的“打开阅读区”。

中心保留同一套 `CenterToolArea`，不同工具切换保留显式状态；左栏与中心不再重复显示两套文件操作表单。Agent 的设置、引用、正文和回执有层级，正文是视觉主轴。

### V02 右侧 Agent 可调整宽度与关闭入口〔Agent 组待合流〕

源码当前 `.product-discussion` 固定 380px，顶栏负责开关。建议在侧栏头部加明确关闭按钮与标题“本活动 Agent”，边界加可键盘操作的 splitter，复用 ShellFrame 已有的指针捕获、取消、键盘和吸附交互经验，不能直接复制全局侧栏尺寸。

建议起始宽 380px；最小约 320px、最大约 560px，同时给中心预留可操作宽度，具体限值按现有断点和 ALU 最小可用宽度实屏确定。宽度按当前设备本机偏好保存，载入时重新约束；关闭保留草稿和会话，拖动不重建 Monaco/iframe/Agent。窄桌面沿现有互斥/覆盖策略，提供返回按钮，不挤出不可操作的三栏。

### V03 视觉与文字

- “作品”作为学生成果概念保留；文件操作区域明确称“作品文件”。阅读页标名称、版本和来源，移除旧版有可读提示，不让学生误认仍在当前材料列表。
- 按钮表达对象与动作：“打开 xxx”“选择 PDF”“加入问题”“补充当前任务”；减少“核实原权威/保留意图”等实现语言，技术详情放可展开记录。
- 正常编辑无保存按钮和常驻保存标签；输入保护故障才就近反馈，并可复制/导出。
- 用 DESIGN.md 的 ink/muted/canvas/line 等语义 token；深色、悬停、焦点、选中、禁用和弹层均覆盖。没有证据的首页统计保留空态，不补假进度。
- 面板切换/折叠仅用现有动效节奏；拖宽期间禁用干扰布局动画，尊重 reduced-motion，焦点回到明确触发器。

### V04 组件与资源使用方案

优先 `@xunjie/ui/workspace` 的 CenterToolArea、FileTabs、FileStrip、WorkspacePopover、CodeEditorHost、比较/引导组件；`@xunjie/ui/chat` 的现有消息、Markdown、PromptInput、ConversationSections；`@xunjie/ui/home`/feedback 的既有首页及反馈能力。先核对实际 props 和消费者，不能因名字相近直接迁入旧业务控制器。

需要新增可复用 splitter、资料选择器或组合发送按钮时，先在 `packages/ui` 补纯展示契约和目录示例，再由业务页接入。Astryx 作为交互资源，shadcn 官方 Resizable/Command/Dropdown Menu 等作为比较对象；采用前按本项目 token、可访问性和依赖适配，不再并存第二套主题/消息列表/滚动权威，不初始化一套新 Tailwind 产品。

本轮已读取 shadcn 官方 skill 及 Resizable/Command 文档。Astryx 的 MCP 在本会话工具清单中未暴露，官网指定页也不可达；当前包已有 `@astryxdesign/core`，实施时须先恢复工具可用性或查本地已安装组件，不假称已搜索其资源。

Impeccable 使用 Operate 模式；本方案对应 shape 的规划、critique 的信息层级审视、clarify 的文案和 harden 的状态边界。需要实施后再做 layout/polish 与 audit。其 context 引擎本次未能安装运行，已直接读 PRODUCT/DESIGN；未生成自动审计分数，不替换品牌或设计系统。
