## 集成回归中发现并修复

- 设备取任务周期为 10 秒，而请求等待仅 5 秒；调整实际任务轮询，验证独立设备个人模型能完成对话。
- Gateway 内部重复远程授权导致接收超时；单次 task 按主体共享准入，SDK 实际外发前独立实时复核。任务已接受后换代际的回归确认没有额外 SDK 请求。
- 同进程丢失模型接收回包后，领取条件阻止重领自己的过期 lease；修复后沿用原 attempt，只有一次实际派发。
- 新增慢 RPC 续租后，旧竞争夹具仍假定健康处理者会自行失去 lease；改为明确关闭原处理者的推进资格，再验证迟到结果和新代际竞争。
- 备份 manifest 的部署类型校验遗漏 `agent`；补齐后 runtime-only 与正式 Agent owner 两条隔离恢复路径均通过。
- 在途授权无法确认而取消模型后，原生段仍开放，后续显式问题反复冲突；非 completed 终态封闭原段，下一 Run 建新段，原 attempt 不重跑。实际进程崩溃、后续问题、撤销真实 grant 和两个 owner 的备份集成已通过。
- 广泛原生回归发现生产清理监视器可能读取并干预另一活处理者的会话，以及停止后的清理查询覆盖晚到 WASM 结果；健康监视改用只读终态事实，正常资格下的停止仍读取原结果。执行清理、工具宿主和工具恢复三个文件 29/29 通过；派发竞争与分片通道 11/11 通过。
- 原配对任务夹具没有响应新的公开选项发布操作，更新该生产边界夹具；同时补充授权提交后丢 ACK、撤销后资源忙的真实 PostgreSQL 反例。临时故障保持同一任务 pending，重查实际 grant 版本，不产生模型调用；两个模式均通过。
- 授权临时故障不能挡住同连接后续查询/取消；客户端逐一处理最多 16 条已返回任务，真实已发送 SDK 的队头 grant busy 反例确认查询和取消仍可达，只有一次外发。
- 并发停止与清理事务曾在持锁时再次从同一池借连接读取 Run；连接池占满后出现互等。三处读取改用当前事务，真实 PostgreSQL 屏障及八个并发停止请求稳定复现 RED→GREEN，原停止、待确认清理与重启断言保持，工具恢复文件 17/17 通过。

## 最终工程验证

完整门禁在最后修复后重新执行，`npm run verify -- --jobs 3` 全部通过：类型检查、构建、公共 wire、文档链接，以及 unit 28、server 88、tools 45 个验证任务。测试没有使用缓存。

广泛原生批次为 196 项，其中 191 通过、5 项在产品进程启动时退出；当时与共享 dist 重建重叠，夹具已删除 runtime.log，无法唯一确定历史启动原因。这五项随后在完整恢复文件中全部通过。复验另发现的停止问题经真实 PG 屏障稳定复现，修复后恢复文件 17/17、受影响核心文件 24/24 均通过。原始失败和最后通过记录分别保留在[工程证据](evidence/wp07-203/engineering-verification.json)，不把首次失败批次写成零失败。

Mac 桌面 Chrome 初轮 15 项通过、1 项旧 UI 基线截图跳过；最后停止修复后的对话与工具用例再次 6 项通过、同一截图用例跳过。个人模型设置、中文组合输入、焦点、CAS/未知保存、正式问答、工具、原生/WASM、关页等待、停止和重开均有实际浏览器检查。

最终双轴复核的行动发现均已处理；工程侧没有剩余阻塞。真实产品包、跨机、Windows Chrome 与一次性环境清理以[部署验收](wp07-203-agent-deployment.md)为准。教学效果未评估。
