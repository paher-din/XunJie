## 1. 范围与来源规则

主路径：主页课程 → 任务和材料 → 进入/重开活动 → 编辑作品 → ALU 运行、观察、检查 → 引用求助和 Agent 辅导 → 用例、解释与成果保留。

- 直接依据：[实施总览](student-agent-implementation-overview.md)中的 WP02、WP03、WP04、WP07；WP06、WP08、WP09 仅取实际支撑这条学生链路的部分。
- 只引用已关闭 issue；不纳入未关闭 issue，也不将未开展的后续包转为本轮缺陷。母票用于确认范围，实施票用于提取可观察行为，平台补验票只解释证据覆盖。
- 已关闭的设计决议不等于实施完成。尤其 #113 的成果目标、#123 的 IP 展示，不证明连续主动教学或正式教师收件已交付。
- 不把旧版任务/教师兼容页自动当作新产品的预期。按正式入口及实际路由记录体验，避免混用两条链。
- 不要求旧 API、旧 RunDriver 包路径或“首问必须建活动”恢复原样。最新 session v2 的普通会话与工作区会话已分开；重点核对固定输入、真实工具、控制和恢复语义。
- 本文未读取 `docs/archive/`，未修改产品或执行业务操作。

### 两个必须保留的范围边界

**Agent 引导**：纳入已实施的对话、明确提问/回应、工具卡片、验证、运行中引导、排队、停止/继续，以及已有 IP 展示层。跨活动主动检测、三档主动性调度、学习画像推断不列为本轮必须存在的能力。

**最终作品交付**：#113 的已确认活动目标为 SystemVerilog 作品、两条有目的的自选用例和简短解释；#194/#202 支撑其记录、比较和引用，但明确不交付教师提交/收件或掌握判断。本文核对到成果可保留、重开、追溯；不由此推导必须有教师收件、审阅和反馈链。体验中若已有提交按钮，可记录实际行为和来源，但在找到本轮已关闭实施票前，不把它当作既定验收要求。

## 6. 体验记录模板

先记录：日期、commit/产品包、正式页面地址、Windows/Chrome 版本、个人/学校空间、课程/任务发布、组件/运行包版本、模型路线、实际部署/数据归属。不记录密码、token 或 API Key。

每条发现复制以下表格；没有体验的条目保持“未检查”，不能写“通过”或“缺失”。

| 字段 | 填写内容 |
| --- | --- |
| 检查 ID | 如 A04 / C10 / D09 |
| 原预期 | 本文条目、已关闭 issue 及具体条件 |
| 操作步骤与输入 | 进入哪个真实活动、先做什么再做什么 |
| 实际结果 | 实际显示、状态、回执和版本；可附必要截图 |
| 判定 | 符合 / 存在 gap / 无法判断 / 本环境不适用 |
| gap 类型 | 功能缺失 / 接线或路由差异 / 行为错误 / 迁移回归 / 体验问题 / 证据不足 / 文档过时 |
| 影响 | 阻断进入 / 丢失或错误归属 / 错误教学依据 / 操作成本 / 视觉或文案 |
| 重现条件 | 稳定或偶发；网络、账号资格和原请求是否未知 |
| 待决定事项 | 若需要新增原计划之外的能力，单独说明，不混入既有缺陷 |

工程测试、浏览器体验、真实模型/执行、教学效果分别记录。本次仅整理文档与查询已关闭 issue，以上四项均未重新验收。
