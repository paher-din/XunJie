# 学生 Agent：能力装配、上下文与质量契约

日期：2026-10-27。服务于[总体架构与复用取舍：模块边界、Agent 内核和部署方式](https://github.com/paher-din/XunJie/issues/119)。这是按[覆盖审计](2026-10-27-agent-design-coverage-audit.md)补齐的长期目标设计，依据已确认产品要求与技术判断委托形成，现已按[最终决议](https://github.com/paher-din/XunJie/issues/119#issuecomment-6443526782)收束；不表示已经实现或验收。

已确认的产品边界继续有效：个人与学校学习空间分开；学生始终可选择个人模型；课程实验按教师运行方案；主动性由学生控制；修改作品需要学生请求或采纳。部署位置和开发调试参数不成为普通学生的设置负担。课程组件是课程装配单元，Agent 工具是模型可调用操作，Plugin 是分发层，三者分开。

## Agent 定义与一次运行的装配

`AgentDefinition` 是版本化配置，由角色目的、Prompt 模板、能力引用、上下文策略、输出契约和预算规则组成。Run 保存不可变的初始装配；后续变化追加新的 `ResolvedAgent` 快照，包含课程发布版本、活动、主体、模型路线、Prompt 内容摘要及引用、工具定义、已加载 Skills 和输出模式。每个 step/attempt 显式绑定当时的装配快照及独立上下文清单身份，恢复使用原绑定，不套用后续步骤才加载的能力。版本号不能替代实际内容身份。

| 使用情形 | 装配与权限 | 与学生会话的关系 |
| --- | --- | --- |
| 学生提问和课程辅导 | 当前课程、活动、开放材料及获准工具，允许的帮助范围由课程规则确定 | 同一连续 Agent；提问、引用和作品依据明确关联 |
| 主动引导 | 同一课程能力，增加当前主动档位、暂停状态与触发依据 | 独立请求；学生新提问优先，过时提示不能插入当前交流 |
| 教学内容生成与修订 | 继承发起请求的范围，增加产物结构与校验要求 | 多步工作属于一个持久 Run；展示只采纳通过检查的版本 |
| 画像整理和活动摘要 | 只读取获准记录，输出候选判断或摘要；不给作品写入、外部发送等无关能力 | 独立有界任务，不能直接冒充学生可见回复或教师正式评价 |
| 个人空间自主学习 | 可直接从问题、资料与目标开始，课程绑定可选；使用个人选用的材料与能力，不带入学校未授权内容 | 独立空间记录，不自动合并学校活动和画像；无须先建课程 |

这些是同一运行基础的不同配置，不默认建立相互委派的多 Agent 团队。后台任务不继承“当前页面仍在线”的假设；新主动推理仍须经过已定的页面与学生意愿检查。

## Agent 工具：定义、选择与执行

`AgentToolRegistry` 收集平台工具、课程组件贡献和已连接外部服务，经适配形成统一定义。每项包含稳定来源身份与版本、名称、用途、参数 schema、结果契约、读写/执行效果、资源范围和真实 executor 绑定。模型侧的短名称只是协议投影；执行端通过清单中的身份和版本定位，不能根据模型返回的任意名称临时查找可执行代码。

候选来源包括课程发布能力和学生自愿接入的个人扩展；可见清单取当前主体、空间、课程规则、活动、运行模式和可用执行环境允许的交集；实际执行前仍按当前资格、输入依据和撤销状态复核。教学材料、工具说明和 Skill 不能自行扩张此集合。模型选中工具后，由确定性程序校验和派发；依赖准备、状态恢复、回执查询和既定作业推进不绕一圈交给模型决定。

常用工具及当前活动直接需要的工具随 Run 暴露。超过上下文预算时，保留发现工具和简要目录，按来源、用途及当前对象缩小候选，再装入选中的固定定义；不能把完整远端目录全部塞进 system prompt。工具变化只在完整步骤边界生效；若改变已固定的 system/tools 前缀，建立新的原生续接段，并记录清单变化，不能改写旧请求。

项目用 JSON Schema 表达参数及结构化结果，并以本地校验器为执行依据。三协议 adapter 把受支持子集投影到端点；端点不支持的约束仍由应用验证，不能标成原生 strict。清单和能力探测在调用前判定必需字段是否可表示；不支持时返回具体缺项，不静默删除关键约束。

| 结果形态 | 运行与模型得到什么 |
| --- | --- |
| 完成 | 稳定结果身份、实际输入身份、结构化结果、简明可读说明和原始内容引用 |
| 业务不满足 | 例如编译失败或用例不通过，仍是一次真实执行结果；说明诊断与依据，不转成 transport 错误 |
| 调用未发生 | 参数无效、权限撤销、环境缺失等，明确未派发；按原生协议回填与 call ID 配对的错误结果 |
| 已接受、尚未完成 | commandId、接收回执及等待对象；Run 持久等待，结果到达后再续接，不用无界轮询占满模型步骤 |
| 效果未知 | 保留原命令身份并查询；不得把超时表述为未执行，更不能自动重跑有副作用操作 |
| 大文件或多模态 | 存储原件，返回有界摘要、资源身份及按范围读取入口；图像/文件由路线 adapter 按已核验能力装配 |

模型可见结果和完整结果分开保存，裁剪附带原件引用和裁剪说明；原始仿真输出、图片、引用或工具错误不能仅留在观测平台。tool-call ID 与 commandId 显式关联，不能互作去重键。多个只读独立调用可并行；共享对象修改按对象依据串行或条件写入。工具声明的“只读/幂等”是接入待核验属性，不是任意远端自称即可取得的执行保证。

### 具体能力表与课程组件映射

以下名称是目标逻辑接口示例，尚非已实现 API。实际模型短名称经注册表映射；同一工具定义跨路线保持业务语义，不要求同一提供商名称或原生消息格式。

| 来源与能力 | 输入与结果 | 实际执行与失败处理 |
| --- | --- | --- |
| 平台 `workspace.inspect` | 活动、对象范围、`current` 或固定内容身份；返回作品、组件状态、待同步事实及其来源 | 学习数据服务/工作区宿主读取。来源不可用或尚未同步明确报告；不把上次缓存叫当前内容 |
| 平台 `resources.search` / `resources.read` | 获准资源集合、查询或资源身份与页/行/区域；返回片段、引用、原件及裁剪说明 | 资源读取器/检索器执行。PDF 按页与图像路线处理；无全文或图像能力则说明缺项，不猜缺页内容 |
| 平台 `tools.discover` / `skills.load` | 用途及对象，或固定 Skill 身份；返回获准候选定义/指定正文与资源索引 | 注册表和资源读取器执行；新增工具定义在配对完成后的新原生段生效。加载说明不执行其脚本 |
| 课程组件 `alu.inspect_observation` | 观察身份、信号集合、时间范围；返回实际输入、已运行作品、波形片段与诊断 | ALU 组件读取已保存实验。观察缺失或与作品不符时明确返回；不据此自动重跑 |
| 同一 ALU 组件 `alu.run_cases` | 固定作品、用例、预期值（若学生已给出）；返回 command 接收回执或实际结果身份 | 按课程运行方案交给浏览器/指定执行器。编译失败是业务结果；无环境为未派发；超时效果未知则查询原命令 |
| 平台 `artifacts.propose` / `artifacts.validate` / `artifacts.present` | 结构化草稿、依赖、状态迁移策略；返回草稿身份、诊断或展示回执 | 产物存储、隔离校验器、工作区宿主。仅通过结构、权限、依赖与状态检查的版本可展示；草稿失败不会替换可用版本 |
| 平台 `student.ask` | 简明问题、可选答案/自由输入、允许跳过与活动依据；返回展示回执及等待身份 | 教学呈现层显示、RunStore 保存等待。响应身份配对；可见或关闭不算回答，重复回应不二次推进 |
| 平台 `work.propose_change` / `work.apply_change` | 固定作品及差异；返回建议，或学生已请求/采纳范围内的实际修改结果 | 作品服务条件写入；对象已变则重新取证/返回冲突。课程帮助范围和学生修改意图不满足时不能应用 |
| 后台 `memory.propose` / `memory.revise` | 获准学习事实、来源与候选判断；返回候选/修订及复核状态 | 画像服务按版本与来源规则处理，主对话不因此获得任意画像写入能力；争议和证据不足保留待复核 |
| 个人连接 `notes.search` 等 MCP tools/resources | 当前连接定义允许的参数；返回个人资料片段和原件引用 | MCP client 调用实际连接，记录原始能力和版本；离线或撤权如实返回，不改用学校或其他连接的同名工具 |

ALU 一个组件同时提供读取观察与运行用例两个 Agent 工具，也可只提供视图而不贡献任何工具。读取代码走公共作品能力，生成解释卡走公共产物能力，不为每门课复制一套 Agent。自主学习无需 ALU 组件；默认从公共资料、学习内容与已选个人扩展装配。

命令回执查询、等待唤醒、接收重试和交付条件检查由运行程序推进，不把无限轮询包装成模型必须反复选择的工具。学生可主动问“实验怎样了”，这时模型获得已核实状态；不会为了显示进度重新发起实验。

## Skills：说明包与渐进装载

采用 Agent Skills 的 `SKILL.md` + YAML frontmatter + Markdown 正文格式，保留 references/assets/scripts 目录约定；格式本身不替项目决定执行权限。[Agent Skills 规范](https://agentskills.io/specification)

发布清单固定 Skill 来源、版本、内容摘要和依赖资源。入口只装载名称、用途与适用条件；学生明确调用、课程活动指定，或 Agent 判断匹配后，通过 `load_skill` 读取正文。加载记录关联 Run 和步骤；资源按需读取并记录具体版本，恢复时使用当时的内容，不能改读“最新版”。必需 Skill 不可用时明确缺失；可选 Skill 失败不阻断无关能力。

课程规则限定允许的教学方法；Skill 是该范围内的操作指导。多个 Skill 有不同步骤时按任务适用性选择，无法同时满足的必需要求由装配检查报告冲突，不能把最后加载的说明当作最高优先级。学生要求暂停或自己尝试优先改变引导行为，但不会扩大课程开放资源。

`allowed-tools` 等声明只作为需求或收窄范围的输入，不创建权限。Skill 中的脚本必须作为固定资源交给已授权的执行器；读文件不等于运行文件，加载 Skill 不安装依赖或获得通用 shell。开发者给 Codex 使用的仓库 Skills 与产品学生 Agent 的 Skills 分别管理。

## MCP：统一接入，保留三类能力语义

使用官方 TypeScript client SDK 接入，锁定实际包版本和所支持的协议版本；具体依赖固定在实施前验证，不把 draft 扩展默认当作稳定能力。连接配置属于相应个人或学校空间，秘密保存在实际连接进程的凭据存储中；日志只记录连接身份。远端 HTTP 与本机 stdio 是不同部署适配，本机进程由已安装的执行环境启动，不能因服务器目录声明而自动安装程序。

| MCP 能力 | 项目接法 |
| --- | --- |
| tools | 协商后获取完整分页目录，映射到 AgentToolRegistry；按连接与原始名称命名空间隔离，保留 schema 和声明快照 |
| resources | 由上下文策略或学生引用触发读取；保存 URI、读取时内容身份和来源，加入材料层，不提升为系统指令 |
| prompts | 明确选用的工作模板，经参数校验和预览进入任务输入；课程作者可固定模板版本/内容，外部 prompt 不能自动替换平台 system prompt |
| MCP Apps | 沿课程组件宿主契约接入交互与状态；模型上下文更新不能冒充可靠保存 |

这是项目接入选择，协议本身分别把 tools、resources、prompts 定义为模型操作、上下文资源和可选模板，并不要求把它们合成一个工具列表。[Tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)、[Resources](https://modelcontextprotocol.io/specification/2025-11-25/server/resources)、[Prompts](https://modelcontextprotocol.io/specification/2025-11-25/server/prompts)

收到目录变更先刷新可用版本，不修改进行中的清单。远端无法提供旧定义时，下一步停止调用该能力并说明变化；不能只固定一个名字就声称远端行为已冻结。取消是否成功以服务的真实响应为准；断线后的有副作用结果未知仍走命令查询，服务无查询或幂等支持时保留未知，不重发冒险。心跳、重连与 capability 失效是连接生命周期，不是让模型反复猜测网络是否恢复。

不启用没有当前用例的反向模型 sampling、任意服务器 roots 访问或通用生命周期 hook。需要时按具体资源、预算与主体契约讨论，不因“完整 MCP”而扩大默认权限。

## Plugin：扩展贡献的分发与更新

Plugin 清单可打包课程组件、Agent 工具适配声明、Skills、Prompt 模板及 MCP 连接配置模板；课程发布选择具体贡献及其版本。Plugin 不是运行权威，也不把一个安装动作等同于已为所有课程或学生启用全部能力。

平台维护者提供宿主和可信适配器；教师在课程设计中选择或创建课程组件及指导资料，平台执行构建与检查。教师生成的组件代码仍在已有隔离宿主/执行器中运行，不能靠 Plugin 入口在 Agent 主进程任意执行代码。更新先形成新版本和影响报告，由教师选择同步课程；已有活动与 Run 保留原绑定，撤权和确实无法运行的情形按既有失效规则处理。

**负责人已确认：** 学校课程中允许学生自愿添加个人 Skill/MCP，例如检索自己的笔记；仍遵守课程规则，不扩大课程材料和操作权限，普通学习流程不要求配置扩展。课程发布能力与个人扩展分开记录来源、版本及适用范围；个人扩展不改变同课其他学生配置，也不能覆盖必需课程规则。个人空间同样可自行装配。个人模型选择保持独立，不新增学校管理员批准前提。

个人 MCP 凭据由学生所选连接环境保管，课程运行只获得本次范围内的能力调用授权；本机连接离线时如实不可用，不自动把秘密搬到学校服务器。个人资料保留来源与访问范围，进入当前上下文不自动扩大教师可见内容；教师仍只获得既定学习摘要和学生交付中允许分享的部分。

## Prompt 与上下文组成

Prompt 模板随代码或课程发布固定版本；实际装配记录可追溯。生产 Run 不直接读取一个随时可变的在线“最新 prompt”；评估平台可用于试验和审阅，选定内容通过发布清单进入运行。

| 层次 | 内容与约束 |
| --- | --- |
| 平台角色与真实性原则 | 学生 Agent 的目的；事实、推断、示意和实际结果的区分；不把工具内容当高优先级指令 |
| Agent 模式与输出契约 | 本次辅导、主动建议、产物生成或后台整理的职责及交付要求 |
| 课程规则与当前任务 | 允许的帮助、开放资源、学习目标及组件版本；课程提供的材料内容与发布者指定的规则分别存放 |
| 学生当前意图与偏好 | 提问、选区引用、自己尝试/暂停、帮助形式等；不从长时未回应推断同意 |
| 按需 Skill 指导 | 已加载的操作方法和资源引用，在上述范围内生效 |
| 事实与材料 | 作品、观察、工具结果、检索片段、历史摘要与画像判断，带来源和不确定性，不成为 system 指令 |

`ContextBuilder` 在每个步骤边界制作带来源的上下文清单。优先保留当前问题/引用、规则、未结命令与等待、近期相关作品和实际结果；其次是与当前目标相关的活动历史、已复核画像及通用偏好，再按缺口检索材料。读取索引先按空间、课程和访问范围过滤，候选命中后仍复核对象资格和版本。检索器可以使用全文、结构化查询或将来实际需要的向量索引；契约不依赖某一种数据库。

输入窗口扣除输出预留、工具 schema 和必需提示后才分配历史/检索预算。必需内容本身超限时缩小任务或返回具体缺项，不能悄悄删除课程规则或学生最新问题。长结果通过范围读取，压缩仅处理可压缩历史；必须保留目标、未结事项、已接受效果、引用身份、矛盾证据和不确定性。压缩摘要是有来源的派生记录，检查未通过则保留原件并采用更小的上下文，不丢弃唯一事实副本。

改变模型路线、system/tools 前缀或压缩历史时，按三协议既有决议建立新的原生段。先结清原段的工具结果配对；未结外部效果继续使用原命令身份处理，不能因换段重新派发。原生记录只在原路线续接，可移植事实用于新路线，不跨提供商复制签名。

## Memory 与运行中新输入

长期记忆从学习事实和学生明确表达中形成候选：保存内容、作用范围、来源、时间、置信依据及复核状态。确定性信息可以直接落为事实；“可能误解进位”等推断保留待验证和相反证据。画像更新按对象版本合并；学生纠正产生修订与来源链，不改写历史实验或教师正式评价。过期、被撤回或来源无权访问的记忆停止进入新上下文；旧输出仍可说明当时依据。同课跨任务积累，跨课仅共享已确认的通用偏好。

个人自主学习的记忆按活动及明确延续的目标组织；不同主题之间不自动共享学科掌握推断，通用偏好仍可复用。没有课程不等于取消来源、纠错与空间边界。

负责人已明确默认 steering、设置可改为排队（L35）。普通引导立即持久接收，在同一 Run 的下一可用边界调整目标；不取消当前模型请求，也不把消息插入在途上下文。完整模型响应后、未开始工具派发前以及最终交付前检查新输入。未开始的旧工具回填明确未执行结果，已开始操作按真实结果收束；长作业已返回接收回执后，引导可唤醒等待继续对话，作业保持单独跟踪。

排队消息等当前完整轮正常结束后，按顺序开启后继 Run；设置变化不重分配已接收消息。停止、失败或预算耗尽后保留并暂停所有未消费输入，包含 steering；终态后的继续建立关联后继 Run，不重放旧操作。回答当前提问通过关联回应恢复等待；选择另发 steering 则替代尚未回应的旧问题等待，晚到旧回答不推进失效 Wait。新消息与收尾用同一有序持久状态裁决，不能留下已接收但无人推进的消息。默认交互、编辑/移除、显示状态与源码差异详见[新消息与过程展示](2026-10-27-agent-interaction-design.md)，不再沿用“转向必另开 Run”的旧建议。

## 交付、调试与评估契约

回答要区分依据、推断与未知；事实引用绑定可访问的实际来源。主动提示还需通过当前意愿、时机和依据检查。生成产物必须通过结构、依赖、资源范围和可恢复状态检查后才启用；修订有预算上限，耗尽时保留诊断和可用草稿，不伪装完成。

按负责人对功能、质量、易用性、协作和本机运行的综合要求，结合[两平台试用](2026-10-27-observability-local-trial.md)，负责人已确认本机 **Phoenix + SQLite**（[L33](../student-agent-decisions.md#来源与状态)），使用同仓集中封装的 OTel/OpenInference 可选集成和 TypeScript 评估工具；团队通过固定调试包和案例共享结果，不要求常驻共享观测服务。功能、导出导入边界及未实测项见[观测与评估研究](2026-10-27-agent-observability-evaluation-research.md)。集成代码、评估程序和合成案例可同仓，真实运行数据、平台 SQLite 和秘密配置独立保存；默认关闭，启用后默认只送本机，选定共享是独立动作，具体见[本机运行与协作](2026-10-27-agent-evaluation-integration.md)。平台不要求安装在学生设备上，也不成为六个产品部署单元的前置。RunStore、命令/结果和学习数据保存业务事实；平台只保存调试投影，不能负责领取 Run、确定操作完成或替代画像。

每次记录至少关联 space/活动/Run/step/attempt/command、AgentDefinition、Prompt/Skill/工具/课程版本、上下文内容身份、模型路线、实际交付身份与结果。跨进程传播关联身份；长等待在工作段边界结束 span，恢复建立新段并关联原 Run，不保持跨天的开放模型 span。重复导出不重复计入模型费用；观测平台不可用时，有限队列和明确丢弃/失败计数保障学习流程继续。

开发样本可保存完整允许的输入输出以便重现；生产记录按空间配置采集范围和保留期，密钥永不采集，原生 reasoning/签名默认只在受控运行存储保留。评估集使用固定输入和获准内容；人工选入的真实案例保留来源与处理记录。个人本地部署不默认向学校或第三方上传完整会话。

| 评估层 | 样例与判据 | 结果用途 |
| --- | --- | --- |
| 确定性契约 | tool-call/result 配对、权限、版本、来源、格式、取消/恢复、未执行与未知效果的区分 | 必须通过的工程回归 |
| 模型行为 | 工具选择与参数、Skill 触发、引用正确、是否凭空声称实验成功、是否采纳学生纠正 | 固定数据集比较模型、Prompt、能力配置；有界、可重复，不执行真实写入 |
| 教学质量 | 是否符合课程帮助范围、提示是否适时和有帮助、是否让学生继续思考 | 量表 + 人工复核；模型评分器作筛查，不能独立证明教学效果 |
| 实际学习效果 | 课程中的学习证据、学生反馈和教师判断 | 另行教学验证；平台评分、任务完成、满意度均不能直接当成掌握或正式成绩 |

每个实验固定数据集、目标 Agent 配置、模型路线、工具 fixture 和评分器版本；记录重复运行的波动及失败，不只挑最好结果。回放有两种明确模式：只复现已记录的事实与结果，或使用固定输入重新生成候选；后一种默认接只读/模拟 ToolExecutor，不重放真实写入、提交和外部通知。候选与基线按同一输入比较，并把可见输出、实际工具轨迹和最终交付同时纳入评估。

## 完整请求走查

下面是**合成设计记录**，身份、输入、输出和预算用于检验契约，不是已运行产品、真实模型回答或学生学习效果。工具 schema 的字段编码在实施时固定；这里保留足够具体的装配与因果关系。

### ALU：引用结果、加载 Skill、引导转向与交付

**输入。** 学生在课程活动中选中已保存观察 `obs-demo-1`：4 位输入 `a=0111`、`b=0001`，结果 `1000`，实际记录 `carry=0`、`overflow=0`。作品 `work-demo-v3` 的相关行示例为 `overflow = carry;`。学生问“为什么有符号结果不对？请帮我检查这个用例”。发送时固定上述引用；继续编辑形成 v4 不替换本次依据。

**初始装配。** 课程发布 `course-demo-r2`、ALU 组件 `alu-demo-v1`、辅导 Agent `tutor-demo-v2`、Prompt `prompt-demo-v4` 和所选三协议路线写入装配快照。示例课程允许解释概念、读实验和执行学生请求的诊断，不允许未经请求修改作品。可见工具为 `workspace.inspect`、`resources.read`、`skills.load`、两个 ALU 工具、三项 artifacts 能力和 `student.ask`；不授予作品写入或教师私有材料读取。能力目录只含相关诊断 Skill。

**实际指令内容示例。** 模板变量在发送前解析，保存实际文本内容身份，而不只保存以下模板名：

```text
平台角色：你协助学生围绕当前学习目标理解、验证和改进作品。
真实性：区分已记录实验、数学推断和教学示意。工具未运行时不能声称运行。
帮助范围：本活动允许概念解释和诊断；保留学生动手机会，不直接修改作品。
当前目标：解释学生选中的 4 位有符号加法结果，并核查该次 overflow 判断。
引用规则：先回答 obs-demo-1 / work-demo-v3 所指内容；读取新版本必须明确区分。
过程输出：重要阶段给学生一两句可读说明；工具完成依据由工具结果提供。
交付要求：回答包含实际观察、推断依据和可选下一步；不得将单次结果当成掌握。
```

这些指令与学生原文、固定引用、材料片段分别装配，后者不会拼成高优先级规则。示例上下文先带输入和作品相关行，排除完整无关历史与教师答案；Memory 只加入“希望先解释概念”的已确认偏好，不预设学生不懂溢出。示例预算为最多 8 次模型 attempt、2 次产物校验修订、独立的工具期限与路线 token 上限；数值仅用于走查，不是所有课程的产品常量。重试计入预算。

| 步骤 | 请求/实际结果 | 状态、上下文与交付 |
| --- | --- | --- |
| 1. 选择方法 | 模型调用 `skills.load({skillRef:"alu-diagnosis-demo-v1"})`；返回“核对实际输入/作品 → 区分数学范围与电路信号 → 必要时验证”的固定正文及材料索引 | 正文作为 Skill 指导加入下一步，记录内容身份；读取脚本不执行脚本；工具定义未变则不必换 system/tools 前缀 |
| 2. 核实事实 | `alu.inspect_observation({observationId:"obs-demo-1",signals:["result","carry","overflow"]})` 返回上述真实记录与固定作品；`resources.read` 返回开放教材中的 4 位补码范围 `[-8,7]` | 两个获准独立读取可并行；结果记录 call/result 配对、资源页码与裁剪情况。UI 显示“读取本次波形”“查阅补码范围”，可展开结果 |
| 3. 接收引导 | 下一次模型生成时，学生补充“先不要运行，先解释进位和溢出的区别”；本次模型最终返回拟运行 `alu.run_cases` | 消息先可靠保存并显示待采纳；完整响应后派发检查发现新输入，给该调用配对 `not_executed: new_input`，无 command 被发送。保留原生响应/推理，不修改已发请求 |
| 4. 按新目标继续 | 下一次模型输入包含原调用、明确未执行结果、学生补充及前述依据；生成简短过程说明和教学卡草稿 | 同一 Run、累计预算，`InputEvent` 标记被此步骤消费；UI 更新为“已采纳，先解释”，停止旧运行计划 |
| 5. 校验与修订 | `artifacts.validate` 首次返回遗漏“教学示意”标签的诊断；在一次修订后通过；`artifacts.present` 返回实际展示回执 | 失败草稿不展示、不替换旧可用内容；校验不是教学正确性的自动证明。若修订预算用尽，给可读解释并说明卡片未展示 |
| 6. 面向学生交付 | 说明实际记录 `1000 / carry=0 / overflow=0`；按补码范围推断 `7+1=8` 超出可表示最大值，当前 overflow 记录与有符号规则不符；问学生愿意先判断哪类输入能区分两种条件 | 给教材与本次观察来源；说明没有新运行、没有改作品。若使用 `student.ask`，Run 进入等学生状态而非伪装完成；对应回应直接恢复 |
| 7. 收尾与追踪 | 学生选择结束当前说明后，交付与输入收尾按同一序列提交；候选画像只记录“学生提出区分概念”，不自动断言已掌握 | 本机 Phoenix 若开启，保存装配/步骤/工具的投影；关闭或离线不影响上述事实。独立 queue 消息在正常结束后才开始下一轮 |

若第 3 步到达时实验已被执行器接受，则不使用 `not_executed`：保留真实 command 与接收回执，显示“实验仍在运行，已收到你的调整”；长作业回执已闭合 tool-call 后，可继续概念说明。完成结果后到仍归原输入，不覆盖新作品或自动追加过时回答。

### 其余组合与失败分支

| 情境 | 装配和执行的具体差异 | 最终可交付结果与恢复 |
| --- | --- | --- |
| 个人资料自主学习 | `courseRef=null`，目标来自“解释这份 PDF 第 3 页”；同一公共 Agent 加入选定资源、个人偏好、`resources.read`/`student.ask`/artifacts。没有课程规则、ALU 工具或教师答案。先读第 3 页实际文本/图像，再给有出处的解释；内容不足才询问缺项 | 直接建立个人活动，不要求建课。图像能力缺失时明确只能解释可读取部分；个人记录不进入学校摘要 |
| 生成交互卡，工具失败或长期等待 | 草稿声明依赖获准组件；校验失败按预算修订。真实实验返回 `accepted(command)` 时，保存工具接收结果和持久 Wait，模型不循环轮询；学生在等待中转向则按新目标继续 | 有效草稿经宿主检查才展示；晚结果只补原实验事实。学生停止后不再发布旧卡；若作品无法迁移，保留旧实例与说明，不清空输入伪装连续 |
| MCP 返回大图片、结构化数据后断线 | 原件入资源存储，工具结果保留有界内容、结构和 URI；后续 `resources.read` 按区域取证。图像按模型路线已核验能力投影；改变 tools/路线时先结清调用配对，保存可移植事实并建立新原生段 | 只读读取可按原资源重取；有副作用调用结果未知则查原命令，服务无查询能力时保留未知。不能重发写操作来“恢复”或把旧签名移到新模型 |
| 教师更新组件/Skill，活动中切换模型 | 当前活动仍用发布 r2 和 Skill 内容身份；新活动可用 r3。学生换路线时，已完成工具结果与作品事实可移植，原生推理/签名留原段；新路线能力不足则缩小到实际可用范围 | 远端旧能力失效时明确不可调用，不偷换最新版。显示“此能力当前不可用”并提供仍可做的解释；不会把当前活动悄悄升级 |
| 压缩、评估或观测失败 | 压缩保留当前目标、未结 command/Wait、引用与相反证据；校验未通过则保留原历史、缩小读取。评分器失败单独记录；观测队列有界 | 能继续则交付已核实部分，必需上下文放不下则说明具体缺项；评估错误不是产品失败或通过，Phoenix 不接管运行 |

以上覆盖装配、模型意图、实际执行、引导、教学交付与恢复的设计因果链；不是生产 API 或产品端到端测试。不同真实模型能否遵守指令、摘要显示是否合适、学生是否更容易理解，仍需分别验证。

## 当前收束状态与下一主题

本轮三个产品问题已有答复：默认 steering/可改排队，需要工具调用、思考摘要和状态显示，个人空间可无课程自主学习。具体时点、显示程度和无课程默认行为见[交互设计](2026-10-27-agent-interaction-design.md)；能力表和完整请求走查已补齐。课程内个人扩展、本机 Phoenix 与固定调试包仍按既有确认，不重复提问。

根据[技术判断委托](../student-agent-decisions.md#第三轮决定与架构重评)，工程机制按已定要求收束，不把笼统的“整体方案待确认”变成逐项技术审批。当前没有为推进本次设计而必须再次选择的已知产品分叉；方案可继续接受负责人对具体交互的修正。负责人本轮要求核对能否关闭后，工程确认本票范围内无已知未决产品分叉，已发布[最终决议](https://github.com/paher-din/XunJie/issues/119#issuecomment-6443526782)并关闭；下一主题承接实施规划，不自动启动产品实现。

Memory 的课程范围、学生纠错和资料访问已有产品边界；数据库、资源存储、迁移对象和实施拆分由[重构迁移与验收：数据存储、兼容范围和实施路线](https://github.com/paher-din/XunJie/issues/120)承接。依赖版本、真实端点、目标设备、恢复与派发竞争属于实施验证；第二门真实验收课程按既有 L15 在重构验收阶段选择，不拿设计反例冒充已选课程。
