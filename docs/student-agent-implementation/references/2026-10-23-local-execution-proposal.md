# 本地优先执行：讨论材料与验证记录

日期：2026-10-23。所属议题：[本地优先执行：设备支持、课程运行方案与实验生命周期](https://github.com/paher-din/XunJie/issues/114)。

状态：负责人已确认首条 ALU 的浏览器执行方向与跨课程边界，并补充教师易用性要求；本议题已收束，决策答案以[正式决议](https://github.com/paher-din/XunJie/issues/114#issuecomment-6363162710)为准。本文保留讨论材料与原生/浏览器小样本，作为决议附件，不是生产验收。已决议的 [SystemVerilog ALU 活动](https://github.com/paher-din/XunJie/issues/113#issuecomment-6348000023) 是首个验证案例，不定义所有课程的工作方式。

## 本轮已明确

1. 首批正式验收目标为 Windows 11 x64 与 Apple Silicon Mac，使用桌面 Chrome/Edge。这是目标范围，不是已经通过的支持声明；具体 OS、浏览器版本随验收记录固定。
2. 允许安装组件，但产品应自动完成下载、安装、依赖配置、检测和更新，减少学生的繁琐流程。不能把环境搭建步骤转交给学生；负责人没有硬性排除某种底层技术，也没有同意将手工配置 WSL/Docker 作为默认准备方式。
3. 首条 ALU 中，自由实验时改输入就更新实际结果；需要保留预测用例时，先写预测，再点一次“运行并比较”。编译、装载等内部步骤由系统处理。这是本活动的交互选择，不要求其他课程都有预测、自动重跑或编译步骤。
4. 继续遵循既有原则：教师设计运行方案，本地优先，仅本地确实不能满足时使用课程明确配置的远端路径；学生不选择节点。首条 ALU 的安装准备在其 50–70 分钟活动预算之前完成，不据此设定其他课程的时长。
5. 平台需要适应多种课程形式，并根据具体任务选择能力与运行方式。教师和 Agent 可以创造真正的新工具，不能把扩展能力收缩为修改预制 ALU 模板。
6. 提供所需工具、减少教师和学生使用时的门槛与繁琐操作，是重要产品要求；工具能运行和教师容易使用分别验收。

## 跨课程边界候选

通用性应来自稳定的接入与执行边界。Icarus/WASM 是一种具体执行适配，不能成为所有课程必须采用的执行器；“代码 → 输入 → 预期答案 → 单次运行”也不能成为所有任务的数据模型。同一课程中的不同任务可以组合不同能力。

| 责任 | 应当负责 | 不由它固定 |
| --- | --- | --- |
| 平台 | 检查并准备声明的环境；绑定输入与版本；启动、查询、取消、收集结果；维护运行身份与恢复边界 | 学科算法、特定信号名、预测步骤、正确答案、任务完成标准 |
| 课程组件 | 提供界面、可调用操作、输入/结果结构和状态；声明环境需求及支持的执行与控制能力 | 学生自行选节点、绕过运行方案安装依赖 |
| 教师发布的任务与运行方案 | 选择工具及版本、任务材料与参数、学生/Agent 可用操作、交互方式和评价方法；为各能力安排本地及必要远端路径 | 平台部署拓扑、每名学生的物理节点身份 |
| 执行适配 | 把工具操作落实为浏览器计算、本机程序或已配置远端服务，返回真实状态、诊断与产物 | 教学是否完成、学生是否掌握 |

这些是行为边界，不在本票预先选定插件框架、包格式或通用工作流引擎。工具输入可以是代码、文件、数据或结构化对象；结果可以是数值、日志、图表、文件、波形或持续事件。工具按需提供接口，无需假装每个工具都具有编译器、测试器或运行按钮。

教师或 Agent 在已有环境与接口范围内可以写新工具、新界面和新算法，经过接入验证后装入课程；并非只能换参数。新增程序包、依赖或语言解释器，只要能通过已有环境装配方式声明或打包，就应随工具交付，无需每门课程都新增平台执行器。只有现有适配无法提供的执行方式、系统能力、硬件访问或控制机制，才需要新增或扩展执行适配并验证。该适配可复用到其他课程，主工作区不应增加按课程名称判断的业务分支。不能承诺任意生成软件及其依赖无需适配就能运行。

### 按任务选择执行方式

至少区分有限作业与保持状态的会话，且二者可以组合：一次构建产生文件，后续会话装载文件并持续交互。它们不是课程分类，也不要求实现一套任意流程编排产品。

- **有限作业**：给定一份确定输入，运行到结束，返回结果与产物；重复实验创建新的运行记录。是否随编辑自动触发由工具和任务声明。
- **保持状态的会话**：启动后接受一系列输入，产生连续观察；每条操作绑定会话身份、实例及顺序。是否支持暂停、单步、复位、检查点、断线续接分别声明，不能假设所有会话都有这些能力。
- **无需计算的工具活动**：编辑报告、标注资料或操作画布仍是有效学习任务；通过工作区状态和证据接口接入，无需制造空的编译/执行流程。

运行位置按具体能力与所需语义选择。浏览器能够完整满足时优先在浏览器；确需原生依赖、资源或硬件时采用自动准备的本机环境；本地确实不满足时才使用教师事先配置的适用远端路径。“存在一个 WASM 包”不足以证明语言特性、资源和交互方式满足任务。一次课程也可以组合不同位置的能力，不强制整课一起切换。

### 反例检查：更换任务后哪些部分需要变化

以下是设计场景，用于检查边界，均不是已交付或已经实测的第二课程。

| 场景 | 课程/工具定义的差异 | 平台应复用的能力 | 本票禁止的泛化 |
| --- | --- | --- | --- |
| 组合逻辑 ALU | SystemVerilog、F/Cout、4096 组验证、即时试验与预测用例 | 环境准备、有限作业、版本与结果归属 | 把该行为表或预测流程写入平台 |
| 时序电路调试 | 时钟、复位、连续信号与波形，需要保留内部状态 | 同一套身份与查询规则，增加工具声明的会话控制 | 改输入就重建进程；把丢失状态后的新会话说成续接成功 |
| 数据分析任务 | 数据集、脚本或 Notebook 操作、依赖、图表与报告；可组合短作业和有状态环境 | 环境检查、文件/对象输入、事件与产物、取消与恢复 | 所有结果必须是 F/Cout 或自动判定对错；宣称当前 Icarus 探针已经验证 Python |
| 开放报告或画布任务 | 文档/对象编辑、引用、解释，教师按任务标准评价 | 工作区状态、证据归属和交付接口 | 强制先编译、运行或得到机器验证“通过”才能提交 |

扩展检验分两档：已有执行能力内的新任务应只改任务配置、工具包或可装配的环境依赖；确实超出执行能力时允许增加适配，但不应改写主工作区或公共生命周期。实际第二类课程、包格式、加载与恢复原型在[课程工具与生成内容：接入、运行宿主和状态恢复](https://github.com/paher-din/XunJie/issues/117)及[重构迁移与验收：数据存储、兼容范围和实施路线](https://github.com/paher-din/XunJie/issues/120)中确定和安排。此处先约束本地执行方案不得把这些能力封死。

## 教师准备与易用性要求

教师决定教学内容与运行安排，平台和 Agent 协助把任务变成可用课程。工具接入的通用性不能变成教师的集成工作；常用能力应有可复用工具与合理默认值，缺少工具时支持借助 Agent 创建并验证。

| 教师需要完成的事 | 产品应承担的工作 |
| --- | --- |
| 表达任务、选择或创建工具 | 推荐/装配所需能力与可用环境，仅呈现教学决定所需的参数，不要求先理解执行器或手写运行清单 |
| 课前检查和预览 | 自动核对依赖、版本和能力，运行工具自检与示例输入，指出未满足条件；预览结果不代替学生真实设备检查 |
| 发布并供学生使用 | 携带工具、依赖与运行方案的关联版本，尽量自动完成学生环境准备，避免反复配置 |
| 处理准备或运行失败 | 自动修复可修复问题，保留已有配置与作品；必须人工处理时给出原因与直接的下一步，减少页面往返和重复操作 |

后续使用验证需覆盖从任务描述到工具装配、检查/预览、发布及故障恢复的过程，记录实际操作、阻碍、重复填项与需要工程人员协助的位置。此处不预设未经试用的耗时或点击次数目标，也不宣称已完成教师体验验收。完整教师端创作界面仍由相应范围设计；本票要求其工具与运行输入契约支持简便的使用流程。

## 技术建议：首条 ALU 在浏览器本地执行

采用 **Web Worker 内的 Icarus/WASM** 作为首条 ALU 的工程方向。预处理、编译、实际仿真与 VCD 生成均在学生浏览器完成；工具链随课程组件自动加载并缓存。首次准备与更新由平台完成，本活动不默认要求安装本机组件、WSL、Docker 或 FPGA 开发环境。

浏览器内的界面与 Worker 直接交换有界任务和结果；自由实验的输入反馈不经过应用服务器，也不需要浏览器连接 localhost。应用服务负责课程、保存/同步、Agent 和教师交付所需记录。此选择解决首条活动的通信路径，不表示已经选定所有未来课程的本机组件协议。

教师发布的课程运行方案引用固定的工具与执行环境版本，平台在进入前检查 Worker/WASM 能力、资源加载和课程自检。新发布版本先验证，已开始的运行保留原版本。第一版 ALU 默认只有已验证的浏览器路径；若某设备确实不能满足，只有教师方案预先包含适用的远端路径才可使用。缺文件、加载失败、未完成权限与结果未知分别处理，不统称为“本地不支持”。

本机组件保留为确需原生能力时的扩展方向，并遵守已确认的自动准备要求。它不成为首条 ALU 的默认安装包，也不因浏览器一次运行失败而自动接管。未来课程若确需本机组件，其直连/中转、安装、隔离和平台支持需随该能力验证；现有 SSH/VM 链不成为默认产品要求。

### 替代路线与取舍

| 路线 | 本轮判断 |
| --- | --- |
| Icarus/WASM + Worker | 优先方向：有实际源码编译、四态输出、VCD、停止/恢复与编译复用证据，最符合减少准备操作的要求 |
| 原生 Icarus + 自动本机组件 | 可行备选：Mac CLI 小样本成功，但新增安装、更新、连接和隔离工作；首条活动尚没有必须承担这些成本的能力缺口 |
| Verilator/Clang WASM | 暂不优先：增加 C++ 编译链；已调查实现主要采用二态语义，不能用正常二值输出证明学生没有产生 X |
| 默认服务端编译/仿真 | 本轮不选：本地小样本已显示能力可行，尚无必须增加远端执行资源与网络往返的依据 |
| 直接沿用现有 VM/容器与 VPI 会话 | 本轮不选：单次有界执行已覆盖主线，旧接线、2800 组验证与持续会话不是新活动需求 |

VeriSim 是能力与性能的实验来源，不作为已经可直接发布的二进制依赖。它的公开产物仍输出 `system.vpi` 动态加载诊断；删除模块声明会导致系统任务不可用，不能靠删除配置或过滤错误文本解决。移植补丁和完整固定构建链也尚未取得。实际交付须重建可追溯的 Icarus/WASM 包、修正系统模块初始化，固定编译选项，并重新运行同一组探针。若这一步失败，必须回来重评路线，不能把本研究通过写成运行包已就绪。

## 学生操作与环境准备候选

进入活动前自动检测课程所需能力。浏览器路径满足要求则直接就绪；确需本机组件时，提供一次明确的准备入口，识别系统与架构，下载安装匹配包、完成配对、执行小型自检，再返回原工作位置。保留系统要求的确认，产品处理其余安装细节。

日常进入不要求再次启动终端、填写端口、选择模拟器、切换节点或重装依赖。组件更新先验证并保留可恢复版本；正在运行的实验继续使用原环境，新环境在下次运行前检查兼容性。更新失败保留作品和可用旧环境，不以未确认的新环境继续给出结果。

环境检测至少区分：

| 情况 | 平台处理 |
| --- | --- |
| 已就绪 | 进入活动 |
| 尚未准备、组件未运行或可修复的版本不匹配 | 自动准备或修复，说明进度与失败原因 |
| 系统确认或浏览器连接权限尚未完成 | 就地解释并给一次操作入口；不能据此断言设备不支持 |
| 设备、组织策略或资源条件确实不满足 | 依据教师已发布方案提供允许的替代路径，否则提供明确的准备/教师协助入口 |
| 组件失联但实验结果尚未查明 | 查询原运行，不把失联伪装成安装缺失或直接重跑 |

资源下限与确切版本范围需要在实际目标机器上测得；当前不凭开发机速度宣布最低内存、下载体积或安装耗时。

## 首条 ALU 的运行方式候选

主线 ALU 是组合逻辑。优先比较“复用编译结果、按需有界运行”的实现，不要求学生维持一场持续的虚拟板会话。底层可以为降低等待复用进程或 Worker；界面和课程契约不依赖某个常驻进程一直存活。

作品稳定后自动准备当前代码的编译结果；自由实验的输入更新合并短时间内的连续操作，并只显示最新输入与对应作品的结果。编译失败时保留代码位置与诊断，旧结果明确属于上次作品，不显示成新输入的结果。波形来自实际执行，不能用教学示意代替。

预测用例进入独立的“预测—运行—比较”过程。该用例的实际结果在运行前不显示，相关结果视图暂停自动反馈，运行时绑定预测、输入和当时的作品；已看过自由实验结果不能被补记成运行前的独立预测。学生仍可选择直接查看结果，记录真实发生的行为与缺项，不加提交门槛。两种操作共享同一实际仿真能力。

Agent 可以进行课程允许的验证，但使用自己的运行身份与明确输入，不抢占或覆盖学生正在观察的结果，也不把后台验证记录当成学生预测。完整提示和教学证据策略交给相应连续教学议题。

## 跨课程最小执行契约候选

这里给出行为契约，不预选 API 名称或持久化结构。与自动保存、作品引用及提交的完整衔接交给[工作区交互与状态：自动保存、选区引用、执行依据和提交](https://github.com/paher-din/XunJie/issues/116)。

| 内容 | 要保持的约束 |
| --- | --- |
| 运行身份 | 有限作业、会话及会话内操作有可追溯的身份、发起者、课程/任务/学生范围；重复投递先查询并去重，不以重试为由产生新执行；同一操作身份不能更换输入，无法确认副作用时保留未知状态 |
| 执行依据 | 绑定实际作品/数据/文件或对象内容、工具与运行方案版本、环境配置及输入；有模拟器、验证器或编译器时再记录对应版本；由系统完成，不要求学生手工保存快照 |
| 产物复用 | 工具声明产物的依赖条件；只有相关输入、依赖、配置和工具链一致时才能复用，作品变化不能沿用旧“通过”状态；无编译步骤的任务无需构造编译产物 |
| 执行位置 | 运行开始后固定实际执行器与其启动实例；重连先找回原运行，不在另一位置默默重跑 |
| 返回结果 | 返回运行身份、实际依据、工具定义的结构化结果/产物/事件、诊断及完成或失败原因；工作区与 Agent 都能判断来源，不把执行成功等同于任务完成或知识掌握 |
| 结果时序 | 同一运行的事件可去重并排序；会话事件还绑定其实际实例和操作顺序，晚到结果不覆盖新运行结果，旧结果仍可追溯 |
| 会话控制 | 声明实际支持的输入、暂停、单步、复位与检查点能力；修改代码、重置或恢复如导致内部状态丢失，必须明确形成新实例，不能冒充原会话继续运行 |
| 停止与取消 | “请求停止”与“确认停止”分开；由实际执行器确认终止才报告已取消，正常完成和停止竞态保留真实终态；不能立即停止的操作说明能力边界，停止不等于撤销已经发生的外部效果 |
| 超时与失联 | 有限作业设置时限及输出预算，会话声明资源/持续时间限制、心跳、断连处置及恢复能力；失联表示尚未拿到可信终态，不等于失败或已停止，查询沿原身份进行，不在别处自动重跑有状态或有副作用操作 |
| 同步 | 本地结果先与其依据一起保存，再同步；应用服务上的 Agent 与教师提交只能引用已经收到的对应记录 |
| 失败分类 | 输入无效、工具/环境失败、取消与结果未知分别记录；编译错误、行为不符等由具体工具补充，环境故障不能归因于学习困难 |

首条 ALU 无需承诺刷新或关闭页面后继续长时间运行。已保存作品、用例和结果应能恢复；执行进程是否存活通过查询确认。其他课程若需要会话跨页面存活、暂停后恢复或检查点续接，运行方案必须选择具备该能力的执行适配，不能继承 ALU 的限制后仍宣称满足任务。完整离线教学、源码绝不上云和对本机结果的防篡改证明不在当前范围。

## 固定 WASM 的浏览器证据

[独立上游调查](2026-10-23-systemverilog-local-execution-research.md) 给出候选与来源；主线程进一步使用 VeriSim commit `dc391801af44ec8e99fcdc12c12a3d9a47a5758b` 的六个固定文件，校验各文件 SHA-256 后从临时 loopback 服务加载。六文件合计 2,994,577 bytes，不含应用页面，亦不代表压缩下载量或内存。

复现入口：[serve-alu-wasm-probe.py](../../../tools/research/serve-alu-wasm-probe.py) 与 [探针页面](../../../tools/research/alu-wasm-probe.html)。

```sh
python3 tools/research/serve-alu-wasm-probe.py --output docs/student-agent-implementation/references/2026-10-23-alu-wasm-probe-results.json
```

命令启动临时 HTTP 服务；在待测浏览器打开 `http://127.0.0.1:8754/`，结果会写入指定 JSON。Ctrl-C 停止并清理临时文件。此命令是研究复现入口，不是面向学生的安装流程。HTML 仅为实验报告页，不是产品界面。

已在同一 Apple Silicon Mac 上运行 [Codex 内嵌 Chromium 155](2026-10-23-alu-wasm-iab-probe-results.json) 和 [真实 Chrome 155](2026-10-23-alu-wasm-probe-results.json)。两次均通过六个功能探针；运行包诊断单独保留，不能视为整个交付通过。

| 检查 | 真实 Chrome 样本 |
| --- | --- |
| 4096 组、进位错误负对照、X 负对照 | 分别零不符、256 组错误、1536 组 X；规范化逐行结果的 SHA-256 与原生 Icarus 完全一致 |
| VCD | 完整输入探针产生约 190 KB，并包含最终时间戳；本探针不包含产品波形查看器 |
| 首次完整链 | 工具文件从 loopback 加载约 75 ms，预处理约 29 ms，编译约 51 ms，仿真与输出约 126 ms；不含公网首次下载 |
| 复用编译产物、改变输入 | 三组新的输入通过 `+CASE` 传入，得到正确输出；含新运行时初始化约 2.7–4.2 ms，恢复阶段为 10.4–13.9 ms；不含最终产品渲染与事件传输 |
| 无限推进、零时间死循环 | 外层 250 ms 定时停止 Worker，观察到约 428/369 ms 后结束；说明定时器会延迟，不能承诺恰好在 250 ms 停止 |
| 停止后恢复 | 新 Worker 重新编译、4096 组验证和单输入执行成功 |
| 原始运行包诊断 | 保留 `Failed to open 'system.vpi'` / `dynamic linking not enabled`，仍是待修正项 |

本地证据说明约 86 秒的滚动演示页记录不是足以否定 WASM 计算能力的证据；本次没有进一步分离那个演示的网络、初始化与页面开销，不能断言其慢的具体原因。上述只是少量样本，不是冷启动标准测试、p95 或整个课程的性能承诺。
