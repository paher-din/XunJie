日期：2026-11-06（Asia/Shanghai）。对应 [#193](https://github.com/paher-din/XunJie/issues/193)，技术和验收依据见 [实施方案](specs/wp04-alu-board-check.md)。本页原为待审阅设计，未修改产品 UI；线框不是实际运行截图。沿用 [DESIGN.md](../../DESIGN.md)及现有标签、分屏、板卡和结果视图，不新增 token。

> **实施状态（2026-11-07）：** 工作区、虚拟板、自由观察、等待态、检查报告和恢复界面已按本设计实现；实际运行截图与验证边界见 [实现与验收记录](wp04-193-acceptance.md)。线框仍不是截图，未执行的平台与教学验收见该记录。

## 使用目标与已有界面的延续

学生在桌面 Chrome 中编辑组合 ALU，运行启用后，用开关试进位和操作差异，再用全部公开输入找反例。代码、行为表和结果可随时往返，课堂操作不要求理解编译缓存、Worker 或装载会话。

#192 的“设输入后点运行”在新发布中演进为“点运行启用代码，之后改输入自动观察”；旧活动仍使用其原固定版本。本票复用作品/ALU 实验中心标签、运行簇和结果区，保留目标与材料、Monaco、工具拖拽分屏、问题草稿和导航。

| 现有位置 | 本票变化及原因 |
| --- | --- |
| 作品标签及运行簇 | 仍用“运行”；点击固定当前代码，成功才启用。旁边仅在代码变动时提示“修改尚未运行” |
| ALU 实验工具 | 虚拟板替代宿主五个原始数字输入为主操作；保留紧凑数值编辑作为同一输入的辅助方式，不造两份状态 |
| 板卡当前读数 | 显示当前输入及其真实 F/Cout；待新观察期间留空结果，不沿用旧灯态冒充新输入 |
| 检查区 | 同一工具内增加“检查全部输入”，显示一份所选报告及反例；不切换到第二个检查页面 |
| 运行记录/详情 | 沿用查询、停止、原依据和下载；观察与检查分组选看，各自保存选择，不因另一任务完成跳走 |
| 目标与材料 | 补映射、自由输入例子、公开 4096 域与采样、检查/停止方法，继续按需展开 |

板卡是仪器区域，周围保持原工作区中性底；检查区用标题、留白和 hairline 分隔，不再给每组输入、数字、摘要和反例各套卡片。板卡与下方读数共用结果来源，不能上方亮旧灯、下方写等待。

在 1024px 左右沿现有分屏能力收放；当实验栏不足以完整呈现板卡和控件时使用现有单工具标签，数值编辑按行换行，反例改为逐条字段布局。窄桌面至少检查 900px 视口及工具栏约 360px 可用宽度；复用原响应策略，不缩小正文或强制三栏。保留板卡信号分组，运行、停止、当前读数不藏在横向滚动末端。200% 缩放仍能定位输入与操作。

## 运行启用与代码修改

“运行”始终使用点击时的当前作品，自动保存照常，无保存/冻结/构建/装载前置步骤。首次运行前可预设输入，板卡输出显示“尚未运行”；检查按钮禁用，旁边写“先运行以启用作品”。

运行时编辑器和输入仍可编辑；显示“正在运行当前作品…”及对应停止操作。成功并保留观察后启用这份代码。若点击后又改代码，成功结果旁仍显示“修改尚未运行”，不能让晚成功替新 head 背书。合法完整的 X/Z 观察也可启用，不用“必须全正确”阻止调试。

| 情况 | 就近文案/显示 | 可执行动作 |
| --- | --- | --- |
| 尚未启用 | “编辑 alu.sv，运行后拨动开关，观察 F 和 Cout。”；输出无默认值 | 编辑、设输入、运行 |
| 已启用，代码相同 | 正常显示输入/结果；不常驻版本/保存标签 | 拨开关、检查、运行 |
| 当前代码有改动 | 运行旁“修改尚未运行”；实验旁“实验使用上次运行的作品” | 继续试旧作品或点运行启用新代码 |
| 新编译失败 | 真文件/行号诊断；“本次未启用，实验仍使用上次运行的作品” | 定位诊断、继续自由实验、修改后运行 |
| 新运行停止/预算/采样不完整 | 显示具体原因及未启用事实；旧依据仍可读 | 查询原记录，修改或显式重跑 |
| 双标签启用冲突 | “另一标签更新了实验作品，请核对后继续。”；本次结果留历史 | 查看两份依据，按既有冲突流程选择 |

诊断路径只映射原固定文件；同内容当前文件可定位编辑器，否则显示原依据只读副本。无需学生抄技术身份判断版本，日期/时间与“该次运行的代码”用于日常识别，完整摘要进入详情。

## 输入、等待与四态读数

开关按 A、B、M、S、Cin 分组，组名显示端口/位宽；每位含编号与 0/1。课程固定 SW3…0=A、SW7…4=B、SW8=M、SW10…9=S、SW11=Cin，顺序和极性见固定映射详情。无绑定的开关/按钮/复位/时钟不作为必做操作；保留板卡外观时明确标“本活动未使用”。

数值编辑提供 A/B 的合法 0–15、M/Cin 的 0–1、S 的 0–3 输入及二进制辅助值，和开关双向同步。非法/未完成文本就地保留并提示范围；不截位、不转零、不触发仿真。M/S 行就近给操作名称；保留组合写“保留组合：预期 F/Cout 为 0”，NOT 忽略 B、逻辑模式忽略 Cin 均说明但不改值。

合法修改自动进入有界观察；短时连续拨动可以合并。当前输入可即时更新，但输出只在对应结果返回后出现：

| 结果状态 | 板卡与数值显示 |
| --- | --- |
| 等待候选/本机保护/排队 | “等待观察”；F/Cout 显示占位及不可用灯态，旧观察仅留历史 |
| 真实运行中 | “正在观察当前输入…”；可继续改输入，新值另成候选；不闪烁播报每个合并动作 |
| 完整 0/1 | 逐位 F/Cout、F 十六进制/无符号十进制与对应输入；写“已取得观察”，不写“正确” |
| 含 X | 例如 F=0X10；逐位文字与非正常灯态；“输出含未知值 X”，不显示十进制零 |
| 含 Z | 例如 F=ZZZZ；“输出含高阻态 Z”；与 X 及缺失区别 |
| 未取得/不完整 | 对缺项写“未取得”；保留部分原串但整体标“不完整观察”，不显示成功徽章 |
| 晚回包 | 只更新原记录；当前输入/读数/所选历史不跳动，必要时给一次“另一次观察已就绪”提示 |
| 服务暂断但仍获准 | 本地实验继续；短暂同步等待不增加常态同步标签，需要处理的资格/存储问题就近说明 |

默认跟随当前输入。学生主动选择历史后，明确“历史观察”并显示原输入，不把它接成当前板卡结果；提供“返回当前输入”入口。选择历史不改开关；“将该输入用于实验”才复制历史/反例输入，经原保护和自动观察链路执行，视图动作不隐式重放。

运行、检查或刷新均不发送或清空问题草稿。未来预测模式由同一 ALU 状态暂停候选自动反馈；进入暂停状态后显示“预测编辑中，尚未运行此输入”，候选的实际读数、相邻波形及旧报告对该候选的自动展开一并屏蔽。#193 不展示尚未交付的预测/波形按钮。

## 检查操作、进度与报告

按钮文案为“检查全部输入”，含义固定为当前已启用作品。代码有修改时按钮仍可用，旁边说明“检查上次运行的作品；要检查修改，请先运行”。没有启用依据、能力未准备、身份失效、本机保护失败或冲突未解时，禁用并说明原因。

检查接受后显示“正在检查已启用作品…”和真实轮次/已确认计数；按钮位置提供“停止检查”。不为检查建立新导航，不替换当前虚拟板观察。检查占用执行槽时，开关仍可改，板卡写“检查中，输入已保留，结束后观察”。停止后确认对应 Worker 已结束才写“已停止”；输入在 live 时继续正常观察，不自动重试原检查。

```text
全量行为检查                           [停止检查]
正在检查已启用作品 · 已确认 2/4 轮
全部目标 4096 组；完整采样 0/4096；已取得 8192/16384 条采样
前驱与采样条件 ▸

完成后示例：
发现行为错误                           [再次检查]
完整覆盖 4096/4096 · 二值比较 16384/16384 · 错误输入 256 组
保留组合 1536/1536 · X 0 · Z 0 · 前驱/时刻差异 0
检查对应上次运行的作品；当前代码有修改。

输入                                  实际 F/Cout    预期 F/Cout
A=1111 B=0000 M=1 S=00 Cin=1           0000 / 0      0000 / 1
[将该输入用于实验]     [查看该次依据]
显示 1–20 / 256 条反例                 [下一页]
```

四轮各采全部目标，2/4 轮完成并不代表全部目标完成套件；示例的完整采样 0/4096 是有意保留的真实区别。初始进度未知就写“正在采样”，不得用动画或时间估计伪造数量。完整检查同时显示 4096 唯一输入和 16384 计划目标采样，不把重复轮次宣传为覆盖更多输入。

报告首行优先给真实结论，再给总量/实际量/覆盖。按需展开各轮和规则版本，不在首屏铺 Worker、requestId、缓存或运行包哈希。反例默认按 index 排序，可筛行为错误/X/Z/不完整/前驱或时刻差异；全部反例可分页读取，空页不称“没有错误”而忽略未读资源。

| 结论/故障 | 显示及后续动作 |
| --- | --- |
| 全部满足公开检查 | “4096 组检查通过”，附完整比较和套件条件；不自动完成任务、推断掌握或提交教师 |
| 二值行为错误 | “发现行为错误”，展示真实与预期、唯一错误输入总数和反例 |
| X/Z | “检查未通过：输出含 X/Z”，区分未知/高阻与数值差异；保持公开预期可读 |
| 前驱/时间差异 | “同一输入的结果不一致”，并列两轮条件与实际输出，指向组合逻辑稳定性说明 |
| 缺行/格式/覆盖不足 | “检查不完整”，列实际覆盖和缺项，禁止通过；能查已取得反例 |
| 编译失败/仿真错误 | 对应真实原因和诊断，显示“未完成检查” |
| 超出预算/主动停止 | 分别为“检查超过运行限制，已中止”“检查已停止”；保留已确认计数，不补齐百分比 |
| 完成/停止竞争尚未核实 | “检查结果尚未确认”，保留原请求和“核对状态”，不直接给再次检查来诱导重复 |
| 资源不可读/损坏/失权 | 具体原因、原记录元信息和恢复入口；不回退到另一个旧通过报告 |

新检查发起时只在学生仍跟随“最新检查”时选择它；已经手动选了旧报告则保留选择，并单独显示在途检查和停止入口。自由观察完成不抢检查选择，检查完成不抢历史观察选择。再次检查明确建立新执行记录，重读旧报告不计算。

## 自动保存、返回与来源详情

输入草稿、已启用依据、观察选择、报告选择和问题草稿自动保护，正常使用无保存按钮和常态保存标记。刷新/返回先恢复本机事实并核实原请求，不声称 Worker 跨关页存活。已确认报告按原身份重读；未知执行不自动重跑，未接受候选只有确认未开始后才可首次提交。

存储故障明确说明“本机未能保护本次输入/结果”，保留可读内容及复制/导出，暂停无法可靠固定的新执行；不是用 toast 一闪而过。双标签冲突沿原产品冲突入口核对，不覆盖另一标签的代码/启用依据。

详情复用“原依据与结果资源”：原代码只读副本、输入/映射、公开规则/采样套件、启用来源、发起者、各轮耗时、组件/工具版本、执行身份、原始观察与诊断/VCD。报告摘要和原资源不能分属不同执行；缺一项如实标记。#194 可消费同一输入/结果资源，不复制板卡或执行链。

## 视觉、键盘与可访问性

复用 `tokens.css`：`--paper`、`--sunken`、`--line`、`--line-strong`、`--ink`、`--ink-soft`、`--muted`、`--primary`、`--accent-deep`、`--danger-deep` 和原状态角色。板卡仪器材质沿既有豁免，板外不扩散硬编码颜色/阴影；X/Z 兼有字符/形态，不能只靠灯色。辅助说明不用 `--faint`。浅深主题用同一角色，不另造 ALU 主题。

正文 15px、紧凑标签/数值 13px、辅助状态 12px；数值 mono、控件系统字体、标题按既有文楷规范。运行/检查/停止复用 `ws-btn` 的 32px 高、13px 字和 8px 圆角；组内间距 8px，组间 12/16px，分区 24px。复用现有焦点 token 和 150/240ms 状态过渡，减少动效模式禁用位移，不做 LED 闪烁庆祝。

- 每个开关有端口、位序、当前值及 `aria-pressed`；Tab 可达，Space/Enter 切换，焦点不随结果回包移走。按视觉信号组排序，未使用控件不占无效焦点序列。
- 数值输入有关联 label、位宽/范围、错误说明及 `aria-invalid`，组合输入期间不运行、不发问题；提交合法值后再同步开关。
- 当前等待与终态使用 polite status，按有意义阶段合并播报；不逐行播 16384 次。真实故障就近 alert，查询回包不抢焦点。
- 反例表有标题和列头，窄栏逐条显示完整标签；“将该输入用于实验”后聚焦输入组并说明已复制，实际新观察仍等待真实结果。
- 停止检查和停止单次观察明确针对哪次操作，按钮重复按下沿原控制身份幂等；无全局模糊停止按钮。

## 实施后的设计验收清单

以下由实施 Agent 实际验证并交付证据，不把线框当截图，也不把人工检查责任全部转给负责人：

1. 变更前后在同一课程、数据、主题和视口拍正式运行界面；覆盖作品/实验分屏、未启用、已改代码仍试旧版、等待时无旧读数、新编译失败、检查反例、停止和刷新恢复。
2. Windows 11 x64 与 Apple Silicon Mac 桌面 Chrome，各从正式本机产品和独立学校 HTTPS 页面操作；录入真实输入到结果、检查、停止、恢复耗时及资源，不用开发代理替代。
3. 键盘完成运行、拨码、数值编辑、检查、选择反例和停止；验证焦点不被后台结果夺走、未使用按钮不干扰导航。
4. 两平台真实系统中文输入法在作品/问题草稿/数值错误草稿上的组合、提交与取消不触发运行或清空；浅深主题、1440/1024/900px、工具分屏窄栏及 200% 缩放均可操作。
5. 检查中连续拨码、快速 A→B→A、手选历史后晚回包、双标签改启用、刷新未知和资源损坏有明确可恢复状态；运行和检查不动问题草稿。

本次仅完成设计，工程执行、仿真、Chrome/平台/部署与教学效果均未验收。审阅重点是运行启用语义、检查占槽时仍可编辑输入、两类结果选择互不抢占，以及完整覆盖和实际采样的呈现是否足够清楚。
