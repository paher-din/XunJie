# 第三轮 UI 方案与数据条件评估

2026-11-16。依据本轮三张验收截图、旧版课程任务设计、DESIGN.md 和当前契约。先提出以下方案，再实施其中已有数据和接口支持的部分。用户已明确：本轮只做关闭／重新开始；删除在全流程方案中单独设计。

| 项目 | 原因／数据条件 | 实施方向 |
| --- | --- | --- |
| 三段说明格式不一 | 目标的 li 被 13px 规则覆盖，要求由引用组件渲染，空材料提示使用 detail 小字；只统一标题无法统一正文 | 三者共享 course-section-body：系统字体 15px、400、1.6 行高、ink-soft；保留多项目标的语义列表和材料操作链接，辅助页数等仍用小字 |
| 活动菜单 | 现有 activity-status 支持 open／closed，关闭会调用 executions.closeActivity；当前列表缺操作入口 | 卡片右上三点菜单，提供打开及关闭／重新开始。关闭前明确停止运行、作品与记录保留；失败保留原卡片并可重试；不导航至工作区 |
| 课程对应 | 现有 activity.course 有 courseId、taskId、固定版本名称，但当前首页把所有活动平铺 | 按 courseId 分组，组标题为课程名及活动数，提供查看课程；无课程绑定的学校活动单列“未关联课程的活动”，不误称个人自主学习。课程磁贴同时显示任务数和真实活动数 |
| 任务进度 | 当前 activity 与 courseActivityBinding 无进度／完成比例；状态关闭不代表完成，组件运行成功也不代表任务通过 | 本轮不显示百分比或空进度条。后续需先明确课程评价单元、分母、完成证据、版本及人工覆盖规则，再由数据所有者提供结果，复用 HomeTaskCard／ProgressBar 展示 |
| 截止日期 | 当前 CourseRelease、CourseActivityBinding 和 LearningActivity 没有截止字段；发布时间不等于截止时间 | 本轮不推算截止时间或显示逾期。后续需学校提供任务／学生分配的 dueAt、时区、延期及取消期限信息，固定或明确追踪其更新口径，再接旧版日期布局 |
| 删除 | 当前无活动删除接口，作品、引用、会话、执行、学校提交均有依赖 | 按用户决定，本轮不显示删除入口；详见全流程方案的删除专项设计 |

## 组件与交互

在 @xunjie/ui 的 LearningTaskCard 增加可选菜单插槽，菜单与卡片的打开按钮为兄弟控件，避免按钮嵌套；新增 ActivityCardMenu 使用已有 Base UI Menu，与库内其他菜单技术一致。关闭确认复用 ConfirmationDialog，通知复用 feedback。未提供菜单的旧 UI 保持原 DOM 和交互。

首页与课程内活动列表共用 ProductActivityList；状态操作显式传入活动所属 spaceKey，不能沿用页面当前来源猜测。服务确认成功后更新相应来源的缓存、状态标签与筛选结果；列表中的操作不设置打开活动，也不修改路由。错误留在确认区域或通知中，不能把请求未成功显示为已关闭。

关闭／重新开始是现有活动生命周期，不新增暂停、完成、掌握或删除状态。“停止活动”统一表述为“关闭活动”，以免与仅停止一次实验混淆。

## 验收

实际运行前后截图使用同一活动和窗口；覆盖深浅主题、1440px／1024px、菜单、关闭确认及取消。新增交互测试覆盖按钮独立性、课程 ID 分组、关闭取消／失败／成功、重新开始及所属来源。真实用户活动仅查看，不为验收关闭其活动；状态写入通过隔离测试模拟服务确认。
