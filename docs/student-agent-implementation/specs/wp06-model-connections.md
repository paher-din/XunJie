# WP06：三协议模型连接

日期：2026-11-02（Asia/Shanghai）。对应 [WP06：三协议模型连接](https://github.com/paher-din/XunJie/issues/163)，测试边界及五张实施子票的拆分已由负责人确认。前置工作包为 [WP02：学习空间与可靠工作区](https://github.com/paher-din/XunJie/issues/148)。本规范承接三协议接入、原生续接、个人模型选择及模块归属的已定决议；规范与子票发布不代表产品能力已实现或通过验收。

## Problem Statement

学生需要在个人或学校学习空间使用可用的模型服务，也需要在学校空间内选择自己的模型。模型服务可能通过 Chat Completions、Responses 或 Anthropic Messages 提供能力；同一服务、同一模型在不同协议下支持的图像、工具、结构化输出及续接方式并不相同。

现有实现以 Chat Completions 的文本与图片消息为中心，模型设置仍使用旧身份和旧服务入口。它不能完整保存三协议的 reasoning、签名、工具配对和原生内容，当前“连接测试”也只查询模型目录。仅增加协议选项、拿到 HTTP 200 或得到可读回答，不能证明下一轮能够正确续接。

网络中断、取消、进程重启和模型设置变化进一步影响可靠性：学生不应因此被悄悄切换模型或费用来源；已经完成的回答不应因回包丢失重新请求；不完整工具参数不应触发实际操作；缺失用量也不能被记成免费调用。后续 Agent 需要一份可查询、可恢复的模型调用事实，而不是从可见聊天文本猜测发生了什么。

## Solution

在现有正式产品外壳中接入模型设置与选择，复用已有表单、模型卡和设计 token。学校提供默认连接，学生可显式为当前学习空间选用自己的连接；配置、授权和费用来源清楚，切换模型不改变活动、作品、课程权限及交付归属。

后端模型连接 module 以 `ModelGateway` 提供统一的配置、能力判定和单次调用/查询/取消边界，使用直接协议 SDK 加三个薄 adapter 连接实际第三方端点。模型连接层保存原生请求、完整结果、续接段、错误与用量事实；运行层消费持久结果引用并决定下一步。正式设置中的连接检查可以独立使用，本包不等待 WP07 才验收，也不以测试连接代替学习对话。

## User Stories

1. 作为学生，我希望学校提供可直接使用的默认模型，以便进入课程后不必先研究模型配置。
2. 作为学生，我希望没有配置模型时仍能进入活动并编辑作品，以便模型故障不会阻止普通学习操作。
3. 作为学生，我希望在学校空间内自行选择个人模型，以便按实际效果和已有服务学习，而无需学校管理员另行开放。
4. 作为学生，我希望一次配置个人连接后显式为所需空间选用，以便复用连接时不合并两个空间的数据。
5. 作为学生，我希望清楚知道当前选用学校服务还是个人服务，以便理解这次调用使用的连接和额度来源。
6. 作为学生，我希望通过服务地址、协议、模型和凭据配置第三方服务，以便不被限制在某个官方模型平台。
7. 作为学生，我希望可以使用受支持的本机模型服务，以便我的模型连接可由本机组件持有。
8. 作为学生，我希望模型目录不可用时仍可填写已知模型标识，以便不因服务缺少目录接口就被阻止配置。
9. 作为学生，我希望连接检查反映所选模型和协议的真实调用结果，以便不会把列出模型误认为模型可用。
10. 作为学生，我希望明确知道连接检查覆盖了什么，以便不把一次文本回复理解为全部图像、工具和结构化能力已经验证。
11. 作为学生，我希望配置失败或发生版本冲突时保留当前输入并说明原因，以便修正设置而不丢失内容。
12. 作为学生，我希望重新打开设置只看到凭据的脱敏状态，以便密钥不被页面读取、复制到事件或混入诊断。
13. 作为学生，我希望替换或清除密钥是明确操作，以便空白输入不会误删已保存的凭据。
14. 作为学生，我希望能停用个人连接或撤销某个空间的使用授权，以便阻止后续调用，同时保留此前结果。
15. 作为学生，我希望更改设置只影响之后接受的请求，以便正在进行的请求不会突然换模型或使用另一方额度。
16. 作为学生，我希望个人连接失败或学校额度不足时得到真实原因，以便由我决定是否切换服务。
17. 作为学生，我希望模型不能满足当前请求所需能力时明确说明缺项，以便不会收到静默丢弃图片或约束后的回答。
18. 作为学生，我希望图片及工具返回的图片能真正传给模型，以便它可以读取图表、截图和后续文档工具提供的页图。
19. 作为学生，我希望模型读取的是这次请求固定的图片版本，以便后续替换文件不改变原问题的依据。
20. 作为学生，我希望流式回答中断后保留已收到的部分内容并说明状态，以便不会把半截回答误认为完整结果。
21. 作为学生，我希望停止请求时知道本机已停止接收与上游是否停止之间的区别，以便不会被错误告知费用或工具效果已经撤销。
22. 作为学生，我希望最终用量缺失时如实显示未知，以便不会把中断请求统计为零消耗。
23. 作为学生，我希望换模型后仍可使用获准的既有问题、引用和已完成结果，以便继续学习时不混入不兼容的隐藏续接数据。
24. 作为学生，我希望个人模型遵守和学校模型相同的课程材料访问范围，以便模型来源不会改变教师发布的帮助边界。
25. 作为学校管理者，我希望配置、更新和停用学校默认模型连接，以便为学校成员提供实际可用的服务。
26. 作为学校管理者，我希望学校密钥不分发给学生浏览器，以便学生通过获准连接使用学校服务。
27. 作为部署维护者，我希望模型连接可与调用方同机或分开部署，以便按本机、学校和混合组合安排服务。
28. 作为部署维护者，我希望远端调用本机连接时通过已认证通道访问，以便学校服务器不会误把自己的 localhost 当成学生设备。
29. 作为部署维护者，我希望模型配置、授权和原生结果纳入产品维护与恢复，以便重启或还原后仍能核对历史调用。
30. 作为部署维护者，我希望恢复后的旧进程和旧连接不能继续产生有效调用，以便不会出现两个实例同时使用原授权。
31. 作为 Agent 接入开发者，我希望三协议共用一步调用和结果查询接口，以便运行调度不依赖协议内部消息形状。
32. 作为 Agent 接入开发者，我希望同一调用身份的重复接收返回原记录，以便丢失回执时不重复请求模型。
33. 作为 Agent 接入开发者，我希望完整模型结果先持久保存再发布完成回执，以便重启后可以继续关联结果而无需重新生成。
34. 作为 Agent 接入开发者，我希望只从成功完成且可读取的结果取得完整工具意图，以便半截参数、失败流或缺失资源不会触发工具。
35. 作为 Agent 接入开发者，我希望 reasoning、签名、内容块顺序和调用身份原样保留，以便同路线的下一轮能够正确回放。
36. 作为 Agent 接入开发者，我希望能力证据绑定端点、模型、协议及参数模式，以便不把服务品牌或模型别名当作能力保证。
37. 作为 Agent 接入开发者，我希望 JSON mode、应用校验和原生 strict schema 分别表达，以便按任务真正要求的保证选择路线。
38. 作为 Agent 接入开发者，我希望重试、预算和工具执行由运行层统一决定，以便 SDK 不在不可见处增加调用或重复效果。
39. 作为 Agent 接入开发者，我希望未知结果、取消竞争和迟到结果有稳定语义，以便恢复时既不丢真实结果，也不错误推进已结束的 Run。
40. 作为后续能力开发者，我希望协议接入只扩展模型连接 module，以便接入 PDF、Skills、MCP 或课程工具时不再复制模型 transport。

## Implementation Decisions

以下把已确认的产品要求与研究结论转为本包工程契约；具体方法签名、表名和内部类结构由实施决定。研究时的端点成功不表示本包已验收。

### 1. 模块与事实所有权

- 模型连接 module 默认位于可组合的后端宿主内，提供 `ModelGateway`；同进程 adapter 与远端 adapter 消费同一套有版本的公开契约。只在有实际跨端消费者或独立构建需要时提取 package。
- WP06 拥有端点配置、模型路线、能力证据、凭据引用、连接使用授权、模型调用尝试和原生结果/续接记录。选用偏好以空间和实际主体为范围，通过所属接口读取与变更；不在 UI 或旧聊天服务再保存第二份可生效配置。
- WP02 提供真实空间、主体与获准活动/资源身份；WP01 提供 PostgreSQL、资源、服务连接和维护机制。模型连接 module 拥有自己的 schema、迁移与资源引用，不直接改其他 owner 的表，也不暴露通用 SQL transaction。
- WP07 的 `RunDriver` 拥有 Run、Step、重试决策、Run 预算预留/结算、等待和工具命令。WP06 只执行一次明确编号的模型尝试，返回模型内容和工具意图；连接检查另有有限的用途授权与调用限额，不依赖 Run。模型连接层不执行工具、不推进课程、不决定帮助策略、不构造另一套 Agent loop。
- 公开 wire 契约由模型连接 owner 定义，表达身份、版本、确认时点、顺序、失败和恢复；原生 SDK 类型及凭据不成为浏览器 DTO。调用方以稳定引用取得获准结果，不依赖数据库对象或 implementation 的推导类型。

### 2. 连接、路线与能力证据

| 对象 | 必须表达的事实 |
| --- | --- |
| `EndpointProfile` | 稳定连接身份、持有服务/环境、所有者、实际地址及路径规则、认证引用、协议、adapter/方言、必要 headers、启停与配置版本。公开投影不含密钥。 |
| `ModelRoute` | 选定连接、实际 `modelId`、协议、参数模式及配置版本。学校/个人来源由选用记录说明，本次预算来源固定在调用尝试中；路线本身不成为预算账本。模型显示名不能替代实际调用标识。 |
| `CapabilityProfile` | 路线与参数组合的能力、限制及证据：来源、验证日期、实际模型版本（如可得）、SDK/adapter 版本、样本范围；区分已验证、声明但未验证、未知及不支持。 |
| 原生续接段 | 路线、原生格式版本、固定前缀/工具集合身份、顺序及上次完整结果引用；与可移植上下文和可见对话分开。 |
| `ModelAttempt` | 调用身份、空间/主体、调用方及可选 Run/Step/活动关联、固定输入和路线版本、接收/派发事实、结果引用、终止原因、错误与用量。 |

协议是独立字段，不能由服务商名称、域名或模型名称暗推。配置清楚区分 SDK 的 base URL 与最终 API 路径，尤其是 Messages 的 `/v1/messages`；不得自动重复拼接 `/v1`。首次实现按已测方言建显式配置，其他兼容端点可以配置，但不能继承目标路线的已验证标签。

能力至少覆盖流式文本、工具声明/选择/参数/结果往返、图像输入、工具结果图像的装配方式、reasoning 与原生回放、JSON mode、原生 schema 约束、上下文及输出限制、服务端存储/查询/取消。格式约束和工具参数的 strict 支持分别记录。缺字段是未知，不由模型名、HTTP 200 或一次符合 schema 的输出补成支持。

调用方声明本次所需能力。缺少必需能力时返回结构化缺项；已有且明确获准的应用校验或图像装配策略须记录实际采用方式。没有预先确定的替代策略时拒绝调用，不静默换模型、协议、费用来源或忽略输入。自动选优和跨路线失败转移不属于首版。

### 3. 学校服务、个人选择与授权

学校维护者可通过受支持的管理入口配置默认连接、授权范围和停用状态，无需直接编辑数据库；不在本包另建完整学校管理台。学生通常使用学校默认连接，也始终可自行选择个人外部端点或本机连接，**不设置学校管理员是否允许个人模型的开关**。

个人连接由持有凭据的组件保管。为某个空间显式选用时，建立连接所有者对该空间内本人主体的使用授权；不能仅凭学校成员身份或一个连接 ID 调用。空间保存引用与选择，不复制个人课程、会话或画像。每次接收及实际派发仍核对有效身份、用途和授权，能力充足不等于有权读取更多材料。

请求接受时固定连接、配置版本和预算来源，之后的普通设置修改只影响新请求。撤销授权、停用连接或清除凭据禁止新的外发调用，包括尚未外发的已接收尝试；已外发的尝试按原身份查询、停止或记录中断，不借用新配置接着调用。原配置已不可用时明确返回原因，不从最新设置补齐。学校额度和个人额度不得互相代扣。

凭据只在持有组件中解密用于授权请求；配置读取、可见事件、错误、回执与公开证据仅含脱敏投影。复用经审查适用的凭据加密和版本机制，覆盖替换、显式清除、停用与恢复；空白密钥保留已有值，清除须有独立意图。仅持有旧结果引用不授予新模型调用资格。

### 4. `ModelGateway` 的接收、查询与取消契约

| 操作 | 确认时点与不变量 |
| --- | --- |
| 配置读取/变更与选用 | 根据真实空间/主体授权；变更带期望版本，过期写入不覆盖新配置。返回可重新读取的已提交版本，不回显凭据。 |
| 能力判定 | 针对固定路线和本次需求返回证据、可用方式或缺项；不通过一次检查改变请求路线。 |
| 接收一步调用 | 调用方提供稳定调用身份与固定输入。可靠登记后返回接收回执；相同身份、相同内容返回原尝试，不重复外发；相同身份、不同内容返回冲突。接收成功不等于已请求上游或已完成。 |
| 观察与结果查询 | 增量内容仅作进度投影；断开后可按原身份查询。结果返回明确状态、终止原因、用量状态及可读取的持久原生结果引用，查询本身不触发模型生成。 |
| 读取与关联结果 | 校验空间/主体、所属调用和资源完整性；调用方可重复关联同一不可变结果。结果不能因短期 URL 过期失去读取途径。 |
| 请求取消 | 接收取消意图与实际停止分别表达；未外发可确认未开始，已外发执行客户端 abort 并记录可确认的事实。已经完成的结果仍可查询，取消不改写历史结果。 |

状态至少区分尚未外发、已外发/接收中、完整完成、不完整结束、明确失败、客户端取消以及上游结果未知；具体枚举可按实现编码。缺终态的 EOF、超时或进程消失不能被当作完整完成，也不能伪装成上游肯定没收到。完成状态与最终用量是否已知分别记录。

重复接收、并发派发及恢复接管由 owner 的持久条件更新和有效代际裁决。外发前记录派发事实；崩溃窗口无法确认是否外发时保守保留未知，不由新的处理者再次生成。这里保证的是本地尝试不被盲目重放，不承诺第三方 API 的端到端 exactly-once。新的模型重试使用新的尝试身份，关联旧尝试并由 WP07 批准其预算。

### 5. 三协议直接 SDK 与薄 adapter

首批互操作基线为 `openai@7.42.0`（Chat Completions / Responses）和 `@anthropic-ai/sdk@1.1.0`（Messages）。实施固定实际使用版本；如升级，重新验证本规范涉及的方言和原生回放，不把研究版本永久冻结。连接目标仍是已配置的第三方服务，不因此改用 OpenAI 或 Claude 官方模型。

SDK 负责 HTTP、认证请求、SSE、取消与原生错误对象。所有模型请求的 SDK 自动重试设为 0；不使用自动执行工具或自动推进多轮的 helper。adapter 仅负责协议/方言参数、必要流聚合、图像装配、原生记录与应用事件/错误/用量的有限映射。教学 prompt、课程规则、工具执行、历史压缩和重试循环留在上层。

系统指令、用户材料和工具结果的语义由调用方明确提供，adapter 按路线支持的角色/instructions 规则编码；不能把所有内容压成同一种 user message，也不能仅改字段名就假定 system/developer 具有相同语义。不支持的必需参数明确拒绝，已有兼容映射记录实际生效方式；不静默丢弃约束或伪装模型名称来开启 SDK 分支。

| 协议 | 首版必须保留与正确处理 |
| --- | --- |
| Chat Completions | 低层流聚合可见内容、实际 `reasoning_content` 等已支持方言及完整 `tool_calls`；按 choice/tool index 组装分片，保留原调用 ID 和参数。完成判断结合真实 finish reason 与流结果；长度截断、内容过滤、半截 JSON 或仅收到结束标记不构成可执行工具结果。 |
| Responses | 保留完整原生 output items、顺序、reasoning 的实际 content/summary 与调用身份，不能只存 `output_text`。区分 item ID 和 `call_id`；允许已测方言的 function-call added 事件暂缺 arguments，等后续完整结果再校验。completed、incomplete、failed 分别处理，arguments done 不等于整个响应成功。 |
| Anthropic Messages | 保留完整 assistant content 数组，包括实际 thinking/signature、文本及 tool-use 块，按 `tool_use_id` 配对结果。使用已验证的 SDK 聚合路径并核对完整消息终态；不能丢签名、重排块、从可见思考文本重新构造原生内容。 |

保留完整原生响应不等于承诺理解所有未知扩展。新字段尽量原样留存；无法确定关键块的组装或续接语义时明确标识不支持/不可续接，不静默删除后继续调用。空 reasoning 合法；不要求每次回复都有非空推理。普通聊天事件与日志不直接输出原生 reasoning、签名或原始错误正文。

工具名称、调用身份、完整参数及 schema 校验均通过，且所属响应成功完成并持久可读后，才能向运行层交付可消费的工具意图。拒绝、截断和失败保留实际原因及可见部分内容，不能顺手执行其中碰巧可解析的工具。工具错误、未执行和取消等结果由调用方明确提供，adapter 仅按协议正确配对。

### 6. 原生结果的持久保存与恢复

原生请求保存可重建的业务 payload、顺序及固定配置引用，排除认证密钥和 secret headers；完整原生响应、必要流聚合证据和资源身份由模型连接 owner 保存。原生记录、可见对话和 Run 运行事实分别存在，不能由聊天文本反推原生历史。

收到完整响应后，先可靠发布原生资源并提交完整结果记录，才对外给出完成回执与结果引用。资源未写完、校验失败或结果事务失败时不得声称完成；调用方不能仅凭流里出现终态文本就执行工具。响应已经保存但回执丢失时，重启后查询原身份得到相同结果；RunStore 的结果关联与工具待发事务归 WP07，不做跨 owner 分布式事务。

如果上游已经产生结果但本地未能可靠保存，按已知事实记录本地持久化失败或未知；不能为修复本地记录静默再请求模型。目标端点没有可用的远端查询能力时，如实返回无法核实，不用 response ID 编造恢复能力。晚到结果只补充原尝试事实，不自动恢复已取消或终态 Run。

配置、使用授权、尝试、原生记录和资源随本包接入 WP01 的迁移、停止接收、排空/中断、备份、独立还原及接管。还原后可读取历史结果；未完成尝试不得自动再次外发，旧服务代际和旧授权不能继续写入。密钥按凭据机制单独处理；恢复缺少可用凭据时明确要求重新配置，不影响获准历史结果的读取。

结果引用带内容身份和保留责任。Run、活动或交付仍持有的引用不得被清理；关联、释放及资源回收通过 owner 的窄接口处理。首版保留必要原生记录及来源，不以日志轮转作为业务删除策略，也不顺带建设通用审计/日志平台。

### 7. 同路线续接与跨路线边界

同一路线、同一原生续接段按顺序重发完整原生历史，保留工具调用及对应结果。DeepSeek Responses 按无服务端存储模式处理，不依赖 `previous_response_id`、远端 conversation 或 background 恢复；其他路线只有取得相应证据后才能使用服务端续接能力。

新工作区观察由上层提供版本和来源并追加，不改写旧工具结果。system/工具集合改变、上下文压缩或切换路线时，首版在工具已结清的步骤边界创建新的原生续接段。模型连接层验证路线/段匹配并拒绝混用；WP07 负责边界时机，WP08 负责可移植上下文与压缩内容的构造。

新段使用获准的学生问题、引用、可见回应和已完成结果，保留原出处；不直接移植旧路线的签名、response ID、tool ID 或隐藏续接块。服务文件 ID 只有在明确可共享且权限有效时复用，否则从所属资源重新物化。尚有工具未配对时拒绝跨段续接，不假装工具已完成，也不在本层偷偷执行或取消工具来凑齐历史。

本包交付续接段的建立、保存、读取、兼容性检查与原生输入装配，并以固定可移植输入验证切换边界；不提前实现 WP07 的运行中换路线交互或 WP08 的摘要算法。

### 8. 图像与工具结果中的图像

图像输入是首版必需能力。公开请求用可授权、可固定版本的资源引用及 MIME/内容信息表达；连接层在实际执行位置取得该版本的图片，按目标协议生成有效图像内容，不能把 base64 串当普通文本传递。图片数量、格式、大小及路线限制在外发前检查，变换后的图像保留与原资源/版本的关联。

首批图像工具链沿用已有实测方式：Responses 在 `function_call_output` 中提供图像，Messages 在 `tool_result` 中提供图像；Chat 保留配对的文本工具结果，再用紧邻的用户图像消息承载图片并保留来源关联。后者明确记录为 Chat 的装配策略，不标成原生工具结果图像支持。若采用其他方式，应有该路线的新证据。

本包验证真实 SDK 的图片输入、工具产图、保存后重放和重启后再读取。图片归属继续由资源 owner 授权；不能为模型抓取直接放开整个工作区或教师私有材料。PDF 阅读由 WP08 的按页工具提供文字、页图和文档版本/页序引用，本包承接其图像和结果输入，不实现解析、OCR、全文检索或 PDF 编辑。

### 9. 错误、用量与执行限额

错误契约区分配置/权限/能力拒绝、输入或上下文超限、认证失败、限流/配额、连接和超时、上游 HTTP/流内错误、协议或数据校验失败、本地持久化失败、取消和结果未知。保留是否已外发、可确认的上游状态/请求标识及必要 retry-after；重试提示只是事实，不授权自动重试。用户看到可操作的原因，原始响应及 secret headers 不直接成为错误文案。

用量分别保存实际取得的输入、输出、缓存、reasoning 等字段及原生统计；缺失字段不补零，不把累计事件相加成重复用量。完整用量、部分用量和未知用量明确区分，估算不得冒充上游实际用量；token、费用与服务端是否停止计算也不能互相代替。WP07 据此预留/结算预算，未知用量继续保留相应预留。

每次调用有有限输出、输入/图片资源、连接/响应等待及本地资源上限，配置来源和实际生效值可核对。连接层可限制本服务物理请求并发，不能再实现跨 Run 的调度与预算权威。客户端已取消但物理请求尚未结束时，不谎报服务端停止或过早释放仍被占用的本地执行资源。超长历史明确返回超限，由上层决定新的上下文段，不偷偷截断原生历史。

### 10. 正式 UI 接入与实际使用路径

沿用统一的产品外壳、导航和设置呈现，遵守现行设计系统。正式外壳当前尚未提供模型设置；本包将可复用的旧模型设置展示与旧 Session/store/API 解耦，接入新学习空间身份和模型连接公开接口。只改旧页面、开发预览或诊断页不算交付。

| 现有入口/组件 | 本包新增或改造 | 消费接口与替换范围 |
| --- | --- | --- |
| 正式产品外壳与导航 | 接入模型设置及当前空间的模型选择，沿用共享外壳、主题、导航和焦点行为 | WP02 身份/空间 + WP06 配置/选择投影；不进入旧 Session 登录或另开简化学习页。 |

连接检查绑定实际 endpoint × model × protocol × 配置版本，其结果不得因切换空间或编辑配置而迟到覆盖新状态。每次显式检查只做有限请求，配置变更、页面刷新或返回不自动触发付费检查。成功表示本次检查通过；完整能力矩阵来自相应验收，不能由检查按钮批量点亮。

保留既有保存前检查交互：检查已保存连接时固定已提交版本；检查尚未保存的表单时建立独立、不可变的检查快照及检查身份，包含本次地址、协议、模型、参数和安全的凭据引用，不更新正式配置或空间选择。已存凭据只能由有权主体在原连接、原配置版本和原认证目标下引用；变更目标地址时不能自动把旧密钥带过去，须显式提供适用于新目标的凭据。临时凭据仅由持有组件用于该检查，不进入业务快照/事件/日志；结束后释放临时材料，崩溃后也不自动重试。编辑表单、清除凭据和切换空间后，原检查结果只属于原快照。

连接检查以独立用途记录授权、固定限额和 usage：一次显式检查最多发起一次生成、SDK 重试为零，具有有限输出、响应时限、频次及并发限制。个人检查由本人操作使用其连接；学校检查按维护者为该用途配置的许可与限额执行，不借个人额度。WP06 负责这些检查的接收与限额执行，沿用适用的既有资源约束；不调用尚未交付的 RunDriver。WP07 后续负责学习 Run 的预算，不重复接管检查事实。达到上限、部分用量或未知用量分别记录，不能将停止检查视为退还已消耗额度。

模型设置沿用明确保存及版本确认语义，失败保留输入；WP02 的作品/问题自动保存继续由可靠工作区负责，二者不是同一个状态机。密钥留空保留、显式清除、保存失败、冲突和连接不可用需真实呈现。沿用现有状态位置、字体、间距、控件和浅深色 token，不增加无必要说明或常驻工程标识。旧管理员禁用个人模型的前提由已确认的个人选择决议取代；连接自身停用或当前不可用仍按事实展示。

本机产品包与学校网页默认入口使用同一套新增设置实现。涉及明显布局/入口变化时，实施前后保留同类实际运行截图，交付正文说明变化、原因和影响；不是在本次规范编写时生成 UI 效果图。

### 11. 部署接线与旧路径清理

模型连接可以与调用方同机，也可由学校或学生本机组件单独持有；所有形式保留相同接收、查询、取消和结果读取语义。复用 WP01 的认证、连接身份和代际机制，WP02 的真实主体绑定继续生效。远端服务调用学生本机连接走已认证任务通道；不能从学校服务器请求它自己的 localhost，离线也不能静默改用学校模型。

明确区分由持有组件访问的本机模型地址与普通远端端点。既有“只允许公网 HTTPS”的旧 transport 假设不能原样阻断已批准的本机模型场景，也不能因支持本机连接全局放开其他调用方的任意网络目标；地址范围与调用资格由实际持有组件和既有连接边界约束。

本包至少完成真实宿主的同机调用和模型连接独立部署的跨进程接线，并验证实际跨机连接的权限、断开和查询路径；完整 Run 的个人全本地/学校/混合部署、等待和恢复验收归 WP07。连接检查是本包的正式产品消费者，自动验收还可使用同一公开契约的受控调用方，不预建临时 Agent 内核。

新模型连接边界不接收旧 transport 所混入的教学 prompt 构造、结构化任务规则和 Agent 推进职责；复用这些代码时将业务规则留在所属调用方。三协议新路径不以文本历史加“请继续”替代原生续接，不在新旧 store 双写同一配置或尝试。

旧消费方在本包的处置明确如下。它们不消费新产品的路线/原生记录，也不作为 WP06 的正式验收入口：

| 旧消费方 | WP06 处置与配置/身份来源 | 后续替换归属 |
| --- | --- | --- |
| 独立个人聊天及其模型菜单 | 暂保留旧个人聊天服务、旧 Session 和旧配置/凭据；原共享并发及取消约束继续有效。正式设置与它不双写、不互相回退。 | WP07 接统一学习对话与 RunDriver 时迁接并清理；能力装配随 WP08 深化。 |
| 旧课程辅导 | 暂保留旧授权、已固定模型配置和调用流程；正式活动问题面板不接回这条路径。 | WP07 接入正式活动的真实接收方时替换；课程能力沿所属 WP 接入。 |
| 旧教师设计及教师模型设置 | 暂保留教师本人旧配置、旧 Session 和独立教师预算；抽取共享表单不改变它们的授权、额度或默认启停。 | WP10 的教师设计/制作接线替换，正式审阅交付由 WP12 负责。 |

这段过渡只保留既有 legacy 入口，不新建第二套正式产品。旧共享 `CompatibleTransport` 因上述消费者仍在，不能在 WP06 整体删除；新正式入口禁止继续依赖它。清理本包替换的展示层旧耦合及无消费者实现，保留仍有用途的旧依赖并记录移除归属。旧配置、旧聊天、SQLite 数据与旧运行记录不自动迁移，原件保留、按需显式提取。

## Testing Decisions

### 测试边界

**主测试边界是生产宿主公开的 `ModelGateway` 配置/接收/查询/取消/结果读取接口。** 经真实身份与配置解析、真实 PostgreSQL/资源持久化、实际三个 SDK/adapter 到受控上游 HTTP/SSE，检查调用方能观察的行为。协议故障只在上游网络边界注入，不 mock 掉 Gateway、SDK 或 repository 后宣称三协议集成通过。同进程与远端 adapter 运行相同契约案例，关键恢复案例跨真实进程执行。

持久化和维护故障在相应存储/进程边界触发：可使用受控资源写入失败、数据库事务失败、真实进程终止、响应丢弃和同步屏障，底层仍运行真实 PostgreSQL 与所属资源实现。必要的窄故障控制点随本包实现，用于命中发布前后、提交前后及接管竞争窗口，不把生产 owner 整体换成内存替身。WP06 负责新增模型事实的维护参与和测试，WP01 已有维护机制继续由原 owner 持有。

浏览器以正式产品设置入口补验身份、配置和选择接线；目标第三方端点补验固定版本 SDK 的真实互操作。这是同一公共边界的三种证据，不为每个内部类各建测试层。只有难以从该边界准确触发的分片/方言反例增加少量 adapter fixture，不重复断言内部函数调用次数或数据库布局。

模型可以返回多个合法答案，验收优先核对终态、身份、结构、图片/工具结果的正确使用及原生数据往返；不把某句措辞当正确性。涉及不重复外发时，应检查受控上游实际收到的请求数；涉及隔离与竞争时，使用真实授权和 PostgreSQL 条件写入，不能用内存替身证明。

### 必须覆盖的行为矩阵

| 场景 | 通过标准 |
| --- | --- |
| 学校/个人选择与隔离 | 真实学校身份可用默认服务并自行选个人连接；两个学生、两个空间、两个环境不能串读凭据或结果。知道连接 ID、伪造活动/资源身份不获得调用资格，个人模型不获得私有课程材料。 |
| 配置与授权生命周期 | 保存冲突、空 key 保留、显式清除、配置版本变化、撤销/停用、空间切换及迟到检查结果行为正确；保存前检查使用独立快照，不保存表单或向新地址带旧密钥。在途尝试不换路线/额度，撤销后未外发尝试不能继续外发。 |
| 三协议基本调用 | 每个 adapter 经真实 SDK 完成文本流、明确终态、正确工具名/参数/调用身份，以及一次无副作用工具结果往返；目录不可用不冒充生成失败。 |
| 原生保真 | 保存、序列化、读取、重启、下一次实际 wire payload 中的 reasoning、签名、items/blocks 和顺序一致；分别覆盖非空 reasoning、合法空值、多工具及完整配对，回答 nonce 正确不能代替保真断言。 |
| 流分片与方言 | UTF-8/JSON/SSE 跨 chunk、多个工具交错、Responses added 暂缺 arguments、reasoning content/summary 差异得到正确处理；system/instructions、用户材料和工具结果按路线语义编码。错误配对、畸形关键数据与未知关键块明确失败/不可续接。 |
| 能力与结构化输出 | 目录声明、手工配置和真实证据分开；必需能力缺项在外发前拒绝。JSON mode、应用校验、native strict 各自有证据；有效/无效 schema 负对照及实际输出校验均覆盖，不能凭 HTTP 200 晋升能力。 |
| 图像输入与回放 | 五条首批路线通过实际 SDK 读取合成图片，并消费无副作用工具返回的文字 nonce + 图片；保存/重启后再次回放仍取同一资源版本。Chat 的装配方式与原生工具图像能力不混淆。 |
| 错误与中断 | HTTP 认证/限流/服务端错误、200 后流内错误、超时、截断、缺终态、参数只到一半、内容拒绝分别可查询；部分文本可见，但无可消费工具意图。 |
| 重复接收与竞争 | 同身份同输入并发接收只产生一个尝试和至多一次本地外发；不同输入冲突。丢失接收回执、丢失完成回执、重复查询不增加上游调用。SDK 重试保持关闭。 |
| 结果持久化与崩溃窗口 | 完整结果已落盘但调用方未确认时，重启查询同一引用；资源发布/结果提交失败不返回完成。已派发但无终态、旧处理者迟到写入、还原旧实例均不能自动重放。 |
| 取消与迟到结果 | 未开始取消不外发；已外发取消、取消与完成竞争、连接断开后取消状态可核实。物理请求未结束和上游停止未知不被谎报，迟到结果保留但不触发新工具或新调用。 |
| 用量与限额 | 最终 usage 缺失/只有部分值、累计更新和已知零值分别正确；不重复相加、不以缺失补零。输出/上下文/图片限制与等待期限生效；连接检查独立限额和一次生成上限成立，学校/个人来源不自动切换。 |
| 续接段与跨路线 | 同段原生回放成立；system/工具集合变化、压缩输入或换路线须用新段。未配对工具拒绝换段；旧签名、response/tool/file ID 不跨不兼容路线搬运，新路线重新检查所需能力。 |
| 维护与跨机连接 | 模型 owner 参与真实备份/还原/接管后配置及原生结果可读；旧代际不能外发。实际本机/学校连接、独立持有组件的认证、离线、恢复查询通过，不把同机端口切换当跨机证据。 |
| 正式 UI 与受影响回归 | 实际产品包及学校网页默认入口可保存/重开配置、选学校/个人路线、执行并取消检查；键盘、焦点、中文输入、浅深主题及窄桌面布局可用，空间切换不泄漏旧结果。被替换的旧消费者保留其授权、取消与预算边界。 |

### 真实路线与证据要求

以下为 2026-10-23 的互操作起点，**不是 2026-11-02 的重新实测结果，也不是实现完成状态**。实施使用实际交付代码重新验证，不用裸 HTTP 探针替代 SDK/Gateway 接线。

| 服务与实际 modelId | 协议 | 已有证据与本包须守住的边界 |
| --- | --- | --- |
| DeepSeek 官方 `deepseek-flash` | Chat Completions | 工具、reasoning 原生回放、基础图像及客户端 abort 有样本；标准 `json_schema` 入口当时被拒绝。 |
| 同上 | Responses | 原生 reasoning items、工具与图像有样本；有效 schema/无效 schema 负对照通过；按无服务端存储的原生历史回放。 |
| 同上 | Anthropic Messages | thinking/signature 和工具/图像有样本；当时未证实 `output_config.format` 执行 schema 约束。 |
| Command Code `deepseek/deepseek-v4.1-flash` | Chat Completions | 工具、reasoning 和图像有样本；无效 schema 当时仍接受，不能标为 native strict。 |
| 同上 | Responses | 完整 items/summary、工具和基础图像有样本；有效/无效 schema 对照通过；added 事件缺 arguments 是必须保留的回归。 |

Command Code 上述型号的 Messages 当时不在模型目录支持列表中，首批矩阵保留“不支持”反例，不拿其他型号替代。DeepSeek thinking 开启且强制具体工具当时失败、auto 成功，必须按参数组合保存限制。实施时若文档、目录或服务行为变化，新增带日期与版本的证据，保留变化前的反例；不能把历史限制写成所有版本永久成立，也不能未经实测直接删掉限制。

真实端点验收记录服务、实际 endpoint/model/protocol、参数模式、SDK/adapter/产品版本、日期、终态、原生保真比较结果及用量是否已知。使用合成图片与无副作用工具，不公开密钥、原生推理正文或签名。先限制调用次数/输出和时限，真实验证失败如实登记；不能换别的模型凑齐五条路线，也不能把客户端 abort 记成服务端停止计费。

### 平台、先例与交付口径

- 浏览器只要求桌面 Chrome，覆盖 Windows 11 x64、Apple Silicon Mac 及本包受影响的本机、学校网页和实际跨机连接路径；记录实际版本。完整学习 Run 的部署矩阵由 WP07 增补，本包不能据此跳过自己的模型连接接线。
- 复用既有宿主 HTTP 集成 + 合成 HTTPS 上游方法、SSE 拆分/中断测试、模型消费者的取消/物理请求/未知结果案例和模型设置交互用例。旧 SQLite/Session、仅目录检查、文本历史和只做页面路由 mock 的部分替换为新 owner/真实接口；保留有效外部行为，删除失效实现细节断言。
- 使用 WP01 的真实 PostgreSQL/资源与维护基础，覆盖本包新增事实和关键故障窗口，不复制底座全量测试。运行受影响工程的类型检查、构建、公共契约检查、文档检查及必要回归；通过后只因新变化、失败或未解疑点扩大测试。
- 工程检查、Chrome 界面、真实端点、维护/跨机恢复分别留证。缺环境、被限流、未测、跳过均不算通过；模型连接验收不证明 PDF 全链路、完整 Agent 或教学效果已经完成。本规范编写阶段未执行这些产品验收。
