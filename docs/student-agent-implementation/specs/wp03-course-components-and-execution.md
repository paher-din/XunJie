# WP03：课程组件宿主与公共执行

日期：2026-11-02。规范母票：[WP03：课程组件宿主与公共执行](https://github.com/paher-din/XunJie/issues/162)。范围对应[实施总览](../student-agent-implementation-overview.md)的 WP03，前置为 WP02。产品与架构决定沿用已有决议；本文补齐实施契约、正式 UI 接线、交付样例和验收边界。本轮按负责人授权完成对抗性审查后定稿发布，规范不代表产品实现或验收已完成。

## Problem Statement

学生在不同任务中需要编辑、标注、计算或持续操作实验。当前正式工作区已经能可靠保存作品、引用和问题，但中心工具仍按既有代码编辑入口装配，尚不能根据任务加载新的课程组件；真实实验也没有接入新的固定输入与接收回执链路。继续沿旧课程分支扩展，会让每门新课重复实现准备、运行、停止和恢复，并把节点选择、保存步骤等工程操作交给学生。

教师需要把已有或新制作的能力用于课程，让学生进入活动后就能使用。组件定义、学生实例、界面状态与真实执行状态必须分开：重开页面不能丢掉作品，也不能把恢复控件误报成实验继续；较早输入的结果不能被解释成当前作品的结果；未核实的停止不能显示为已经停止。

## Solution

在当前正式学习工作区内交付统一课程组件宿主和公共执行能力。任务固定组件版本、配置、开放资源及课程运行方案；平台按声明装载组件、准备兼容依赖并自检，按实际设备采用可满足要求的浏览器、本机或预先配置的远端执行路径。学生围绕任务使用组件，无需选择节点、手工冻结作品或配置工具链。

无需执行的组件直接保存结构化作品与状态；计算能力通过同一契约接收固定输入，提供有限作业或持续会话，返回可查询的真实结果。宿主统一接入 WP02 的自动保存、语义引用与待发意图，执行端管理真实运行及恢复。交付三类可导入、可实际使用的最小组件，验证新增能力可以只增加组件及声明，不改主工作区课程分支。

## User Stories

1. 作为学生，我希望从现有课程任务进入相应组件，以便继续使用熟悉的工作区完成学习。
2. 作为学生，我希望没有课程的自主活动仍能编辑和重开作品，以便组件能力缺失不妨碍学习。
3. 作为学生，我希望任务自动加载所绑定的组件与配置，以便不用理解包名、执行节点和端口。
4. 作为学生，我希望材料标注等活动不要求编译或运行，以便按任务本身的需要操作。
5. 作为学生，我希望同一组件在不同活动中保有独立状态，以便我的输入不会串到另一任务或其他学生。
6. 作为教师，我希望预览使用独立实例，以便试用不会修改学生进度。
7. 作为学生，我希望组件编辑自动可靠保存，以便无需增加手动保存或冻结步骤。
8. 作为学生，我希望刷新或重开后恢复已保存输入，以便继续原活动。
9. 作为学生，我希望存储失败时保留可取出的输入，以便不会因切换组件丢失内容。
10. 作为学生，我希望旧页面与迟到消息不能覆盖新输入，以便多标签页或重连后仍能信任当前作品。
11. 作为学生，我希望从图形、结构化标注或计算结果选择有含义的部分加入问题，以便准确表达疑问。
12. 作为学生，我希望来源变化后仍能看到选中时的副本，以便原问题不会变成另一个问题。
13. 作为学生，我希望添加引用只修改问题草稿，以便选择内容不会自动发送问题或调用模型。
14. 作为学生，我希望运行只使用点击时固定的输入，以便运行期间继续修改作品不会改变该次结果。
15. 作为学生，我希望实验操作保留正在写的问题和引用，以便运行不会发送或清空我的提问草稿。
16. 作为学生，我希望已就绪的本地计算不等待无关的远端同步，以便短暂网络故障不妨碍获准实验。
17. 作为学生，我希望平台自动检查和准备缺少的兼容依赖，以便不必手工搭建工具链。
18. 作为学生，我希望准备失败时保留配置并给出具体可执行的下一步，以便不必重新开始。
19. 作为学生，我希望设备不满足要求时使用教师已安排的适用路径，以便不必自行决定部署位置。
20. 作为学生，我希望一次加载或运行失败不会自动换位置重跑，以便不会重复产生结果或副作用。
21. 作为学生，我希望有限计算能给出真实状态、输出及失败原因，以便知道发生了什么。
22. 作为学生，我希望持续实验能接收多次输入并保持实际内部状态，以便探索有状态系统。
23. 作为学生，我希望只看到当前组件确实支持的暂停、单步、复位或恢复操作，以便不会被无效控件误导。
24. 作为学生，我希望会话操作保持顺序且重复请求不重复生效，以便重连不会多推进一次实验。
25. 作为学生，我希望点击停止后区分正在停止与已经停止，以便知道何时真正结束计算。
26. 作为学生，我希望停止与正常完成竞争时保留真实结果，以便已经完成的工作不会被错误标为取消。
27. 作为学生，我希望断线后先核对原运行，以便结果未知不会被当作未执行。
28. 作为学生，我希望关闭视图与停止实验具有清楚的区别，以便返回时知道实验是否仍在运行。
29. 作为学生，我希望丢失内部状态后明确看到无法继续或新的恢复实例，以便不会把重建当作原实验延续。
30. 作为学生，我希望结果显示其对应的作品和输入，以便区分历史结果与当前编辑。
31. 作为学生，我希望输出文件和观察可以保存并重新查看，以便无需重跑实验取回已有结果。
32. 作为学生，我希望较早运行的结果不替换当前选择，以便连续试验时不会看错依据。
33. 作为学生，我希望教师发布组件新版后已开始的活动仍使用原版，以便学习过程与历史引用保持一致。
34. 作为学生，我希望组件停用或无法运行时仍能读取已有作品与结果，以便保留已完成的学习内容。
35. 作为教师，我希望已有环境中的新组件通过清单、资源和依赖装配接入，以便新课程不必等待主工作区专门改版。
36. 作为教师，我希望自检说明实际设备、版本和失败条件，以便预览通过不会被误解为所有学生设备都已就绪。
37. 作为教师，我希望学生只获得开放材料与反馈，以便私有原文不会随组件和运行包下发。
38. 作为组件作者，我希望一个组件可以没有界面、没有执行或提供多个操作，以便真实教学任务不被固定模板限制。
39. 作为组件作者，我希望使用稳定的状态、引用和执行接口，以便不用另建保存队列或恢复协议。
40. 作为后续 Agent 能力接入者，我希望学生操作与 Agent 命令共用执行事实并区分发起者，以便 Agent 验证不会冒充学生观察或抢占学生实验。
41. 作为维护者，我希望备份、还原与接管保留组件版本、原命令和已确认结果，以便恢复不产生重复执行。
42. 作为维护者，我希望旧连接与旧安装失权后不能发起新操作，以便迁移后只有当前获准实例能推进执行。
43. 作为维护者，我希望 Windows、Mac 和实际跨机路径分别给出证据，以便清楚知道哪些组合已经可用。

## Implementation Decisions

### 1. 事实所有权与模块边界

| 模块或所有者 | 本包责任及公开边界 |
| --- | --- |
| 课程组件模块 | 固定组件清单与资源、兼容性校验、依赖准备、自检及活动实例绑定语义；提供注册、读取、准备和能力查询。WP10 后续消费这些能力建设教师组件库与发布交互。 |
| 工作区组件宿主 | 根据活动绑定装配视图、连接与授权能力，向组件提供内容、状态、引用和执行接口；仅拥有挂载与展示生命周期。 |
| WP02 学习数据与可靠工作区 | 继续作为作品、可恢复组件状态、问题草稿、固定引用及待发意图的唯一可变权威；本包通过其公开接口扩展所需类型。 |
| 公共执行模块 | 拥有命令接收、固定依据、执行器绑定、作业、会话、操作顺序、真实状态、观察、产物与回执；提供接收、查询、停止、会话控制和结果读取。 |
| 执行适配 | 将公共契约落实为真实 Worker 或获准原生进程，报告真实终态、资源限制与恢复能力；不判断任务完成或知识掌握。 |
| WP01 产品运行与存储 | 提供安装、连接、原生 PostgreSQL、所属资源及维护机制；新增服务登记自己的迁移与维护参与，不跨所有者直写表。 |

组件实例绑定稳定的空间、主体、活动、组件身份与版本；课程、任务和发布版本对自主活动可空。需要持久化的实例绑定和显式状态通过学习数据所属对象保存，组件模块不另存一份当前作品。执行事实由执行所有者保存；工作区只保留固定引用与可见投影，不能凭本机 UI 状态改写执行终态。

Web 宿主与公共执行分别形成窄的公开接口；后端先使用内部模块，只有真实跨入口共享或独立构建需要才提取 package。原生执行入口随本包实际适配建立，并由产品运行组合装配。公开 wire 不反向依赖 runner、数据库或宿主实现，浏览器导出不引入 Node 专属依赖。不建立 Agent RunDriver、通用工作流引擎或另一套后台问题派发循环。

### 2. 固定清单与课程绑定

组件最小交付使用可校验、有格式版本的清单与不可变资源。稳定身份、发布版本、内容摘要和各协议版本分别表达，不以显示名称、可变 URL 或“最新版”代替。

| 清单内容 | 必须表达的语义 |
| --- | --- |
| 定义与兼容 | `componentId`、固定版本、清单格式版本、内容摘要及支持的 `hostApiVersion`；未知必需能力或不兼容版本明确拒绝。 |
| 入口与资源 | 可选视图入口、算法/执行入口，资源身份、摘要、长度和媒体类型；允许纯视图、纯算法和无执行组件。 |
| 数据契约 | 输入、输出、显式状态及语义范围的结构与版本；大小、数量等支持上限可验证，不能接纳无界未知 JSON。 |
| 能力声明 | 操作身份、参数与结果结构、读/写/执行效果、所需对象范围及当前状态前提；课程组件可以提供零个或多个 Agent Tool，二者不等同。 |
| 准备与自检 | 兼容宿主和设备条件、固定样例、预期自检结果，以及需要执行时的环境、锁定依赖、资源预算、作业/会话类型与恢复能力。 |

复用现有课程导入与固定发布记录，扩展带版本的组件绑定：固定组件、配置内容身份、开放资源映射及课程运行方案身份/版本/摘要。现有 `component` / `executor` 能力引用不能单独被解释成这些完整信息，也不能依名称猜配置。原已发布记录保持不可变；增加配置形成新发布，旧格式可读，未声明组件的活动继续现有作品能力，不伪造执行就绪。

组件注册先校验资源，再发布可读引用，按稳定登记身份查询与去重；相同组件版本不可换字节。跨组件与课程所有者通过固定引用、保留和可查询确认衔接，不拼接跨所有者事务。可复用定义不携带学生答案、操作进度或具体会话句柄。

兼容的新组件可通过受支持的注册/导入入口装入活动，无需重建主前端；内建组件允许直接注册。新算法、视图及兼容依赖归组件装配，超出现有系统、硬件或控制能力才增加执行适配。教师编辑、入库、选择同步和发布页面由 WP10 负责，本包交付其可调用接口及真实开发资料导入链路。

### 3. 统一宿主与挂载连接

内建可信视图与隔离页面通过不同适配消费同一宿主语义。教师或第三方界面运行在隔离页面，计算进入获准 Worker 或执行器；不能仅凭“来自组件包”取得宿主身份、存储或任意网络能力。

| 接口组 | 本包确定的契约 |
| --- | --- |
| 绑定与生命周期 | 读取固定实例绑定、当前能力及可恢复状态；每次挂载/重载建立新 `connectionId`，握手核对宿主 API、组件版本和实例；准备、可用、失败、关闭视图分别表示。 |
| 内容与状态 | 读取获准对象；以稳定操作身份、预期内容/状态身份提交变化；返回所确认的本机或所属服务接收结果。 |
| 执行 | 读取实际可用能力，创建固定执行请求，按原命令查询、停止或发出声明支持的会话操作；收到接收回执不等于已经完成。 |
| 观察与交互事件 | 关联实例、连接、事件身份及顺序；控件变化、主动回答、预测、确认和真实运行观察分型，不自动触发模型或形成掌握判断。 |
| 引用与定位 | 提交固定来源、类型化语义范围、当时副本及可用定位；返回可定位、来源已变化或不可用。 |

消息校验方向、来源窗口或绑定通道、连接、实例、协议版本、操作身份和 payload。旧挂载、重载前的未完成回调及不同实例消息均不能获得新的写入或派发资格；重复消息返回同一回执，过期基线明确冲突。组件握手成功与持久化成功分别确认。关闭连接清理监听、订阅与未完成请求，不把内存快照或桥接超时回退当作可靠保存。

连接失效针对被替换、关闭或失权的视图；两个仍有效的标签页不靠“最后挂载者覆盖全部”解决竞争，而是对同一持久状态执行已有条件写入。执行控制器的生命周期独立于组件视图；切换工具或重建 iframe 不新建原命令，也不丢弃原命令的查询和停止入口。

首版宿主协议为 `hostApiVersion=1`，消息共同携带 `connectionId`、`instanceId`、`messageId`、`method` 与经对应结构校验的 `payload`；响应通过 `replyTo` 对应原消息。`messageId` 只用于传输配对，业务去重使用另行保留的稳定 `operationId` / `requestId`。首版方法分组固定为 `host.initialize` / `component.ready`、`workspace.read` / `workspace.change`、`execution.capabilities` / `execution.submit` / `execution.query` / `execution.stop` / `execution.control`、`reference.select` / `reference.locate`、`component.event` / `component.close`。进程内适配保持同样输入输出语义，不强制走消息序列化。

状态变化请求携带 `operationId`、目标对象、`expectedContentId` 和新内容；确认区分 `local-protected` 与 `owner-accepted`，两者都返回实际确认的内容身份。公开错误至少区分 `invalid-input`、`unsupported-version`、`capability-unavailable`、`forbidden`、`stale-connection`、`conflict`、`resource-unavailable` 和 `outcome-unknown`；错误包含原请求关联与可采取的下一步，不用一个通用失败触发所有动作重试。宿主消息编码、课程清单格式、组件状态结构和持久库迁移各自版本化，不能共用一个数字推定兼容。

沿用现有 iframe 桥接可复用的来源检查、生命周期和主题能力，补齐上述契约。组件不能直接持有学习服务凭据；资源和操作经获准接口访问。隔离还覆盖浏览器自动携带的 cookie、宿主存储和可发起的网络请求：教师/第三方代码不能因为运行在同源 Worker 而绕过桥接调用已登录业务 API。iframe 与 Worker 的源、资源加载、CSP/网络范围和能力授予分别实测；单有 `sandbox` 属性或 Worker 线程不证明这条边界成立。

### 4. 显式状态与作品恢复

组件使用可靠工作区的类型化对象读写能力，状态有结构版本与不可变内容身份；即时交互可在组件内保留，但恢复只读取已确认的状态。宿主通过条件写入拒绝过期基线，保留双方候选并复用既有冲突处理。切换活动、组件或空间先完成本机保护；失败时保留内存输入和可导出内容，不能卸载后才发现丢失。

DOM、焦点、浮层和进程句柄不是持久作品。选择、筛选、标注等需恢复的交互由组件显式提交；作品与关联状态必须在同一个固定动作中一致捕获。大数据、图片、检查点和输出文件通过不可变资源引用保存，不反复塞入每次状态消息。

界面保持静默自动保存，不新增保存按钮、冻结前置步骤或常态保存标签。状态保存窗口沿用可靠工作区；需要额外节流时不得无限推迟保护。恢复视图不调用运行或会话操作；恢复了滑块和参数也不表示执行器内存、时钟或数据环境已恢复。

### 5. 非文本语义引用

在现有问题草稿和固定引用协议中增加带版本的组件来源与类型化范围，保留文本/代码行为和既有记录读取。来源至少绑定所属活动/实例、组件版本、对象与内容身份；执行输出还须绑定原命令、观察或不可变产物。引用保存当时摘要及必要的数据/图像副本，副本资源先保留再确认引用。

组件注册可验证的范围结构及定位适配，例如标注对象集合、图表系列与数据点、波形信号与时间区间。宿主提供固定外层语义与验证入口，不为每门课添加枚举分支；新增范围须有注册的版本、验证器和可读副本，不以任意 JSON 绕过校验。WP03 交付结构化标注/样例结果的真实适配，ALU 波形和 Flights 图表的专用语义由 WP04/05 接入。

去重覆盖作用域、稳定来源、内容版本及规范化语义范围，不能继续仅比较文本 `start/end`。来源所有者验证实际内容、权限及范围；客户端摘要不单独证明记录真实。原对象变更、删除、同名重建、组件不可用或查看器不支持时保留原副本，定位明确失败，不猜测相似对象。选择只改草稿；交互沿用既有选区入口、引用区、顺序、移除与恢复。

创建新引用必须有兼容的类型校验与来源授权；读取已保存引用则可以只呈现已校验的固定摘要/副本。不能因原组件或定位适配暂不可用，就拒绝整份问题草稿或清空未知范围；同时不能为恢复显示而加载未经校验的执行代码或把未知类型当作可操作对象。

### 6. 确定性准备、自检与版本固定

平台按固定清单及实际设备完成资源取得、摘要核对、依赖准备、能力检查与自检，不依赖模型在线。准备记录绑定组件、配置、环境/依赖和设备能力指纹；只有相关输入变化才重做受影响检查。新环境先验证后启用，失败保留上一个可用环境及准备进度，既有运行继续绑定原环境。

区分尚未准备、正在准备、权限待确认、可修复依赖问题、设备确实不满足、自检失败和原运行失联。可确定修复的安装或准备步骤沿原准备身份继续；运行结果未知不进入通用“重试准备”路径。实际不可用条件影响相应能力，不阻塞仍可用的编辑、历史阅读和无执行组件。

可用性不是单一全局 `ready`：返回每项操作在当前设备和策略下是否可用、限制及原因。自检使用独立实例和公开固定输入，不改学生作品、实验或学习证据。教师预览记录与学生设备检查分开。首批示例至少包含一项真正需要准备的锁定依赖，验证缺失、错误版本、中断、继续和缓存命中，不能用空声明冒充依赖装配。

### 7. 课程运行方案与实际位置

运行方案按任务和能力声明允许的执行位置、所需语义、版本、资源条件及适用的远端路径。平台优先选择完整满足要求的浏览器能力，其次是产品自动准备的本机环境；只有本地确实不满足且方案已有适用远端安排时才使用远端。学生不选节点。缺安装、待授权、暂时下载失败和原运行失联不等于设备不满足。

每个新运行在接收前固定选择结果，并绑定实际执行所有者、节点稳定身份、安装/恢复代际和该次执行器启动实例。重连按这些身份查询；修改连接地址、重启节点或出现另一可用节点不能改变原命令归属。若原状态不能核实，保留未知及原结果查询关系；新的明确运行必须使用新身份并与原记录区分。

本包交付浏览器 Worker 适配，以及承载实际样例的原生适配；同一原生契约用于本机和明确配置的学校执行节点，不为位置复制业务语义。具体原生隔离/监督实现由适配实施时用目标平台验证后固定。它必须限制文件与资源范围、网络权限、进程树、时间和输出，并能确认本次拥有的执行单元终止；不能仅启动普通子进程就宣称支持任意不受信任程序。

复用 WP01 安装与连接机制准备本机能力，学校通过获准的主动连接/领取通道与本机节点协作，不能访问自己的 localhost 代指学生设备。网页、本机与学校各自地址、授权和所需浏览器连接权限纳入真实路径验收；不把 SSH 开发隧道设为学生使用前提。只使用浏览器/无需执行能力时，不要求安装原生节点或本机数据库。

### 8. 固定执行请求与 WP02 接收链

扩展现有动作 wire 和可靠动作入口，按用途承载类型化执行 payload：组件实例与版本、操作及效果、输入参数、必要作品/状态/资源内容身份、预期对象条件、运行方案、发起者和执行能力。执行动作只固定自己的依赖，不强制捕获问题草稿，不用问题文字或文件名暗中编码命令；接受实验请求不能清空、发送或改变问题草稿。

动作协议新增显式版本与按 `kind` 区分的 payload；现有无版本问题记录按既有格式读取，新增执行记录使用新格式。协议演进同时覆盖浏览器持久记录、服务端验证、接收方和恢复检查。既有问题动作的原字节、摘要、取消事实与回执保持可核实；不能迁移时重算摘要或新建身份掩盖未知。固定依据在第一次异步等待前一致捕获，之后的新编辑不改变或扩大该动作依赖。

学生操作使用 WP02 的可靠动作创建与 `ActionReceiver` 接收/查询/取消语义。浏览器/本机路径在本机可靠保存意图和输入后即可交接，远端路径等待本次依赖到达所选执行端；二者都不等待无关问题或新的作品同步。本机执行仍检查当前已知授权和适用 grant，已知资格撤销阻止新接受，单纯网络不可达不伪装成撤销或新授权。

执行端先持久保存命令与待处理事实，再返回 `accepted`；相同请求身份和相同输入得到原记录，换输入拒绝。记录至少关联 `requestId`、执行命令身份、作用域、输入摘要、版本、发起者、实际绑定和接收回执。浏览器执行账本持久在本机，原生/共享执行事实使用所属 PostgreSQL 与资源；不可仅靠组件内存承诺已接受。

`execution.submit` 明确选择 `job` 或 `session`，返回接收回执及固定执行引用；`execution.query` 支持在首次回包丢失时仅凭原请求身份和摘要查到同一执行引用，不能要求调用者先拥有丢失回包中的命令 ID。停止和会话控制也分别具有稳定请求身份，并指向原执行引用。接收前取消形成不可复活记录；接收后取消请求转为原执行的停止流程，原接收回执继续保持 `accepted`。暂时查无记录、节点不可达或从旧备份恢复均不能单独证明从未执行。

学生、Agent、自检和教师预览具有不同发起者与用途，由已认证宿主/调用服务及真实操作依据确定，不能只信组件自行填写的角色或“学生已同意”。WP07 后续从已可靠保存的 Agent 命令接入同一执行接口，不需要伪造问题草稿；WP03 提供可消费契约与独立作用域验证，本包不产生真实 Agent 回复。执行前重新检查当前权限、效果范围和对象条件；需要写当前作品的操作最终由作品所有者条件写入，不能拿固定旧输入无条件覆盖新编辑。

权限撤销阻止新的读取、接受和会话推进，但不妨碍执行所有者按既定生命周期结束其已拥有的进程及保留真实终态。面向学生的查询/读取仍检查当前访问资格；停止和资源回收由执行所有者及维护身份完成，不为清理重新授予学生访问。这样既不会以旧授权继续新实验，也不会因为普通业务接口返回拒绝就留下无法管理的会话。

### 9. 有限作业、状态与停止

有限作业接收一次固定输入，产生真实输出、诊断和产物。平台不强制每个组件都编译、检查答案或返回通过/失败评价。产物复用只在输入、算法/组件、依赖环境、配置与相关选项一致时成立，不能按文件名或“同一课程”复用。

执行状态至少区分已接收待处理、执行中、请求停止及执行器确认的成功、失败、取消；结果未知是需要核实的事实，不是由网络错误推定的终态。输入/程序错误、环境故障、预算耗尽和课程行为不符分别表达；成功运行不代表课程检查通过。

首版执行查询分别返回 `state`（`queued`、`running`、会话适用的 `paused`、`succeeded`、`failed`、`cancelled`）、`stopRequested` 和 `statusKnowledge`（`confirmed` / `unknown`），并保留最后可信状态、确认序号与原因。未知时 `state` 仅表示最后确认状态，不能解释为仍在运行；网络断开不自行把它写成失败或取消，`stopRequested=true` 也不是终态。`confirmed` 只说明状态经执行权威确认，不代表已经产生最终结果。已确认终态不因后续断网、重复或较早响应退回未知；产物暂不可读另行报告，不抹去已确认的执行完成事实。命令接收回执沿用 `accepted` / `cancelled` / `rejected`，其中执行接收后的停止与业务接收前取消分开查询。适配必须声明并实际执行时间、内存、输出、并发及会话数量上限，超限不以无限排队掩盖不可用。

待处理请求和派发记录不能出现“已接受但只留内存”的窗口。并发领取及状态提交使用有效代际和条件更新；旧处理者不能再次派发或提交有效新进展。重启后明确未开始的请求可以继续原请求，已经可能产生效果的请求先查原执行单元，不以重新领取为由重跑。

停止请求有稳定身份并可查询；未开始时形成不会被迟到接受复活的取消记录，已开始时由实际执行器确认。终态以真实竞争结果为准：正常完成先发生则保留完成与结果，停止先确认则保留取消；停止不撤销已发生效果。超时和输出超限也须实际停止或明确仍未知，不能先释放占用、显示已停而留下运行进程。

### 10. 持续会话、操作顺序与检查点

会话建立固定初始依据、会话身份、执行器启动实例和资源限制；后续每项输入/控制有自己的稳定操作身份、输入摘要与预期序号/状态。冲突操作按会话顺序裁决，相同操作重试只返回原结果，过期操作不得推动当前状态。互不影响的不同会话可以按实际资源预算并行，不共用全局学生状态。

适配分别声明输入、暂停、恢复推进、单步、复位、检查点、断线续接及跨视图存活能力。`execution.control` 的首版操作为 `input`、`pause`、`resume`、`step`、`reset`、`checkpoint`；只开放声明支持且在当前会话状态合法的操作。未声明的控制不展示为可用，不用终止重建模拟暂停。复位是明确的会话操作；从检查点恢复则通过 `execution.submit` 建立带 `resumeFromCheckpoint` 与原会话引用的新执行实例，区别于对仍存活会话的 `resume`。

检查点由执行器产生，关联会话、已应用操作位置、固定环境与内容摘要，先可靠保存再宣布可恢复。进程内部状态丢失后，只有经过验证的检查点恢复路线可建立关联的恢复实例；缺少检查点或环境不兼容时保留作品、历史与中断原因，显式新建会话，不自动重放历史操作猜测原状态。

会话声明心跳、空闲/最长持续限制、资源预算和断连处置。页面隐藏、关闭视图、关闭网页、主动停止、节点重启分别处理。浏览器 Worker 默认不承诺关页后存活；原生会话只有实际支持时才可跨视图继续。心跳丢失先标连接/状态待核实，不能直接确认终止；重新挂载先查询原会话再恢复视图。

### 11. 结果、观察与资源归属

结果、诊断、事件、检查点及产物都绑定固定输入、组件/环境/方案版本、实际执行实例和发起者。事件有稳定身份及单调序号，可去重和补读；缺失区间明确表示，不用客户端到达顺序伪造完整轨迹。会话观察同时标出对应操作与状态位置。

本地输出先可靠保留，再按原身份同步到所属服务；大资源使用 WP01 的不可变资源发布与保留机制。资源写入成功但记录确认丢失时核实并继续关联，不重新计算取回文件。结果只能引用已完成且可重读的资源；损坏、缺失、无权限和暂不可达区分反馈。

工作区结果视图绑定学生当前选择，旧请求的晚结果归档在原运行，不覆盖新结果或当前作品。显示必要的作品/输入关系，技术标识进入详情。应用服务的 Agent、教师交付和后续证据判断只能引用它们已接收到且可核对的相应记录。WP03 提供真实观察及验证/保留接口，WP11 拥有学习判断；控件变化与执行成功不直接记作掌握。

### 13. 停用、维护与恢复接管

已开始活动固定组件版本，发布新版只影响采用新发布内容的新活动。当前包不迁移进行中活动到新组件版本。停用能力、关闭视图、请求停止、移除目录入口和删除学生数据分别处理；被活动、命令或引用保留的固定资源不随入口移除而清理。不能再次运行时仍提供获准的只读作品、引用副本和历史结果。

组件及执行所有者随实现登记 schema、资源、迁移、维护关闸、排空和恢复校验。维护先停止新接受与派发，将已接受但未开始、执行中、停止待确认及未知操作分别保留；不能只等 HTTP 处理结束就宣称执行已排空。持续会话按声明检查点/停止，无法确认时维护明确未完成，不能生成冒充完整的恢复结论。

备份包含服务已收到的组件固定资源、绑定、命令、回执、结果与可恢复检查点，不声称涵盖浏览器独有未同步内容或任意活进程内存。独立试还原默认隔离，不能自动派发实验；正式接管遵守 WP01 的源实例失权、接收端拒绝旧安装和新恢复命名空间规则。

接管保留原命令和输入身份，旧挂载、旧安装、旧处理者都不能发起新的有效操作。来自原执行的晚结果仅在核实原身份和真实依据后归档，不作为旧实例恢复派发权。已接受/未知命令先查询原执行，只有声明支持且实际验证的恢复能力才能继续；不自动把旧本机队列转交新节点。

| 样例 | 实际能力与必须证明的契约 |
| --- | --- |
| 结构化材料标注 | 动态隔离视图，读取开放材料，创建与编辑标注对象；无执行声明也可保存、重开并引用稳定标注对象。两个活动/主体互相隔离。 |
| 固定表格聚合计算 | 对真实固定数据及用户所选参数做聚合，生成数值和可下载的结果文件；浏览器 Worker 真正计算，验证固定输入、预算、停止、结果保存及版本复用。不得硬编码预期输出。 |
| 离散状态模拟会话 | 原生执行器保持内部状态，连续接收输入并提供至少暂停/单步、复位、检查点和恢复样例；以状态推进和恢复后的下一步结果证明不是界面变量模拟会话。 |

同一原生会话组件还在教师方案允许的远端节点运行，验证真实跨机查询、停止、失联和原节点归属；不要求每个样例机械遍历全部执行位置。至少一个兼容的新组件/操作及其锁定依赖，在主前端产物不变时完成导入、准备与使用。样例包含确定的预期结果、错误输入、资源超限及依赖失败负例，交付来源、版本和操作说明；不对尚未测量的容量与准备耗时作承诺。

## Testing Decisions

### 主要测试边界

以 **正式桌面 Chrome 工作区操作 → 同一组件宿主/可靠动作公开接口 → 真实 Worker 或执行节点 → 真实 IndexedDB、业务 API、原生 PostgreSQL/资源 → 重开或重启后的可见结果** 为主要验收边界。三类样例共用这条路径，断言作品、状态、固定输入、实际结果、回执和归属，不断言 React state、私有方法、SQL 次数或内部目录结构。

对浏览器难以稳定控制的时点，仅在**同一宿主消息边界及执行接收/查询边界**补充故障与竞争注入：旧连接、乱序、落盘失败、接收后丢 ACK、派发前后崩溃、停止/完成竞争及旧代际。测试调用生产模块，保留真实存储与执行器；故障替身只控制时序或传输，不能替代实际计算、会话或跨机验收。已有接口优先，不为每个内部类另设验收接缝。

### 必须覆盖的行为

| 范围 | 通过依据 |
| --- | --- |
| 动态装入与兼容 | 固定主前端产物装入兼容新组件；缺资源、摘要错误、未知必需能力和版本不匹配明确拒绝；没有执行声明的标注组件可完整使用。 |
| 实例与权限 | 同一组件在不同学生、活动及预览实例独立；跨范围消息、资源、引用和操作被实际所有者拒绝；组件不能借 cookie/同源 Worker 绕过桥接或自报角色扩大能力；私有材料不在学生包和响应中。 |
| 状态保护 | 在真实组件中连续编辑、双标签竞争、刷新与切换；已保护状态恢复，旧连接和较早确认不覆盖新输入，本机失败保留可导出内容。 |
| 语义引用 | 非文本选择进入现有问题草稿；去重、移除、多引用、刷新、来源变化/删除和无定位能力均保持原副本；组件/适配缺失不阻断已有草稿的只读恢复；伪造来源/范围被拒绝。 |
| 动作类型演进 | 旧问题动作/摘要/取消可继续核实；实验只固定所需参数和作品，不发送或清空问题；旧动作接受后新草稿仍完整。 |
| 依赖与自检 | 真正锁定依赖的缺失、错误版本、下载/准备中断、继续及命中缓存；相关版本变化只失效受影响检查，自检不产生学生观察。 |
| 位置选择 | 浏览器满足即本地执行；缺安装先准备，设备确实不满足才用已配置适用远端；失败/失联不换节点重跑，无执行任务不依赖节点在线。 |
| 有限作业 | 真实计算输出与独立预期一致；运行后继续编辑仍绑定旧输入；正常结果、输入错误、预算超限、停止与未知分别取证，产物可重读。 |
| 持久接收 | 并发重复接受只产生一份实际命令；同身份换输入拒绝；首次接收回包丢失后仅凭原请求及摘要查到原执行引用；查无记录不自动重跑，原地恢复不产生第二次效果。 |
| 停止竞争 | 接受前取消不复活；已开始停止待执行器确认；正常完成/停止竞争保持真实终态；确认停止后实际进程树/Worker 不再推进。 |
| 持续会话 | 多次输入真正依赖前次内部状态；重复/乱序操作不多推进；暂停、单步和复位按声明工作；旧会话/启动实例不能控制新实例。 |
| 检查点与丢失状态 | 检查点前后结果可核对；明确支持的恢复建立可追溯实例；无检查点、损坏或版本不兼容时不冒充续接，不回放未知操作。 |
| 返回与晚结果 | 关闭/重开只恢复视图和查询，切换工具不丢原停止入口；按生命周期继续或中断；晚结果保留原归属且不覆盖当前选择；心跳失联不直接判已停止，已知终态不倒退。 |
| 撤销后的资源处置 | 已知资格撤销后不能新接受或推进，也不能继续读取无权结果；执行所有者仍能按已声明策略停止、回收并持久确认终态，不留下因学生鉴权失败而失管的进程。 |
| 资源与事件 | 输出/检查点先可重读再发布引用；保存确认丢失只续关联；重复事件去重、缺口可见；缺失/损坏资源不靠重跑修补。 |
| 真实部署 | 两类目标设备的正式包/学校页完成适用路径；至少一个真实跨机执行组合验证严格 HTTPS、获准连接、断网、原节点查询与撤销。 |
| 维护与接管 | 新增所有者真实备份、独立隔离还原和接管；原版本/结果/命令身份可读，试还原不执行，旧安装与旧浏览器队列不能自动恢复派发。 |
| 产品接线与回归 | 默认 Web 与实际产品包使用同一宿主；无测试接收器/夹具依赖；现有编辑、引用、导航、焦点、主题和中文输入回归通过；被替代接线实际清除。 |

### 平台、先例与证据

- 浏览器只要求桌面 Chrome，分别覆盖 Windows 11 x64 与 Apple Silicon Mac。记录实际 OS、浏览器、产品包、组件、执行器和环境版本；原生适配及学校服务采用实际交付的受支持组合。
- 浏览器 Worker 与无执行组件在两个客户端平台验收；原生会话在两个本机平台验收；远端路径至少连接一台独立机器，分别验证两个目标客户端的适用访问。学校网页执行不要求学生安装无关数据库，不以同机多进程或开发代理替代跨机路径。
- 复用 WP02 可靠作品、问题草稿、动作与 `productUi` 的真实 Chrome/IndexedDB/HTTP/PostgreSQL 用例，扩展为组件状态、执行 payload 和真实执行接收器。现有受控接收器继续作为竞争测试先例，不作为 WP03 业务完成证据。
- 旧 runner 已有重复接受、取消墓碑、未知状态、权限复核、进程控制和结果读取先例，旧 HDL 也有会话操作案例；复用行为断言及必要实现，替换旧 Session/快照/节点选择假设。仅 Linux 或合成 transport 的通过记录不算新原生适配的平台验收。
- 复用 WP01/02 的资源、维护排空、真实备份恢复与旧安装拒绝测试，经新增所有者公开接口验证接入；不机械重复已完成底座的全部安装或引擎升级矩阵。
- 工程检查包括受影响 workspace 的类型、构建、公共契约浏览器边界、文档和相关回归。只为外部行为、真实故障与契约竞争补测试，不为薄包装或可逆文案逐项写测试；通过后仅因新变化、失败或未解疑点扩大验证。

工程测试、真实计算/会话、Chrome 使用、产品部署与教学效果分别报告，跳过不算通过。记录准备、启动、结果和恢复耗时及资源用量，作为后续课程容量判断的输入。UI 交付给出实际前后对照截图；本规范编写不宣称上述验收已执行，也不产生教学效果结论。
