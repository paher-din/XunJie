## 问题与交付边界

学生需要从本人获准的课程中选择任务及明确发布版本，阅读开放材料并建立活动；教师发布新版后，旧活动仍使用原目标、要求、材料和起始作品。固定版本不能成为绕过当前资格或下载私有材料的途径。

本票交付受支持的课程登记/导入和课程授权入口、真实 PostgreSQL 发布记录、学生课程页面、课程活动建立/列出/重开、资源保留以及新增状态的迁移和恢复校验。作品编辑、引用草稿和执行接入不作为开始活动的前置条件；完整教师设计、组件装配、预览与发布界面归 WP10。固定组件/执行能力引用只表示依据，不表示能力已安装或可运行。

## 领域身份与事实归属

| 对象 | 身份与不可变内容 | 所属 owner |
| --- | --- | --- |
| Course | 稳定 `courseId`，所属空间；名称仅供展示 | 空间/课程 |
| ProjectTask | 稳定 `taskId`，绑定一个课程；重名不合并身份 | 空间/课程 |
| CourseRelease | 稳定 `releaseId`，所属课程/任务，规范化内容摘要及格式版本 | 空间/课程 |
| 发布内容 | 学习目标、任务要求、学生开放材料、起始作品清单、固定能力引用；私有部分单独标识和投影 | 空间/课程 |
| CourseAccess | 空间、主体、课程的当前有效资格，支持管理者授予和撤销 | 空间/课程 |
| CourseActivityBinding | 原课程 authority、空间、课程/任务/发布身份、内容摘要、材料身份和固定引用，以及原学习数据服务绑定 | 学习数据 |
| 操作及保留记录 | 稳定请求身份、输入摘要、阶段、结果；课程侧活动关联与版本保留责任 | 各 owner 持有所属部分 |

发布中的材料和起始作品条目都使用稳定条目身份、资源身份、摘要、媒体类型及长度；路径/标题不充当身份。能力引用固定类型、稳定对象身份和版本，不存“latest”作为已固定依据。初始作品是发布内容，不在本票提前创建另一套可编辑作品仓库；后续可靠作品编辑票按原活动绑定消费它。

发布后不可原位改写。相同登记操作和相同内容返回原结果；同一请求身份改内容、同一发布身份改摘要或把发布关联到另一任务均拒绝。课程提供者修改内容须产生新 `releaseId`；新版不批量重绑旧活动。页面可以推荐一个版本，但建立请求必须提交选定的具体 `releaseId`，响应同时显示其版本依据。

## 登记、资源发布与管理入口

建议在现有产品 CLI 和受认证管理 HTTP 边界增加课程导入、查询操作结果、课程资格授予/撤销能力。正式命令名在实施时与现有 CLI 命名对齐，随交付记录准确用法。入口消费有版本的清单和本地资源文件；管理者身份沿用宿主控制授权，普通学生会话或客户端 grant 不获得管理能力。不为本票新增教师创作页面。

导入清单包含课程/任务/发布身份、目标与要求、开放材料和起始作品、私有材料分区及固定能力引用。未知格式、重复条目、非法路径、越出导入根的资源、身份归属冲突、缺少资源、摘要/长度不匹配均在发布前拒绝；不把清单中的任意文件路径或远程 URL 当作后端可自由抓取的指令。所需文本、二进制材料必须持久入库/资源后端，外部链接只能作为明确标示的外链，不能宣称其内容已冻结和保留。

登记顺序：

1. 核验管理授权，按稳定 `requestId` 查询既有登记结果并核对输入摘要。
2. 校验完整清单；用稳定 `uploadId` 经 `stageResource` 写入并重读校验每项资源，不在 SQL 事务中上传文件。
3. 所属短事务登记课程/任务、不可变发布、所有资源引用及登记回执；任何必需资源未 ready 时不得发布。
4. 返回可查询发布结果。上传未知用原 `uploadId` 核实，提交未知用原 `requestId` 查询；不得换请求身份掩盖未知。

验证失败不生成可供学生选择的半份发布。事务前完成但尚未关联的资源沿 WP01 规则处理；已发布版本及已被活动使用的材料持续持有引用，不因新增版本、课程撤权或关闭活动解除保留责任。本票不提供课程版本和历史材料自动删除策略。

## 公开领域接口与访问投影

建议将课程逻辑收拢为 `packages/learning-space` 内的课程 module，消费空间身份/绑定接口；不新建独立进程或 package。它和 spaces 同属空间/课程 owner，不能把其 repository 或 SQL 事务交给学习数据 owner。后续混合部署消费同一领域语义及传输适配，不另设远端数据模型。

| 建议的公开操作 | 调用者和结果 | 必须保持的约束 |
| --- | --- | --- |
| registerRelease / registrationResult | 受授权课程提供者登记并查询原操作 | 真实持久化、不可变、身份冲突可辨 |
| grantCourseAccess / revokeCourseAccess | 受授权管理者变更课程资格 | 不改变成员身份、既有活动归属或版本 |
| listCourses / listTasks / readRelease | 当前学生读取本人获准列表和明确版本的学生投影 | 每次核验主体、空间、成员及课程资格 |
| readMaterial | 当前学生按发布和材料身份读取已校验内容 | 核验材料确属该发布且学生开放；不暴露裸资源后端下载路径 |
| prepareActivityBinding / confirmActivityBinding / bindingResult | 学习数据服务通过受认证领域边界关联原创建操作 | 固定身份、目标、版本和保留责任，结果可查、重试幂等 |
| createCourseActivity / receipt | 当前学生建立或查询原课程活动请求 | 沿用既有活动归属和请求模型，未完成不返回成功活动 |
| open / list / setStatus | 当前学生读取、列出和关闭/重开活动 | 课程活动读取当前资格和原版本，自主活动继续原路径 |

wire 在 `@xunjie/contracts` 增量导出，公共契约不反向依赖服务实现。自主活动与课程活动使用可区分的输入；自主活动不需要伪造课程字段。已有无课程活动、请求身份、关闭/重开行为保持兼容，不能靠严格 schema 丢弃原记录。

权限判定发生在所属后端，覆盖列表、详情、创建、重开、操作查询、材料下载及客户端代理。学生投影以允许字段构造，不能把完整教师 DTO 发出后前端隐藏；不得泄露私有材料名称、正文、资源 locator、私有测试或未发布草稿。即使拿到真实资源 UUID、旧发布 ID 或另一学生活动 ID，仍须核验。身份来自真实会话/本机主体或受认证服务，不相信浏览器提交的主体与目标 owner。

固定版本只固定内容，不固定授权。撤销课程资格后，拒绝新读与新建；撤销成员、会话或客户端授权继续沿既有边界生效。其他获准课程和个人自主活动按各自资格工作。已下发的设备副本不能宣称已远程擦除；旧活动和关联仍保留原归属，不转存为个人活动。

权限拒绝、对象缺失、资源损坏和 authority 暂不可达分别反馈。跨主体/空间资源可用统一不可见响应避免枚举，但服务内部仍区分原因；合法主体读取其已绑定而丢失的版本/资源时报告缺失或损坏。服务故障不转换成空列表、权限成功或最新版内容。

## 跨 owner 建立与未知结果恢复

不能把两个 owner 的 SQL 拼成一笔事务。建议由学习数据 owner 持久记录创建协调状态；每一步先查询已有结果，再续做缺失步骤。内部待完成记录不进入成功活动列表。

1. 真实身份解析后，解析并固定成员学习数据服务绑定；以完整主体、空间、目标和规范化输入摘要登记创建操作。重复同一请求返回或继续原操作，不生成第二个活动 ID。
2. 课程 owner 按稳定关联身份核验当前资格与明确发布，保存原活动 ID、目标服务和版本关联的准备记录，并建立资源保留责任，返回仅含学生开放内容的固定描述。
3. 学习数据 owner 在自身事务持久保存活动的固定绑定与待完成状态。课程准备失败或资源不可读时不对外确认成功。
4. 课程 owner 按原关联确认，重新核验当前资格及资源完整性，持久确认关联；学习数据 owner 查询确认结果后在自身事务提交可见活动和成功回执。
5. 回包丢失或任一步中断时，从原操作身份及两侧公开结果续接。返回成功前走正式读取路径核实；期间若权限撤销或资源故障，返回对应错误并保留原结果查询入口，不承诺之后权限永远有效。

建议查询状态区分 `pending`、`accepted`、`rejected`，传输/提交未知继续查询原操作，不伪装为领域拒绝。`accepted` 只对应已完成关联的活动；读取结果仍经过当前授权。相同请求改发布/主体/目标返回身份冲突；用户明确再次建立可用新请求创建另一活动。

步骤之间崩溃、确认后最终提交丢失、完成前撤权均须测试。协调恢复不触发组件执行、模型调用或教师交付。待完成关联的资源保持保留，不能在“不确定是否有活动”时回收。完整备份需包含两侧操作状态和保留记录；维护排空停止新协调，已持久的 pending 可在一致恢复后按原身份核对，不要求跨服务长事务。

## 学生页面与接线范围

在现有生产学习入口按当前空间展示获准课程和活动；课程下显示任务及已发布版本，详情先呈现目标、要求、开放材料和起始作品说明，再提供“开始活动”。已有活动单独进入原活动，刷新、服务重启及关闭后重开都不把“进入”解释为新建。

课程详情允许选择明确发布版本，进入活动后以原版本读取目标和材料；新版可见不改变旧活动。版本缺失、材料损坏、无权限和连接失败分别显示可理解的异常及重试入口，不静默切到最新版本。未完成创建使用原请求核对状态；切换空间后旧异步结果不得写入新空间或覆盖新请求。无课程自主活动入口继续可用。

呈现遵守 [DESIGN.md](../../../DESIGN.md)，复用现有色彩、排版、间距、焦点和浅/深色 token。无需学生选择存储节点、手动保存或冻结；不分叉课程专用工作区。未接入的作品编辑、实验或 Agent 能力不显示虚假可用状态。按需只读呈现发布起始作品不构成作品编辑器交付。

## 迁移、维护与恢复接入计划

实施时在空间/课程 owner 追加课程、任务、发布、资格、资源保留和关联操作迁移；学习数据 owner 追加可选课程绑定与协调状态迁移。既有迁移不改写，已有自主活动和回执保留。实际 schema 变更与迁移执行仍须遵守根规范的单独授权红线，本轮没有该授权动作。

两个 owner 各自登记领域校验器、维护参与者与恢复目标。校验课程/任务/发布关系、摘要和资源清单、活动绑定及操作状态一致性；跨 owner 关系通过公开只读核对完成，不能直接 JOIN 对方 schema。完整备份还原包含历史版本、全部引用资源、课程资格、操作回执与未完成关联；恢复发现丢失或损坏保持隔离，不能重新导入同名课程或自动重建活动冒充恢复。

本票验证自身新增状态的原生 PG 迁移、升级、完整备份及独立恢复重开。真实跨机混合部署和权威接管由[混合部署与业务恢复接管](https://github.com/paher-din/XunJie/issues/154)继续验收，本票提供可直接消费的接口及恢复校验，不把首次持久化和恢复验证推给后续票。
