# WP07：Agent 提问与明确回应

需求以 [#199](https://github.com/paher-din/XunJie/issues/199) 为准，沿用 [#196](https://github.com/paher-din/XunJie/issues/196) 已确认的生产接口、session log、真实 PostgreSQL/资源与 Chrome 测试边界。前置工具与 Wait 的实现选择见[固定工具](wp07-agent-tools.md)。本文记录本票实施选择，不复制动态议题状态。

## 能力与事实

固定能力 `student.ask` 由 Agent owner 实现；三协议原生函数名为 `student_ask`，满足既有公共模型名称约束，不由材料或模型输出登记能力。参数只包含简明问题、来源说明、稳定选项、是否允许自由文字及是否可跳过。来源关联由宿主固定到原 Run、步骤、命令、输入和快照，学生不填写内部身份。课程帮助策略同时约束问题与续接。

在原工具命令取得准入后，问题、版本化 Wait、接受事实、日志与等待状态由同一所属事务提交。工具已接受、实际呈现、明确作答分开保存。关闭、忽略、切换焦点、断线与历史读取不会自动消费 Wait。

## 回应与恢复

既有活动对话提供同一回应入口，IP 可以定位到它。回应有独立的稳定 requestId、问题版本与 Wait 版本，以及选择、文字或明确跳过的输入语义；普通新消息不由自由文本分类成回应。浏览器沿现有工作区 IndexedDB 保存固定待发回应，回包不明先查询原身份，未确认前保留输入。

有效回应在锁定原 Run/问题/Wait 的事务中唯一消费，保存处理回执和学生发言，更新原命令的实际结果，随后才唤醒原 Run。相同身份换内容冲突；不同身份的重复、过期、取消和版本不符均保存实际拒绝结果。终态不复活，不回答另一问题。恢复沿原生工具配对加入有来源的明确回应，实际请求快照可核对采用内容。

等待释放模型连接和内存推进者，使用既有持久调度与 Run 的剩余计算预算；学生等待期限单独计算。重启读取原问题，不重新提问或生成。新表/Wait 版本参加迁移、保留、只读恢复校验与维护接管；隔离还原不呈现写入回执，也不派发模型。

## 实施与验证顺序

1. 真实 HTTP → Agent → ModelGateway → PG：固定问题、Wait、明确回应与原 Run 续接。
2. 同一公开边界：重复/换内容、丢回包查询、错误版本/活动、未呈现、停止与晚回应、等待超期。
3. 实际停止/重启、备份与隔离只读还原，核对问题、回执、Wait 和请求快照保留，历史读取不调用模型。
4. 正式 Web 和完整 Windows 产品包的桌面 Chrome，验证选择/中文文字/跳过、可靠输入、焦点、滚动、主题与 IP 定位，提供实际前后截图。
5. 受影响工程检查、单文件持续回归、完整本机测试一次，之后双轴审查并修复；真实模型与平台证据按实际结果分别记录，未执行项不计通过。

不增加通用生成页面、主动触发器、强制学习步骤锁或新的队列推进权。后续 steering/queue 直接使用本票的明确回应接口。
