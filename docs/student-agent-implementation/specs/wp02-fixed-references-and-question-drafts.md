## 目标与边界

学生从真实开放课程文字或自己的代码选取内容，带着固定引用组织问题；收起输入区、切换活动、刷新或同浏览器返回后，问题和引用仍能继续使用。引用始终解释选择时的对象、内容与范围，后续修改、重命名或删除不能把它改指新版或同名对象。

本票交付生产材料/编辑器选取、固定引用、可靠问题草稿、授权来源核验、定位和来源状态、历史内容保留，以及新增状态的维护/恢复接入。复用可靠工作区与已有引用组件，不建立课程专用工作区、第二套可变草稿库或模型接收通道。

选择可以触发自动持久化和后台同步；这不是发出问题。真实发送由后续 [#153 固定依据与持久待发意图](https://github.com/paher-din/XunJie/issues/153)及 WP07 接入，本票明确禁用业务发送，不产生模型调用、业务接收回执或示例 Agent 回复。草稿同步回执只证明所属学习数据服务接收对应修订。

## 建议的领域契约

### 工作区、草稿与修订

隔离键继续由产品恢复命名空间、空间所属环境、空间、主体、活动构成。服务端主体从真实认证取得，并核验原活动及学习数据服务绑定；不能用页面传入的 `principalId`、路径或 `workspaceKey` 字符串证明权限。

每个活动拥有一个稳定 `draftId`。`QuestionDraft` 包含问题原文及有序引用集合；每次实际问题/引用变化形成稳定的 `draftRevisionId` 与内容摘要。草稿头使用单调版本/CAS，和作品头、浏览器本机修订及同步请求 ID 分开表达：修订身份固定内容，操作身份负责幂等，确认不能互相冒充。

草稿与作品归同一个可靠工作区 module 和学习数据 owner。建议在现有工作区状态中增加类型化 `questionDraft` 分区，草稿有自己的远端基线、待同步项与冲突结果；不伪装成用户文件，也不把它放进另一个独立资源库。一次选择所涉及的来源快照、草稿变化及待同步依赖必须在同一 IndexedDB 可恢复事务中保存。问题编辑无需和不相关文件变化争用同一个远端版本；语义上互相独立不代表再造同步引擎。

读取恢复数据前后用工作区身份及本机编辑代际校验；旧结果不能覆盖当前问题或引用。未同步的后续修订始终保留。具体字段上限和错误契约随实施的公共 schema 固定并验证；超限保留内存与复制/导出能力，不静默截断、丢引用或假称已保护。

### 固定引用与来源

| 字段组 | 建议语义 |
| --- | --- |
| 引用身份 | 稳定 `referenceId`，属于原活动/草稿；显示名、路径与加入序号不是身份 |
| 来源对象 | 可区分的来源联合：本人作品对象，或获准课程发布中的明确字段/材料；不接受任意 URL、DOM selector 或跨活动对象作为已验证来源 |
| 来源内容 | 不可变作品 `contentId`，或原 `releaseId`、内容摘要、字段/材料身份与摘要；课程字段路径只在该不可变发布内解释 |
| 范围 | 本票使用 `text`/`code` 对应的原文 UTF-16 半开范围；保留实际 BOM、CRLF、换行及代理对边界，不能直接使用 Monaco 的 LF 投影偏移 |
| 选中副本 | 选择时原文，独立于当前来源；摘要和后端范围校验必须与所指原内容一致，不能只信浏览器提交的副本 |
| 依据与定位 | 完整所属空间/活动；课程引用固定原课程 authority、课程/任务/发布及材料或字段身份。定位依赖可重新建立的来源能力，DOM Range、组件实例和函数不持久化 |

课程字段来源可包括原发布的目标、要求；字段路径/数组下标必须在已固定发布中验证，不以同名任务推导身份。课程材料引用只接受该发布已开放的文本材料。作品来源必须是原活动本人已登记的文本/代码对象，不能借资源 UUID 读取他人历史内容。

去重键包含隔离范围、稳定来源对象、来源内容身份和类型化范围；同文字出现在不同对象、版本或位置时是不同引用。引用按加入顺序持久保存。一次完成选择使用独立手势 token，失焦、重绘、滚动或无变化通知只更新几何位置，不重复添加；移除后被动通知不使其复活，新的明确选择仍可重新加入。手势 token、浮层坐标和打开/焦点状态属于临时呈现，不作为持久引用身份。

公开契约为后续组件保留可区分的类型化范围及可读摘要扩展方式，具有版本和严格校验；不以不透明任意 JSON/DOM 范围充当通用语义。本票仅实现普通文本与代码适配，未知组件范围显式不可定位/不受支持；不提前编造波形、图表、虚拟板或隔离页面已可引用的结果。

### 未同步代码与固定依据

选中内容不能只靠 `sourceText` 内存副本，也不能等到同步时重新读取“当前文件”。选择时由共同工作区取得同一编辑代际下的稳定对象、实际 `contentId`、原文及范围，校验与编辑器选择一致，再原子持久保留该依据和草稿变化；不一致时重新核对，不猜测新正文位置。

本机快照可以早于远端作品确认。例如选中 A 后立即把文件编辑为 B，引用仍指 A，即使 A 从未成为远端作品 head。建议在作品模块补充“不推进当前 head 的不可变引用依据登记”窄接口，复用所属对象授权、资源校验和冲突规则；若对象创建也未确认，先以原稳定创建/同步身份完成所属登记，再登记固定 A。依赖固定在选择时对象/内容，不等待持续变化的最新 B，也不为保留 A 把当前作品倒退。

该接口只接受已有或经原作品创建操作登记的本人对象及其实际类型；未知、跨主体/活动对象身份明确拒绝。相同内容身份改字节必须冲突；后端校验完整原文字节摘要、编码、范围及副本。注册自己的不可变作品依据不授予读取外部资源的能力。来源登记、资源 ready 和草稿接受可能分步完成，但未完成依赖不得返回已接受的完整草稿回执；每步可用原操作/上传身份查询或续接。

本机保留尚未同步的 A 是真实草稿保护，不能冒充服务端已验证来源。只有后端确认原依据及保留关系后才确认对应修订；断线时允许继续组织问题并自动恢复同步，不要求学生冻结或手动保存。该能力仍归现有作品与草稿 module，不建立通用任务队列或第二套待发引擎。

## 交互与生产接线

1. 在原课程活动中将授权目标/要求和可读 UTF-8 开放文本材料接入已登记普通文本来源；材料应能在页面内阅读/选择，不能用浏览器外下载链接冒充引用适配。不执行材料中的 HTML/脚本；PDF、图片、外部页面阅读及任意格式转换不在本票承诺中。
2. 在原可靠编辑器接入代码来源适配，使用稳定作品对象和原文映射；保持既有编辑模型附着、选择、查找/替换排除和中文输入法行为。
3. 输入区关闭时，有效选择只呈现“询问 Agent”；点击才展开并带入引用。输入区已打开时，新的有效完成选择直接加入引用。两条路径均不调用业务接收端或模型。
4. 草稿问题输入、引用添加/移除沿共同工作区自动持久化；收起再开保留内容，保持顺序，移除不改原文。来源注册表只登记获准的展示容器/编辑器，密码框、问题输入区、查找输入、任意页面片段及未授权材料均排除。
5. 发送入口明确不可用，并说明真实 Agent 尚未接入；Enter/表单提交和程序回调都不能绕过。不得把占位 `onSubmit` 成功、草稿保存回执或旧开发页的示例收据包装成发送成功。
6. 活动/空间切换和退出沿既有离开保护完成本机持久化；失败保留原内存和复制/导出入口，不强行导航。旧异步来源、回执和定位结果不得显示在新身份下；重新认证按原归属核实后恢复。

生产装配复用[设计系统](../../../DESIGN.md)的 token、图标、字体、间距、焦点及动效，不另建一套问题面板或课程分支。正常过程无保存按钮、冻结操作或常驻“保存中/已保存/待同步”状态；仅真实存储失败、授权问题、损坏和分歧给出必要异常。

## 来源变化、定位与当前权限

| 情形 | 读取与定位行为 |
| --- | --- |
| 原对象、原内容仍可用 | 通过登记适配器定位原范围，滚动后工具条/焦点可用 |
| 作品只重命名 | 按原对象定位；显示名称可提示当前名称，但原引用身份和副本不变 |
| 原对象内容前进 | 保留原文，标记来源已变化；可提供经授权的历史只读定位，不将新正文范围冒充原位置；未提供历史视图时明确无法定位当前来源 |
| 删除后同名新建 | 原对象仍是旧身份；保留历史副本，新对象不继承旧引用，不自动跳转同名路径 |
| 课程发布换版 | 继续按原发布和材料/字段读取；不改查 latest，也不重建同名来源 |
| 权限失效 | 新读取、同步、查询旧回执和定位均核验当前资格并拒绝未授权访问；原本机副本隔离保留，不能声称已远程擦除或挪到个人空间继续派发 |
| 缺失、损坏或不可达 | 区分缺失/损坏、权限和暂时故障；保留已可靠保存的原副本并准确说明定位不可用，不用空草稿覆盖历史 |

后端草稿与引用接口逐项检查活动归属、当前成员/课程资格、来源对象类型、固定版本与材料开放性。教师私有材料不出现在草稿响应、错误详情、直接资源读取或课程投影中；后端不能以“前端注册过”代替来源验证。缓存回执返回前也重新授权，不能重现已修复的状态操作重放绕过课程撤权问题。

课程来源核验由课程 owner 的公开只读/保留接口负责，学习数据 owner 消费结果；两者不共享可写 repository、SQL transaction 或直接跨 schema JOIN。同机合设不改变这个边界。外部授权/资源读取在所属短事务之外完成，事务内只提交本 owner 已核实的引用依据、草稿修订、资源引用与回执；返回前核验当前可读性，失联不能退化成授权成功。

## 持久化、竞争与历史保留

建议在现有学习数据 owner 内深化草稿 module，并扩展共同工作区的本机记录/候选分歧结构；保持既有作品记录可读，不重置或删除现有 IndexedDB。草稿头、不可变修订、同步请求、固定来源依据及保留关系通过真实 PostgreSQL 和 WP01 资源机制接入。原始大内容先持久写入并重读校验，再在所属短事务发布引用，不在事务中调用外部服务。

同一请求和输入摘要重试返回原结果，改输入拒绝；提交/上传未知查询原身份。旧回执只结清原草稿请求，不确认或清理后续问题、移除动作或引用集合。问题/引用变化与必要来源快照在本机同一事务确认后才宣称受到保护，未保护的内存仍可取出，自动重试不能覆盖它。

断网、配额失败、持续输入及确认乱序沿共同工作区契约处理；继承有界自动保护/同步原则，持续打字和连续选取也不能无限推迟保护。双标签或另一客户端从同一草稿基线产生分歧时，保留双方完整问题、引用顺序和来源依据，提供比较/明确选择或编辑合并；不能按时间戳、最后回包、文本拼接或自动引用并集静默胜出。草稿分歧不覆盖作品，作品竞争也不丢草稿。

活动、仍保留的草稿修订及其请求回执对引用副本和历史依据承担明确保留责任。移除当前引用不立即回收仍被旧修订使用的源内容；作品删除、课程换版或关闭活动也不提前回收。保留从源登记准备阶段开始，不能在跨 owner 结果未知时释放。课程版本沿已有课程保留规则，学习数据侧登记自身引用责任；后续若需释放策略另行明确，本票不新增自动删除历史或 GC 策略。

后续 #153 可按 `draftRevisionId` 读取/固定明确修订，并独立取得发送时当前作品依据；选中时历史 A 不被当前 B 替换。未来接收回执只能作用于其关联草稿修订；条件清理须比较修订身份，不能清空后来输入。此处只提供接口约束，不实现待发状态机、取消、真实派发或业务成功回执。

正式完整备份/独立恢复后，服务端已接收的问题、引用顺序/副本、历史作品/课程材料和原操作结果仍可读；缺资源保持隔离并报告，不重选来源或重发问题来补证据。新恢复命名空间不能自动消费旧浏览器待同步内容，重新核验主体、目标和原操作后才能接回；仅留浏览器的未同步草稿不在服务端备份保证中。混合部署与接管仍由 #154 验收，本票不能把首次持久化与自身恢复验证延期给 #154。
