# WP07：固定依据、课程工具与持久等待

需求与验收以 [#198：Agent 读取作品、调用课程工具并解释结果](https://github.com/paher-din/XunJie/issues/198) 为准；母票 [WP07](https://github.com/paher-din/XunJie/issues/196) 已确认生产接口、session log、真实存储与执行的测试边界。本文记录实现选择，不复制动态议题状态。ALU 专属适配属于 [#202](https://github.com/paher-din/XunJie/issues/202)。

## 模型与工具

同一 `ModelGateway` 的原生 segment 接收固定的工具定义。模型选择工具并返回原生 call ID 与参数；平台校验 schema、获准对象和版本，可靠保存命令后才调用宿主。模型、作品、材料和工具输出都不能登记新能力或修改权限。

基础工具为 `read_work`、`read_reference`、`read_material`、`read_result`、`execution_query`、`execution_stop`；活动有可执行组件时增加 `course_operation`。定义描述携带版本，实际 schema 保存于每次请求快照。课程操作从固定组件 manifest 与课程运行方案派生；Driver 不认识 ALU 信号、聚合算法或累加器输入。没有通用 shell、代码修改、动态发现、Skills/MCP 或 PDF 管线。

作品与引用只使用本次问题固定并获准的内容身份，开放材料来自原课程发布，已有结果来自所属执行记录。取证不得用后来同步的 head 替代。帮助策略进入系统指令，同时约束回答、公开过程、摘要与工具反馈；原件与有界模型反馈分别保留。

## 所有权与持久屏障

| 所有者 | 保存的事实 |
| --- | --- |
| 学习数据 / WP02 | 活动、不可变作品内容、固定引用、可靠问题动作 |
| 模型 / WP06 | 固定配置、实际协议请求、完整原生结果、原生工具配对及用量 |
| Agent / WP07 | Run、步骤计划和请求快照、原生结果关联、工具命令与派发许可、Wait、预算及 session log |
| 执行 / WP03 | 可信发起者和关联、固定输入与方案、原执行接收、查询、控制、停止和完整结果 |

模型步骤先保存稳定 attempt 身份与完整输入计划，再创建同一 Gateway attempt，保存可重读快照，取得派发许可后才外发。已保存的模型结果通过原 attempt 重读，不重新询问模型。

只有完整、可消费、已保存且可读取的原生结果产生工具意图。原生结果关联、步骤完成与全部工具待发项在 Agent owner 的同一事务提交；原生 call ID 与独立 command ID 均保留。执行点再次核对权限、版本、前置条件与取消。取得许可后丢回包，恢复只查询原命令；查无记录不能换身份或执行位置重跑。

## 等待、停止与并发

工具结果区分未派发、已接受、完成、业务失败与效果未知。长任务的接受回执先闭合原生工具调用，再保存独立 Wait；完成结果以关联原命令的新观察进入下一次原生请求。接受不表示实验完成。

Wait 保存 Run、步骤、命令摘要、原身份、消费状态、期限及下次核对时间。等待释放模型连接和 Run 的内存处理者，由每轮最多 20 项的确定性程序查询原执行；重启从相同记录恢复，重复结果只消费一次。到期暂停自动推进，保留原命令与结果核对依据。

停止首先关闭 Run 新派发，再停止该 Run 发起的原执行。尚未派发的调用以 `not-executed` 配对；已发生的结果保留。晚结果可追加到原记录，但不会复活终态 Run。学生独立发起的实验不属于 Agent 停止范围。

共享对象使用持久冲突范围串行；当前默认并行度为 1。浏览器计算仍使用 WP03 的真实 Worker/WASM 与持久 broker，首次领取在所属 owner 中固定浏览器身份。回包丢失、关页或重开不能换浏览器补跑。

本票工具循环默认每 Run 最多 16 个模型步骤、64 个工具命令、1 个并行工具，Wait 期限 24 小时；这些是宿主运行配置，不是学生表单。模型输出按保存的 `maxOutputTokens` 预留，以原 attempt 唯一结算；缺失用量保持 unknown 并保留占用。工具命令准入同事务扣留，组件的时间、内存和输出预算继续由 WP03 实际执行器约束。这里不改变 #197 的单次模型配置，也不把字符数冒充 token 计数。

## 验证位置

- 正式 HTTP → 可靠动作 → RunDriver → Gateway → 真实作品/组件 → PostgreSQL/资源，核对固定版本、原生配对、结果与快照。
- 同一公开边界注入结果关联前中断、丢回执、双推进者、乱序、停止及晚结果；受控 transport 只确定模型时序，工具必须真实读取、计算或推进状态。
- 复用正式活动对话、组件与结果定位，验证 Apple Silicon Mac 和 Windows 11 x64 桌面 Chrome 的引用、工具、等待、停止及重开。
- 迁移、维护、备份与隔离恢复验证步骤、Wait、命令、预算、请求与结果资源保留；只读重建不调用模型或执行工具。

实际通过项、失败与未执行项在本票交付记录中分别报告；工程、真实模型/工具、浏览器和教学效果不互相替代。
