# 运行中引导、排队与暂停续接

来源：[运行中引导、排队与暂停后继续](https://github.com/paher-din/XunJie/issues/200)、[持久 Agent 与学习对话](https://github.com/paher-din/XunJie/issues/196)。沿用既有 Agent、可靠动作、模型 Gateway、课程工具、学生提问与产品 UI；以下是本票实施选择，不扩展主动教学任务。

## 输入事实与顺序

个人忙碌输入偏好属于学习数据 owner，按 environment/space/principal 隔离，默认 steering。更新带预期版本和稳定请求身份，旧回执可查询。发送时固定本次方式及偏好版本/显式选择依据；后续设置变化不改写旧请求。旧版可靠动作字节原样保留，新方式使用带版本的可选扩展。

Agent owner 新增输入、不可变修订和控制回执。接收顺序沿 session log 分配，记录接收、纳入步骤、修订、移除、转引导、暂停与后继关系。浏览器的接受回执只表示收到，采用以步骤快照中的输入版本为准。输入及修订始终保留发送时的引用和作品，不能用当前版本补旧证据。

Agent 的持久写入使用同一 PostgreSQL owner 事务顺序屏障，覆盖接收、上下文固定、工具许可、明确回应、收尾与控制；外部模型/工具调用在事务外进行。该保守屏障只串行化短元数据事务，不能持有整条生成或实验。多进程仍由持久 lease/generation 决定唯一推进权。

steering 在下一次允许的步骤进入当前 Run，不重置预算、不取消或改写已发请求。上下文已固定但未获许可的旧工具按原 call ID 配对为因新输入未执行；已有有效许可的命令继续按原身份查询。收尾若先收到 steering，则保留原答复来源并继续当前 Run；已收尾才收到则建立后继。

queue 在整轮正常结束且需要结果的 Wait 已结清后 FIFO 建立后继 Run。失败、停止、预算或硬期限终止将未消费输入保留为可见暂停项，不自动连跑。学生明确选择待处理内容后才恢复可恢复的原 Run，或建立关联后继；未知效果先查询，不盲目重放。只有明确 queue 会在正常结束后自动推进。

## Wait 与修订

明确回应始终绕过普通 queue。steering 可按同一顺序取代尚未回应的问题，原卡保留“已暂缓”、旧入口关闭；晚回应保留未采用结果。queue 不解除 Wait。

长工具的接受、等待与最终结果分开保存。steering 可继续讨论，原操作继续跟踪；迟到结果保留原命令和作品来源，不覆盖新问题，也不释放仍在进行的真实物理调用占用。

编辑、移除、转引导携带输入预期版本，与消费在同一事务裁决。修订不可变；消费先发生则控制明确失败，浏览器保留待发文本。转引导追加新输入顺序，原事实保留。停止、继续与编辑等控制均保存原请求回执。

## 产品与验证边界

复用个人设置中的 Agent 交互区、活动输入区、原对话与暂停项；沿用根目录 DESIGN 的 token、控件与焦点规则。后台轮询不覆盖编辑、不抢焦点或阅读位置，中文输入提交依既有保护。显式状态分别显示收到、待处理、已纳入、已移除和暂停原因，不把协议身份暴露为学生操作。

按母票已确定的公开 HTTP/输入/运行/查询边界做 TDD，生产 owner、PostgreSQL 与资源保持真实；只在模型 transport/回执边界控制故障时点，工具仍执行实际操作。补真实三协议用途、Windows 桌面 Chrome 的普通 Web/完整产品入口与前后截图，工程、平台及教学效果分别报告。Mac 待验单独建票，由已有合格环境的人执行，不包含搭建 macOS。
