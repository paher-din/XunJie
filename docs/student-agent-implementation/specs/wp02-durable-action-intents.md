# WP02：固定依据与持久待发意图

对应 [#153](https://github.com/paher-din/XunJie/issues/153)，实施基线 `269d41a`。沿用[母规范](wp02-learning-space-and-reliable-workspace.md)已确认的公开工作区、真实 IndexedDB、HTTP、PostgreSQL/资源和桌面 Chrome 边界；Mac 与真实跨机执行集中 [#155](https://github.com/paher-din/XunJie/issues/155)。

## 实施范围

1. 同一次同步调用捕获问题、引用及其未同步来源、所需作品/类型化状态和已有证据引用。动作身份由调用者为一次明确动作提供；相同身份只允许相同输入，明确新动作可用新身份。一个 IndexedDB 事务保存完整动作及依据，事务完成前不得交付。
2. 共同工作区提供创建、查询、取消、恢复为独立草稿和真实回执接纳。远端动作单独登记自己的固定依据，不推进可编辑作品/草稿头，也不等待之后的编辑。学习数据 owner 保存固定内容、依赖确认、派发及接收事实；同步接收与业务接收分开。
3. 接收器是按稳定身份注册的窄接口：同身份幂等接受、可信查询及取消。派发前先持久写入派发事实；未知结果先查询原接收器，按契约同身份重试。取消先落地的未派发动作永不发送；已派发动作的取消必须核实接收器结果，接受后的事实不能伪装撤回。
4. 远端业务派发在真实学习入口和维护关闸/排空内执行，不另建后台 RunDriver。本机执行只交付已在本机可靠保留的固定输入及原身份，后续 WP03 接收器接入时不强制等待远端同步。本票不运行实验。
5. 学习数据迁移、资源保留及恢复校验覆盖固定动作与回执。浏览器队列按恢复命名空间/空间/主体/活动隔离；新命名空间不消费旧队列。显式取回只能保留原身份并重新核实原主体、目标与请求，不能复制为新业务效果。
6. 生产页面消费同一待发查询/取消/恢复呈现，复用现有设计 token。没有真实 Agent/教师接收器时发送明确不可用。可控接受、拒绝、丢回包与取消竞争接收器只在测试支持中存在，不进入正式分发。

## 验证切片

按一个公开行为失败 → 最小实现通过推进：固定输入登记与头部互不影响；同身份冲突及当前授权；真实接收回执/未知/取消竞争；浏览器原子保护与刷新恢复、持续新编辑、双标签和失败取回；维护与正式 CLI 备份恢复。工程全量检查按 implement 流程在末尾执行一次，失败如实记录；Windows 安装版 Chrome 与 Mac 工作分别登记，测试接收器不充当真实 Agent/教师验收。
