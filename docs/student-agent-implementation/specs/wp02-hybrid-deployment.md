# WP02 混合部署与业务恢复接管

对应 [#154](https://github.com/paher-din/XunJie/issues/154)，实施基线 `e36b1bfb97693713c0dd777bbb054b8fe0659a18`。沿用 [WP02 母规范](wp02-learning-space-and-reliable-workspace.md) 已确认的公开 API、产品 CLI、真实 PostgreSQL 与桌面 Chrome 测试边界；Mac 执行归 [#155](https://github.com/paher-din/XunJie/issues/155)。

## 实施方案

- 个人与学校共享组合沿用当前装配；混合组合由安装客户端持有学习数据 owner，学校持有身份/成员/课程 owner。同一学习数据 owner 可以按真实学校主体隔离记录。
- 部署维护者在创建成员时固定目标环境、学习数据 service ID 与绑定版本，再把已认证的学校连接和 WP01 运行连接关联到本机 owner。绑定仅允许首次登记或同值核对，不通过改 URL 迁移既有活动。
- 本机主动发起 WP01 认证连接，消费学校登记的窄领域能力；运行授权和学校主体授权分别核验。学校不需要访问学生私网端口，学校账号库不复制到本机。课程协调继续使用 prepare/confirm/authorize 的原公开接口和原请求身份。
- 学校失联、连接撤销、成员/课程资格失效、服务身份或版本不符均停止原绑定操作，不转存学校共享或个人作品。
- 两个业务 owner 仍是必要维护参与者；本机学校出站连接进入 WP01 receiver 清单并参与源失权核验。完整备份只证明本安装持有的 owner；跨安装材料和学习数据要分别在明确关闭边界备份，不伪称跨机器分布式原子快照。
- 恢复保留业务对象、内容与请求身份，换安装/凭据/客户端命名空间。目标默认隔离，源退休并完成必要 receiver fencing 后才开放；学校连接重新授权并显式核对原绑定后才可读取恢复作品。浏览器未同步内容不在产品备份中，旧队列不自动重放。

## 验证安排与当前限制

逐个纵向切片执行红/绿测试：部署管理和混合课程/作品公开 HTTP 路径；身份、版本、断连与撤销；真实课程/作品并发备份、资源缺项、独立恢复及源拒绝；正式 CLI 和独立产品包；Windows Chrome 的个人、学校和跨机路径。最后运行工程检查、一次完整测试和 Standards/Spec 两轴审查。
