# #174 会话控制、检查点与返回恢复：实施方案

日期：2026-11-03。依据 [#174](https://github.com/paher-din/XunJie/issues/174) 和 [WP03 母规范](wp03-course-components-and-execution.md) §10、§14。负责人已授权明确方案后实施；Mac 验收暂缓，不将 Windows 结果记为双平台通过。开发分支 `codex/issue-174-session-recovery`，基线 `upstream/wp03@e5b3743`。

实现与阶段验证见[交付记录](../wp03-session-recovery.md)。本票追加 owner 迁移 8 和原 IndexedDB 的 v6 待确认请求分区；执行事实仍只由原执行 owner 裁定，不自动重放恢复前的未知操作。

Mac 专项验收独立跟踪于 [#187](https://github.com/paher-din/XunJie/issues/187)，暂不指派任何人。审查后恢复选择改用独立分页检查点目录，不受最近会话窗口或观察投影长度影响。

## 目标与边界

沿 #173 的执行所有者和真实受监督子进程，补齐声明式 pause/resume/step/reset/checkpoint。继续使用 execution.control；每项控制有稳定 controlId、参数摘要、预期 appliedSeq。暂停和恢复不重建进程，复位不更换会话，检查点恢复明确建立新请求与实例，并保留原会话及检查点关系。既有问题草稿与当前作品不因恢复而改写。

已有原生适配 v1 与组件 v1 保留；新版适配和组件声明支持的控制、检查点格式与跨视图生命周期，旧组件不显示未声明能力。样例仍是实际进程内的四态累加器；单步在暂停状态只执行一次显式输入，复位清空模拟内部数据但公共操作序号保持单调。

## 实施顺序

1. 扩展公共契约、组件能力声明和有界检查点/恢复关系。旧动作和清单不增加默认值，保持原摘要可核验。
2. 执行适配支持真实模式切换、幂等单步、复位与序列化检查点；恢复以受校验的快照初始化新进程，不回放操作历史。
3. 学习数据 owner 追加迁移，登记检查点、控制类型及恢复关系。检查点绑定原会话/操作位置、适配版本、固定组件/配置/运行环境，资源先保存并重读核验，再事务关联操作与保留关系。保存确认丢失查询原操作，不重新采样。
4. 新 execution.submit 的 resumeFromCheckpoint 从 owner 读取并验证资源、权限、原会话、组件与环境兼容性；原会话终态不变。缺失、损坏、失权和不兼容分别拒绝。
5. 现有控制器承担返回查询、心跳与晚响应单调合并。现有会话面板仅展示已声明控制，区分仍存活会话的继续和新恢复实例，保留显式输入并说明不可恢复原因。沿 DESIGN.md token 和现有布局，提供实际前后截图。
6. 资源保留、备份恢复验证和维护排空随 owner 接入。未知操作不盲目重放；关闭视图/网页不暗中停止声明可继续的会话；活动关闭和节点结束按 owner 策略停止并保留事实，未确认真实进程退出不宣布安全排空。

## 验证

- 工程：公共导出浏览器边界、类型/构建、旧动作摘要与旧清单回归。
- 真实进程：同实例暂停/继续、单步只推进一次、重放不重复、错序和控制竞争、复位、检查点后下一步与恢复实例下一步一致。
- PostgreSQL/资源：检查点保存确认丢失、资源损坏/缺失、权限/版本不兼容、重启与恢复验证、维护边界。
- Windows 桌面 Chrome：原工作区控制、返回/刷新先查询、保留输入与问题草稿、原引用/编辑/停止回归、深浅色及窄桌面，实际 UI 前后证据。
- Mac 暂缓；新远端能力及真实跨机组合由相应接入票补验。本票不冒充任意内存恢复，不自动重放未知操作，不调用模型；教学效果另列未评估。
