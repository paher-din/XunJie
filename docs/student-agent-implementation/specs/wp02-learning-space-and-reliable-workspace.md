# WP02：学习空间与可靠工作区

日期：2026-10-30（Asia/Shanghai）。对应 [WP02：学习空间与可靠工作区](https://github.com/paher-din/XunJie/issues/148)，测试边界已由负责人确认。前置工作包为 [WP01：产品运行与数据底座](https://github.com/paher-din/XunJie/issues/142)；本规范承接已定学习空间、工作区交互、状态归属和直接重建决议。

本轮明确修正：**编辑后系统自动持续保存，无需学生手动操作；界面不提供保存按钮，也不显示“保存中／已保存／待同步”等常态保存状态。** 本机持久化、服务端确认和待同步状态仍是可靠性契约，用于自动恢复与故障处理，不作为日常操作步骤或常驻界面。实际保存失败且需要学生处理时才给出异常反馈。

## Problem Statement

学生需要在同一个客户端进入自己的个人或学校学习空间，围绕课程任务或自主学习目标持续编辑作品。现在的工作区依赖课程分配和手动确认、冻结流程，本机草稿、远端确认、提问引用和恢复分散在不同入口中；个人与学校身份、无课程活动和新 PostgreSQL 底座尚未形成可使用的完整链路。

学生不应先理解保存版本、同步顺序或服务位置才能开始学习。编辑应自然保留；刷新、短暂断线、返回活动或切换空间不应把作品、问题和引用丢失、混用或替换。系统还必须能够分辨本机已经保护的内容、服务端已经收到的内容，以及某次明确请求实际绑定的内容，不能因一次旧确认、迟到响应或重试把后续修改误当作已处理。

## Solution

交付可实际使用的学习空间入口和可靠工作区。学生可以进入个人空间，或通过学校身份进入学校空间；选择已发布课程任务，或不建课程直接建立自主学习活动。工作区提供可编辑的文本与代码作品、课程开放材料、问题草稿和固定引用，修改自动持久化并持续同步，正常使用过程保持安静。

同一浏览器返回时恢复已经可靠保留的作品与草稿；尚未同步的内容自动继续同步，迟到确认不覆盖新输入。明确交给接收方的请求由共同工作区能力固定当时依据、保存待发意图并跟踪真实回执，后续编辑不改变该次请求。WP02 完成这套通用能力及真实存储接入；实际实验、Agent 对话接收和教师交付分别由 WP03、WP07、WP12 接入并验收。

## User Stories

1. 作为学生，我希望在同一个客户端切换个人和学校学习空间，以便分别管理自主学习与学校课程。
2. 作为学生，我希望个人空间可以使用本机身份独立开始，以便不必先注册循阶中央账号或加入学校。
3. 作为学校学生，我希望通过学校提供的入口和认证进入获准空间，以便获得属于自己的课程与作品。
4. 作为学生，我希望切换空间、退出登录或换用另一个账号后，原空间的作品、问题和待发内容不会出现在新身份下，以便保持清楚的数据归属。
5. 作为学校学生，我希望连接过期或权限变化时保留尚未同步的本机内容，并明确告知需要处理的访问问题，以便不会误发到个人空间或其他成员名下。
6. 作为学生，我希望只看到获准的课程、任务和学生材料，以便按实际开放的要求开始学习。
7. 作为学生，我希望开始活动后继续使用当时绑定的课程发布版本，以便教师后续更新课程不会突然改变正在完成的任务。
8. 作为个人空间用户，我希望可以从自己的目标、问题或选定资料建立活动，以便无需先创建虚构的课程和作业。
9. 作为学生，我希望能找到并重新进入已有活动，以便跨多次使用继续学习，而不是每次重新开始。
10. 作为学生，我希望工作区先呈现目标、材料与当前作品，以便知道要做什么、正在修改什么。
11. 作为学生，我希望在工作区创建、编辑、重命名和删除自己的文本或代码文件，以便完成实际作品。
12. 作为学生，我希望文件重命名后仍是原对象，删除后新建同名文件也是另一个对象，以便历史引用不会指向错误内容。
13. 作为学生，我希望每次修改即时显示并由系统自动持续保存，以便专注编辑，不需要手动保存或冻结。
14. 作为学生，我希望正常编辑时没有保存按钮和常驻保存状态，以便界面只保留与当前学习操作有关的信息。
15. 作为学生，我希望持续输入时也能不断得到本机保护和后台同步，以便系统不必等我停下来才开始保存。
16. 作为学生，我希望短暂断网时继续编辑已打开、资源可用的作品，恢复连接后自动同步，以便不会因为网络波动打断思路。
17. 作为学生，我希望旧保存确认不会覆盖新修改，以便等待网络时继续输入仍然安全。
18. 作为学生，我希望保存回包丢失后系统能查询并续传原操作，以便不会生成重复作品或多份相同动作。
19. 作为学生，我希望本机存储不可用或配额不足时得到明确的异常提示，并能取出仍在编辑器中的内容，以便知道哪些内容尚未获得可靠保护。
20. 作为学生，我希望同一活动在多个标签页打开时不会互相静默覆盖，以便旧页面不能丢弃较新的作品。
21. 作为学生，我希望选中课程文字或代码后就地加入提问引用，以便准确表达我关注的内容。
22. 作为学生，我希望选择、添加或移除引用不会自动发送问题，以便先组织自己的想法。
23. 作为学生，我希望多处引用保持加入顺序，重复通知不增加副本，移除后不会因焦点变化重新出现，以便控制问题的范围。
24. 作为学生，我希望修改或删除来源之后仍能看到选中时的引用副本，以便保留原来提出问题的依据。
25. 作为学生，我希望来源已变化或无法定位时得到准确说明，以便不会误认为引用对应当前同名文件或新版材料。
26. 作为学生，我希望问题草稿和引用在收起、切换活动及同浏览器返回后恢复，以便中途离开不会丢失思路。
27. 作为学生，我希望明确发送时使用点击那一刻的问题、引用和相关作品，以便之后继续编辑不会改变这次请求。
28. 作为学生，我希望待发动作只等待自己的固定内容同步，以便持续修改其他内容不会让它无限等待。
29. 作为学生，我希望网络和必要同步恢复后待发动作自动继续，以便不用重复点击或重新填写。
30. 作为学生，我希望可以取消尚未被接受的待发动作，返回后它也不会复活，以便保留对发送意图的控制。
31. 作为学生，我希望取消或失败的问题可以查看、恢复为草稿，同时不覆盖新写的问题，以便继续调整自己的想法。
32. 作为学生，我希望结果未知时系统核对原请求，而明确再次发起同内容问题时可以形成新请求，以便网络重试与我的新动作被正确区分。
33. 作为学生，我希望刷新和重开只恢复已保留的状态，不自动重跑实验或重新发送已经取消的动作，以便返回本身不会产生新的效果。
34. 作为学生，我希望暂时无法连接原服务时保留原活动和归属，以便系统不会静默换到另一个服务建立第二份作品。
35. 作为学校管理者，我希望能建立学校成员、课程访问关系及可撤销的客户端授权，以便学校空间可以通过真实身份使用，而非依赖测试账号注入。
36. 作为教师，我希望学生读取的是固定发布版本中的开放材料，以便私有材料和未发布草稿不会被一并下发。
37. 作为部署维护者，我希望空间、成员和学习数据服务之间有明确绑定，以便学校服务与学生本机服务可以组合，学生无需选择存储节点。
38. 作为部署维护者，我希望新增的空间与学习数据被纳入产品备份和恢复，以便恢复后仍能读取原活动、作品、固定内容和已接收回执。
39. 作为后续能力的接入开发者，我希望编辑器、课程组件、提问和提交共用同一工作区接口，以便不用各自实现保存顺序、快照和恢复。
40. 作为接入开发者，我希望能够区分本机持久化、远端同步与业务接收，以便真实实验、Agent 和教师流程不会误用另一层的成功状态。

## Implementation Decisions

以下把已定产品要求转为本包的工程契约，不表示负责人逐项指定了内部方法、表名或认证供应商。

### 1. 学习空间、主体与真实授权

学习空间表示个人或学校的归属范围，与安装环境、服务部署位置和活动工作区分开。同一客户端切换空间，不自动合并账号、作品、个人记录或模型配置；一个学习数据服务可承载多个空间，但每次访问仍按空间和成员校验。

个人空间由其身份服务建立稳定本机主体，首次使用不依赖中央账号。学校空间由学校身份服务拥有账号与成员关系，至少交付一条真实学校账号登录路径；管理者通过受支持的管理入口建立成员、授予课程访问和撤销资格，不直接编辑数据库或依赖测试夹具。已有统一登录可以通过身份接入边界扩展，本包不承诺对接所有学校 SSO。

学校网页和已安装客户端共用学校身份事实。本机组件从学校入口或邀请开始认证，认证在学校页面完成，再获得绑定实际学校主体、空间及能力范围的可撤销连接凭据；不把学校账号库复制到个人实例。产品运行连接授权承接传输身份，业务模块继续核验成员与资源权限，不能以连接有效代替课程或作品权限。

退出登录、成员资格撤销及连接授权撤销各自生效。服务端拒绝后续未授权读写；客户端停止该身份下的新同步和派发，其他身份不能读取其草稿或恢复项。已经存在的本机副本不被冒充为已从设备远程删除。尚未同步的内容保留在原隔离范围，恢复授权后再按原归属核实；不得转存为另一空间的作品。

### 2. 空间与课程、学习数据的事实归属

后端分别形成空间/课程 module 与学习数据 module。前者拥有空间、主体映射、成员、课程资格、任务、发布记录及成员级服务绑定；后者拥有活动、作品、不可变内容、固定引用和已接收的恢复状态。浏览器可靠工作区 module 拥有本机编辑、持久化、待同步和待发协调。各模块的公开接口说明身份、版本、确认时点、错误和恢复方式。

宿主负责配置和装配，模块通过领域接口协作。两个 owner 使用 WP01 提供的 PostgreSQL、资源和维护能力，分别登记自己的 schema 迁移、引用和约束；不向其他 owner 暴露通用 SQL transaction 或可写 repository，同机合设也不跨 owner 拼接事务。

空间与成员的服务绑定记录目标环境、服务身份和配置版本。创建活动时解析并固定相关绑定；普通连接重试和空间切换不重选事实所有者。变更既有活动的数据服务须走明确迁移与接管，不能只改 URL 后允许两边继续写。发布内容读取、活动建立和权限判断通过可重试、可查询的领域操作完成，跨 owner 失败不能留下对外已确认却无法读取的活动。

### 3. 课程基础记录与可无课程的活动

课程、项目任务和不可变发布版本分别有稳定身份。发布版本固定学生目标、要求、开放材料、起始作品与后续能力需要的版本引用；学习活动记录其实际绑定，不读取“最新课程”冒充原来版本。新增发布版本不修改已开始的活动。

本包提供真实的发布记录登记、校验、读取和访问投影边界，以及可供维护者或课程提供者使用的受支持导入/管理入口。生产课程入口不得依赖后端测试夹具。完整教师设计、组件装配、预览与发布交互归 WP10；本包不借基础记录建设另一套教师创作产品。

学生读取材料时由所属服务执行权限投影，私有测试、教师材料和未发布草稿不下发后再由前端隐藏。有效成员读取既有活动仍按所绑定版本；成员资格失效与课程内容更新分别处理，不能用固定旧版本绕过当前访问资格。

个人自主学习活动允许没有课程、任务和发布版本，只需所属空间、本人主体、目标或起始问题，以及必要资料引用；不创建占位课程、Assignment 或虚构教师。课程活动和自主活动共用作品与恢复模型。本包支持建立、列出及重开活动；学习目标推理、Agent 回复和连续教学判断由后续包实现。

### 4. 作品对象、不可变内容与恢复状态

工作区对象身份与显示名称、路径分离。文本、代码和资源对象都以稳定对象身份关联所属空间、主体与活动；每次已固定内容有不可变身份及内容。重命名保留对象身份，删除后同名新建得到新身份；被引用的历史内容不随当前对象删除而失去保留责任。

本包交付实际可用的文本/代码文件编辑和文件管理，以及类型化资源引用、可恢复状态的读写边界。后续组件通过这套边界保存其状态，不建立另一个“当前作品”仓库；波形、图表、虚拟板、报告等具体交互由对应工作包实现。本包不预建动态组件宿主或强迫所有内容转换成代码文件。

需要一起确认的对象变化、请求身份、内容引用和接收回执在所属短事务中提交。大资源先经 WP01 资源接口持久写入、重读校验，再发布引用；上传未知查询原上传身份，不能为补资源重跑产生该内容的外部动作。活动、固定引用及未结请求持有明确保留责任，旧内容不会因为当前作品前进就被回收。

### 5. 自动持久化、持续同步与安静界面

编辑即时反映到当前作品，系统自动写入本机 IndexedDB 并持续同步到绑定的学习数据服务。调用者提交变化后，由共同工作区接口处理保存、重试和确认；页面、编辑器和后续动作入口不再各自拼接保存步骤。常规编辑没有手动保存、确认作品或冻结快照的前置操作。

本机写入和网络传输可以合并，但必须各有明确的最大等待窗口；持续输入也要定期提交，不能不断重置防抖计时而永远不保存。实现时固定可测的窗口，验证持续输入期间实际产生持久记录与同步接收，不把每次按键都发 HTTP 当作实时保存的必要条件。已确认内容不得依赖关闭页面时最后一次异步写入才能恢复。

本机事务成功后才确认该内容受到本机保护；服务端接收回执只确认对应操作与内容身份。较早回执可归档和清理对应待同步项，但不能确认、覆盖或删除更新的编辑。网络回包丢失按原请求身份查询；重复同步不新建作品，同一请求身份不能换内容复用。服务重启、连接恢复和错误重试使用同一规则。

**常态界面不展示保存按钮，也不展示“保存中／已保存／本机已保存／待同步”等状态。** 短暂断网且当前编辑仍受可靠本机保护时后台继续处理，不把内部同步过程变成学生必须关注的信息。实际存储失败、未解决冲突或访问失效影响当前操作时，才在相关位置反馈问题和可采取的动作；不堆叠工程标签。详细确认记录保留在按需查看的诊断中。

本机持久化失败时不谎报成功；仍保有的编辑内容可复制或导出，系统自动恢复可恢复的写入，但不在学生不知情时丢弃未保护内容。新的不可恢复副作用不能越过“意图及依据已可靠保留”的前提。该异常处理不引入日常手动保存流程。

### 6. 竞争、冲突与空间切换

每次可变状态更新携带所依据的版本和操作身份，所属服务拒绝过期基线覆盖；浏览器本机记录也通过实际事务保护。至少覆盖同浏览器双标签页、旧页面恢复和跨连接迟到写入。发现真正分歧时保留本机与已接收内容，提供比较及明确选择/合并入口；不按回包先后或本机时钟静默胜出。本包不承诺多人实时协作编辑。

切换空间、活动或登录主体时先落实当前可保存的本机状态，再切换呈现和订阅；若本机写入失败，必须保留尚在内存中的内容并反馈异常，不以导航完成代替可靠保存。旧请求、回执和缓存继续属于原范围，不能应用到当前活动。仍获授权的原请求可按自己的绑定完成，但不得借新空间凭据派发或把结果显示到新空间。

浏览器存储以产品提供的客户端命名空间、空间、主体和活动隔离。新产品不自动打开、迁移或消费旧演示版 IndexedDB、outbox、SQLite 或执行账本；保留旧原件，所需资料另行显式提取。

### 7. 问题草稿与固定引用

复用现有普通文本、代码选区与引用呈现能力，将问题、引用顺序及副本接入真实工作区持久化。对话关闭时选择内容后出现“询问 Agent”，点击才展开输入区并加入引用；对话打开时有效选择直接进入引用区。选择、添加和移除只修改草稿，不发起业务接收或模型调用。

引用记录稳定来源对象、来源内容身份、类型化范围、选中时副本及可用的定位能力；名称和路径只是显示信息。重复通知去重，移除后不因失焦复活，多处引用保持顺序。来源变动后保留原副本并指出变化；无法定位时不猜测另一个同名对象。

问题草稿与引用随活动恢复，收起输入区不删除它们。发送时区分选中时的引用和发送时的当前作品。后续非文本组件可贡献类型化范围及可读摘要，本包建立可消费契约，不伪装已经交付波形、图表或隔离页面的引用适配。

### 8. 固定依据与待发意图

可靠工作区对调用方提供创建、查询、取消待发意图及接纳回执的共同接口。一次明确动作先固定当时问题、引用、必要作品/状态与已有证据引用，形成不可变依赖清单和稳定请求身份；本机在一个可恢复边界中保存意图与依据，之后才允许派发。固定动作不得读取一半旧内容、一半后续编辑。

待发意图只等待自己的依赖得到相应确认，不追随最新工作区；其与新编辑的同步不能互相饥饿。网络、授权和必要依赖恢复后自动继续，恢复不要求学生再次点发送。发送到远端只等待本次所需内容；后续本机执行器可在意图和输入已本机持久化后直接执行，不能因不必要的云端同步被阻塞，具体执行由 WP03 接入。

状态至少能区分尚未可靠保留、等待依赖、可派发、已派发待核实、已接收、已取消和失败。业务回执必须来自对应接收方并绑定请求与内容；工作区同步成功不产生 Agent 或教师接收回执。超时或断线不能当作未接收，先按原请求查询，重试沿用原身份；学生明确开始的新动作可使用新身份，即使内容相同。

取消与派发必须协调：取消先可靠落地则不再派发，刷新和重连也不复活；已派发且接收结果未知时先核实或请求接收方取消，不直接宣称撤回成功。接收方已接受的请求不承诺撤回。取消和失败内容可作为独立项查看、恢复或另建草稿，不覆盖后来输入。

本包交付可由 WP03/07/12 直接消费的意图能力，不建立通用后台运行引擎。工程测试使用可控制的接收方验证确认、未知和取消竞争；该接收方仅存在于测试。正式界面可组织和恢复问题草稿，未接入真实 Agent 或教师接收能力时相应发送操作明确不可用，不显示假的回答、教师收据或“发送成功”。真实业务接收与后续处理由所属包完成。

### 9. 同浏览器返回与恢复

刷新、关闭后重开或短暂断线后，从已确认的 IndexedDB 状态及所属服务读取作品、活动定位、问题草稿、引用和未结意图。核对本机版本、服务端已接收版本及未知请求后再继续同步；旧服务响应不覆盖当前页面输入。缺失资源、权限不足、存储损坏与服务不可达分别处理，不统一当作空工作区覆盖原数据。

恢复不等于重新执行：不自动运行实验、不重发已取消动作，也不让旧视图连接写入新实例。后续执行、Agent 及教学动作按自己的原身份查询和复核，工作区仅恢复其已保存状态与来源。浏览器可用内容的恢复范围不等于完整离线首次启动；另一设备也不能取得只保存在这台浏览器的未同步内容。

### 10. 产品运行、维护与真实部署接入

将本包的生产 Web 入口、空间/课程和学习数据模块装配到 WP01 的产品运行组合，而非只提供开发验收页面。安装包启动后能进入真实学习空间和工作区；学校网页模式不要求学生安装数据库。准备、初始化和启动所需模块与资源纳入正常构建及分发，不导入测试宿主或样例数据库初始化逻辑。

交付个人本机组合、学校共享组合，以及至少一种真实跨机混合组合：学校空间/身份服务与本人本机学习数据服务分开，通过成员绑定和获准连接完成课程读取、作品写入与重开。学校服务不直接访问学生私网端口，也不把自己的 localhost 当成学生设备。失联保持原绑定；本包不依赖尚未交付的 Agent、模型或执行服务宣称 ready。

两个业务 owner 随实现登记迁移、维护参与者、完整备份 owner 和恢复校验。维护前停止新接收及派发并排空到可确认边界；恢复时校验成员/课程、活动/作品、固定内容、资源和回执，再按 WP01 接管规则开放，源旧实例不能继续写入。

产品备份覆盖服务端已经接收的业务记录和资源，不包含仅留在浏览器的未同步内容。恢复建立新的客户端命名空间后不得自动消费旧 namespace 的待发队列；保留旧本机内容，只有重新核实原主体、目标与请求结果后才能显式接回。已接受记录和请求身份保持不变，不能通过新建动作掩盖恢复前的未知结果。本包验收新业务 owner 的实际备份还原，不重复宣称 WP01 所有引擎升级和安装矩阵都已重新运行。

### 11. 结构改造与 UI 接入

可靠工作区作为 Web 内部深模块统一编辑、持久化、同步、固定引用和待发协调；现有页面通过其公开接口消费状态和操作。后端空间/课程与学习数据保留独立职责，公开 wire 契约按事实 owner 定义，不能从数据库或 runner 实现反推，也不把 Node 专用依赖带入浏览器。

随本包一起替换新工作区涉及的旧手动确认/冻结流程、课程必填初始化和页面级保存编排，清除已被替代的接线及实现细节测试。尚未被新能力替换的执行、Agent、教师等路径继续按所属工作包处理，不为“统一重构”把 WP02 的必要调用者接线延期，也不在本包重写全部旧业务。

遵循当前设计系统并复用 token、编辑器、导航和选区组件。工作区围绕目标、材料与作品组织；不固定所有课程必须采用三个面板。技术身份和内部确认状态进入诊断；影响操作的异常才在相应位置呈现。新增入口保持键盘操作、中文输入法和已有焦点行为，发送期间的新草稿不被旧回执清空。

## Testing Decisions

### 主要测试边界

以 **真实桌面 Chrome 工作区操作 → 可靠工作区公开接口 → 真实 IndexedDB、业务 API 与原生 PostgreSQL/资源 → 刷新或服务重启后的可见结果** 为主边界。空间登录、活动建立、文件编辑、自动持久化、引用与重开沿同一条用户路径验收。断言作品原文、归属、固定依据、冲突结果和实际回执，不断言组件 state、私有方法、SQL 调用次数或内部文件结构。

难以从浏览器稳定控制的竞争和故障，补充在**同一个工作区公开接口及其真实服务接收边界**注入网络丢包、乱序、存储失败及接收方时序。真实 IndexedDB、PostgreSQL 和资源机制保留；仅尚未交付的 Agent/教师接收端使用明确的可控测试接收方。该补充用于证明工作区契约，不替代后续包的真实业务接收验收，也不另造一套只供测试使用的工作区实现。

### 必须覆盖的行为

| 范围 | 通过依据 |
| --- | --- |
| 空间与身份隔离 | 真实个人入口及学校账号登录、同客户端切换；A/B 学生、个人/学校、两个环境之间不能串读串写；伪造对象/内容/资源身份仍受后端权限检查。 |
| 授权生命周期 | 退出、会话过期、成员/课程资格撤销、连接撤销后拒绝新操作；待同步内容保留原范围，重新认证不转移归属；旧异步结果不出现在新身份中。 |
| 课程基础记录 | 真实登记并读取固定发布版本，学生拿不到私有材料；教师新增发布后旧活动仍绑定旧版，新的活动按入口选定的发布记录建立。 |
| 无课程活动 | 不创建虚构课程即可建立、编辑、列出并重开活动；目标与资料保留，无需配置模型、执行节点或教学框架。 |
| 作品与稳定身份 | 文本/代码多文件创建、重命名、删除和同名重建；中文、换行及约定编码准确往返；旧引用和内容身份不被新对象继承。 |
| 自动保存与持续输入 | 从实际编辑器连续输入，观察本机持久记录和服务端接收在约定最大窗口内推进；无手动保存按钮或常态保存状态，刷新后得到已保留内容。 |
| 迟到与丢失确认 | A 内容发出后继续编辑 B，A 的回执不覆盖/确认 B；提交已成功而回包丢失时查原请求并得到原结果，不重复产生业务记录。 |
| 断线与本机失败 | 断网时继续编辑，重开后保留已本机确认的内容，联网自动续传；真实浏览器存储拒绝/配额故障或可控事务失败时不声称已保护，保留可取出的内存内容。 |
| 并发冲突 | 两标签页或两客户端基于相同旧版本竞争，过期写入不能静默覆盖；冲突时双方内容保留并能经公开入口处理，不把冲突丢弃当同步完成。 |
| 固定引用与草稿 | 真实文本/代码选区、重复通知、移除后不复活、多引用顺序、来源变动/删除/同名重建；关闭、刷新和活动切换后草稿及原副本可恢复。 |
| 固定请求与有限等待 | 点击时固定问题和依赖，之后不断编辑仍能完成原依赖同步；接收方只收到该清单；重复点击/重试沿操作身份判断，明确新动作可获得新身份。 |
| 取消与未知结果 | 保存意图后关闭、取消后刷新、取消与派发竞争、已接收但回包丢失；取消成功不复活，未知先查询，已接受不虚假承诺撤回，新草稿不被旧动作清空。 |
| 真实部署 | 个人本机、学校共享和学校身份/本人本机学习数据的真实跨机混合组合，验证生产模块、成员绑定及连接撤销；学校网页不依赖学生本机数据库。 |
| 业务维护与恢复 | 使用两个实际业务 owner 完成关闭、备份、独立目标还原和接管；原活动/版本/资源/回执可读，旧实例和旧浏览器命名空间不能自动恢复写入或派发。 |
| 生产接入与回归 | 正式产品入口使用共同工作区实现；生产依赖无测试夹具；受影响的登录、文件管理、编辑器、选区和导航回归通过；未接入接收方不会出现虚假业务成功。 |

### 平台、已有先例与证据

- 浏览器只要求桌面 Chrome，覆盖 Windows 11 x64 和 Apple Silicon Mac，以及本包涉及的本机、学校与真实跨机连接路径；记录实际版本。学校服务沿用 WP01 已支持的组合。
- 复用现有真实浏览器保存恢复用例的多文件原文、刷新、新草稿保留和丢 ACK 验证方法；它目前使用的旧 SQLite 后端须替换为本包真实 PostgreSQL 模块，旧成功不能作为新链路通过证据。
- 复用现有服务端 HTTP 集成与访问测试中按身份拒绝他人作品、屏蔽私有材料、成员撤销、版本冲突和重复回执的先例；保留外部行为，调整旧课程必填与手动确认假设。
- 复用选区引用的真实文本/代码、中文输入法、键盘和发送期间继续编辑案例，将开发页内存态扩展为生产接线与真实持久恢复；不把开发页成功等同于正式工作区完成。
- WP01 已有真实事务、资源发布/回收、维护和独立恢复测试。本包通过新业务公开入口验证接入，不机械复制底座全量测试，也不用内存库替代 PostgreSQL 竞争证明。
- 运行相关工程类型检查、构建、公共契约及文档检查与受影响回归；按票完成相称验证，新变化、失败或未解疑点才扩大或重跑。工作包交付包含与 WP01 的真实集成及自身完整验收，不另设只有全量验收的收尾票。

工程测试、Chrome 浏览器验收和教学效果分别报告。浏览器路由 mock、故障接收方、静态检查及跳过项均需说明边界；WP02 不产生学习理解或教学效果已提升的结论。本规范编写阶段不宣称上述产品验收已经执行。

## Out of Scope

- 真实课程组件动态加载、执行器/节点调度、有限作业与持续会话、ALU 或 Flights 的实际实验与完整课程资料交付，分别归 WP03–05。
- 模型连接、真实 Agent 接收、RunDriver、steering/queue、上下文、Skills/MCP/Plugin、生成教学内容，分别归 WP06–09。本包的待发接口不成为第二个 Agent 运行引擎。
- 完整教师课程设计与发布界面、连续引导、证据推断/画像、教师进展摘要、正式作品提交、审阅及反馈，分别归 WP10–12；基础发布记录和固定依据不冒充这些业务已完成。
- 学生手动保存/冻结、常驻保存状态、多主数据库、跨空间自动合并、中央账号平台、通用数据联邦、所有学校 SSO，以及多人实时协同编辑。
- 完整离线首次启动、浏览器缓存永不被清理、未同步内容跨设备恢复、退出学校后的通用数据迁移政策或远程擦除设备副本。
- 旧开发数据库、旧 DTO/API、旧 IndexedDB/outbox、旧聊天或运行的自动兼容迁移；旧原件保留和按需显式提取继续有效。
- `xj-dev` 新基线与调试包适配、Phoenix 和 Agent 评估，以及整轮重构总验收。
