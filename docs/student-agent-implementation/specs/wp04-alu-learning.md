# WP04 #194：预测、比较、解释与真实波形引用

需求与验收以 [#194](https://github.com/paher-din/XunJie/issues/194) 为准。前置是已交付的 [#192](wp04-alu-edit-run.md)、[#193](wp04-alu-board-check.md) 及 [#211 验收](../wp04-211-acceptance.md)；本票沿用现有 ALU 工具、虚拟板、作品编辑器和问题草稿，不增加平行工作区或执行链。

## 学生行为

新用例将输入切到预测编辑：可以选择进位 / 边界、操作区别或其他目的，填写或留空预测 F/Cout、理由及获得帮助的自报。输入仍由原开关和数值编辑器修改，编辑候选不自动执行。候选期间，板卡输出、旧比较、历史执行和全量检查报告均不展示。

「运行并比较」固定点击时的输入、预测、理由、已启用作品及已有应用内来源，然后提交原 `observe-enabled` 操作。输入与解释可以继续修改，新草稿不能写回原命令。可以恢复自由观察、选择历史、以原用例继续编辑；没有问答锁、成功门槛或强制补全。

原预测与实际观察并列展示。普通「运行」和自由观察也可事后保存解释，此时原预测仍为缺项，不补造预测，也不再次运行。失败、待核实、缺项及 X/Z 均保留，不填造二值；相同与不同仅比较同一固定输入的合法二进制值。解释可说明错误、未解决的问题和用例能发现的错误。目的只是活动目标，不据一次预测或全量通过推断掌握。

## 所有权与兼容

新组件与发布使用版本 3、`stateVersion: 3`，发布与导入请求使用新身份。既有版本 1、2 活动仍通过原宿主入口读取和运行；不会就地改写旧发布或旧状态。

| 数据 | 原所有者与事实 |
| --- | --- |
| 可变输入、预测 / 解释草稿、选择 | 原组件状态文件，由 `ReliableWorkspace` 保护、同步与处理双标签分歧；不另建保存队列 |
| 固定预测 | 原执行命令的不可变 state basis，`caseRequestId` 必须等于原 requestId；关联 `caseId`、`revisionId` 和已启用作品 |
| 实际输出、失败、原 VCD | 原执行账本及保留资源；不复制到组件状态，不通过重新运行补回历史 |
| 解释修订 | 原作品 owner 的不可变 `alu-reflections/<binding>/<noteId>.json`；只含学生文字、父修订与原执行链接，不复制 F/Cout |
| 问题及引用副本 | 原可靠问题草稿、固定动作与资源引用机制；新增引用不派发问题 |

解释资源的 objectId/contentId 均等于 noteId，同身份只能保持同字节。作品 owner 校验活动、主体、组件、原 ALU 观察命令和父链；同批父子按原内容校验并拒绝环。从历史解释继续修订时，正文、所选父项和原执行一起受组件状态保护，保存以所选解释为父项，可以形成分支。服务尚未收到原命令时返回 `unavailable`，继续保存本机待同步内容，不确认远端成功。

已有同作品 / 输入的观察与该作品的检查以原 requestId/inputDigest/executionRef 留存。代码等同性比较编译相关原字节，复制到新对象身份也不会隐藏应用内已有来源。执行 owner 在接收与恢复检查时重新核对来源；学生自报的帮助与真实发起者（学生、Agent、自检、教师预览）分别保留，不判断应用外接触过的答案。

## 波形与语义引用

波形只读取原结果的 `trace.vcd`。解析保留完整作用域信号、别名、原十进制 tick 和时间单位；超过浮点安全范围的 tick 不转成 Number 事实。范围是闭区间，包含起点的保持值及区间内全部变化。0/1、X、Z、首次取值前的缺失、损坏 VCD 与执行不完整分别表示；非数字 real/string/event 明确拒绝。显示缩放只改变绘制宽度。

解析、选择和引用均有资源界限；过大范围要求缩小，不抽样后冒称完整。范围在原组件状态中保护；历史读取不需要编译缓存或活 Worker。

| 适配 | 可信来源 |
| --- | --- |
| `alu-case` | 原作品 owner 登记的组件状态副本；原输入及预测文本 |
| `alu-observation` | 原执行 owner 的命令、结果元数据与真实保留资源 |
| `alu-waveform` | 同一执行的原 `trace.vcd`，由共享解析器重新核验信号及 tick 范围 |
| `alu-reflection` | 原作品 owner 的不可变解释及原 case 链接 |

服务从实际资源重新生成副本，不接受调用方摘要作为证明；跨主体、活动、组件和范围均拒绝。资源先于终态报告到达时，合法本机副本保持可重试的待同步状态，终态到达后核对同一原关联，不把这段延迟永久判成无效引用。未知适配或来源后来变化时，已接受的固定副本继续只读恢复。代码保持原文本 / 代码选段引用。

新状态、命令、解释、引用和资源沿原作品 / 执行 / 草稿 owner 的同步、资源 pin、维护与恢复校验参与保留，不新增 schema 或独立 owner。完整备份、隔离还原与接管验收属于 [#195](https://github.com/paher-din/XunJie/issues/195)。本票不提供改写学生代码的 Agent 操作、画像、教师提交或虚假接收。

## 验证边界

实现按以下公开边界验证：固定 runtime action 及原 receiver、真实 PostgreSQL 作品 / 引用 owner、VCD 输入到范围副本、现有 ALU 工具与问题草稿页面。没有以私有方法或镜像实现断言代替行为测试。

平台验收使用 Windows 11 x64、Apple Silicon Mac 的桌面 Chrome，分别访问完整本机产品和独立学校 HTTPS 页面。故障控制使用现有服务 / 宿主接口，保留真实 Worker、IndexedDB、API、PostgreSQL 和资源。类型检查、工程测试、产品 / 网络验收与教学效果分别报告；具体结果与实际前后截图由本票交付记录登记，未运行不算通过。
