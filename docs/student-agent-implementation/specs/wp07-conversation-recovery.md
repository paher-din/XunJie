# 学习对话的备份、还原与接管

来源：[WP07 学习对话的备份、还原与接管](https://github.com/paher-din/XunJie/issues/204)。实施基线 `798199ca0e1d27683bbd6472e699e0bb327106ef`，沿用同一 `wp07`，不新开或合并 PR。Mac 与真实跨机恢复另外新建交接票，执行者使用已有合格环境。

## 实施与核对方案

1. Agent owner 通过自己的公开维护接口给出版本化事实清单：请求、会话日志、快照、Run/步骤/预算、工具命令/Wait、学生提问/回应、输入修订/消费、控制、模型段切换、依赖和分片。摘要包含稳定内容身份，不公开正文或凭据。运行层只装配这些接口，不读写领域表。
2. 正常装配和独立 Agent 使用同一清单。还原通过 owner 重新读取实际记录和资源核对；已发布迁移保持原字节，旧通用维护材料仍按原结构验证，不伪造不存在的历史证据。
   日志仍使用已发布 v1 外壳；可忽略扩展明确使用 `kind: extension`，正文包含 `ignorable: true`、扩展名、扩展版本和原 payload。它不承载必须执行的语义，未知扩展版本仍保留原件；未知必需事件、外壳版本或未声明可忽略的扩展明确拒绝，不据新配置重新解释。
3. 使用既有正式备份、隔离还原、退休/接管与命名空间机制，逐片验证等待、修订、未结调用、未关联结果及逻辑预算。只读环境无推进和外发；旧安装、旧浏览器身份和失去领取资格的处理者不能取得新许可。
4. 学生恢复提示复用现有对话、工具记录与只读工作区；维护诊断复用正式 CLI/状态入口，区分等待、未知、停止待确认与失败的实际下一步。

## 验证边界

沿用已确认的真实生产 HTTP、所属 Agent/模型/执行 owner、正式恢复接口、PostgreSQL 18.6 和资源边界。控制外部模型 transport 或原回执的时点；不替换领域 owner、不跨服务查询业务表做测试断言。先用一个真实学生 Wait 与修订队列的备份/只读还原场景确认缺口，再实施并继续下一片。

后续覆盖 WP03 通用真实工具与原生结果、同机学校/独立 Agent 连接、重启及接管确认丢失、损坏资源拒绝；Windows 完整包与桌面 Chrome 验收使用实际产品入口。Mac、真实跨机及任何未执行项分别登记，不将同机安装算作跨机，不将工程路径成功解释成教学效果。
