## 设计决定

1. 复用 `createMaintenanceCoordinator`、`RecoveryOwner`、`RecoveryTarget`、`createRecoveryManager`；各 owner 经公开 Interface 关闸、排空、导出和验证。编排 Module 不直接查询或写入其他 owner 的业务表。
2. 一致边界由真实参与者确认。先关新接受与派发，再允许受管收尾写完成，最后冻结存储。HTTP 返回、队列为空、心跳消失都不是实际执行结束的证明。
3. 快照覆盖服务已经接收的事实。浏览器未同步作品、待发队列和 Worker 内存留在原 namespace；源安装冻结期间也不能接受它们来改变已确认边界。
4. 原请求、命令、输入摘要、执行引用及原节点关系不变。恢复安装、客户端 namespace、连接、执行器启动实例换新；不能用重算摘要、换节点或新命令隐藏未知。
5. 试还原允许恢复内部数据和校验，学生侧仅只读展示；不能创建实验、连接真实执行器、执行自检或自动续发队列。
6. 接管依赖源退休证明和每个真实接收端的拒绝证明；两个数据库独立递增代际不能产生互斥。退休 installation 为永久拒绝对象，新安装授权不清除它。
7. 检查点恢复是新的明确动作及执行实例，保留 `resumeFromCheckpoint` 和原会话关系；与仍存活会话的 `resume` 分开。不自动重放检查点之后结果未知的操作。

## 维护边界与未结执行

建议新增有版本的 owner 恢复材料，至少包含 `backupId`、维护边界身份、environment/service/installation 身份、schema 及组件协议版本、受影响命令集合、原节点/执行器身份、最后确认/已应用序号和逐项处置证据。材料写入加密 owner 数据，不在公开 catalog 暴露学生内容。

流程：预检完整 owner/receiver 清单 → 持久关新接受与派发 → 按原身份排空 → 写完收尾事实 → 冻结所属 storage → 校验边界 → 各 owner 快照和资源复制 → 逐项重读认证 → 发布完整备份。任何必要参与者无法确认则保持关闭，返回可重试失败与阻塞项，不发布“完整成功”。

| 边界前状态 | 需要确认的证据 | 备份/接管后的处理 |
| --- | --- | --- |
| 已接受、明确未开始 | 原执行权威确认没有 claim/启动/生效，持久冻结原请求，旧处理者不能再领取 | 保留原身份及取消事实；接管后仍不自动派发。只有原权威出具未开始与移交依据，且新入口明确确认，才按原身份继续 |
| 执行中或暂停 | 按已声明能力生成可重读检查点并确认停止，或确认真实终止；保存已发生观察和收尾序号 | 不把暂停视为可迁移活内存；保留历史，适用检查点由新请求创建关联实例 |
| 停止待确认 | 原 `stopId`、取消意愿、原实例退出/进程树回收证据及最终事件落盘 | 保持原 accepted 回执；没有实际停止确认不写 cancelled，也不允许接管开放 |
| 未知/丢回包/原节点失联 | 按原 requestId + digest 和原节点核实，取得“未开始”或真实终态/停止依据 | 查无记录、超时不等于未执行；不能安全核实时完整维护失败，保留未知与原查询关系 |
| 已确认终态 | 不可倒退终态、最后序号、原回执及产物字节 | 原样保留；晚到旧响应不覆盖终态和当前作品 |

浏览器正在执行且服务已接收该命令时，也必须核实 Worker 终止/终态；浏览器失联不能由服务伪造终止证据。浏览器独有命令不计入服务备份完整性，但必须写明覆盖范围；产品恢复的新 namespace 不读取它们，旧 namespace 的队列不能向退休安装或新安装重新派发。

维护期间晚结果分两段处理：边界固定前，经原 owner 验证的收尾写入本次快照；边界固定后不再修改该备份，只能经独立、收窄权限的核实归档通路进入当前权威，或留待原 owner 查询。通路只接收既存命令事实，不支持创建/控制/重新授权，核对原命令、输入摘要、节点/启动实例、事件位置与产物摘要，去重并保留冲突证据。不能用已退休安装的普通业务写权上传。无法核实则不展示为可信结果。

## 备份集合、保留与校验

| 材料 | 恢复时必须核对 |
| --- | --- |
| 固定发布与组件包 | 原定义身份/版本/摘要、入口与依赖字节长度和摘要、自检版本、宿主/适配协议、原任务运行方案及配置；停用不改变固定活动绑定 |
| 学习数据 | 活动与主体归属、实例绑定、作品及显式状态版本、内容身份、语义引用范围与原副本、问题草稿；原对象不可定位时仍可读副本 |
| 执行命令与回执 | 请求/命令/执行引用、原输入摘要及固定依据、接收者、原节点关系、取消墓碑与停止请求；接受不误写为完成 |
| 结果、事件与检查点 | 原请求/会话归属、确认/已应用序号、事件缺口、资源引用/摘要/长度、检查点固定环境与兼容版本、恢复父子关系 |
| 维护与接管材料 | 同一边界、必要服务/接收端、held backupId、源 installation、目标 installation、逐端失权证明与持久阶段 |

复用 `OwnedStorage.snapshot` 和资源保留 pin；数据库、资源引用及保留清单在各 owner 关闭边界内一致。每份资源实际重读并核对身份、版本、摘要、长度，不能只校验 SQL 行或文件名。跨 owner 关联通过公开校验 Interface 比对，不跨表修补。导出完成后不能继续追加文件/pin；失败清理复用原恢复操作日志，超时未结束的导出不得提前释放资源。

缺少清单所列材料、摘要/长度不符、未知必需格式或配置不兼容，均失败，保留源与原备份。若原组件明确不支持检查点，可合法保留只读历史与“无法续接”原因；若备份声明含检查点而实际缺件，则是损坏，不能降级成恢复成功。只读打开固定副本不加载未经验证的组件代码。

跨机器组合记录每个 owner 的原位置、关闭证据及快照身份。可变执行方先确认冻结/停止，再建立学习记录边界；涉及另一安装的材料也必须取得相应 owner 的确认和匹配材料，不能把单机备份称为全系统分布式原子快照。固定不可变材料可以按原身份验证已保留副本；可变 owner 不可达且没有安全边界时阻止完整备份。

## 隔离试还原与正式接管

### 隔离目标

目标 root、数据库和资源位置必须空且独立，拒绝与源/备份重叠。先认证全部材料与完整 targets，再恢复；保留业务身份，生成新 installation、client namespace 和本地凭据，不复活源 token/秘密。

恢复校验与应用打开使用明确 `isolated` 模式：允许内部格式迁移、资源核对和授权后的只读投影，不能运行组件自检、创建 Worker/原生进程、发远端命令或启动待发调度。只读展示与执行能力装配分开，不能仅把按钮禁用而保留后台自动派发。检查点兼容性用声明与材料静态核对；实际恢复执行留到接管后的明确动作。

正式产品 CLI `restore` 仍默认隔离；试还原后的产品只读入口沿用首页、活动和工作区。当前 CLI/运行库若只能恢复并退出，实施时补齐隔离模式的正式只读打开能力，不能用测试浏览器页面替代。学习数据写入、问题发送、实验操作在服务和宿主双侧拒绝，浏览器原有未同步内容不覆盖或清除。

### 接管协议

接管在目标执行，持久阶段为：`isolated → verifying → retiring-source → fencing-receivers → validating-target → active`。这是领域操作阶段，不另起一套运行库维护状态枚举；失败阶段与证据落入原操作日志。

1. 核对最新 held 备份仍对应源的关闭边界、全部 owner 与完整 receiver 清单；普通备份后源已重新开闸，须重新建立 held 备份并重新还原，不接管旧副本。
2. 源按 `backupId + targetInstallationId` 幂等退休，持久永久拒绝旧 installation、新连接及普通 resume，返回绑定的退休证明。来源不可达或证明不匹配，目标停在 isolated。
3. 每个真实接收端按原 environment/service/installation 持久 fencing。除拒绝旧 grant/旧连接/旧处理者，还必须核对已受理执行均到安全边界；只等认证 handler 返回不够。证明绑定本次备份、源/目标安装、接收端、执行边界及拒绝结果，不含秘密。
4. 在实际接收端尝试旧 token、旧安装重连/重新申请授权、旧浏览器挂载及旧处理者派发，均须拒绝。再为新 installation 授权，重复尝试旧 installation 仍拒绝，证明永久退休没有被新授权覆盖。
5. 验证目标业务和恢复关联，再开放目标新写/新动作。派发在此之前保持关闭；开闸本身不回放恢复队列，不启动旧会话。原命令的核实/明确未开始交接仍按前表处理。

旧挂载拒绝不能只靠前端换 IndexedDB key：服务接受新动作时核对当前 installation、恢复 namespace/授权代际和本次有效连接，组件桥接也核对新 `connectionId`。恢复关系只允许读取原事实，不能替旧挂载换取新派发权。明确未开始的原请求继续必须携带原权威绑定 requestId、digest、原执行引用和新接收实例的移交依据，不能由浏览器自称“未开始”获得例外。

任一接收端失败、断线、超时或遗漏，目标保持隔离；已经退休的源不能自动复活。部分 fencing 成功后幂等重试同一接管，不能换 backupId 绕过。目标开放失败重新封闸并核对是否产生新事实，不能把已经写入的新事实当作可撤回。接管完成后源继续只保留维护核实材料；恢复源旧磁盘或 grant 文件不能恢复权限。

## 学生侧恢复与交互设计

不新增学习导航、恢复专用简化页面、保存按钮或常态技术标签。维护入口沿用产品 CLI 的 `backup / backup-list / restore / takeover / maintenance-resume`，CLI 输出逐 owner 阶段、未结命令分类与失败原因；本票不把管理员密钥和维护权限放入普通 Web 设置。现有[运行状态页](../../../apps/web/src/runtime/DiagnosticsPage.tsx)仍用于状态与按需诊断。

| 场景 | 在既有产品中的行为与文案 |
| --- | --- |
| 源维护关闭 | 原活动保留已加载作品；受影响动作就近显示“正在维护，暂时无法运行”；当前输入继续本机保护，失败沿用原导出能力 |
| 目标隔离核对 | 原首页/活动/中心组件和结果面板只读；持续提示“这是还原校验环境，实验尚未启用”；显示最后可信结果，不暗示正在运行 |
| 接管后重开 | 按原活动读原作品、标注、固定结果、语义引用及问题草稿；新编辑走新 namespace 和当前授权，历史结果仍标识其固定输入 |
| 组件停用或定位不可用 | 显示只读作品/原引用副本，定位明确说明不可用；不猜测新对象，不使整份问题草稿失效 |
| 有兼容检查点 | 原会话显示中断与可恢复检查点，提供“从检查点新建会话”；动作后显示新实例与原会话关系，恢复下一步确实来自内部状态 |
| 无适用检查点 | 显示具体原因，如“该会话未保存可恢复检查点”；保留作品/历史。只有正常能力允许时才展示“新建会话”，不把它称为继续 |
| 原执行未知 | 显示最后可信观察和“原执行状态待核实”，保留原查询入口及取消意愿；不能把重新运行放成默认恢复动作 |
| 旧浏览器队列 | 原 namespace 原样保留，不自动迁入或发送；提示旧环境已接管。内容导出沿用原能力，不能借迁移内容复活原命令 |

布局复用现有中心工具区、执行记录及问题面板；状态提示靠近受影响操作，身份/版本进入按需详情。复用根 DESIGN 的浅深色语义色、文字、间距、圆角与焦点 token，不引入新主题和多层卡片。实施验收覆盖键盘、窄桌面、中文输入、浅深色；若实际布局有较大变化，必须附同一路径的运行前后截图。本轮未修改 UI，不以示意图冒充实屏证据。

## 格式演进与实施切片

外层 `RecoveryManifest` / `OwnerRecoveryData` 继续使用已有受认证格式；新执行维护材料在所属 `data` 内显式版本化。数据库迁移和浏览器持久记录版本分别演进，实施前从最新 migration 列表分配编号，不预占固定数字。

保留旧命令原字节/规范化规则及摘要，不通过格式升级重建 requestId、stopId、controlId、结果身份。旧备份缺少新边界证据时可以明确标识为历史只读材料，不能声称满足 #176 完整接管；缺失必需材料或未知格式则拒绝恢复，不猜默认值。若需要格式升级，先独立目标验证迁移前后的原身份、摘要、回执与资源字节，再允许接管。

建议按以下顺序实施，每片通过相关检查后再继续：

1. 核对最新 #174/#175 已公开的检查点、运行方案、原节点和恢复记录 Interface，补充 owner 维护材料与恢复校验；记录生产包内实际必需参与者。
2. 既有执行 Module 的维护材料接入现有 participant，覆盖关新接受/派发、收尾写和真实进程/Worker/远端边界；故障时不冒充安全排空。
3. 接入同边界导出、资源/pin 保留、独立目标校验及正式只读打开；禁止隔离目标执行与旧队列自动发送。
4. 扩展 installation 永久退休与真实执行接收端 fencing；加入原命令核实、晚结果归档及幂等失败重试，不复制执行账本。
5. 正式工作区重开三类样例并实现适用检查点恢复；完成真实产品包、两客户端平台与独立机器组合验收。

写集预期：`packages/contracts` 的新增窄 wire 类型（如确需），`packages/learning-space` 内所属数据/执行 Module，`packages/product-runtime` 的维护/恢复/连接和生产装配，`apps/local-runtime` CLI，`apps/web` 原宿主/可靠工作区/执行面板，相关测试、探针与交付文档。保留无关工作，不修改 CI、密钥或现有数据。schema/迁移实际实施及任何临时环境删除按根 AGENTS 红线另行说明风险并取得授权。
