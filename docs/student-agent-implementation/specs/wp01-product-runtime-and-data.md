# WP01：产品运行与数据底座

日期：2026-10-29。范围依据[实施总览](../student-agent-implementation-overview.md)及已确认的重构、存储与部署决议。测试边界与包内拆分已由负责人确认，规范已发布为 [WP01：产品运行与数据底座](https://github.com/paher-din/XunJie/issues/142)。同日依据负责人确认的代码结构与实施节奏，补充有限结构准备及各实现的归属。WP01 无前置工作包；实时实施状态由 GitHub 原生子议题与阻塞关系维护。

## Problem Statement

学生或教师需要安装后直接使用循阶，学校需要部署共享服务，并能把部分能力安排在个人设备上。数据库、进程、端口和服务位置应由产品准备与连接。关闭网页、停止服务、断网或更新产品后，已经确认保存的数据不能变成来源不明的副本；维护者还需要把数据库和对应资源一起恢复到可用状态。

当前实现已有 SQLite 持久化、开发进程管理和备份先例，但开发成员接入、源码工作树、云端演示环境及逐库复制不能直接承担产品安装与完整恢复。统一原生 PostgreSQL 已经确定，仍需交付两平台运行管理、所属服务的事务与资源机制、隔离环境、部署连接，以及经过实际还原验证的升级恢复路径。

## Solution

交付一个独立于开发工具的产品运行与数据底座。个人安装组合管理自身所需的原生 PostgreSQL 和服务；学校部署可使用受支持的既有 PostgreSQL，并向浏览器或已安装本机组件提供入口。维护者配置本机、学校或混合组合，产品核对环境、服务身份、协议与能力后建立连接。学校网页使用者无需安装数据库。

各服务通过同一套 PostgreSQL 事务与迁移机制保存自己的事实，通过所属资源存储保存文件或对象。产品在进程重启、备份、升级和搬迁中保留这些关联，明确何时停止接收写入、何时允许新实例接管。安装和运行状态可查询，失败能够定位并按保留的数据继续处理。

WP01 交付运行机制和可供后续业务包消费的接口，不提前实现课程、工作区、模型或 RunDriver 的领域规则。验收使用实际分发包、原生数据库、真实资源后端和进程间连接；必要的测试宿主直接调用这些产品实现。每个后续包接入自己的真实数据和业务后，负责新增路径的完整验收。

## User Stories

1. 作为个人使用者，我希望安装循阶后直接启动所需服务，以便开始使用而不先手工配置 PostgreSQL、Node、端口或容器。
2. 作为 Windows 11 x64 使用者，我希望产品在受支持的普通用户环境安装和运行，以便使用学校或个人电脑上的本机能力。
3. 作为 Apple Silicon Mac 使用者，我希望安装包包含正确架构的运行资源并通过实际打开检查，以便不依赖开发工具完成安装。
4. 作为学校网页使用者，我希望直接访问学校入口，以便在没有本机数据库的设备上使用学校提供的服务。
5. 作为部署维护者，我希望选择本机、学校或混合组合，以便按设备和管理需要安排服务位置。
6. 作为使用者，我希望启动、停止和当前连接状态清楚可见，以便知道产品是否准备好，以及失败后应采取什么操作。
7. 作为本机使用者，我希望重复启动复用本次安装的实例，以便不产生多份进程或竞争同一数据目录。
8. 作为使用者，我希望停止服务后保留数据、关闭网页时遵守已有工作生命周期，以便返回后继续使用。
9. 作为本机使用者，我希望端口冲突、残留进程或启动中断不会破坏已有数据库，以便修复问题后仍能读取已保存内容。
10. 作为部署维护者，我希望产品与机器上已有的数据库和其他循阶环境共存，以便测试、升级或停止一套环境不影响另一套。
11. 作为开发或部署维护者，我希望新旧环境使用明确且独立的身份、目录与客户端命名空间，以便旧队列和旧开发数据不会被新产品自动接管。
12. 作为服务开发者，我希望本机和共享部署使用相同的事务与迁移语义，以便不为同一个领域维护两套数据库行为。
13. 作为服务开发者，我希望只有所属服务可以更新其事实，以便同机合设后仍可按相同边界拆开部署。
14. 作为调用方，我希望记录、接收凭据与必要待发项能原子提交，以便超时或重试时按原身份查明是否已经接收。
15. 作为服务开发者，我希望冲突更新、重复请求和旧代际写入得到明确结果，以便后续运行模块建立唯一推进权。
16. 作为使用者，我希望确认保存的资源在重启后仍能读取并校验，以便记录不会指向半写文件或过期地址。
17. 作为部署维护者，我希望默认使用本机文件保存资源，也可配置受支持的 S3 兼容后端，以便按部署条件选择存储。
18. 作为服务开发者，我希望资源清理保留仍被记录或备份引用的对象，以便清理与新引用竞争时不会造成数据丢失。
19. 作为混合部署使用者，我希望本机组件能主动连接远端服务，以便学校不必直接访问个人设备的私网端口。
20. 作为使用者，我希望失联时保留正确的环境和服务归属，以便不会悄悄写入另一套数据库或把未知结果当作失败重做。
21. 作为部署维护者，我希望备份同时覆盖数据库、引用资源及必要恢复材料，以便实际还原出可使用的环境。
22. 作为部署维护者，我希望在独立目标环境先验证备份，以便不通过覆盖当前可用环境来试探备份是否有效。
23. 作为部署维护者，我希望区分应用 schema 升级和 PostgreSQL 引擎升级，以便选择正确工具、窗口与恢复方法。
24. 作为使用者，我希望升级中断、磁盘不足或恢复失败后保留原数据和明确状态，以便能够继续修复或恢复。
25. 作为部署维护者，我希望搬迁时明确交接唯一写入和派发权，以便源实例与恢复实例不会同时推进同一份工作。
26. 作为后续业务模块开发者，我希望登记自己的持久记录、资源和维护参与动作，以便新增业务自然纳入已有备份与升级机制。
27. 作为使用者，我希望未结请求和外部效果的身份在恢复后保留，以便后续模块查询原结果，而不是换身份重新执行。
28. 作为部署维护者，我希望看到实际备份时点、版本、资源检查和平台验证结果，以便判断能够恢复到哪里及当前支持范围。

## Implementation Decisions

### 1. WP01 的事实边界

WP01 拥有产品环境、安装资源与版本、所管理进程、部署连接、schema 迁移记录和备份恢复过程的事实。学习空间不等于安装环境：一个环境可以承载多个学习空间，一个学校空间也可以绑定不同成员的本机组件。

底座提供连接配置、事务、资源和维护接入边界；各业务包定义自己的表、资源引用、幂等身份和迁移。WP02 拥有学习空间身份、成员、活动和作品；WP03 拥有执行器与组件；WP06 拥有模型连接；WP07 拥有 Run/Command/Wait/预算；其余领域依照实施总览归属。WP01 不建立集中拥有这些业务事实的通用数据服务。

### 2. 产品运行管理与平台支持

首批本机目标为 Windows 11 x64 和 Apple Silicon Mac。实际分发包应包含受支持架构的应用运行环境、原生 PostgreSQL 及所选生命周期、备份和升级工具。无需已有 PostgreSQL、Node、Docker、JDK、Homebrew 或编译工具；安装前提、必要权限和额外系统依赖由真实安装验证明确，不预先把“完全免管理员”记作已通过。

产品管理自身私有目录、初始化、连接凭据、监听范围、端口选择、就绪检查、进程监督及正常停止，不接管系统已有 PostgreSQL。同机所需服务可共用物理数据库实例，仍保持所属服务的写入边界。仅连接远端服务的安装组合不强制准备本机数据库。

[产品安装、独立环境与部署连接](https://github.com/paher-din/XunJie/issues/143)票内先完成最终 PostgreSQL 二进制来源与版本的打包探针，再固定可交付组合；新增的结构准备票不承担此探针。选择证据包含 artifact 版本与摘要、来源及分发许可、运行库和工具完整性、目标架构，以及 Windows 签名验证与 macOS 签名/公证和 Gatekeeper 实际打开结果。只下载包、使用开发终端启动或引用上游 CI 不算安装交付。

### 3. 生命周期、诊断与唯一进程

管理入口提供安装/准备、启动、状态、停止与卸载行为，返回明确的成功、进行中或失败原因。入口具体命令和最小界面在实现中确定；面向师生的入口不要求输入数据库或服务端口。需要界面时遵循项目设计规范。

重复启动保持同一环境、进程与已分配地址；正常停止先停止接收和派发，再等待所属服务完成必要持久化，最后按依赖顺序停止数据库。超时、未正常退出和强制中断分别留证。关闭网页不等于退出本机服务；未来已接收请求是否继续由所属业务契约决定。

启动失败只清理本次拥有的进程；端口占用、目录被其他实例持有、残留锁和数据库不兼容须可诊断。不得靠删除有数据目录的锁文件、重新初始化或杀死外来进程“修复”。异常退出后验证已确认提交、未提交事务和待发记录的实际状态。

### 4. 独立环境与重建入口

每个独立环境有稳定身份、安装实例身份、公开配置版本和明确的数据/资源/运行范围；客户端获得相应存储命名空间。日志和状态展示可核对当前环境，秘密配置通过独立凭据引用读取，不进入公开配置或日志。

新环境不自动导入、清空或复用旧 SQLite、IndexedDB、outbox、个人 Agent 材料或执行账本。旧原件保留；有价值的内容由后续业务包或开发基线工作显式提取。环境创建、停止、升级、还原和删除都以明确目标为作用域；A 环境的操作不得改变 B 环境。卸载默认保留数据，删除数据是独立明确动作。

WP01 提供隔离原语和产品入口。开发成员登记、SSH 接入、共享 seed、`xj-dev` 编排及复现包适配由 WP13 消费此能力，不成为产品安装前提。

### 5. 同一 PostgreSQL 实现与服务所有权

本机和共享端使用原生 PostgreSQL、同一套 SQL/事务实现及 schema 迁移体系。共享端可接入受支持的已有实例；不要求其交出数据库进程生命周期。开发与 CI 的事务集成测试同样使用原生 PostgreSQL，不以 SQLite/PGlite 替身证明并发和恢复语义。

运行安装与数据存储可以并行开发；数据存储的最终关键事务验收必须使用首批打包探针固定的 PostgreSQL 版本和初始化条件，并覆盖已支持的共享端组合。取得这些输入即可完成相应验收，无需等待运行安装整票结束；自行选择的临时数据库版本不能替代最终组合。

初始化及连接契约固定受支持引擎版本、编码、时区、所需排序规则与扩展集合，并验证应用实际使用的标识、数值、时间和结构化记录往返。不同机器默认设置不能隐式改变记录含义。按服务划分可写 schema/对象与访问权限；同机组合也不跨服务直写表、拼接跨所有者事务。

短事务允许所属服务把状态、稳定请求身份、接收结果及必要 outbox 一起提交。唯一约束、条件写入、事务冲突与回滚必须可被调用方明确处理；网络中断导致提交结果未知时按原身份查询，不把连接错误解释为一定未提交。资源上传、模型、工具或网络等待不占用数据库事务。

WP01 提供这些机制及真实竞争验证；Run 领取、取消、预算、Wait 和调度策略由 WP07 实现。底座不另造一套业务队列或 RunDriver。

### 6. 服务所属资源与引用发布

默认实现所属服务管理的文件资源后端，并提供可选的 S3 兼容后端。S3 不是本机安装前提；交付至少固定并验证一个明确实现与版本，不以接口兼容宣称支持所有供应商。

资源引用包含稳定身份、所属服务与访问范围、摘要、长度、格式版本及可解析定位。长期身份不使用过期 URL 或本机绝对路径；定位可以随恢复和搬迁变化。小型正文可在元数据事务内保存，大型资源和需要保持原字节的记录通过不可变对象保存。原生模型字节不能依赖 JSONB 重编码保持原样。

先按稳定上传身份完成资源持久写入并确认可重读，再在短事务中发布业务引用、状态和必要待发记录。上传超时按原身份核实；资源已写入但事务失败允许重新关联或之后回收，不能出现已确认记录指向未完成资源，也不通过重新执行外部效果补回资源。

资源清理与引用创建共享持久保留协议，覆盖活动、运行、提交及备份/恢复清单的引用。清理不能在“刚检查无引用”与“实际删除”之间误删新引用；损坏、缺失、无权限和后端不可用返回可区分的结果。

### 7. 部署组合与连接契约

保持客户端、空间/课程、学习数据、教学协调/Agent、模型连接、工具执行六个逻辑部署单元。允许同机合设，不要求制造六套进程。配置表达环境、服务身份与类型、入口、协议版本、能力及凭据引用；后续业务包再登记空间/成员范围的真实绑定。

WP01 提供本机组合、学校共享组合和至少一种真实跨机混合组合的装配及连接机制。学校端固定一套可复现的服务器 OS/架构、PostgreSQL 和运行方式作为首个受支持组合，记录实际版本；这不自动扩大本机客户端平台范围。连接时核对目标身份、版本、授权范围与能力，必要依赖不满足时不能报告 ready，可选能力缺失则明确报告该能力不可用。

本机组件主动建立经过认证的远端连接或领取通道；学校服务不能把自己的 `localhost` 解释为学生设备，也不要求学校直接连接学生私网端口。重连延续原环境和服务身份，取消连接授权后拒绝新的连接/请求。持久待发、业务接收及完成回执由各自所有者实现，连接成功不冒充请求已接收或教师已收到。

失联不静默改换数据所有者、节点或付费模型。基础连接与撤销在 WP01 用受限测试主体验证；学校登录、成员映射、课程访问和个人模型选择分别由 WP02、WP06 接入，不在这里建立替代身份体系。

### 8. 维护参与与一致备份

每个持久服务登记其 schema 版本、资源根/后端、恢复所需配置，以及停止接收、停止派发、排空/持久化、恢复校验和重新开放的参与动作。缺少必要参与者或无法确认其状态时，维护操作失败并保持明确状态，不能跳过后给出完整备份。

初期允许明确维护窗口：先停止新写入与派发、等待已开始的事务和资源发布到可确认边界，取得与之匹配的数据库快照与资源清单，完成校验后再恢复服务。多个库或后端的“时间接近”不构成一致备份；资源清理在备份期间保留被清单引用的对象。

备份清单记录源环境、配置与 schema/引擎/资源格式版本、受影响服务、摘要、可恢复时点及必要恢复材料。若含加密数据，须验证对应恢复材料确实可用；秘密不进入明文清单或日志。独立备份的位置、周期与保留可由维护者配置，状态记录最近结果及可恢复时点。与工作数据同一介质上的副本不能当作介质损毁后的恢复证据。

### 9. 还原、迁移与唯一权威交接

还原先进入独立目标环境的隔离维护模式，核对数据库、引用资源、关键约束和读写能力，之后才允许启用。缺文件、摘要错误、格式/版本不支持或必要恢复材料不足应明确失败，保留当前可用环境与原备份。

记录和未结请求/效果身份保留；目标的安装实例、连接凭据和恢复代际按接管流程建立。试还原副本默认不得连接真实外部执行能力或继续派发。正式搬迁须停止或撤销源环境的写入/派发权，并使接收方拒绝旧实例的新请求，再开放目标。源不可达且无法证实失权时，目标保持隔离，不把两个独立数据库中各自递增的数字视为互斥保证。

WP01 验证维护与接管机制、旧实例拒绝和身份保留。未来模型/工具结果未知时查询原效果、Run 唤醒及预算结算由相应业务包接入维护参与接口并验收，不由底座恢复动作自动重放。

### 10. 应用与引擎升级

应用 schema 升级与 PostgreSQL 引擎升级分开标识、检查和执行。迁移由所属服务登记并记录版本，只允许一个有效执行者；本机与共享实例运行相同链。未来已发布记录须有明确迁移或旧记录读取路径，不因本轮旧版未发布就永久忽略升级。

升级先核对支持矩阵、所需工具、空间与可恢复备份，进入维护窗口，再执行和校验。分别演练应用 schema 变化、PG minor 更新及一次 major 迁移；路径可以使用经过验证的逻辑导出/还原，不强制选择某一升级工具。跨 Windows/Mac 的搬迁使用验证过的逻辑恢复，不复制 PGDATA 作为跨平台交付方式。

失败时保留源数据、备份与进度记录；在已知安全边界恢复旧版本或继续修复。数据已变化后不能只切回旧二进制就宣称回滚完成。启用前验证状态、资源和版本的一致性，再交接写入权并解除维护。

### 11. 接入与交付形态

对后续业务包交付环境/服务配置、事务、资源引用发布与维护参与四组可用边界，附最小接入示例和错误语义。实现可以沿用现有应用工厂、HTTP 注入、真实 CLI 子进程和独立服务测试宿主；旧同步 SQLite 事务调用若被复用，必须连同受影响调用链正确调整，不能机械替换 driver。

WP01 自身的环境记录、迁移账本和维护记录使用真实存储；跨服务及资源竞争使用调用实际产品模块的测试宿主验证，不创建假的课程、Run 或教学结果冒充后续业务完成。与业务无关的测试宿主不进入师生日常流程。后续新增服务须登记维护参与，不等待一次全产品总验收。

### 12. 代码归属与有限结构准备

遵循实施总览的[代码结构与实施节奏](../student-agent-implementation-overview.md#代码结构与实施节奏)。先由[工程目录、公共契约与构建入口整理](https://github.com/paher-din/XunJie/issues/146)完成 `apps/student → apps/web`、`apps/teaching → apps/server`、最小公共契约提取及受影响的构建/测试/打包入口，再让运行安装与存储两票并行。准备票不先重写旧业务、不建立未来业务空壳；存储的最终关键事务验收仍只需取得运行安装探针确定的 PG 版本与初始化条件，不增加等待完整安装票的阻塞关系。

| 位置 | 本包拥有的 implementation 与 interface |
| --- | --- |
| `apps/web`、`apps/server` | 师生共用浏览器入口与可组合后端宿主；本包修正搬迁路径与运行装配，空间/课程、学习数据、Agent 等业务 module 的深化由对应 WP 完成。 |
| `apps/local-runtime`、`packages/product-runtime` | 前者提供产品管理入口，后者集中环境、进程、部署连接及维护编排；本机入口、学校部署和后续开发工具消费同一套公开能力，不分别复制生命周期逻辑。 |
| `packages/storage` | 提供 PostgreSQL 连接/事务、迁移机制、资源发布/保留及维护接入；所属业务 module 登记自己的表、迁移、引用和领域规则，不向其他 owner 暴露通用事务或可写 repository。 |
| `packages/contracts` | 按 owner 提供跨端/跨进程使用的环境、服务、资源和维护状态等公开 wire 契约；仅提取真实共享内容，内部实现类型留在所属 module。 |

公共契约是实现的输入，不从 runner、数据库或其他 implementation 推导；浏览器可消费的导出不依赖 Node 专属库。师生权限投影仍由所属后端完成。`packages` 不反向依赖 `apps`、`tools` 或测试支持，宿主只负责装配；`product-runtime` 通过已登记参与者操作事实，不另建全系统业务 repository。

沿用 npm 建立 workspace、明确 package exports 和运行入口，保留浏览器与 Node 各自的编译条件；本地与 CI 共用构建、类型检查和测试发现规则。搬迁同步 import、现有发布包、开发脚本、锁文件定位和有效文档；`xj-dev` 这里只修正受影响路径，PostgreSQL 基线、新对象复现及对产品运行入口的完整适配由 WP13 负责。旧 runner 的执行重构及 `execution-node` 的实际创建归 WP03 起的执行工作。

产品入口及其传递依赖不得导入开发 `tests/`、fixtures 或验收宿主；构建输入与分发清单也要排除这些内容。测试宿主作为独立消费者调用同一份产品实现。现有开发工具的夹具依赖不因此成为新产品入口的依赖，后续由 WP13 替换。

备份、升级、还原与接管沿 `product-runtime` 的维护路径编排，复用生命周期工具与 `storage`，各 owner 提供自己的维护动作。此处验收已登记的真实参与者；未来工作区、执行、Agent 等真实数据和未结操作的恢复随对应 WP 接入，不成为 WP01 的前置。

## Testing Decisions

### 主要测试边界

以**产品管理入口 → 真实进程和服务 API → 重启、升级或还原后的可读状态**作为主要验收边界。生命周期、部署组合、备份与恢复共用这条黑盒路径，避免为每个内部类分别建一套验收。

补充一处**所属服务的事务与资源接口 → 两个真实 PostgreSQL 会话和真实资源后端**的故障/竞争边界。它用于控制提交前后、连接断开、旧代际写入和资源发布/清理的时点；断言外部可观察状态与回执，不断言内部调用顺序或文件名。它不能替代分发包、操作系统和跨机连接验收。

### 必须覆盖的行为

| 范围 | 通过依据 |
| --- | --- |
| 有限结构准备 | 改名后的 Web/后端、公开契约及受影响开发/发布入口完成干净安装、类型检查、构建与相关既有回归；本地与 CI 选择同一套生产输入与测试。检查浏览器契约无 Node 依赖、公开契约不引用实现、分发物不依赖测试夹具；此项不代替后续产品安装和行为验收。 |
| 实际安装 | 干净 Win11 x64、macOS arm64 从实际包完成安装、首次启动、正常停止、再启动及卸载保留数据；覆盖中文/空格路径、已有 PG 共存与实际签名/打开流程。记录首次安装/启动的网络需求，不能暗中依赖开发机缓存。 |
| 进程与环境 | 重复启动不增加实例；端口/目录冲突可诊断；中途失败不伤外来进程；强杀后已提交可读、未提交不出现；睡眠/唤醒与残留进程可恢复。对 A 创建、停止、升级、还原或删除不影响 B。 |
| 真实事务 | 两会话竞争同一请求/版本、唯一冲突、条件更新、跨行原子变化及整体回滚；提交后回包丢失仍可按原身份查询；旧领取/维护代际不能继续写；连接恢复后状态明确。 |
| 资源与清理 | 文件后端及一个固定 S3 兼容实现完成上传、重读、校验、引用发布、断点失败和 GC；覆盖资源已完成但 DB 未提交、上传结果未知、缺失/损坏对象和新引用与删除竞争。 |
| 部署连接 | 本机、学校共享和至少一种真实跨机混合组合；正确环境/服务/协议/能力核对、连接撤销、断网与重连；必要依赖故障使 readiness 失败，可选能力按实际降级；网页客户端不需要本机数据库。 |
| 一致备份 | 有并发写入与资源发布时进入维护，实际停止接收/派发后产出一致清单；在独立存储保存并还原到独立环境，逐一重读引用资源；损坏、缺项、错误恢复材料和缺失参与者明确失败。 |
| 升级与回退 | 应用 schema、PG minor、PG major 路径分别实际运行；中途退出、磁盘不足及版本不兼容不破坏源数据；按记录完成恢复/继续，Windows/Mac 间至少一次逻辑导出还原成功。 |
| 权威交接 | 源实例仍存活、旧连接重连及旧进程复活时均不能向新权威写入或产生新外部效果；试还原默认隔离；已有身份和未知结果标记保留，不能因切换新建请求。 |

实际安装矩阵分别留证 Windows 11 x64 与 Apple Silicon Mac；涉及网页入口和浏览器到本机/远端连接的路径覆盖桌面 Chrome/Edge，记录实际版本。基础测试宿主可固定请求与资源样本，但数据库、文件/S3、生命周期工具与网络连接均为实际实现。

### 已有测试先例与取舍

- 应用持久数据库测试已有关闭重开、独立目标保护和经 HTTP 查询 readiness 的先例。
- 持久性测试已有真实子进程提交后强杀、持锁事务中断、条件写失败整体回滚的先例；方法可以复用，SQLite 结果不是 PostgreSQL 结果。
- 开发 CLI 集成测试已有重复启动、双环境、停止保留数据且不伤外来进程、重启后读取记录的先例。
- 备份测试已有真实 CLI 往返、错误恢复材料/篡改拒绝和不污染目标的先例；须扩展为 PostgreSQL 与资源共同还原。
- 运行包测试已有排除开发接入服务的先例；继续检查产品运行无需成员登记、源码工作树或云端演示基线。

不为可逆文案、内部薄包装或复述实现的函数另写测试。各票只运行与改动相称的工程检查及上述对应的真实验收；新失败、新改动或未解疑点才扩大验证。安装包体、启动耗时、空闲/实际底座负载的资源占用和恢复时间记录实测，不预设无依据的性能阈值或教学容量。

工程测试、目标平台安装、浏览器操作及教学效果分别报告。WP01 不产生教学效果结论；未执行的平台、故障或恢复项目须明确保留为未完成，不能以文档、容器或探针成功替代。

## Out of Scope

- WP02 及以后各包的领域模型、页面和业务行为，包括学习空间登录/成员、工作区保存与提交、课程组件、模型协议、持久 RunDriver、画像与教师反馈。
- 旧 API/DTO、旧 Agent 会话和实验进程的兼容接续，旧开发数据全量迁移、生产双写和无停机切换；旧原件保留和显式提取边界继续有效。
- 个人与学校学习空间数据自动合并、跨独立环境联邦、通用双向数据库同步及无具体用例的集群编排平台。
- 强制完整离线、所有操作系统/CPU/数据库版本/S3 供应商支持、零数据丢失或零停机承诺。
- `xj-dev` 成员接入、开发共享基线、业务复现包、Phoenix 和 Agent 评估平台的适配；这些由 WP13 承接。目录改名所需的现有路径修正属于有限结构准备，不因此重建复现链路。
- ALU 与 Flights 课程资料制作、实际教学效果研究及整轮重构总验收。

## Further Notes

产品已确定统一原生 PostgreSQL、产品管理本机实例、直接重建旧开发模型和服务事实所有权。本规范将这些选择转为可交付行为；最终二进制/版本、具体安装形态、共享端首个支持组合及传输实现由首批实施验证选定，不把尚未运行的探针记为结论。

按相关工作成组拆票，不受单次 Agent 会话容量限制。[工程目录、公共契约与构建入口整理](https://github.com/paher-din/XunJie/issues/146)完成后，[产品安装、独立环境与部署连接](https://github.com/paher-din/XunJie/issues/143)和[PostgreSQL 事务与服务资源存储](https://github.com/paher-din/XunJie/issues/144)按写集并行，[一致备份、版本升级与恢复交接](https://github.com/paher-din/XunJie/issues/145)消费两者交付。恢复交接票有独立维护功能交付，不另建只有全量验收的收尾票。实施和实时状态由规范母票的原生子议题及阻塞关系维护；母票承载规范，不作为另一份重复实现任务。
