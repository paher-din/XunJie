# 学生端 Agent：需求与决策记录

更新：2026-10-29。状态：记录已确认产品要求、长期目标架构的工程选择与待验证事实。按 Wayfinder 决议及负责人本轮明确答复更新来源与边界；长期设计在实际新问题出现时修订，设计定稿与实现验收分开。

## 上下文工程讨论补充（2026-11-17）

来源：本轮基于 `xunjie-context-engineering.html` 的讨论，负责人确认 Q1—Q9、Q11—Q30、Q32—Q33、Q35—Q39 和 Q41—Q54，对 Q10 补充了场景区分，并要求按截图顺序优先讨论基础设施。Q29 以最终单题的讲义要求发布方式为准。Q31、Q34 和 Q40 分别按负责人修正的整轮固定模型、压缩期间消息排队、生成质量优先原则记录。

- **CE1：优先目标。** 优先保证持续辅导中正确理解学生当前处境，包括当前作品与观察的版本、学生纠正、提示前后表现和工具实际状态；在质量不退化的前提下优化容量、速度与成本。
- **CE2：上下文与长期了解。** 当前会话的连续理解与跨会话了解学生分开设计，先明确当前会话的上下文闭环；跨会话偏好和学习证据另行定义纳入、修正与使用规则，聊天摘要不能直接成为长期能力判断。长期了解学生的重点是学习能力，能力判断主要依据具体学习场景中的任务完成水平，不能以 Agent 使用风格或交流偏好代替。
- **CE3：能力判断的粒度。** 长期记录以具体能力为单位，区分当前能做到什么与如何利用反馈、迁移方法和逐步减少帮助；从多次表现积累学习变化的证据，不生成笼统的学习能力高低标签。
- **CE4：完成水平的依据。** 同时考察成果是否达标、解释与验证、应对变化的表现，并保留获得帮助的条件。使用 Agent 本身不扣能力分，求助次数不直接代表能力弱；任务完成不能直接等同于能力掌握。
- **CE5：讨论顺序。** 当前优先讨论上下文工程基础设施，依次为系统提示词、上下文装配、上下文管理、上下文压缩、会话日志；长期记忆后置，暂不展开能力证据的更新与使用机制。CE2—CE4 保留为后续设计依据，不扩展当前实施范围。
- **CE6：系统提示词组成。** 采用共同底线、场景职责、适用课程规则三部分。共同底线包括真实依据、事实与推断及未知的区分、工具状态保真和材料不能扩大权限；主页与工作区明确各自职责，课程提供目标、帮助范围、答案开放程度及评价要求。具体工具参数由工具定义承载，详细操作流程按需加载，执行权限由代码检查。
- **CE7：帮助策略归属。** 平台守住真实、授权和评价边界，并要求遵守适用的帮助规则；课程任务由教师发布的策略决定帮助程度，个人学习采用单独的默认策略。学生请求和 Skill 均不能越过课程限制。是否允许修改作品属于独立操作权限，不与是否允许展示完整示例绑定；不对所有 Agent 统一禁止完整答案，工作区的提示式帮助要求按后续 CE11 处理。
- **CE8：规则冲突。** 在进入模型前处理可识别的规则矛盾。明确的策略选项作为约束，自由文本只补充说明，不能隐式覆盖选项；发布时对能识别的冲突提示教师修正。运行时遇到无法判断的矛盾，继续提供无争议的帮助，对争议部分说明限制，不擅自放宽；不宣称能够自动识别所有语义矛盾，不依赖文本排列顺序决定效力。
- **CE9：规则维护。** 共同底线与场景职责作为仓库中独立、可读的工程模板，随代码审查和版本发布；课程目标、要求与帮助策略由教师与 Agent 协作编写，经教师确认后随课程发布；个人学习默认策略由产品统一维护。最终系统提示词由确定性程序组合并保留各部分来源与版本，运行模型不自行改写约束；不为此预建通用提示词管理平台。
- **CE10：规则生效边界。** 课程规则随活动绑定的发布固定，新发布不自动改变旧活动，版本切换作为明确操作且迁移另行设计。平台与场景提示词在新 Turn 开始时采用当前版本，同一次 Turn 内保持一致。操作权限在实际执行时重新检查，提示词版本固定不保留已经撤销的权限；已发出请求与运行中任务由执行和取消机制处理。
- **CE11：两个 Agent 的区别。** 工作区 Agent 保留只能提示的帮助方式；主页 Agent 可直接解释和提供完整示例，但必须辨别个人探索与教师要求的任务，并遵守适用课程限制。负责人本轮所说的“学习空间 Agent”按其随后使用的“工作区 Agent”对应现有 workspace-assistant，不另增场景。后续系统提示词、装配、管理、压缩与日志设计均分别考虑主页与工作区的特点，不把个人探索与主页、教师任务与工作区简单等同。
- **CE12：工作区帮助上限。** 提示式帮助是工作区场景的固定上限，教师策略可以进一步收紧，不放宽为直接代做当前任务。提示可以包含概念解释、排错建议和必要的局部示例，不意味着只能反问；不直接产出当前任务的完整可提交成果。
- **CE13：主页任务来源判断。** 已关联课程任务或资料时读取并遵守对应策略，不因进入主页解除限制；学生明确说明是作业、实验或教师任务时，按教师任务处理，必要时定位对应任务。普通知识问答直接回答；请求完整成果且存在教师任务迹象而来源不明时先澄清，期间可提供概念解释和提示。未查到课程来源不等于确定为个人探索，不承诺识别完全隐去来源的任务。
- **CE14：默认材料与按需读取。** 必要上下文主动提供，大量正文按需读取。工作区主动提供当前任务目标与帮助规则、学生问题和选区、相关作品版本、关联任务执行状态及近期对话；其他文件、完整实验日志、波形、课程资料正文和较早记录按需读取。主页主动提供当前问题、附件信息、明确关联任务及适用规则和近期对话，其他课程、项目、作品和历史会话按需读取。学生明确引用的内容优先进入上下文，大附件无法完整放入时提供准确范围与读取入口，不能仅凭标题视为已读全文。
- **CE15：固定输入与后续变化。** 提问时的选区、作品与引用保持原版本，后续 Step 单独获得相关作品变化和任务新结果等简短事实；需要分析新版本时明确读取，旧结果始终归属于旧版本。模型生成期间的变化不改写已发出的请求，不默认每次编辑都触发新回答。主页读取课程或项目资料也保留已读版本，并明确区分后续更新。
- **CE16：工具与 Skills 装配。** 常用工具直接提供，其他能力按需发现和加载。工作区的基础工具围绕当前作品、相关执行状态与提问；主页的基础工具围绕学习任务查询、资料读取、提问和项目创建，不暴露操作现有工作区的能力。Skills 先提供简短说明或发现入口，使用时读取正文；学生明确选择的 Skill 在回答前必须读取，不能只凭名称套用。发现和加载限于当前获准范围，可见不等于单次操作已获授权；具体常驻集合依据真实使用频率和定义体积调整，不要求学生逐次手动选择。
- **CE17：多来源装配。** 每份材料保留所属课程、任务或项目、版本、已读范围及适用帮助规则。主页可以跨来源比较，但区分归属，不能借其他来源的宽松规则绕过目标任务限制；工作区以当前活动为主，外部资料不自动替换任务要求。课程规则约束相关任务和材料，不因曾经读过就永久约束主页后续无关问题。内部来源标记供模型与系统使用，界面使用课程名、文件名等自然表达。
- **CE18：材料缺失。** 缺少决定授权或帮助范围的必要信息时先补齐，不猜测权限或放宽限制；缺少判断所需证据时说明缺口，继续提供不依赖该证据的解释；缺少可选背景时正常回答，仅在影响结论时说明。不因可选材料失败中断整轮，也不将未知表述为确定结论。
- **CE19：大结果回读。** 被截断材料须提供真实可用的继续读取方式，默认返回关键观察、状态、版本、截断说明及工具专属读取参数，支持按合理范围读取同一份结果。优先沿用工具的领域读取方式，不定义所有工具共用的 `readWith` 字段；无法回读时明确说明，不提供无效引用，不以重新执行实验替代读取旧结果。
- **CE20：非文字材料。** 根据问题需要选择文本、结构化数据或图像；可准确表达为文本或结构化数据时优先使用，视觉判断需要时提供相关原图、页面或区域并保留来源与范围。不默认发送完整 PDF 的全部页图或全部波形截图，当前模型无法处理必要媒体时明确能力缺口。两个 Agent 共用此原则，工作区围绕当前作品和实验，主页围绕本次问题与选定资料。
- **CE21：请求预算与材料优先级。** 基于实际请求核算输入、输出预留与估算误差，累计费用预算单独管理。工具在结果进入上下文前按自身合同限制返回范围、字节数、字符数、行数或结果项数量，并保留截断状态和领域读取方式。上下文压缩采用模型路线的上下文窗口、输出预留和压缩 headroom，阈值为 `min(contextWindow × 0.80, contextWindow - reservedCompletionTokens - compactionHeadroomTokens)`。达到阈值后保留最近 `(contextWindow - reservedCompletionTokens) × 0.10` 的上下文尾部。保护适用规则、当前问题、关键版本与执行状态及支撑当前结论的必要证据。必需信息仍放不下时说明具体缺口，缩小本次处理范围或暂停依赖该材料的部分，不悄悄丢弃关键依据后继续判断。
- **CE22：有效上下文与去重。** 按内容版本、读取范围及内容是否实际仍在有效上下文中去重；退出上下文后重新需要时允许回读，不能以曾经读取代替当前可见。工作区围绕当前活动保留必要材料，主页转向新话题后让无关课程正文与 Skill 细节退出模型工作上下文，保留来源引用和必要约束。工具定义不无限累积，也不逐 Step 反复加载卸载，优先在任务变化、预算压力或明确失效时调整。
- **CE23：模型切换。** 用户明确切换后重新核验容量与能力，保留可移植的规则、对话和证据，正确处理工具调用与结果关联；不兼容内容明确处理，已执行操作不因切换重跑。容量或媒体能力不足时可以建议切换，默认不静默改用其他模型或服务；未来自动切换须另行定义用户授权的候选范围与触发条件。
- **CE24：压缩选区。** 按模型路线的近期 token 预算保留上下文尾部，首版取 `(contextWindow - reservedCompletionTokens) × 0.10`，摘要更早的已闭合历史。切点不得拆开工具调用与结果关联，当前问题、关键纠正与未决事项优先保护。保留范围随模型容量与材料大小调整，不固定消息条数或 Step 数量。工具结果先按工具合同限制，历史压缩只处理已经进入上下文的消息和工具表示。
- **CE25：摘要语义与场景。** 沿用事实、推断、矛盾、未知和未完成事项的共同结构，作为有来源的交接记录。工作区保留目标、已尝试方法、作品与结果版本、学生纠正、已给提示及尚未验证问题；主页保留当前请求、已确认选择、相关课程或项目、已读资料及未完成查询或创建事项。规则、权限与实际任务状态从权威记录重装，摘要只保留必要关联，不成为新的权威；学生表现如实记录，压缩不顺便生成能力判断。
- **CE26：压缩执行。** 先采用自动、同步、有界的压缩。当前 token 计量达到 `min(contextWindow × 0.80, contextWindow - reservedCompletionTokens - compactionHeadroomTokens)` 时，选择安全的已闭合历史区间并保留近期 token 尾部。首版近期比例为 10%，压缩后仍超过阈值时最多再尝试一次。不要求学生逐次确认，不按固定消息条数或 Step 数量压缩。限制次数与开销，失败保留原上下文，原请求可容纳时继续，否则缩小范围或说明阻塞。有实测证据表明等待成为明显问题后再考虑后台执行。生成结果只是候选摘要，采用前核验来源、保留项及最终请求容量。
- **CE27：摘要质量验收。** 运行时检查结构与来源，离线验证语义与后续行为。运行时核验工具截断状态、领域读取方式、摘要来源范围、近期 10% 保留预算、历史是否变化及采用后请求容量，不通过则不采用；离线案例覆盖学生纠正、提示前后回答、作品与结果版本、受理与完成、课程规则及跨来源混淆，同时检查摘要内容与后续 Agent 判断。两个场景分别建立案例，根据稳定复现的问题增加针对性约束，不默认每次压缩调用审核模型，不将结构检查当成语义正确保证。
- **CE28：日志与只读回看。** 优先支持解释某次回答的真实依据。每次模型调用关联实际规则、工具定义、输入与材料版本、真实请求和返回结果、模型配置及用量、材料选择与截断和回读及压缩采用记录、工具身份和真实状态及结果。通过已有记录和不可变引用关联，减少大内容重复存储；历史请求须能准确还原，不以当前规则重拼冒充。学生看正常对话及必要来源说明，技术细节只向获准排查者开放，不自动向教师开放学生全部主页会话；回看不调用模型或执行工具。恢复沿用中断后新建 Turn、读取既有事实且不重放历史动作的已定边界。
- **CE29：保存与清理。** 会话存续期间保留准确还原历史请求和操作所需的记录及依赖。压缩、换模型和关闭页面只改变使用状态。暂缓按天数自动过期，先统计体积并用内容引用减少副本。清理会话须由明确操作发起，事前说明历史、回看和继续能力的影响，只处理该会话拥有且无其他有效引用的记录。教师课程、已提交作品与独立实验记录按各自生命周期管理。临时诊断副本限于实际排查和验证用途，用后按仓库规范清理。两个场景各自维持会话归属与访问权限。
- **CE30（Q30）：动态状态缺省的含义。** 来源明确报告清空时，先前值只作为历史引用。读取失败时，当前值标为未知，必要时说明上次观察的版本。本步未查询时沿用已有记录及其观察时间，需要就当前状态下结论时重新读取。三种情况均保留提问时固定的引用。工作区选区和主页任务关联适用同一原则，变化随下一次正常调用提供，光标移动本身不触发回答。
- **CE31（Q29）：讲义中的教学要求。** 备课 Agent 从讲义中提取教学要求及其出处，写入对应任务的规则草案。教师可在发布预览中修改或移除，随整份任务一次确认。主页和工作区依据已确认规则辅导该任务。学生单独上传同一讲义时，按阅读材料处理。
- **CE32（Q31）：模型切换以 Turn 为界。** 主页与工作区在 Turn 开始时固定学生选定的模型，整轮的所有 Step 和重试沿用该选择。学生可在本轮结束后切换模型。若想在处理中换模型，须先显式停止本轮，再切换模型，并在同一 Session 中手动继续，开启新的 Turn。停止后的任务取消、迟到回执与恢复按 ADR 0004 处理。
- **CE33（Q32）：容量估算不确定时的派发与重试。** 明确超限时说明需要缩小的范围。估算存在不确定性，但计入输出预留和安全余量后判断可容纳时，以本轮选定的模型尝试一次。供应商明确拒绝容量后，仅在请求实际缩小且仍保有判断所需证据时有限重试。无法再缩小时，请学生选择更小的处理范围。容量重试的具体次数上限留待结合实际任务校准。
- **CE34（Q33）：复用实测输入用量。** 两个 Agent 仅在模型路线与计量口径一致、能确认上一请求已计量的输入原样保留且本次仅追加内容时，采用上次实测输入用量加新增内容估值。历史被摘要替换、工具定义变化、图片取样范围变化或新 Turn 更换模型时，按新请求重新估算。混合实测与估值所得的总数用于窗口判断。
- **CE35（Q34）：压缩期间的消息。** 压缩按开始时已接纳的历史正常进行。期间到达的消息统一排队，等本次压缩结束后按既有消息顺序和接纳规则处理。消息到达本身不触发摘要重算。学生点击停止沿用 Turn 的停止与取消机制。
- **CE36（Q35）：按教学阶段提供工具反馈。** 当课程明确要求先预测再观察时，预测提交前，工作区 Agent 只收到实验执行状态。学生提交预测后，Agent 才能读取对应作品版本和输入条件下的实际结果，比较预测并讲解。自由实验中可直接提供学生已经能够观察的结果。
- **CE37（Q36）：已展示结果的预测练习。** 同一作品版本、同一实验条件的结果曾在自由实验中向学生展示时，工作区 Agent 可获知展示事实，预测提交前仍隐去具体数值。展示记录只证明界面呈现过结果。学生对原因的说明可作为解释思路的依据；若教师需要独立预测，则换用尚未展示结果的输入。
- **CE38（Q37）：失败用例的选择。** 当前教学阶段允许展示结果时，学生明确指定用例，就优先提供该用例的完整对照，即使它在界面首屏之外。学生询问整体问题时，先提供总体结果，再按诊断类别选取少量代表用例。各类现象的根因需要结合进一步证据判断。
- **CE39（Q38）：访问权限明确撤销后的上下文。** 后续模型请求仅保留该来源已不可用的事实。排除其原文、引用片段及可追溯到该来源的摘要内容；混合摘要无法可靠拆分时，从其余获准材料重建。两个场景仍可使用学生自己的实验数据和通用知识。历史请求按会话保存规则保留，回看受权限控制。发布新版材料而旧版仍获准访问时，原版本仍可用于回答。
- **CE40（Q39）：结果未知时的继续与重跑。** 学生要求继续讲解时，使用已有依据，涉及仿真结论时说明证据缺口。学生询问上次结果时按原任务身份查询，仍无法核实则说明状态。确需重新验证时征求学生意愿；学生已明确指定版本并要求重跑且课程和权限允许时，直接发起新实验。结果归属新运行，旧运行保留其真实状态。
- **CE41（Q40）：以生成质量比较上下文方案。** 在已定预算内优先选择能让 Agent 给出更准确、更有依据、更符合当前教学要求的回答的方案。达到最低质量门槛后仍比较完整回答的质量。首次有效帮助的等待时间只作观测指标。负责人预计主要等待来自模型调用，装配调整的时延收益需实测。
- **CE42（Q41）：生成质量的评阅依据。** 每个案例注明学生问题、可用证据、证据能支持的结论和课程允许的帮助范围。事实归属、实验结果及教学要求作为硬条件。允许多种合理的解释与排查路径；评阅者在满足硬条件的回答之间比较准确性、依据和下一步的验证价值。主页资料比较尤其核查引用对结论的支持及不同来源的归属。
- **CE43（Q42）：多轮压缩验收。** 用少量成对案例固定学生消息、作品版本、工具结果和模型配置，让现行方案与候选方案各走一遍相同会话。评阅者对照原始证据匿名评阅两处回答：学生刚作出纠正时，以及经过多次压缩、学生再次追问时。工作区检查问题指代和作品版本，主页检查跨资料结论的来源归属。
- **CE44（Q43）：首版的压缩格式与采用规则。** 主页与工作区统一使用循阶可读取、可追溯来源的摘要延续会话。模型可以生成摘要内容，循阶掌握格式、来源校验和采用规则。后续接入供应商原生压缩，应先用成对多轮案例证实回答质量明显改善，再验证撤权、换模型和恢复仍满足已定约定。
- **CE45（Q44）：学生可核对的出处。** 依赖具体材料且会影响学生下一步行动的判断，在对应语句附近提供可打开的原始依据。工作区定位到对应作品版本、输入与实验观察，主页定位到对应资料和页码或片段。排错假设说明其不确定性及验证方法，一般概念解释与过渡句无需逐句标注。回看时区分本次请求包含了哪些材料，以及哪条证据能支持具体结论。
- **CE46（Q45）：引用错误与后续失权。** 发出回答前发现引用的页码、作品版本或实验依据有误时，先核对对应原件。核实支持后给出判断和出处；无法核实或来源不支持时，修正或撤回依赖该来源的结论，保留回答中有依据的部分。若答复当时引用有效、后来访问权限撤销，入口提示来源目前不可访问，按当前权限限制展示；历史记录保留当时实际引用的版本。
- **CE47（Q46）：依赖具体材料的回答先取证。** 主页与工作区先读取所需材料，查阅期间可显示真实进度。取得依据后，带出处流式输出依赖该证据的答复；只核实了部分范围时说明范围。普通概念问题可直接流式回答，按问题决定取证需求。
- **CE48（Q47）：保持工具调用含义。** 实际执行须符合本 Step 展示给模型的工具定义，并复核当前权限。兼容升级可照常执行；若设备只支持含义已变的新版，在执行前返回工具已更新、本次未执行。下一 Step 读取新定义，有足够依据时自行调整参数，确实缺少必要信息时再询问学生。
- **CE49（Q48）：装配记录范围。** 对学生明确选择、规则要求或 Agent 实际尝试读取的材料，关联其来源、版本、模型实际收到的范围以及省略或读取失败的原因。优先引用实际请求与工具回执，以便区分读取失败、预算省略和回答遗漏。未参与本次请求的目录材料无需逐项登记。
- **CE50（Q49）：主页定位工作区实验。** 从实验结果发起主页询问时携带固定的结果引用，主页按当前权限与教学阶段读取。学生自行回到主页提到“刚才的实验”时先按线索查询，唯一定位后说明对应版本和检查再回答；候选之间的歧义会改变判断时，询问学生指的是哪次。跨会话按需传递结果引用，无需默认装入工作区整段对话。
- **CE51（Q50）：部分会话历史无法恢复。** 依据仍可核验的材料继续学习。缺失原答或提示记录时，只在问题依赖它们时说明缺口，摘要不能替代学生原话或证明其独立表现。旧会话无法可靠保存新消息时保留可读历史，学生可在同一工作区开启新会话，带入自己选定的实验引用。
- **CE52（Q51）：压缩在学生端的呈现。** 主页与工作区在现有回答进度区呈现正常压缩，等待明显时提示正在整理前面的对话，完成后继续回答。影响结论的证据缺口在回答中指出具体材料和可用的补救方式。用量数字放在已有入口，区分上次实测、估算与未知；压缩前的实测值不能直接代表下一请求的占用。
- **CE53（Q52）：首轮验收课程范围。** 数字逻辑走真实产品流程，串起工作区的固定作品、预测、实际仿真、作品修改与主页追问。C 语言用可重复的多轮案例核对代码版本、输入、学生预测、测试输出与压缩后的判断，检验工具反馈对不同课程的适用性。正式 C 语言工作区、编译器接入与课堂教学效果分别验收。
- **CE54（Q53）：上下文改动的收益证据。** 先对照固定案例中的实际模型输入，核查版本、学生纠正、教学限制和工具状态，再以相同模型配置对预先选定的代表性案例做少量重复，匿名成对评阅完整回答并保留所有结果。分别报告输入改进与回答质量变化。优势不稳定时记为尚无定论，硬条件失败单独追查并保留记录。
- **CE55（Q54）：学生表达、引用与自动观察的归属。** 两个 Agent 在装配、回答与压缩时保留学生本人的表达、学生引用的材料以及系统自动补入的观察各自的来源。主动引用和提问只证明学生引用并询问，学生明确表达认同时才能记录其认同；能否作为独立预测还须核对先前展示与提示。归属不清时仍可答疑，将学生观点留为未知。
- **2026-11-22 工程约定。** 已确认固定选区按需装入、同 Session 跨 Turn 重新授权回读，以及“稳定请求头、有序消息组、工具批次配对、派发前必要状态增量”的装配顺序。工具结果采用工具级输出预算、截断状态和领域读取方式。上下文压缩采用模型路线的 80% 压力阈值、10% 近期 token 保留比例和一次有限压缩重试。最终 payload 准入由 model-gateway 独立核验，不把三段式 `P` 分支写成 DeepSeek Harness 机制。完整接口要求与边界用例见[实施方案](context-engineering-implementation-plan.md)。Q55 的连续摘要回查条件仍未决定，长期记忆后置。

- **2026-11-19 架构评审通过。** `agent-runtime` 决定每个 Step 可见的材料、顺序与表示，`model-gateway` 负责最终协议编码、合法续接或重建，并以实际派发的 payload 验收。这样，内核决定缩短或撤回的材料在协议重放时也按本步决定处理。见[实施方案中的职责分工](context-engineering-implementation-plan.md#每步可见历史与最终请求的职责分工)。

## 最初 idea 中需要保留的产品原则

教师主导教学设计与最终判断；Agent 提供主动、引导式帮助，让学生参与思考；项目完成与知识掌握分开判断；个性化需要可持续维护的学习画像；课程组件与教学产物可复用。教师设计 Agent、教学分析 Agent 与跨学生案例库保留为产品方向，本轮不展开其实现。

I0 中的“零适配门槛”按 L8 拆成可验证的边界：教师可复用或借助 Agent 创建新工具，现有执行能力内的新依赖通过工具与环境装配接入；超出已有接口或执行能力的机制才需要适配。配置与检查应由产品和 Agent 协助，不能把“可配置”变成要求教师手写清单或自行集成。架构不能承诺自动理解所有外部工具或无需适配就支持任意系统能力。

L9 明确首条数字逻辑活动是样例，不能将其预测、仿真、时长或只解释不改代码的规则推广到所有课程。L10 明确课程准备由教师与 Agent 协作，学生端默认轻度主动并尊重学生选择；帮助体验与主动性要根据真实反馈改进。L11 已确认学生设置与轻量反馈方式；L12 已确认无扰检测首版采用活动证据、规则与时机控制。体验满意、任务完成与知识掌握不合并成同一种结果。[原始研究](references/2026-10-23-unobtrusive-guidance-evidence.md)与[开源实现调查](references/2026-10-23-unobtrusive-guidance-implementations.md)提供选型依据，具体阈值、标签质量和算法效果仍需验证。

## 第三轮决定与架构重评

**Q7 用户决定：运行方案由教师设计，优先本地。** 原提问把执行位置交给学生选择，不符合产品意图，现已撤销该建议。教师/教师 Agent 先评估本地环境能否满足课程；仅对无法满足的能力配置远端资源。学生按发布的课程方案使用，平台负责设备检测和方案内调度。

教师决定运行规则，不需要预先指定每位学生的物理节点。设备不符合要求时，平台引导环境准备；只有课程已配置相应远端替代路径时才能使用，不能静默把任务转上云或展示节点选择器。

**Q8 用户委托技术判断。** 用户没有对五条旧方案作统一批准，而是要求自行判断是否合适。本轮据此确定 P1—P5，修正教师运行方案、统一 UI/状态宿主、限制自研范围与本地交互路径；不再把 SDK 选择或整体技术结论留作等待用户勾选的事项。

当前研究见[执行位置研究](references/2026-10-18-execution-topology-research.md)。它证明相关机制有边界，不代表本项目已通过跨平台兼容或性能验收。

## 开发协作与产品运行边界（L7）

当前共享数据和部分服务的云端环境服务于团队开发复现，应保持尽量小的范围；它不决定产品的应用服务、执行节点或数据最终放在哪里，也不锁定产品数据库和资源存储。产品仍按 Q7 由教师设计课程运行方案、尽量学生本地执行。P1/P5 已按长期目标明确运行与部署选择，L24 指出的完整 Agent 能力缺口已通过能力契约、交互设计与完整请求走查补齐，组合设计继续采用自有持久 RunDriver。

L18 进一步明确：产品部署方案由使用者或组织决定，首版即需要各部分可本地或云端组合；课程运行方案仍由教师设计。这是两种不同决定，不能把前者收窄成学生只连接统一后台，也不能把后者改成学生挑选实验节点。

开发复现需能对齐代码 commit、工具链与配置版本、相关数据/schema/seed 版本，并记录输入、复现步骤、预期与实际结果；共享环境还需避免成员测试数据和任务互相污染。DEV1—DEV2 已进一步明确隔离方向与工具需求，开发工具已按 #126 实施，实际能力与验收边界见[当前交接](../references/2026-10-24-team-development-handoff.md)。运行位置与部署候选见[架构正文](student-agent-architecture.md#运行位置与部署组合)，课程运行原则见 [ADR 0001](adr/0001-teacher-owned-course-execution-plan.md)。

DEV1 将开发体验细化为本地前后端均可修改，DEV2 认可本地全栈与独立可写数据副本作为默认，共享版本化的数据基线和问题复现场景；云端应用保留作集成与演示，另提供可选的本地前端连云端后端模式。具体理由、源码约束和使用边界见[开发协作方案](../development-collaboration.md)。

DEV2 进一步明确开发工具面向开发 Agent，并与普通用户的安装和运行隔离。工程建议用独立 CLI 执行确定性的环境与数据操作，项目 Skill 提供调用说明，通过独立文件存储传递带版本和摘要的场景包；具体设计见[开发协作工具](../development-tooling.md)。这些开发设施不决定产品部署位置；工程、实机连接、真实执行与教学效果分别报告。

DEV3 将模式切换、成员接入和运行管理纳入同一开发体验。服务器实测为 2 vCPU / 2 GiB / 40 GiB、3 Mbps 公网出口，当前业务健康；据此建议大文件直达对象存储、CI 承担构建，ECS 保留共享业务与轻量开发授权。切换模式不隐式同步数据或部署，基线更新保留旧副本。详见[成员接入与运行策略](../development-access-operations.md)和[服务器核查](../references/2026-10-23-development-server-assessment.md)；资源预算与五人窗口已完成独立验收，具体范围见当前交接。

DEV4 后形成轻量开发接入服务，最初以邀请自动登记；随后按负责人本轮要求加入 GitHub 固定用户 ID 名单和网页设备授权。现行成员使用 Skill 与 CLI 自动完成接入，维护者通过原 owner 通道管理权限。该流程与教师产品架构隔离；当前工具、旧入口退役及恢复线索见[开发协作工具](../development-tooling.md)和[当前交接](../references/2026-10-24-team-development-handoff.md)。
