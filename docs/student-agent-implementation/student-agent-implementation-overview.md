# 学生端 Agent 与工作区实施总览

更新：2026-10-29。建议将本轮建设拆成以下 **13 个工作包**，每包交付一项可使用、可独立验收的能力。已定产品与架构要求见[Wayfinder 本地决议](wayfinder/student-agent/README.md)；本次确定拆分边界和依赖，后续逐包形成规范，再拆包内实施子任务。

工作包编号是本地规划标识，不是 GitHub Issue 编号。`blocked by` 表示该包完成交付与验收所需的前置包；表中省略可沿依赖链推导的前置。资料准备、技术探针和规范讨论可提前并行，实施子任务的具体阻塞关系在后续拆票时确定。

## 代码结构与实施节奏

2026-10-29，Robert 确认采用按运行职责组织的入口、内部业务 module 与少量共享 package；先做目录、契约归属和构建规则的有限整理，深层改造随对应 WP 一次完成。以下是后续规范与拆票的设计输入，**不表示目录已搬迁或能力已实现**。取舍依据见 [ADR 0003](adr/0003-runtime-entrypoints-and-owned-modules.md)。

```text
apps/
  web/                  # 师生共用浏览器应用，由 student 改名
  server/               # 可组合的后端宿主，由 teaching 改名
  local-runtime/        # WP01：产品安装、启停、状态与维护入口
  execution-node/       # WP03 起：实际需要的本机/远端原生执行入口
packages/
  contracts/            # 按事实所有者导出的公开 wire 契约与纯校验
  product-runtime/      # WP01：环境、进程、连接与维护机制
  storage/              # WP01：PostgreSQL、迁移与资源机制
tools/
  xj-dev/               # 成员开发、编排与复现
  xj-dev-access/        # 团队接入
```

四类 `apps` 是运行职责，不要求先建齐空工程。`web` 同时承载学生与教师界面；`server` 按配置装配空间/课程、学习数据、教学协调/Agent、模型连接等内部 module，不要求一个 module 对应一个 package 或进程。客户端、空间/课程、学习数据、教学协调/Agent、模型连接、工具执行六个逻辑部署单元仍保留独立事实归属，可分别启动或同机合设。浏览器执行 adapter 留在浏览器运行环境，不因存在 `execution-node` 就强制走本机进程。

### 依赖与 interface 规则

- **公开契约由事实所有者定义，实现依赖契约。** `contracts` 只容纳实际跨端/跨进程消费的可序列化数据、版本、错误与纯编解码/校验，按 owner 分组导出。不得从 runner、数据库或其他 implementation 的 `ReturnType` 反推公开契约，也不依赖 Node 专属运行库。师生权限投影留在所属后端，UI viewmodel 留在 Web；共用类型不能替代权限检查。
- **宿主负责装配，业务 module 负责事实。** 宿主提供配置和实际 adapter；module 通过窄的公开 interface 协作，不创建另一整套业务 app，不把通用 SQL transaction 或底层 repository 交给外部调用者。跨所有者使用稳定身份、请求和可查询回执；同进程与远端 adapter 保持相同的接收、失败和恢复语义，不借同机部署扩大事务范围。
- **package 必须有实际消费者或独立构建/分发需要。** 业务 module 默认留在所属应用内；确有复用、不同运行环境或独立分发需求时再提取。`packages` 不反向导入 `apps`、`tools` 或测试夹具，应用间不穿透对方 implementation。`storage` 不集中持有领域表和业务规则，`product-runtime` 不接管 Run、课程或执行结果。
- **构建规则覆盖实际入口。** 沿用现有 npm 建立 workspace 与明确的 package exports，保留浏览器、Node 和原生执行各自的编译与分发条件。本地与 CI 复用同一组构建、类型检查和测试发现规则；产品包不依赖源码工作树或 `tests/`。共享测试支持与课程样本各有明确用途，不混进生产依赖图。
- **测试跨越调用者使用的 interface。** 每个 module 的 interface 包括输入输出、状态与身份、确认时点、顺序约束、错误及恢复方式；不能只列 TypeScript 方法。实际变化的存储、模型、执行与网络放在对应 seam；不为没有实际变化的内部调用额外造 adapter。替换旧路径时保留有效行为回归，撤去失去意义的实现细节测试，不并存两套运行权威。

### 重构前的有限整理

有限整理由 WP01 的[工程目录、公共契约与构建入口整理](https://github.com/paher-din/XunJie/issues/146)子票承接，先完成 `student → web`、`teaching → server`，同步 import、脚本、`xj-dev`、现有打包流程、CI 和有效文档中的路径。只提取当前已被多端消费的公开契约，解除契约对实现的反向依赖，并建立后续 package 的构建/测试入口。旧 runner 的实际执行改造留给 WP03，产品运行和存储实现分别由 WP01 对应子票建立；此时不预建未来业务空壳。

整理后现有演示入口、受影响构建与回归仍应可用；这不承诺新产品兼容旧 API/DTO、队列或数据。运行安装和存储两票以该准备票为共同前置，之后按各自写集并行；具体状态与阻塞关系只在 GitHub 原生关系中维护。对 `xj-dev` 的当前路径修正属于准备票，产品底座接入、旧数据库表清单和复现链重建属于 WP13。

## 边界与共同契约

- **WP01 管运行和存储机制，各业务包拥有自己的事实。** WP02 拥有空间、活动和作品；WP03 拥有组件实例接入与实际执行；WP06 保存原生模型结果；WP07 拥有 Run 推进、Command/Wait 与预算；WP11 拥有学习证据及判断；WP12 拥有教师交付与评价。统一数据库不变成跨服务直写表。
- **WP02 的课程记录不替代 WP10 的教师产品路径。** WP02 提供固定课程/任务/资源版本及访问边界，允许从开发资料装入课程；教师确认学生活动所需的目标、评价依据、能力与帮助策略，以及组件创作协助、装配、自检、预览、发布和版本同步由 WP10 负责。这条必要路径不等待完整教师设计产品。
- **WP02 固定待发内容，接收方负责真实业务回执。** Agent 请求从工作区发送到可靠接收与恢复的完整链由 WP07 验收；教师提交由 WP12 验收。提前完成保存不显示为模型已接收或教师已收到。
- **WP07 交付可工作的 Agent，WP08 扩展能力装配。** WP07 以固定的基础能力和课程帮助策略跑通真实请求，拥有步骤快照和执行前复核；WP08 增加完整配置、动态发现、扩展和上下文组织，沿用同一运行与执行权威。PDF 的解析/页图/来源链归 WP08，协议图像输入归 WP06。
- **WP03 负责宿主，WP09 负责生成与修订，WP10 负责共享复用。** 页面在活动中可保存和重开；教师明确收纳为组件时，由 WP10 提取可复用实现和示例数据，避免把学生答案或实例进度带给其他人。MCP 连接与工具/资源/Prompt 归 WP08，交互界面的 Apps 适配归 WP09。
- **WP08 的记忆接入不另建学习判断体系。** 通用偏好、活动事实和课程材料按来源读取；学科判断、证据、不确定性及学生纠正由 WP11 提供，教师正式评价由 WP12 保持独立。跨课不自动共享学科掌握结论。
- **教师私有材料在产生和消费两端落实边界。** WP02/10 的发布投影决定学生可获得什么；WP03/08/09 的组件、工具、Skills/MCP 和生成内容遵守同一范围；WP12 的教师视图只共享对应课程允许的资料。确需私有评测时由受控评测侧执行，不随学生运行包分发。
- **WP13 提供复现与评估能力，后续包维护自己的接入。** 基础数据适配可在 WP01 后开展，Agent 采集在 WP07/08 后闭环；之后新增数据和案例随各业务包接入已有采集、基线和回归机制，不能积压成最后一次全量改造。

## 逐包完整验收

每个工作包完成自身行为、失败与恢复、与已完成依赖的真实集成，以及受改动影响的回归。接口替身和局部探针用于开发，但不能替代交付时的真实接线。前置包不等待未来消费者，后续包负责新增组合路径的验证。

不另设整轮重构总验收，也不设一个“集成所有模块”的收尾包。跨包义务落到引入该行为的包中：

- WP01 首先验证 Windows 11 x64、Apple Silicon Mac 的 PostgreSQL 安装、正常退出、崩溃恢复、备份还原和升级；WP02 以后各包的真实数据和运行恢复由对应包接入此机制并验收。
- WP03—05 验证所用执行位置、设备及桌面 Chrome/Edge 组合；不能用 Mac 研究探针代替产品矩阵。浏览器、本机、远端和无需执行的活动按实际能力分别取证。
- WP06 验证三协议真实端点；WP07 在已实现服务上验证个人全本地、学校服务及至少一种真实跨机混合组合的请求、等待、取消和恢复。之后新增的能力在所属包中补验对应组合，部署要求不推迟到最后。
- WP10 用真实教师操作检查装配、预览、发布和更新恢复；WP11 检查教学引导与纠错，WP12 检查教师接收、反馈和修订。每包都对实际消费的已完成能力负责。
- WP13 验证固定条件和版本可交接、独立环境互不影响、平台不可用时产品照常运行。容量结论来自各包实际负载下的延迟、冲突、恢复和资源记录。

工程检查、浏览器/教师使用体验、真实端点与教学效果分别留证。工程和演示通过不证明真实学生的理解与迁移；WP11 的检测路线仍按回放、只记录候选的观察、实际活动试用逐步取证。教学效果结论需要相应研究证据，不作为所有工作包共同等待的整轮门禁。
