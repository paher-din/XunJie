# 正式 ALU 活动：编辑与单次运行交互设计

日期：2026-11-05。对应 [正式活动中的 ALU 编辑与运行](https://github.com/paher-din/XunJie/issues/192)。本页保留初稿交互设计；2026-11-06 已按负责人授权实施，实际界面与结果见 [Windows 本机交付](wp04-192-windows-acceptance.md)。技术边界见 [实施方案](specs/wp04-alu-edit-run.md)。本页不替代 [DESIGN.md](../../DESIGN.md)，不引入新 token 或独立 ALU 页面。

## 使用目标与界面落点

学生在桌面 Chrome 课后编辑一个组合 ALU，常在代码、行为表和一次输入结果间切换。主要动作是“编辑 → 选择输入 → 运行 → 看诊断/结果 → 继续修改”，任何时刻都能查看材料、提问或返回。不把编译工具步骤变成学生的任务流程。

沿用正式 `ActivityPage` 的沉浸布局与 `CenterToolArea`，课程入口仍是现有首页/课程任务。现有“目标与材料”“作品”“询问 Agent”和文件条位置不变；课程通过固定组件绑定增加“ALU 实验”工具。编辑与实验既能切标签，也能用已有拖拽分屏并排，复用原活动级布局保存。

| 现有位置 | 本票设计 |
| --- | --- |
| 活动标题 | 课程名与 ALU 任务标题；返回仍经过本机保护，不增加独立 ALU 导航 |
| 目标与材料 | 学习目标、公开行为表、端口说明、允许内置加法、补学索引与只解释帮助策略；按需展开材料，不显示工程配置表 |
| 中心标签及运行簇 | “作品”“ALU 实验”；通过已有通用运行插槽在编辑时也能运行同一个已绑定实验，不要求切换才能运行 |
| 作品 | 既有文件条、Monaco、代码选区引用；`.sv/.svh` 有 HDL 高亮，诊断能返回正确文件 |
| ALU 实验 | 紧凑输入表单、所选一次运行的原输入与真实 F/Cout、失败诊断、折叠历史与详情 |
| 问题与引用 | 原草稿和代码引用继续使用；本票运行不发送问题、不清空草稿；结果/波形的新增语义引用随后续票交付 |

下面是结构示意，显示“分屏”这一种既有布局，不是新增默认三栏或真实验收截图。首次进入保持现有作品默认标签；选择 ALU 实验后使用同一工具标签。运行结果就近可见，必要时打开对应工具，不重建编辑器或改变光标。

```text
┌ 返回  数字逻辑与部件设计 · 4 位 ALU           目标与材料  询问 Agent ┐
│ 作品  ALU 实验                  修改尚未运行              [运行]  │
├──────────────┬───────────────────────┬───────────────────────────┤
│ 目标与材料    │ 作品                  │ ALU 实验                  │
│              │ 文件   alu.sv          │ A [0000]   B [0000]       │
│ 学习目标      │                       │ M [0]  S [00]  Cin [0]    │
│ 公开行为表    │ 现有 Monaco           │                           │
│ 按需补学      │                       │ 本次观察                  │
│              │                       │ 原输入 A=… B=… M=… S=…    │
│              │                       │ F  0101      Cout  0      │
│              │                       │ 该次运行后的代码有修改     │
```

输入与输出位串来自当前选择或真实记录；示意里的数值仅说明格式，不作为产品默认结果。初始输入建议全部为零且明确可改；未运行时 F/Cout 显示“尚未运行”，不预填数值。

## 输入、运行与编辑

A/B 各 4 位、M/Cin 各 1 位、S 为 2 位。首版用带显式标签的二进制控件，旁边可显示只读十六进制/十进制辅助值；M/S 旁显示当前操作名称，保留组合写“保留组合：F/Cout 为 0”。所有实际端口仍可见，NOT 忽略 B、逻辑模式忽略 Cin 通过行内说明表达，不偷偷改写输入。

输入框接受合法位宽，非法草稿保留原输入并就地说明，禁止截断高位、转成零后运行或以颜色独自表达错误。首次不自动运行。修改输入只保护草稿；“运行”始终使用点击当刻的代码与输入。本票不提供连续虚拟开关，也不提前显示全量检查/预测/波形空壳按钮。

运行簇与实验面板调用同一个注册操作、同一冻结逻辑。可在实验视图给出就近的同动作入口，但不建立另一套运行状态。单活动存在本组件在途请求时，主按钮显示“运行中…”并提供“停止”；学生仍能编辑代码/输入，新内容等待下一次显式运行，不隐式取消或替换已接受任务。

运行按钮可用的条件为作品已读、无未解冲突、身份/课程仍获准、运行能力准备完成且本机保护可用。禁用时附近说明具体原因；可编辑内容不因缺少工具链而被锁住。运行点击等待本机保护时防重复提交，输入和代码继续接受新编辑。

## 结果与失败状态

| 状态 | 就近呈现与可执行动作 |
| --- | --- |
| 尚无观察 | “设置输入后运行，查看你的代码产生的 F 和 Cout。”；无数值、无绿色通过标志 |
| 首次准备 | 实验区显示“正在准备实验环境…”和有意义的阶段，编辑器照常可用；只在详情显示资源数、版本等 |
| 准备失败 | 原因 + “重试准备”；缺资源、摘要不符、不支持版本、加载中断、存储不足分别解释；已有历史不被隐藏 |
| 正在运行 | “运行中…”；原观察保留在明确的“上次观察”区域，新输入的结果位置不复用旧数值；可停止 |
| 得到完整二值观察 | F 显示 4 位、Cout 显示 1 位，附该次输入；仅写“已取得观察”，不写“行为正确/任务通过” |
| 出现 X/Z | 按位显示 X/Z，说明“输出包含未知值/高阻态”；不给十六进制零或成功替代值 |
| 观察缺失/不完整 | “未取得完整观察”，显示实际诊断；已有部分数据明确不完整，不显示为合法输出 |
| 源码或依赖改动 | 运行操作旁显示“修改尚未运行”；原观察标明“对应上次运行的代码”，查看原依据可读，当前作品继续编辑 |
| 仅输入草稿改动 | 提示“输入已改动，尚未运行”；原观察保留它自己的原输入，不能让新输入标签覆盖旧输出 |
| 编译失败 | 当前这次显示“编译失败”，列真实文件/行号与原诊断；旧观察放在历史/上次观察，不把它当本次结果 |
| 停止请求未确认 | “正在停止…”；保留原记录与查询入口，不提前显示“已停止” |
| Worker 已终止 | “本次运行已停止”；不补 F/Cout，可修改后显式再次运行 |
| 刷新后终态未知 | “上次运行结果尚未确认”，提供“核对状态”；明确再次运行建立新记录，不自动启动 |
| 本机存储故障 | 清楚说明未能保护哪部分，保留当前内存与导出/复制入口；新运行不启动，不显示“已保存” |
| 服务暂断 | 已准备且获准时本地运行可用；短暂同步等待保持安静；需要用户处理的身份/冲突/存储故障才显式提示 |

编译诊断中的路径只映射到该次固定资源集合，不打开任意 URL。若当前对应文件与原依据相同，点击定位文件和行；若已编辑、改名或删除，打开原依据的只读副本并说明“诊断对应上次运行的代码”。不将旧错误 marker 贴到新代码，也不自动还原/覆盖学生作品。

## 历史、详情与恢复

结果外层清楚区分当前作品、当前输入草稿与所选观察。默认选择本次运行记录；新运行失败也选择该失败记录，不能回退选中旧成功结果而无提示。运行期间手动选择历史后，新回包只更新相应记录并提示“本次观察已就绪”，不强行跳走历史选择。

历史按时间展示单次输入与真实状态，选择只改变视图。顶部始终可重新打开在途记录并查询/停止，工具切换不移除控制入口。默认展开当前诊断，历史列表和技术详情折叠，避免每次运行占满长列表。资源读取失败保留元信息与具体原因，不提供“重算历史”替代按钮。

“详情”包含原作品依据、行为/采样规则、组件及运行包版本、运行阶段与耗时、原始诊断/日志和可下载 VCD。技术身份、编译缓存命中等只在这里出现，不常驻标题或状态栏。VCD 本票可读取/下载，信号缩放、范围选择、引用随波形票完成。

刷新恢复本机保护的代码、实验输入、历史选择和问题草稿。选择历史不改写输入草稿；若所选资源未能读取，明确显示错误而不改选其他记录。浏览器独有结果与已同步结果使用同一身份继续关联；正常使用无“本机已保存/同步成功”常态标签。

## 布局、视觉与可访问性

保留白色中性底、hairline、近黑主按钮及单一蓝强调；使用现役 `tokens.css` 的 `--paper/--sunken/--line/--ink/--ink-soft/--muted/--primary/--accent-deep/--danger-deep` 与字体/间距/圆角角色。辅助文字不用 `--faint`；不新增橙/紫强调、渐变、大色块状态卡或嵌套卡片。深色沿同一角色映射，不独立定义 ALU 主题。

正文/控件用系统字体，数值用 mono，标题沿既有文楷；正文 15px、紧凑标签与数值 13px、辅助状态 12px，字重 400/500/600。主操作复用 `ws-btn`，输入与操作间距复用 8/12/16px，按已有控件高度与焦点样式实现。动效只使用现有时长/曲线，减少动效模式不新增位移动画。

在 1440px 桌面可并排作品与实验，材料按需收放；1024px 附近沿既有布局容纳两工具；更窄桌面优先单工具标签，材料/讨论沿现有互斥收放，不压缩 Monaco 成不可编辑窄条。复用原拖拽分屏与键盘菜单，输入组允许换行，运行/停止不得溢出或被横向滚动藏住。

所有输入有端口与位宽标签、键盘可达及错误关联；输出标签含原输入，不仅靠颜色区分未知值。状态变化用 `role=status`/polite，一次运行只报告有意义的阶段/终态；真实故障用 alert，不逐日志播报。点击运行后保留当前焦点；诊断定位才主动聚焦编辑器。中文输入法组合事件不触发运行、提交问题、丢失未完成文字或改写实验值。

## 设计验收与后续边界

实现前从真实正式活动拍摄原界面，完成后以相同视口、主题、课程与数据拍摄新界面。至少包含作品/实验布局、准备失败、代码改动后旧观察归属、编译失败与历史恢复；补浅深主题、窄桌面、键盘与中文输入实际操作。截图只证明其显示行为，执行与资源事实另外核验。

2026-11-05 设计当日未启动产品，文本线框只用于审阅；2026-11-06 的实际前后截图和 Chrome 分项验收已另记在交付记录，教学效果仍未评估。线框不作为运行证据。

负责人审阅重点：是否沿用上述现有标签/分屏与运行插槽、单输入先独立使用、旧观察始终可读且标明原依据。虚拟板连续输入、4096 全量检查、预测/波形引用及真实 Agent/教师提交按各票边界接入，不能借后续票延后本页已经规定的保存、失败与日常恢复。
