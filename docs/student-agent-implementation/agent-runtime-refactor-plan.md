# 循阶 Agent 架构重构：最小内核、能力装配与部署接线

## 1. 设计结论

**采用可插拔模块的设计思路，本轮用明确接口和代码组合实现。** 当前需要解决的是能力复用、场景隔离和按需启动；安装、热加载、插件依赖管理等机制没有进入本轮范围。

原方案的“不建立通用插件框架”改为：

> 建立可组合的场景、工具、上下文和执行策略接口。Plugin 后续负责贡献的分发与更新，接入这些接口；运行内核不承担插件安装与生命周期管理。

这与仓库已有的 [Plugin 设计](/Users/robertwu/Documents/Projects/AI+教育创新技能大赛/XunJie/docs/student-agent-implementation/references/2026-10-27-agent-capabilities-design.md:88)保持一致，也保留未来接入教师 Agent、MCP 和个人扩展的位置。

本轮完成运行时拆分、两个学生场景、主页学习查询与自主学习创建闭环。教师创作、通用作品编辑、DDL 数据模型和学习画像算法继续留待后续。

## 2. 代码组织与公共接口

新增三个包：

| 包 | 职责 |
|---|---|
| `@xunjie/agent-runtime` | 会话、输入控制、Run／步骤推进、命令与等待记录、派发许可、原子提交 |
| `@xunjie/agents` | 场景装配、共享能力、业务工具适配和可选执行策略 |
| `@xunjie/model-gateway` | 现有模型配置、协议适配、调用、原生上下文与结果管理 |

新 `agents` 包在 [packages 目录](/Users/robertwu/Documents/Projects/AI+教育创新技能大赛/XunJie/packages)下，源码布局为：

```text
agents/src/
  student-assistant/       # 主页角色、提示词、上下文与装配
    tools/                 # 学习查询、创建个人工作区
  workspace-assistant/     # 当前工作区角色、规则与装配
    tools/                 # 当前作品、组件、实验等工具适配
  capabilities/
    documents/             # 资料与 PDF
    skills/
    user-questions/
    context-compaction/
    tool-discovery/
  execution/
    direct-runner.ts
    async-waits.ts
    run-coordinator.ts
```

**工具的 Agent 接口在 `agents`，业务操作仍由实际数据 owner 实现。** 例如查询课程调用课程公开接口，创建工作区调用学习数据接口，实验调用执行接口；工具不自行跨库操作业务表。

接口和依赖遵守以下约束：

- `contracts` 提供独立的 `AgentSession`、`AgentInput`、`AgentRun`、`AgentEvent` 和 Port；不再从具体实现的 `ReturnType` 推导跨包接口。
- `agent-runtime` 与 `model-gateway` 均不依赖 `agents` 或 `learning-space`。`agents` 使用领域公开接口；`product-runtime` 完成身份、部署和传输接线。
- 跨模块 HTTP／RPC 装配上移 `product-runtime`，消除 `learning-space → agents → learning-space` 的循环。
- Skills 包解析从运行逻辑中分离；通用分块持久化、来源校验下沉为独立功能模块，领域规则仍留在对应 owner。
- 沿用现有能力声明、固定工具绑定和步骤快照；模块通过功能子路径显式装配，未装配模块不启动扫描、定时器或任务。进行中的步骤继续使用原绑定，能力缺失不能静默换实现。

## 3. 会话、运行与学生场景

**独立会话与固定路由**

- 普通会话使用 `sessionId`，不再要求活动、课程或作品字段；工作区工具仍使用真实 `activityId`。
- 学习数据 owner 保存会话目录、固定 Agent owner 与可选工作区关联；Agent owner 保存会话执行状态和完整消息。
- 创建会话时固定主体、场景和 Agent owner；修改成员绑定只影响新会话。跨 owner 初始化使用原操作身份续接。
- 主页与工作区会话独立，不通过切换提示词把同一会话变成另一种场景。

**最小执行机制**

- 具备宿主独占保证时使用 `DirectRunner`，按 Run 串行处理输入、回应和结果事件。
- 增加待处理唤醒标记及退出前复查，修补当前 `kick` 在推进者退出期间可能丢唤醒的问题。
- 普通问答也可能等待模型容量，因此活跃调用保留针对原 attempt 的通知或有界重试；等待学生回应不轮询。
- 异步工具按需装配等待与唤醒模块；只有同一 Run 存在多个推进者竞争时才装配 `RunCoordinator`。远端部署本身不等于需要租约。

**派发权限与恢复**

- 派发许可与租约分离。内核保留绑定 session、Run、步骤／attempt 和持久 generation 的可撤销许可；模型与工具在实际派发前复核。
- 停止、撤权、维护关闭及迟到回调不能产生新的未授权派发；读取原结果使用独立的恢复路径。
- 主页切换页面继续回答；进程重启后恢复历史、问题和原回执，未完成生成进入“需要继续”状态。明确续接才允许新的外部派发。
- 工作区沿用已有恢复语义，由启动恢复和实际等待模块接续；纯资料工作区不因此加载常驻实验扫描。
- 提问／等待创建、回应消费、模型结果与工具意图、压缩采用分别保持原子提交。共享模块与内核通过窄提交接口协作，不因拆包拆散事务。
- 未知结果沿原 attempt／command 查询；压缩、换段、模型切换均保留原调用和来源身份。

**场景能力**

| 能力 | 主页 Agent | 工作区 Agent |
|---|---|---|
| 知识与资料问答 | 支持 | 围绕当前任务 |
| 学习数据查询 | 本人获准范围内搜索课程、作品、实验记录和对话 | 当前任务完整上下文，以及同课相关学习事实 |
| 操作已有工作区 | 不装配 | 按实际组件和任务规则装配 |
| 创建自主学习工作区 | 支持 | 不装配 |
| PDF、Skills、提问、压缩 | 按需组合 | 按需组合 |

主页采用 `list_learning_tasks`、`search_learning`、`read_learning`：先目录或搜索定位，再分页、按范围读取。返回稳定来源、版本、可继续读取的入口及缺失信息，不推测不存在的 DDL 或执行结果。

宿主提供可信的个人／当前学校身份映射，各 owner 在查询和详情读取时授权。跨工作区对话作为来源数据，不能作为当前用户指令；课程帮助规则随相关来源适用，检索课程不会自动装载该课程的全部 Skills。

**自主学习创建与附件**

- 普通首问和上传资料只建立会话。明确要求创建时直接调用；仅表达学习目标时，先提问，确认后创建。
- 创建目标固定为**本机个人身份和本机学习数据 owner**，模型不能选择学校落点。
- 一次创建产生一个项目、一个工作区和一张个人卡片，包含目标、简洁任务清单、相关资料与必要交接上下文；只使用已有组件，不自动运行实验。
- 工作区拥有独立会话。依据真实创建回执，在回答末尾显示 `MessageTaskCard`，并更新首页 `CourseTiles`。
- 项目创建、资料关联、会话初始化和卡片投影使用同一操作链的稳定身份。已确认创建成功后可幂等补齐关联；丢回执不能再创建一份。
- 主页附件归本机学习数据的 session 范围。交接给本机工作区时建立独立保留引用，删除主页会话不能破坏已采用资料；远端资料保留固定来源引用，读取时重新授权。

## 4. 部署影响与实施顺序

**会影响构建和部分服务契约，但不要求改变现有部署拓扑。**

2026-11-14 已更新开发学校的应用快照并显式重建受影响的旧 Agent 开发数据。学校为 `ready`，启用 `space-course`、`learning-data`；停用的 Agent 和模型 owner 保留并使用新备份边界。本机正式预览按五模块配置运行，已退役六条无消费者的旧教学依赖连接记录；当前学校学习授权连接、全部凭据文件、原身份、模型配置和无关业务数据保留。

| 链路 | 处理方式 |
|---|---|
| 默认本机五模块＋学校两模块 | 保持分工；账号、课程受领、明确提交等既有学校接口保持可用 |
| 独立／学校 Agent、配对模型 | 同步更新 session 路由、派发许可及受影响 RPC 契约 |
| 学校之后更新应用快照 | 同时检查共享数据结构及停用 owner 的维护验证 |
| 本机预览、产品包、旧 server 云端制品 | 分别维护各自构建入口，不能用一种制品替代另一种 |

源码包名与安装模块标识分开处理；本轮保留现有 `teaching-agent`、`model-connection` 部署标识及环境、服务、安装身份。

受影响的 Agent／依赖／模型调用契约显式升版本，在产生副作用前识别不兼容组合。默认学校未变化的业务接口不被整体版本升级牵连；历史 owner 不可用时不静默改派。

实施顺序调整为：

1. **建立包与依赖方向，同时接通工程入口。** 一并修改 exports、构建图、开发预览依赖准备、源码 resolver、CI 制品清单和产品 bundle 白名单。
2. **完成独立会话与派发许可。** 同步迁入历史列表、附件、HTTP／RPC、传输幂等、模型来源及恢复校验。
3. **装配两个场景和执行策略。** 完成主页查询、创建闭环，迁入工作区已有能力，删除被替代入口。
4. **完成部署与数据切换验证。** 在隔离环境验证后处理既有开发环境，更新当前架构与部署文档。

按已确认范围允许重建受影响开发数据，不承担旧 Agent 数据和旧备份兼容。重建按 owner 及引用关系处理，覆盖旧会话、关联历史、模型任务来源和传输记录；保留模型配置、凭据、安装身份及无关数据。不得清空整个模型 owner，也不得在普通启动时隐式删除数据。新结构必须具备自身的完整备份与恢复校验。

## 5. 验收与完成标准

- **架构：** 无循环依赖；内核不引用教学领域；主页未装配全库扫描和租约续期；缺失可选能力不启动相关过程。
- **运行：** 覆盖回应与退出竞态、模型容量等待、并发输入、steering、停止后迟到回调、重复回应、未知结果、压缩中断及重启续接。
- **产品：** 普通问答不创建项目；确认、拒绝、直接创建、丢回执、卡片刷新、双会话独立及附件保留均符合约定；学校视图下创建仍落到本机个人空间。
- **部署：** 覆盖默认本机／学校组合、独立 Agent、配对模型、受影响契约的混合版本拒绝，以及保留停用 owner 的备份恢复。
- **工程：** 运行相关真实存储、三协议模型、工具与恢复测试，再完成统一验证；显式运行相关 `.runtime.test.*`，不能把默认 `verify` 当成已覆盖这些测试。
- **浏览器：** 桌面 Chrome 验证主页、工作区、附件、创建入口、页面切换与应用重启；默认链路核对本机模型调用和学校无新增模型任务。工程、浏览器、真实模型与真实执行结果分别报告。

## 6. 实施状态（2026-11-14）
