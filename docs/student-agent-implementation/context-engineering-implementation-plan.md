# 循阶上下文工程实施方案：先交付两个学生 Agent 的完整学习链路

## 一、交付目标与实施基线

**第一批交付以学生能完成一次可信的持续学习为准。** 学生在工作区引用一版作品、提出问题、作出预测、查看实验结果、修改作品，隔几轮后仍能得到针对正确版本的辅导。回到主页追问时，主页 Agent 能定位同一次实验，遵守原课程的帮助范围，并给出可以打开核对的出处。

优先级已确定：**在授权、教学要求和预算约束内，优先保证完整回答的质量。** 首次回复速度、缓存命中、压缩率和 token 消耗用于发现问题和比较代价。选取方案时，先看模型是否拿到了正确依据，再看它是否给出了更准确、更有帮助的回答。

**第二批交付教师发布规则预览，以及获准排查者的专用回看界面。** 第一批就要形成这两个入口依赖的规则来源、请求记录和访问控制，以免第二批被迫重做数据链路。长期记忆、能力评分、后台压缩和供应商不透明压缩不进入本次范围。Q55 的连续摘要回查规则保持未决，本方案不追加压缩要求。

**交接基线。** 本方案对照的本地提交是 `c965b015`，检查时处于 detached HEAD。本次讨论形成的领域术语和决策记录是工作区内已有的未提交改动。下一会话先检查这两份文档是否可见、是否出现新决议，再核对目标分支与该提交的差异。若换了工作区，不能假定这些未提交内容已经随 Git 同步。决策记录中的 **CE 编号与 Q 编号并非一一对应**，执行时按条目标题与正文取义。[决策记录](student-agent-decisions.md) · [学习领域术语](../../CONTEXT.md)

当前代码已有一条可继续改进的正式链路：

| 环节 | 已有能力 | 本次要补齐 |
|---|---|---|
| 两个 Agent | 主页与工作区独立场景、独立会话；工作区已有分层提示词，主页已有获准学习查询与个人项目创建流程 | 共享底线和场景职责统一维护；整轮固定模型与规则；主页任务来源、工作区提示上限落实到工具、回复及出处 |
| 上下文装配 | 场景提供 `system/facts/sources`；内核合并输入、历史、任务通知和有界任务事实 | 来源身份、已读范围、作者、版本和省略原因贯穿到实际请求；历史重新授权；避免用拼接文本承担全部语义 |
| 模型连接 | 三种协议、原生段续接、真实请求资源、Attempt、usage 与工具回执配对 | 在最终协议请求上核算窗口，给容量不足提供有界退路；撤权或更换有效材料时安全重建模型视图 |
| 工具与压缩 | 具体工具支持部分范围读取；已有约 8 KiB 的工具反馈策略、分类摘要、来源校验与压缩采用记录 | 各类工具提供可用于判断的反馈和真实回读入口；保护近期完整交互；纳入教学阶段、最终容量与语义验收 |
| 产品与日志 | 已有正式聊天、附件、引用、任务记录、进度与用量入口；事件与模型原件已有各自持有方 | 学生可点回证据，缺口可解释；串起一次回答的装配决策和实际请求；按权限回看与清理 |

沿用 `Session → Turn → Step → Attempt / ToolCall` 和唯一主循环。产品宿主处理身份与路由，场景处理教学含义，内核处理每步装配和生命周期，模型连接模块处理协议、请求与真实用量。**不另建上下文服务、第二套会话库或第二个工具循环。** 恢复继续遵守既有决策：中断结束旧 Turn，手动继续开启新 Turn，已经执行的操作按原身份核实。[直接 Turn/Step 主循环决策](adr/0004-direct-turn-step-loop.md)

## 二、第一批实施顺序

### 0. 固定基线与验收案例

先建立一小组能反复执行的输入，保存课程发布版本、作品版本、学生消息、工具回执以及评阅依据。**先跑现状，再修改行为**，避免把已有正确行为计为改进，也避免把研究文件旧快照中的缺口直接当成现行缺陷。

- **工作区主案例**用数字逻辑：v7 选区提问 → 预测前只见执行状态 → 提交预测 → 读取真实结果 → 修改为 v8 → 学生纠正问题 → 多轮后追问。加入一次结果未知，以及一次停止后更换模型再继续。
- **主页主案例**用同一实验的明确引用、两次实验造成的歧义、两份讲义的跨来源比较，以及其中一份资料随后撤权。覆盖一次“主页个人探索可给完整示例”和一次“教师任务仍受帮助限制”。
- **跨课程案例**用固定的 C 语言循环、触发输入、学生原预测和测试输出。用它检查版本、来源、诊断与压缩后的回答。正式 C 编译器、第二套课程工作区和课堂教学效果分别验收。
- 工程定位优先从 `@xunjie/agent-runtime`、`@xunjie/agents`、`@xunjie/model-gateway`、`@xunjie/product-runtime` 和正式 Web 产品入口开始。旧教学 `RunDriver` 文档、带 v2 名称的旧测试和独立 server tutoring 链路只作对照，先核实真实调用者再复用。

### 1. 固定整轮模型与规则，统一两个 Agent 的行为

**Turn 首次开始处理时，建立一次不可变的运行配置。** 配置至少关联场景及版本、平台规则模板版本、适用课程发布与帮助规则、模型连接持有方、连接及配置版本。普通首问、手动继续、后台终态通知启动的 Turn，都经过同一个入口。将固定结果与 Turn 持久关联，各 Step、主模型重试和辅助压缩都从这里取值。

- 现状中主模型生成、建段和压缩路径分别读取当前模型选择。改为把同一份固定选择传到底层；宿主设置变化不能让同一 Turn 的后半段换模型。固定连接失效时如实结束或说明原因。**活动中的 Turn 禁止切换模型**；学生可以停止、切换，再在原 Session 手动继续。执行权限依旧在每次工具调用时检查。
- 在 `@xunjie/agents` 中维护共用规则、主页职责、工作区职责和课程规则的确定性装配。记录组成版本。学生材料、课程正文和工具输出进入资料位置。课程始终使用活动绑定的发布版本。个人项目仍有工作区提示上限。
- 主页直接处理普通知识问答和个人探索。明确关联教师任务时，先取得该任务的规则；只有任务迹象明显、来源不明且回答边界受影响时才澄清。创建个人项目继续使用既有真实确认和幂等回执。
- 工作区提供概念解释、验证步骤、排错建议和必要局部示例，帮助程度以“提示”为上限。教师规则可以进一步收紧。展示示例、修改作品、执行实验是三个不同决定，各自由原有权限和场景约束控制。
- 第一批通过**已有课程发布导入路径**接入教师已确认的规则。现有帮助合同只有问答开关、范围和备注；首次需要机器执行的教学阶段约束时，增加可版本化的明确选项，至少能表达“预测提交前隐藏实际结果”。旧发布按原固定规则读取。自由文本用于说明，不能覆盖明确选项；需要新增持久 schema 或迁移时，先向负责人说明范围、风险及回退方式，取得同意。

**完成标志：** 在模型 A 的同一 Turn 中连续使用工具、重试、触发压缩，真实请求始终使用 A；停止后改用 B，新 Turn 继承允许携带的对话和事实。主页与工作区对同一请求能按各自职责给出不同、合规的帮助。

### 2. 让一次 Step 的材料可以识别、核对和重新授权

#### 每步可见历史与最终请求的职责分工

**已通过架构评审（2026-11-19）。** 沿用 `ScenarioContext → ContextPlan → GenerateInput`。场景提供获准材料及其业务含义，`agent-runtime` 决定每个 Step 的逻辑可见历史，`model-gateway` 负责把这个决定落实到实际派发的协议 payload。

- **内核输出。** 交付有序材料项、上一份已采用投影的标识，以及本步的新增项和表示变化。每项保留稳定身份、来源、版本或范围，并指定内联正文（`inline`）、简短观察与回读引用（`compact`）或仅引用（`reference`）。学生输入按输入身份区分，作品片段按固定版本和范围区分，工具结果按逻辑 `toolCallId` 区分。
- **Gateway 续接。** 对照上一份已提交投影和 `expectedSequence`。如果只有新增项，就复用原生历史并追加。如果旧工具反馈改为简短观察，就用产生调用的 Attempt 和 `nativeCallId` 定位协议中的结果，仅在本次请求副本中替换其可见内容，保留原调用、同批顺序和结果状态。历史请求及工具执行回执继续按原版本保留。
- **安全重建。** 来源撤权、映射失效或协议无法安全替换时，先依据已有执行回执结清未闭合配对，再从当前获准的可移植材料开新段。重建后仍无法满足授权、配对或容量条件时，停止本次派发并返回具体原因。重建不重跑历史工具。
- **装配回执与验收。** Gateway 在最终编码后核验容量，将投影标识、材料与协议位置的映射关联到实际 Attempt 的 `requestRef`。重试沿用本步材料选择并复核授权，各次请求分别留痕。验收核对三种协议实际外发的 payload 和对应保存的请求，覆盖下文超过 8 KiB 的工具反馈用例。

**消息顺序（2026-11-19 确认）。** 请求头承载适用规则及本步工具定义，由协议决定具体字段。首次建段或重建时，在依赖它的消息之前提供必要活动背景。保留已有历史的先后关系，之后按接纳顺序追加消息组：

1. 一次学生输入形成一组，先放原话，随后关联本次显式引用的版本、范围和首次片段。两次输入保持“问题 A 和选区 A、问题 B 和选区 B”的顺序。选区提问默认只内联选区、文件名、版本与位置，附范围读取入口。相同片段仍在有效历史时只关联引用。同一 Session 后续 Turn 可在重新授权后回读最初固定的版本。
2. 工具续接先闭合上一条 assistant 调用的整批交换，按原调用顺序配对。期间收到的学生纠正随后按队列接纳。纯工具续接可直接以反馈结束。技能正文、PDF 页或波形经工具取得时随对应反馈出现。
3. 动态事实单独标来源。已知事件沿用接纳顺序；本步接纳输入后才读到的变化，在派发前追加一次。未变快照不重复注入。旧历史摘要占据被替换的闭合区间，之后保留近期消息的原顺序。

**工具反馈保留。** 同一 Session 最近四个已完成 Step 构成初始窗口，跨 Turn 计数，每个 Step 的多个 Attempt 共用一个名额。窗口内普通文本工具反馈正文按 UTF-8 累计，24 KiB 以内原样保留。超出时从最旧的可压缩项开始替换，并计入带回读指令的摘要大小。窗口外只处理正文超过 8 KiB 的反馈。摘要最多 1200 字符。`readWith` 采用当前 Step 实际暴露的读取工具，附固定版本、页码和范围。图像、失败或未闭合状态以及没有可执行回读计划的结果保留原文。若保留的证据使窗口仍超预算，由最终请求的容量检查处理。

首版默认值采用本地对照结果。Codex CLI 默认工具输出上限为 10,000 bytes，约 90% 上下文时自动压缩。DeepSeek Harness 默认 80% 时触发压缩，保留约 16% 近端上下文，默认文件读取上限 50 KiB，普通 shell 默认收集 64,000 bytes。

**请求级用例。** 捕获首次选区提问、纯工具续接、工具期间收到纠正、压缩后重建四种请求，对照材料来源、顺序、配对和出现次数。Step 1 返回带唯一标记、超过 8 KiB 的可回读文本时，最近四个已完成 Step 的请求各含一次该标记；出现第 5 个已完成 Step 后的请求中原标记消失、短反馈与 `readWith` 仅出现一次，仍能还原 Step 2 的原请求。

| 最小合同 | 输入与结果 |
|---|---|
| **材料引用** | 标识来源持有方、场景或任务、对象、版本、范围和内容类型；记录作者或产生方式，包括学生原话、学生引用、系统观察、工具结果、历史摘要。正文可内联，也可指向已有不可变原件。 |
| **本步装配结果** | 提供固定规则、当前问题、近期历史、已选材料与工具集合。对明确选择、规则要求或实际尝试读取的材料，记录已发送范围、只发送引用、权限拒绝、读取失败、预算省略等结果。 |
| **动态事实** | 有来源、作用域、观察时间或版本。明确清空使旧值退出当前状态；读取失败表示当前未知；本步未查询保留上次观察的时间和版本。 |
| **模型可见反馈** | 工具执行状态、关键观察、适用作品版本、已读或已省略范围、真实回读入口。完整原件继续归实际工具或资料持有方。 |

实施要求：

1. **固定学生提问。** 保留发送时的原话、选区、作品和附件版本。后来的修改、任务完成或结果更正，作为后续 Step 的新事实。学生引用讲义中的一句话，只能说明他引用并询问；记录其认同或独立预测需要对应原答和当时的提示条件。
2. **按场景主动提供最小集合。** 工作区提供活动目标、适用规则、问题、固定选区、相关作品与执行状态；主页提供当前问题、附件信息和明确关联的任务。其他文件、旧会话、完整报告按需读取。学生指明第 37 条反例时优先读第 37 条；整体排错则给总体情况及分类型的少量代表用例。
3. **把权限检查接到实际历史投影。** 产品分派器目前在缺少场景钩子时可原样返回历史。对含课程或外部受控来源的历史，必须由对应持有方复核。明确撤权后，原文、引用、受影响的摘要及原生历史都不得进入新请求；混合内容无法拆分时，从其余获准事实重建。临时无法核验时，只暂停依赖该资料的判断。发布新版且旧版仍可访问，不触发撤权处理。
4. **避免从协议续接绕过授权。** 仅过滤可移植文本还不够：模型连接可能从上一请求重放原生历史。当前有效来源发生撤回时使旧段失效，先按真实回执结清工具配对，再从获准材料开新段。历史回看继续遵守当前查看权限。
5. **固定本步工具含义。** 模型看到的定义与执行登记来自同一集合。远端设备执行时检查原绑定及兼容性。若范围单位或行为已改变，返回“未执行、工具已更新”；下一 Step 再读取定义。常用工具直接提供，其他能力按需发现。显式选择 Skill 时读取其固定版本正文；对同一有效上下文中已经可见的相同范围去重。
6. **教学阶段过滤放在读取端。** 预测提交前，结果查询、范围回读、波形图片及主页查询同一实验都只返回该阶段获准的信息。提交后可读取对应输入和版本的结果。已在自由实验展示过的现象可标记为“曾展示”；不推断学生一定看过、记住或掌握。
7. **大结果按实际语义返回。** 编译提供关键诊断和行号；波形提供信号、输入和时间范围；资料提供页码和片段。沿用已有 `read_result`、作品、PDF、Skill 等读取入口。确有缺口的工具才补固定结果的范围读取，重新授权并校验版本。读取失败保留原状态，不能以重新运行实验代替读取。

**完成标志：** 能区分“学生明确选了 B，但读取失败”“B 因预算未发出”“B 已发出而模型遗漏”；同一请求可追到模型实际收到的版本、范围和角色。无需为整个资料目录逐项记录未采用原因。

### 3. 在最终模型请求上管理容量，并接回现有压缩路径

**窗口压力（2026-11-19 确认的首版基线）。** 设 `W` 为有效窗口，`O` 为本次实际输出预留，`M` 为误差余量，`B = W - O - M` 为可用输入预算，`I` 为最终协议输入估值。仅在窗口已知且 `B > 0` 时计算 `P = I / B`。缓存命中的输入计入 `I`。首版余量取 `W` 的 5%，涉及图片估值或未经校准的启发式计量时取 10%。窗口未知时标明未知，沿用路线限制和有界溢出处理；预留已用尽窗口时先处理配置或输入范围。

| 压力 | 动作 |
|---|---|
| `P < 80%` | 正常投影、去重和派发，无需生成摘要。 |
| `80% ≤ P ≤ 100%` | 先去重、缩减可回读的大结果并重算。降到 80% 以下即可派发；否则有合法旧前缀才摘要。没有可压前缀且仍可容纳时直接发送。 |
| `P > 100%` | 当前候选不能直接派发，处理可选材料或已闭合旧历史后，以最终 payload 重新核算。必要材料仍超限则说明具体缺口。 |
| 摘要采用 | 目标回落到 60%。为保住必要证据，可采用确实缩小且可容纳、但未降到 60% 的候选。保留现有 240,000 字节摘要源、2,048 输出 token、每 Turn 两次尝试的上限作为启动参数，摘要请求自身也须能容纳。 |

边界用例取 `W=64,000`、`O=8,000`、`M=3,200`，软触发为 42,240 输入 token，回落目标为 31,680。若实际投影从 43,000 减到 40,000，应派发且摘要调用次数为零。实现时分别覆盖略低于触发线、恰好达到触发线、超过准入线，以及只有大附件而无旧历史可压的情况。

**窗口预算在模型连接持有方计算。** 该模块能看到三种协议编码后的完整 payload，包括系统规则、工具定义、原生历史、图像和工具结果。内核决定如何减量，但不从抽象消息列表推测最终请求的精确 token 数。

- 抽出已有原生 payload 构造逻辑，让容量检查、实际派发和请求快照使用同一结果或同一规范化指纹。检查发生在外发前，并区分**上下文窗口、传输字节硬限制、Turn 累计预算与模型持有方共享准入**。当前代码还有独立的 payload 字节限制；不能把字节超限都解释成模型窗口不足。
- 给内核返回最小预算结果：模型与协议版本、请求指纹、计量方法、输入估计、输出预留、安全余量、未知项、是否可派发及主要占用来源。返回后另存供应商原始 usage，区分实测、估算和未知。缓存与 reasoning 字段按路线口径处理，避免重复结算。
- 精确计量可用时优先使用。同模型、同路线、同计量口径且原输入原样保留，才允许“上次实测输入＋本次增量估计”；历史、工具、图像范围或规则前缀发生实质变化，重新估算。完整历史被同一原生协议重放时，不能因应用层没有再次拼接就漏计。
- 超限处理顺序固定：去除实际重复 → 缩减无关和可回读正文 → 对已闭合的旧历史做有界同步摘要 → 按最终 payload 再检查。当前问题、适用规则、关键版本、未决操作身份和支撑判断的证据优先保留。媒体是必要证据时，保住相关页、图或区域；能力不足就说明缺口。
- 容量不确定但留出余量后可容纳，使用本轮模型尝试一次。供应商明确拒绝容量后，**建议首批工程默认最多一次缩小后的容量重试**，且必须证明确实缩小、必要依据仍齐全、未重复派发工具。这是可按基线校准的实现默认值，不是此前确认的产品阈值。收到未知回执时先按原 Attempt 查询，不按容量错误盲重试。
- 压缩沿用现有分类摘要、来源验证、次数及开销限制。补入近期完整交互的独立预算，保证调用与结果成对；按工作区或主页的既定重点交接。候选摘要先构造候选请求并核验容量，再采用。摘要失败保留原上下文，若仍能容纳即可继续。压缩期间新消息按现有队列在之后处理，停止操作按原取消机制处理。第一批不实现 Q55 的新规则。

**完成标志：** 三种协议均能解释一次派发为何可容纳、为何减量或为何暂停；缩小、压缩和换模型后不沿用失效的实测基准，不会为通过容量门槛丢弃问题所依赖的一张图或一份结果。

### 4. 接通学生端出处、跨场景询问与日志回看依据

- 给正式会话回复增加可选的结构化出处，关联**回答中的具体判断、固定来源与定位范围**。工作区能打开对应版本的实验、用例或信号；主页能打开相应资料页或片段。一般概念解释保留普通文本，推断注明依据和可验证的下一步。
- 依赖具体材料的问题先查证，再带出处流式回答。查证期间可显示真实进度。链接生成前验证该来源确实在本次获准且已读范围内；页码错误时补读，不能核实时修正或撤回相关句子。技术校验只能证明定位有效，语义是否支持结论由质量案例验证。
- 从实验结果发起主页询问时传固定结果引用，主页复核权限与阶段。自然语言“刚才的实验”先查询，能唯一定位就交代对应版本后回答；多个候选会导致不同结论时再请学生选。主页不接管已有工作区的执行操作。
- 复用正式聊天、进度区、输入框用量和已有材料查看入口。正常压缩只在等待明显时显示进度；影响结论的材料缺口写进回答。用量标明实测、估算或未知。修改 UI 前读取根 `DESIGN.md` 和 `packages/ui/README.md`，沿现有 `@xunjie/ui` 入口实现。
- 每次实际模型调用能够从 `sessionId / turnId / stepId / attemptId` 查到装配记录、实际请求、返回、压缩采用及工具结果。第一批实现**可被自动化验证、受权限约束的只读查询**，复用原件和引用。第二批专用界面直接消费该查询。回看不能触发模型请求、实验或历史重放。
- 保留会话时，同时保留还原它所需的持有关系。压缩、换模型、页面关闭和会话归档均不删除原件。清理前显示影响范围，只释放本会话拥有且无其他有效引用的资源；教师课程、已提交作品与独立实验记录继续保留。受保护来源撤权后按当前权限展示。历史不完整时，允许依靠独立可核验的原件继续辅导。

**完成标志：** 从正式工作区到主页走完数字逻辑主案例，学生能打开出处；获准排查者能查清某条回答用的是哪份材料。学生看到的正常对话、模型工作上下文和技术回看各自满足自己的用途。

## 三、验收、兼容与交接

| 验收层 | 必跑场景 | 通过条件 |
|---|---|---|
| 内核与授权 | 同一 Turn 多 Step、重试与压缩；停止后换模型；权限撤销；迟到回执；消息在压缩期间到达 | 固定模型和规则生效；无隐式重派、串版本、越权原生重放或丢失新输入 |
| 模型协议与预算 | Chat、Responses、Messages；中文、代码、PDF 页图、长工具结果；缓存字段、未知 usage、容量拒绝 | 调用与结果配对合法；计量与账单可区分；用量失效后重新估算；重试有界且只在请求实际缩小后发生 |
| 证据与教学 | 预测前后、曾展示的结果、学生引用与认同、v7/v8、缺页、来源撤回、课程任务和个人探索 | 工具和公开答复都遵守教学阶段；给出的判断能回到正确版本与范围；观察、学生原话与推断清楚可辨 |
| 质量对照 | 现行方案与候选方案采用相同案例、配置和证据；评阅刚纠正后的回复与多次压缩后的追问 | 先核对模型实际输入，再做少量重复的匿名成对评阅。硬条件失败逐项追查；更好的解释可以有多种。优势不稳定就记为尚无定论 |
| 桌面 Chrome | 正式主页、工作区、打开出处、跨场景追问、停止/切换/继续、缺失资料提示、进度与用量 | 用真实产品主链验收。合成浏览器夹具、真实 PostgreSQL/宿主、真实模型提供方及真实实验结果分别标明，互不替代 |
| 保存与恢复 | 请求回看、备份/隔离恢复、旧会话读取、同一原件被多个会话引用、共享资料撤权 | 已保存请求按原版本可还原；回看零外部副作用；清理不影响仍被持有的资源。历史来源不明时不能按现行规则猜造 |

**验证顺序。** 开发时先运行对应包的 typecheck 和定向测试。优先扩展现有 `loop.runtime.test.mjs`、会话恢复、模型选择、三协议模型回归、工作区引用和正式会话控制用例。每个用例先确认命中当前生产入口；某些历史浏览器用例名称或 fixture 仍指向旧链路。集成后运行 `npm run typecheck`、`npm test`、`npm run build`，并用 `npm run test:e2e -w @xunjie/web` 运行相关桌面 Chrome 场景。依赖 PostgreSQL、学校/设备配对、真实模型或真实仿真的项目按实际条件单列。未执行不得记为通过。

**兼容与回退。** 优先使用现有不可变资源、事件、Step 快照和可选版本字段。旧记录缺少出处时标为未知，旧历史没有可证明授权的受控正文时采用保守投影。新增字段必须能让旧会话继续正常打开；不能用当前发布或当前模型重建一份冒充历史的快照。若需要数据库 schema 变更、迁移、删除文件、修改密钥或 CI/CD、公开发布，按仓库红线先说明操作和风险并单独获准。回退以停止新写入、保留原件、恢复经验证可读取该数据版本的实现为原则。

**第二批交付。** 教师端在既有备课与发布预览中展示从讲义提取的规则、出处和冲突，允许修改、移除并随任务发布一次确认。排查者界面按回答和 Attempt 只读展现“明确选择了什么、发出了什么、哪些内容因何缺失、哪些出处支持结论”，沿用第一批权限与索引。两个入口各自做正式产品验收；第一批宿主与学生端门禁无需等待这两个专用界面完成。
