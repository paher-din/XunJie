# 本地优先执行与课程运行方案

## 原决议

负责人已确认以下方向，并明确补充：平台需要适应不同课程及教师任务；提供所需工具、减少教师与学生的繁琐操作，是重要产品要求。**关闭本票表示运行方向、边界与验收要求已确定，不表示运行包已经发布或跨平台支持已通过。**

### 1. 公共执行契约，课程按任务组合

平台采用“公共执行契约 + 可扩展工具和环境 + 按任务组合”。公共层负责环境准备、运行身份、依据绑定、查询、停止、结果交还与恢复；学科算法、具体交互和评价方法由课程工具与任务定义。同一课程的不同任务可以使用不同工具与运行安排。

- 工具可以提供有限作业、保持状态的会话，或无需计算的编辑/标注活动；一次构建也可供后续会话装载。预测、编译、单次运行、自动判定对错都不是平台强制步骤。
- 输入可以是作品、代码、数据、文件或结构化对象；结果可以是数值、日志、图表、文件、波形或连续事件。执行成功不等于任务完成，也不等于知识掌握。
- 教师/Agent 可以创造新界面、新算法和新任务流程，经过接入验证后装入课程，不能只允许修改预制模板参数。
- 现有执行能力能承载的新依赖、程序包或解释器，应通过已有环境装配方式随工具交付；只有新的系统能力、硬件访问或执行/控制机制超出现有支持时，才新增或扩展执行适配。主工作区不得按课程增加专用业务分支。
- ALU 是首个具体适配。时序电路的状态与时钟、数据分析的文件与图表、报告/画布的编辑与评价都不得被其模型限制；这些是设计反例，尚不是已验证的其他课程。

本票确定上述行为边界，不提前决定插件框架、包格式或完整教师创作系统。

### 2. 提供可用工具，并把准备复杂度交给产品

教师负责表达教学任务、选择或创建所需工具、核对教学内容与运行安排；平台与 Agent 应承担工具推荐/装配、依赖配置、环境检测和可自动完成的准备。通用性不能以教师手写运行配置、安装编译链、填写端口或排查执行节点为代价。

- 常用能力提供可复用工具与合理默认值；缺少能力时可借助 Agent 创建工具，并明确它是否满足任务，不能只交付抽象 SDK 让教师自行集成。
- 课程准备应串起任务描述、工具装配、检查与预览、发布；默认只展示教师做教学决定所需的参数，保留高级配置入口而不把它设为必经步骤。
- 工具及运行方案须提供可执行自检和示例输入，便于课前预览、发现依赖缺失、环境不匹配或未支持的操作；学生进入时仍检查其实际设备，教师预览通过不冒充所有学生设备通过。
- 可修复问题由产品准备或修复；必须人工处理时，说明原因并给出明确下一步，保留已完成的配置和作品，避免来回切换页面、重复填项或从头配置。系统必需的确认集中、清楚地呈现。
- 后续验收同时记录教师准备与试用中的实际操作、阻碍、错误恢复及需要工程人员介入的位置；不能只用“工具运行成功”判断教师体验合格。具体耗时与步骤阈值由体验验证确定，不凭空承诺。

本条是教师工具交付与运行安排的输入要求；完整教师端 Agent、市场和创作页面仍不在本地图展开。

### 3. 本地优先与设备准备

首批正式验收目标：Windows 11 x64、Apple Silicon Mac，桌面 Chrome；具体版本随验收记录固定。允许安装，但下载、安装、依赖配置、检测与更新由产品尽量自动完成，学生不手工搭建工具链。未硬性排除 Docker/WSL 等底层技术，也未同意把其手工配置作为默认准备方式。

按具体能力选择位置：浏览器完整满足所需语义、资源及交互时优先浏览器；确需原生能力时使用自动准备的本机环境；仅本地确实不能满足时，才使用教师方案预先配置的适用远端路径。课程可组合多种位置的能力，学生不选节点。

尚未准备、权限待确认、可修复版本问题、设备确实不满足、原运行失联分别处理；一次加载或运行失败不自动成为换位置重跑的理由。环境与工具版本随方案固定，新版本先验证，已有运行保持原环境，失败可回到已验证环境。最低资源需求与安装耗时通过目标设备测量确定。

### 4. 首条 ALU：浏览器 Worker 内 Icarus/WASM

采用浏览器本地预处理、编译、仿真及 VCD 生成的方向。界面与 Worker 直接交换任务及结果；自由实验不经应用服务器或 localhost 组件。保存/同步、Agent 和教师交付仍需要对应应用能力。本活动不默认安装本机组件、WSL、Docker 或 FPGA 工具链。

组合 ALU 复用符合依赖条件的编译产物，按输入进行有界执行；系统处理编译和装载。自由实验改输入即反馈；预测用例先记录预测，再点一次“运行并比较”，运行前不泄露该用例实际结果，已观察结果不能补记成独立预测。Agent 的验证使用独立身份，不抢占学生结果或冒充学生预测。具体教学引导仍遵循首条学习活动决议。

该选择不要求其他课程采用 Icarus、4096 组验证、预测流程或无状态执行。未来原生能力的通信与隔离随具体适配验证，旧 SSH/VM、容器与 VPI 会话不成为默认架构。

取舍：原生 Icarus 增加安装、更新、连接与隔离成本，当前 ALU 尚无必须承担这些成本的能力缺口；已调查的 Verilator/Clang WASM 路线增加 C++ 编译链，主要二态语义不适合用来诊断学生代码中的 X；默认服务端执行目前缺乏必要性证据。

### 5. 共同生命周期约束

- 有限作业、会话和会话内操作均有稳定身份、发起者及课程/任务/学生范围；同一操作身份不能更换输入。重复请求先查询、去重，未知副作用不自动重试。
- 绑定实际输入内容、工具与运行方案版本、环境及相关配置。只有依赖一致时才复用产物；平台不要求每个工具都有编译器或验证器。
- 运行开始后绑定实际执行器及其启动实例；结果、诊断、事件与产物可追溯到实际依据。事件可排序和去重，晚到结果不覆盖新结果。
- 持续会话分别声明输入、暂停、单步、复位、检查点、断线续接等能力。丢失内部状态后建立新实例，不能冒充原会话继续；有状态或有副作用的操作不跨位置默默重跑。
- 请求停止与确认停止分开，由实际执行器确认终止；正常完成和停止竞态保留真实终态。停止不等于撤销已发生的外部效果。
- 有限作业设置时限及输出预算；会话声明资源与持续时间限制、心跳、断连处置及恢复能力。失联意味着尚无可信终态，沿原身份查询，不能直接宣称失败或取消。
- 本地结果与依据先保存再同步；应用服务上的 Agent 与教师交付只能引用已收到的对应记录。代码/输入问题、行为不符、环境失败、取消与未知结果分别记录。
- 首条 ALU 不要求关页后继续长期运行；其他任务若需要跨页面存活或检查点续接，必须选择具备该能力的适配。完整离线教学、源码绝不上云及结果防篡改证明不在本票范围。

### 6. 已取得的证据及其限度

[上游调查](https://github.com/paher-din/XunJie/blob/f7fa9dcc913a889c67450987e80b79aabb060c78/docs/references/2026-10-23-systemverilog-local-execution-research.md)、[原生探针](https://github.com/paher-din/XunJie/blob/f7fa9dcc913a889c67450987e80b79aabb060c78/tools/research/probe-alu-iverilog.py)、[固定 WASM 复现入口](https://github.com/paher-din/XunJie/blob/f7fa9dcc913a889c67450987e80b79aabb060c78/tools/research/serve-alu-wasm-probe.py)记录来源及复现方法。

- [Mac arm64 / Icarus 13.0](https://github.com/paher-din/XunJie/blob/f7fa9dcc913a889c67450987e80b79aabb060c78/docs/references/2026-10-23-alu-iverilog-probe-results.json)：全部 4096 组零不符；进位错误负对照检出 256 组错误，X 负对照检出 1536 组未知输出；生成 VCD，超时可结束直接子进程。
- VeriSim 固定 commit `dc391801af44ec8e99fcdc12c12a3d9a47a5758b` 的六文件经 SHA-256 校验后，在同机[真实 Chrome 155](https://github.com/paher-din/XunJie/blob/f7fa9dcc913a889c67450987e80b79aabb060c78/docs/references/2026-10-23-alu-wasm-probe-results.json)和[内嵌 Chromium 155](https://github.com/paher-din/XunJie/blob/f7fa9dcc913a889c67450987e80b79aabb060c78/docs/references/2026-10-23-alu-wasm-iab-probe-results.json)完成同组行为验证、产物复用、无限推进/零时间循环的 Worker 终止及恢复；逐行规范化结果哈希与原生一致。
- Chrome 样本编译约 51 ms，完整仿真与输出约 126 ms；单输入复用执行约 2.7–4.2 ms，恢复阶段约 10.4–13.9 ms。均为本机小样本，不含公网首次下载或最终产品端到端体验；250 ms 外部定时终止实际有延迟，不能承诺精确墙钟停止。
- 原始 WASM 仍有 `system.vpi` 动态加载诊断；删除模块声明会导致系统任务不可用，不能过滤诊断冒充修复。完整固定构建链尚未取得，不能直接把研究二进制当作可发布包。
- 现有旧验证的 2800 组采样不能代替新活动全部 4096 组。Windows/Edge、正式工作区、教师准备体验和学生教学效果均未通过本次探针得到验证。

可复现 WASM 构建、系统模块初始化修正、固定版本与编译选项、目标 OS/浏览器矩阵、准备/更新恢复、资源与权限边界、产品并发/时序/恢复测试属于后续实施与交付；若无法满足，回到本议题重评路线，不能降低证据要求。

- [工作区交互与状态：自动保存、选区引用、执行依据和提交](https://github.com/paher-din/XunJie/issues/116)：落实作品/数据依据、异步结果归属、自动保存及教师交付。
- [课程工具与生成内容：接入、运行宿主和状态恢复](https://github.com/paher-din/XunJie/issues/117)：落实工具/环境声明、教师与 Agent 创造工具、装配自检及低门槛准备；明确有限作业与持续会话的接入，不能把具体 ALU 行为写入公共宿主。
- [总体架构与复用取舍：模块边界、Agent 内核和部署方式](https://github.com/paher-din/XunJie/issues/119)：检查这些行为契约与整体架构的组合，不由本票替其决定所有模块和部署。
- [重构迁移与验收：数据存储、兼容范围和实施路线](https://github.com/paher-din/XunJie/issues/120)：安排实施与验证；选择差异足够大的第二类工具/课程，检验新任务能否靠工具、配置和环境依赖接入，必要新适配是否无需重写主工作区；加入教师从任务到检查/预览、发布及故障恢复的可用性验证。

工程测试、浏览器验收、教师使用体验与教学效果分别记证据。已知缺口已经明确交接，不在本决策票内伪装成已交付；后续相应议题继续开放，本会话仅解决本票。
