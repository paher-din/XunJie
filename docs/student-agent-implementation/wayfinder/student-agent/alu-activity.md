## 原决议

依据负责人本轮对活动定位、实现深度、语言、主线范围、交付与帮助策略的明确选择，本议题收束为以下活动设计。具体行为表和场景将这些选择落实为后续主题共同使用的设计输入。

### 学习问题与前置知识

学生在课后用 **SystemVerilog** 设计一个 4 位 ALU，并用有目的的用例验证与解释其行为。允许使用 `+` 等内置运算符，学习重点为运算选择、固定位宽、进位、预测与验证；手工全加器推导放在扩展。

学生已经接触课程前三节理论中的进制与码制、逻辑代数、卡诺图，但允许遗忘并在项目中补学。不能把“讲过”当作“掌握”，也不据此假设学生已经熟练编写 HDL、搭建仿真或操作 Vivado。相关材料、页码与补学入口已整理到本地 `course_matrial/README.md`。

完整活动预算为 **50–70 分钟**，是待试用检验的设计目标。建议约 60 分钟分配为：进入理解 5、设计编辑 20、预测实验 15、解释交付 10、穿插补学 10；学习过程可以自由往返，不设强制问答或步骤锁。安装和运行环境提前准备。

### 主线与公开行为约定

负责人选择五种核心操作，减法作为扩展。输入为无符号 `A[3:0]`、`B[3:0]`、`M`、`S[1:0]`、`Cin`，输出为 `F[3:0]` 与 `Cout`：

| M | S | F | Cout |
| --- | --- | --- | --- |
| 0 | 00 | A 的 4 位按位 NOT | 0 |
| 0 | 01 | A AND B | 0 |
| 0 | 10 | A OR B | 0 |
| 0 | 11 | A XOR B | 0 |
| 1 | 00 | `A + B + Cin` 的低 4 位 | 完整和的第 5 位 |
| 1 | 01、10、11 | 0，本版保留组合 | 0 |

逻辑操作忽略 Cin，NOT 还忽略 B。控制表与输出约定向学生公开，有效二值输入在稳定采样时应产生确定输出；不以未说明的约定作隐藏判分标准。扩展减法时另行定义编码和借位等语义。当前题目与旧 ALU PPT 的接口不同，不混入旧 PPT 的 aluSel 或 nf/zf/ovf/cf 要求。

学生完成运算选择、操作行为与位宽处理，作品使用 `.sv`。起始工程提供端口骨架、验证入口、用例输入和结果观察，显示与接线预先提供，学生不用从零写 testbench。动态扫描显示设计、有符号标志位和全加器推导不占用主线预算。具体模拟器、执行器和组件结构由相应后续主题决定。

### 学生交付与证据

交付由 SystemVerilog 作品、两条有目的的自选用例和简短解释构成。用例保存输入、运行前预测、实际结果与选择理由；一条覆盖进位或边界，一条能够区分容易混淆的操作。学生解释一条结果，或说明如何修正预测与结果的差异、仍存在哪个问题。无错误时可以解释用例能发现哪种错误，不人为要求先失败。

**允许带失败或缺项提交给教师。** 明确显示验证通过、仍有失败或修改后待验证等实际状态，并保留困难。缺少预测时记录缺项，不能补造先验理解；后台验证与 Agent 回答不能记作学生独立预测。提交与自动保存独立，之后的修改不覆盖该次交付。

末尾可用一个相近的新输入，观察学生能否给出有理由的预测。功能验证、学生解释与迁移表现分别记录；自动检查全部通过不单独证明掌握，新输入回答也不成为强制提交门槛。

### Agent 帮助策略与工具支持

负责人选择 **只解释，不修改学生代码**。这替代先前“请求或采纳后可以局部修改”的建议，仅作为本活动的课程帮助策略，不改写其他课程的通用权限规则。

Agent 可主动观察、诊断并进行课程允许的验证；可引用代码位置，解释概念与错误原因，给概念示意、短例子和下一步验证方法。学生主动要求代改时，仍不写入其 SystemVerilog 或自写测试代码，不应用代改补丁，不提供整份可直接提交的 ALU 答案；代码由学生修改。该边界必须在实际行为中成立，不能仅依赖回复措辞。

IP 承担简短、可忽略的持续引导；对话承接解释与追问；选区引用保留学生所指内容与自由提问；卡片用于局部补学、操作和预测；编辑器、结果视图及必要时的波形提供真实实验。教学示意和实际运行结果必须区分。相同提示被忽略后不反复弹出，只有新的相关证据才支持再次提示；不因停留时间或未回应就推断不理解。

### 共同验收场景

| 情形 | 应有行为 |
| --- | --- |
| 正常推进 | 学生可直接编辑、运行、选例、解释和交付，不先通过固定问答 |
| 反复进位错误 | 引用当前失败输入和相关代码，比较低 4 位与完整和，引导学生修改后重试 |
| 遗忘概念 | 打开相关材料片段或短卡片，补学后返回原工作位置 |
| 主动求助或索要答案 | 按选区解释、定位和建议验证，不代做整份答案 |
| 明确要求代改 | 只解释策略仍生效，Agent 不修改学生代码或应用补丁 |
| 忽略提示 | 可以继续工作和提交，不重复打断，也不作负面掌握推断 |
| 中途返回 | 恢复作品、输入、用例和相关讨论；修改后未重跑时显示待验证，不冒用旧通过结果 |
| 未完成提交 | 将当前作品、失败、缺项和问题交给教师，提交成功与任务通过分开 |
| 环境或工具失败 | 说明执行故障，保留作品并提供恢复路径，不当作学生概念错误 |

### 三类验收与交接边界

- **工程行为**：后续验证 SystemVerilog 运行链、公开行为表的 4096 组二值输入、稳定输出、自动保存与恢复、运行结果与作品对应、教师交付一致性，以及主动或受请求时均不能由 Agent 修改学生代码。
- **浏览器体验**：真实走通上表全部情形，检查 IP、对话、引用、卡片与实际实验的对应，以及自由往返、忽略提示、返回和未完成提交。
- **教学效果**：需要真实学生试用，逐人记录有效活动时间、卡点、获得的帮助、用例理由、解释及相近新输入的预测。分别判断功能完成、边界与操作差异的解释、迁移预测，保留失败和无法判断的情况。50–70 分钟可行性及教学效果不能由工程测试代替；总体达标阈值需根据试用对象与数据确定。
