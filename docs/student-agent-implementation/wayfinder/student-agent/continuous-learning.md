## 原决议

本票完成设计决策，交接总体架构与重构验收规划。以下产品边界来自负责人本轮实际答复；活动状态、证据分层和恢复约束是据此形成的工程设计，不表示生产实现或教学效果已通过验证。

### 1. 课程输入与平台复用

面向真实使用中的多种课程，数字逻辑与部件设计仅作为首条已设计样例。教师提供材料、任务要求与已有目标，Agent 协助形成学习目标、评价依据、可用能力及帮助策略，由教师确认后使用，不要求教师编写完整教学脚本。

平台复用活动身份与恢复、引导控制、证据来源、画像修正、持续摘要和提交契约；课程、任务和工具提供实际目标、作品类型、进展含义、评价依据与帮助限制。没有代码、运行或唯一标准答案的活动同样可表达；缺少可靠进展判据时保留未知。ALU 的预测—运行—比较流程和只解释不代改规则不提升为全课程模板。

### 2. 学生控制与无扰检测首版路线

- 学生可选“仅在我提问时 / 适时提醒（默认） / 更多引导”，可暂停当前活动；全局默认可在课程覆盖。算法不自动换档或解除暂停，课程帮助策略继续约束帮助程度。
- 默认有依据地提供简短、可忽略的轻度帮助；正常推进时安静。先针对具体困难给最小有用帮助，问题、解释、示例和验证方式随课程与情境选择，不固定要求学生先完成一种问答流程。
- 首版采用正常活动语义事件、课程进展依据和可解释规则，分别判断呈现时机、可能持续受阻、帮助后变化及学习目标证据。检测只产生候选，呈现前再次核对当前作品、目标、设置和已有提示；依据过期或学生已自行推进时取消旧帮助。
- 多次失败但仍有新假设或局部进展时保留探索；一次停留、点击、未回应或工具故障不直接成为能力判断。先合并事件，必要时才调用模型解释有限、可追溯的内容。
- 反馈采用平时可选加少量活动结束询问，区分有帮助、没解决、现在不需要、太打断；用于校准，未回应保持未知。内容、时机与打扰分别调整，不把一次好评直接转换成更高频率。
- 验证先做事件回放和只记录候选的观察，再做少量真实活动试用。有可靠标签后再比较浅树／逻辑回归；有真实结果、动作概率与覆盖后再评估 bandit。pyBKT 只考虑用于具备明确技能和可靠响应观测的课程局部，不是首版通用检测的依赖。

IP、对话和教学产物承接持续引导。生成、投递、实际展示、回应、忽略与失效分别记录，实际展示仍不等于注意、理解或学会。作品修改仍须学生明确请求或采纳，并受课程帮助策略约束。

### 3. 活动进展与恢复的工程设计

一次学习活动围绕具体目标，可跨多次交流、作品修改、工具操作和返回会话。保存课程与任务归属、目标及要求版本、作品和运行依据、已尝试方法、未解疑问、等待事项、已提供帮助、学生选择和目标切换关系。模型会话和聊天摘要不是这些事实的唯一来源。

活动生命周期、等待对象、目标达成情况分别表达。工具完成只更新等待事项；模型调用结束、活动结束、作品提交和知识掌握不是同一个状态。课程可自行组织活动顺序，允许分支、补学、回退和目标切换，不要求统一步骤链。

返回时恢复已有目标和状态，在学生设置允许且确有需要时提供简短进度说明；方向有歧义才询问。原活动暂停继续有效，不能重建同内容活动绕过暂停。迟到结果核对实际输入与当前作品，未知执行结果先查询，不默认重跑；失效提示不重放。环境失败作为环境事实处理，不写成学生知识不足。

### 4. 证据、判断与学生纠正

| 层次 | 语义 |
| --- | --- |
| 事实观察 | 真实作品、解释、操作和结果，附版本、时间、来源与发起者；学生、Agent 与其他帮助分别归属 |
| 评价依据 | 关联课程目标或量规及所用标准，说明观察支持什么、缺什么 |
| 阶段性判断 | 保留支持与反对证据、帮助情况、不确定性及修正历史，范围有限且可更新 |

任务完成、体验满意和知识掌握分别判断。通过工具检查只证明对应版本满足已检查条件；获得帮助后的表现不冒充独立表现，保持和迁移需相应证据。缺失、冲突和未观察区间允许未知，不强行汇总一个跨课程掌握分。学习画像同课跨任务积累，跨课仅复用明确通用偏好。

学生可查看简明能力判断、主要依据与不确定性，提出异议或补证。争议推断标记待复核，复核前不作为确定事实推动同类补学；核对后更新或撤销并保留理由。提出异议不改写原始记录，Agent 画像修正不自动改变教师正式评价。纠正入口不以额外测试或先认同 Agent 为前置条件。

### 5. 教师持续摘要与固定交付

负责人已确认：教师可持续查看本课程进展摘要、可能的困难、阶段性判断及必要依据；争议判断同时标注待复核或已修正。摘要随已收集的新事实更新，保留更新时间与观察缺口，用于及时支持，不构成正式成绩。

学生提交时固定作品版本、关键过程证据、帮助情况和当时判断。后续编辑不静默替换已交付内容，后续判断修正通过关联记录体现。教师可以追溯依据并作最终评价；不把学生选择安静或拒绝提示当作能力差的证据。本票只确定必要共享接口，不展开完整教师端产品。

### 6. 设计走查与跨课程验收边界

数字逻辑设计走查覆盖：学生表达预期、自主修改与真实运行，持续失败中识别局部进展，依据当前设置解释，保留实际帮助，收集后续独立解释；中断返回核对迟到结果与暂停，最后固定提交并允许画像纠正。报告论证反例使用问题、主张、论据和解释，不制造编译步骤或用字数代替质量。

反例另覆盖未展示提示后学生自行解决、学生忽略或拒绝、目标切换、工具失败、缺少观察、证据冲突、Agent 验证与学生操作区分，以及提交后画像修正。上述属于设计走查，不是已运行的学生活动。

负责人明确第二门真实课程及任务“未确定”。本票完成通用语义与选择标准；真实课程选择、材料准备和实际验证由已有的[重构迁移与验收：数据存储、兼容范围和实施路线](https://github.com/paher-din/XunJie/issues/120)及实施阶段承接。报告仅是设计反例，不宣称第二课程已接入或通用性已实测。
