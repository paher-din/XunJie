## 原决议

负责人于 2026-10-24 确认运行、等待发送与同浏览器恢复三项行为，并对可操作原型及工程建议答复“符合预期，可据此形成决议”。本票据此完成设计决策，交接工具宿主、总体架构和重构验收；不表示生产能力或教学效果已验收。

### 1. 自动保存与实验交互

学生修改即时显示，系统自动写入本机并持续同步，不要求手动保存、冻结或选择内部版本。界面区分正在保存、已保存在本机但待同步、已保存，以及保存失败；旧确认不能把后续修改标成已保存或已同步。持续输入也要有有界的同步等待，不能永久被防抖推迟。

首条 ALU 活动中，点击“运行”才使用新代码；实验输入即时作用于当前已经运行的代码。运行中允许继续编辑，已发起实验保留实际作品与输入，新修改提示“修改尚未运行”；每次实验观察保留其输入与结果，后续开关操作不改写旧观察。较早的结果可以留档，不替换较新实验的展示。

本地实验先可靠保存执行意图和实际输入，再交给已准备的本地工具；不因应用服务尚未同步而等待远端。其他课程仍按工具声明采用有限作业、持续会话或无需执行的活动，不把 ALU 的按需重算推广为所有工具的生命周期。

### 2. 通用选区与引用

对话关闭时，选择后出现“询问 Agent”；点击才展开对话并携带引用。对话已打开时，有效选择自动加入引用区，学生可继续组织问题。选择、添加或移除引用均不发送模型请求。

引用包含当时内容的副本、稳定来源对象身份、来源内容身份和类型化范围。代码可记录文件片段，波形记录实验／观察与时间范围、信号，板信号记录当次输入与读数；其他工具提供自身可解释的选择语义，不必强制转换为代码行号。文本与代码现有组件可延续，非文本适配由工具宿主议题承接。

多处引用按加入顺序并存，重复通知去重，移除不修改原文或因失焦复活；对话开合与焦点切换保留草稿。原文变化后继续保留原引用并说明来源变化；来源失效时保留当时副本，不能按显示名称或同名文件猜测替代对象。发送时引用原文与当时的当前作品分别表达，不把新作品冒充学生选中的旧片段。

### 3. 明确发送、等待同步与接收回执

学生明确发送问题或提交时，创建具有稳定请求身份的意图，固定该次问题、引用、作品与相关证据。服务端 Agent 或教师接收方只等待这个请求需要的内容；学生之后继续编辑，不替换本次依据，也不让本次请求追着最新工作区无限等待。

待发意图与固定依据可靠保存后，网络与相关同步恢复时自动继续。等待期间可取消；取消结果持久记录，恢复后不复活。取消或失败后的问题仍可查看、恢复为草稿，不能覆盖学生新写的草稿。已经被接收方接受的请求不承诺撤回。

接收回执是成功依据。响应丢失时显示结果未知，先按原请求身份查询；重试复用原身份，避免重复交付。原型用同内容重复点击展示此要求，生产实现以请求身份区分一次操作的重试和学生明确发起的新交付，不把内容相同永久等同于同一次提交。

Agent 持续观察与每次具体判断分开：客户端未同步内容不能被服务端当作已知。需要读取当前内容的动作应重新取证；明确指向历史实验或引用的问题则保留其历史依据，不静默改指新内容。

### 4. 返回与旧教学动作

同一浏览器刷新或短暂断线后，恢复已经完成本机保存的作品、实验输入、问题草稿和待发动作。尚未确认本机保存的内容不能声称已可靠恢复；本机保存失败必须明确提示。已经准备好、资源仍可用的本地工具可继续操作，不能据此承诺完整离线首次使用或多设备协同。

中断实验不自动重跑。恢复时依据真实工具生命周期区分已结束、中断和结果未知；远端仍可能运行的操作按原身份查询，不将页面关闭直接解释为远端已停止。历史结果可以查看，不冒充新作品已通过验证。

旧教学解释可以作为历史保留；教学动作执行前重新核对作品、观察、目标、课程帮助策略与学生设置。依据已过期时停止旧动作，重新检查后给当前建议，不重放过期提示。首条 ALU 仍只解释、不修改学生代码；通用权限遵守对应课程策略。

### 5. 教师固定交付

提交面向教师，与自动保存、实验完成、功能通过和知识掌握分别表达。点击提交时固定作品、关键过程证据、解释、帮助情况和当时判断；允许失败与缺项，真实状态如实标注。

如果实验尚未结束，本次交付记录其未结束或未验证状态，不强制等待它，也不在结果稍后到达时补入该次交付。后续修订形成关联的新交付；画像纠正通过关联记录体现，不改写过去交付。教师持续进展摘要仍按连续教学决议更新，不与正式提交混为一谈。

### 6. 状态归属与最小语义契约

以下是职责与事实边界，不预选数据库、队列、插件框架或独立服务数量。

| 对象与责任边界 | 最小内容 |
| --- | --- |
| 工作区作品与恢复状态 | 学生／课程／任务归属、稳定对象身份、不可变内容身份与内容、本机保存确认和远端接收确认；本机保留待同步内容，应用服务持有已接收的共享事实 |
| 运行与观察记录 | 请求和运行身份、发起者、工具／环境版本、实际作品与参数、状态、每次观察与结果；具体工具状态由声明的生命周期承接 |
| 草稿与上下文引用 | 问题、引用顺序、选中副本、来源身份、类型化范围及定位能力；恢复数据归工作区体系，临时浮层位置和焦点归前端呈现 |
| 发送与提交意图 | 稳定请求身份、点击时的内容清单及依赖、保存／等待／取消／结果未知／已接收状态和回执；接收方按同一身份处理重试 |
| 教学动作与学习证据 | 依据、目标、权限及设置约束、实际展示／回应／失效记录；教学事实归教学运行时与证据层，视图点击不自动等于教学完成 |

课程工具持有实现其交互所需的运行状态，但作品和需要恢复的状态通过统一工作区契约交回；素材或教学产物仓库不再另存一份可变权威状态。组件、宿主与 Agent 不各自维护互相竞争的“当前作品”。

最小事件按语义表达：作品变化、本机保存确认、远端接收；运行请求、完成、中断；引用选择；问题／提交请求、取消、结果未知、接收确认；教学动作请求、重新核对、失效。事件带归属、对象／请求身份和所依据内容，具体编码与传输协议交给工具宿主和总体架构议题。

### 7. 后续实现应验证的不变量

- 当前作品、实际运行输入、已发送引用和教师交付允许不同；每份结果可以解释其依据，后续编辑不改写过去内容。
- 本机保存、远端同步、模型接收、实验完成和教师收到分别确认；失败或结果未知不伪装成成功。
- 待发请求只等自己的固定依赖；恢复、重试、重复事件与取消不得重复交付或复活取消的动作。
- 同名对象不继承旧引用，旧同步回执不确认新编辑，迟到实验不覆盖较新展示，旧教学动作不越过重新核对。
- 提交可带失败、缺项和未结束实验；不补造学生预测，不把工具通过或提交成功解释为掌握。
