## 原决议

日期：2026-10-28（Asia/Shanghai）。本票交付重构决策与工程路线，按设计完成收束；不表示已经完成产品实现、数据库迁移或教学验收。

### 负责人已明确的选择

- **本机与共享端统一使用原生 PostgreSQL，由产品管理本机实例。** 负责人对这一具体方案回复“ok”“同意”；此前本机 SQLite / 共享 PostgreSQL 的默认双适配建议撤回。
- 旧版尚未发布，只有开发数据。新领域模型、schema 和接口直接重建；保留旧原件，按需提取有价值的对象，不承担旧 API、旧 Agent 会话/实验进程接续、生产双写或无停机切换。未来已发布产品仍须满足升级与恢复契约。
- 第二个开发、验收与演示样本选择伯克利 STAT 20《Introduction to Probability and Statistics》的 2025 秋季 Flights 实验。它与 ALU 在数据表、图表、报告、引用及统计解释反馈方面形成补充。[课程目录](https://undergraduate.catalog.berkeley.edu/courses/1220421/overview-aoYks)、[原实验](https://stat20.berkeley.edu/fall-2025/2-summarizing-data/labs/flights/part-2.html)
- 教师端课程设计与制作属于产品能力，当前学生端地图尚未深入设计。ALU/Flights 的具体内容是开发资料，其材料、数据、起始作品、组件配置和演示/验收案例的准备属于开发交付；两套具体课程内容本身不是产品功能。

以下为依据这些选择及[总体架构决议](https://github.com/paher-din/XunJie/issues/119#issuecomment-6443526782)确定的工程安排，不将工程推导冒充负责人逐项指定的实现细节。

### 权威记录与资源

1. 业务与持久运行的权威事务记录使用统一 PostgreSQL 引擎、SQL/事务实现和迁移体系。六单元保持各自事实所有权，同机可共用物理实例；跨单元通过领域 API、持久待发与回执协作，不跨服务直写表，不依赖跨服务数据库事务。本机部署不等于个人空间，学校空间也可使用本机权威服务。
2. 本机安装组合负责二进制与私有数据目录、初始化、连接凭据、端口与就绪检测、进程监督、正常退出、崩溃恢复及版本升级。学生不手配 PostgreSQL、端口或 Docker；只使用学校网页的学生无需安装数据库。页面关闭与本机服务退出分别处理，遵守已接收请求和预算的既定契约。
3. 浏览器 IndexedDB 继续保存草稿、组件本机状态和待发内容；执行器内部工作文件与不可变资源按职责保存，不另造一套同义课程/活动/RunStore。“本机已保存”“权威服务已接收”“教师已收到”分别对应真实确认。
4. 资源默认由所属服务管理文件目录，可选 S3 兼容后端。稳定身份包含归属、摘要、长度、格式版本和可解析定位；原生模型记录与课程资料分别管理访问和保留责任。先完成可重读的持久资源，再在短事务发布业务引用、状态和必要 outbox；GC 与新引用协调，不能删除仍被活动、Run、提交或恢复清单引用的对象。
5. 初期升级和整套导出允许明确维护窗口；备份必须覆盖数据库及引用资源。应用 schema 与 PG 引擎升级分开。恢复/部署搬迁交接唯一写入和推进权、阻断旧 worker；未知模型/工具效果按原身份查询，不因恢复或切换生成新身份重放。恢复能力按实际独立备份及可恢复时点报告，不承诺未验证的零丢失/零停机。

取舍：统一引擎减少持续的双事务/双迁移维护，把差异集中在安装与运行管理；这些管理成本仍然持续存在。统一 SQLite 经领域服务共享也可行，没有负载证据证明其不适用；本次未采用。PGlite 的单连接、socket 复用、VFS 与升级路径不等价于原生多会话 PostgreSQL，本次也不采用。[SQLite 使用边界](https://sqlite.org/whentouse.html)、[PG 生命周期](https://www.postgresql.org/docs/18/app-pg-ctl.html)、[PG 升级](https://www.postgresql.org/docs/18/upgrading.html)、[PGlite 连接边界](https://pglite.dev/docs/pglite-socket)

原生 PG 最终二进制来源和版本由打包探针确定。已查 wrapper 在 Windows 强杀进程且跳过 Windows 运行测试，Zonky 精简包缺少 pg_dump/pg_restore/pg_upgrade；因此不能原样依赖封装库退出 hook 或把可下载包当成完整产品。以官方生命周期工具建立有界运行管理层，并包含所选备份升级工具。[wrapper 源码](https://github.com/leinelissen/embedded-postgres/blob/8c8c16d1b81bec8ae3315d59a050654086a85e23/packages/embedded-postgres/src/index.ts)、[精简包脚本](https://github.com/zonkyio/embedded-postgres-binaries/blob/c56022003f8b1a6284567c365f44738b7e83514b/scripts/repack-postgres.sh)

### 重建对象与共享接口

- 新模型覆盖空间/成员、课程/组件及内容版本、活动、作品/快照/固定引用、提交、证据/判断/画像，以及 Run/step/attempt、InputEvent/Inbox、Wait、Command、预算、原生模型记录和能力/Prompt/Skill 装配版本。
- 盘点到的旧教学 SQLite、个人 Agent SQLite/加密材料、浏览器 IndexedDB/outbox、执行与 HDL 文件账本分开保留；新环境使用独立数据目录、浏览器命名空间和环境身份。旧聊天不伪造为新 Run，旧 outbox/执行队列不自动消费，有价值的开发资料通过显式提取进入新基线。
- 教师发布、学生任务与工作区、模型设置、提交和审阅接口随新契约一起调整，不为旧 DTO 保留永久兼容层。继续实现课程/组件版本固定、主体材料投影、持续摘要、固定提交、反馈与修订。当前关联路径不是完整教师端产品范围的上限。

### 实施顺序与并行边界

1. **新契约和可复现基础。** 固定对象/身份/版本、资源引用与存储边界，验证 PostgreSQL 关键事务；优先做 Win11 x64、Apple Silicon Mac 的实际安装、正常停止/崩溃恢复、备份还原和引擎升级探针。同时处理 Icarus/WASM 可复现构建与系统模块诊断、固定 MCP/Apps/SDK/宿主组合、Flights 的 R/数据/报告环境，并准备两样本资料。
2. **真实持久运行链。** 完成接收、固定依据、step/attempt、工具意图/回执、等待、预算、取消与恢复；先用可控能力验证竞争和故障，再接三协议实际端点。早期即验证跨进程/跨服务调用；个人自主学习、课程活动与主动引导共用基础。
3. **ALU 完整路径。** 交付可用样本资料，贯通组件装配、保存、引用、真实执行、Agent 帮助、提交、教师摘要/反馈及返回恢复；覆盖 steering/queue、过程显示和暂停保持。
4. **Flights 扩展验证。** 交付可用材料、固定数据、起始分析/报告和演示案例；接入表格、图表与报告，检验非文本引用、输入/结果版本、解释性反馈、依赖装配。新增能力进入组件或执行适配，避免主工作区课程特判；验证教师组件复用、更新选择、失败保留原绑定及进行中活动使用旧版。
5. **部署与交接验收。** 覆盖个人全本地、学校统一及至少一种真实跨机混合组合；完成安装更新、备份恢复、真实设备/浏览器/端点、成员间复现和可选 Phoenix 调试包。

共享对象、身份和版本契约稳定后，执行适配、工作区呈现、模型连接与开发工具可以按明确写集并行；涉及共同接口先协调。最终二进制与版本、安装资源预算及具体任务拆分属于实施工作，本票不因此启动开发或批量建实施票。

### 开发复现与验收证据

开发沿用本地全栈、独立可写副本和版本化共享基线。seed/reset 只作用于明确选定的独立环境；重置、升级或删除 A 的环境不能影响 B。记录源码 commit/显式差异、锁文件、实际 OS/架构与工具链、可公开配置身份、schema/seed/课程/组件版本、输入步骤和结果，排除凭据。旧 xj-repro/1 仅支持其约定 schema，须适配新记录与资源；业务复现包、Agent 调试包、导入旧结果和重新执行分别表达。

验收分别留证：

- **事务与故障：** 两真实会话竞争、领取代际/CAS、预算、重复接收、取消/派发和收尾竞争、过期 Wait、半截模型响应、未知效果查询、资源引用/GC、备份真正还原。
- **产品与教师操作：** 保存/固定发送/提交回执、材料范围、非文本引用、结果版本、恢复与暂停保持、持续摘要与固定交付；教师装配→预览→发布→故障恢复，记录阻碍、重复操作和工程介入。两套资料可实际使用，不能只交外部课程链接或测试占位文本。
- **平台与互操作：** Win11 x64、Apple Silicon Mac 的桌面 Chrome/Edge，记录实际版本；Chat Completions、Responses、Anthropic Messages 的实际目标端点、原生续接、多模态、工具、取消/中断和能力缺项；本机/学校/混合真实组合。
- **复现与容量：** 成员 B 在独立环境重现 A 的固定问题；用真实保存、调度与结果负载记录延迟、锁等待、恢复和资源占用，不从开发服务器规格或学生人数外推容量。
- **教学效果：** 受阻误报/有益探索、旧提示失效和画像异议先用明确案例核对；真实学生理解、迁移与体验提升需要独立研究证据，工程或演示通过不等于教学效果通过。

本次完成仓库静态盘点、官方资料/源码研究、决策与文档检查；未实现新存储或安装器，未运行数据库探针，未制作/接入课程包，未完成产品工程、浏览器、真实端点或教学效果验收。后续进入实施规范与工作拆分，按本决议和前序契约执行。
