# 工作区选区工具条与上下文引用

状态：已授权实施的前端范围。日期：2026-10-23。

## Problem Statement

学生希望直接选中正在阅读或编辑的内容向 Agent 提问，并在继续输入自己的问题时保留引用。现有代码编辑器能够读取选区，但求助入口仍要求确认作品、冻结快照；普通文本和对话输入也没有统一的引用呈现。把新交互直接绑定旧求助链路，会把尚在研究的同步和执行契约提前固定下来。

## Solution

交付可在真实页面使用的选区工具条、引用区和前端协调能力。对话关闭时，选择后出现“询问 Agent”；点击后打开输入区并携带引用。对话已打开时，有效选择自动进入引用区，学生自行输入并明确发送。先提供普通文本与现有代码编辑器两种真实来源适配，使用同一套呈现组件。

组件以调用方提供的工作区身份、来源信息和回调连接产品。开发验收页直接复用这些组件和真实编辑器，使用明确标识的样例内容，展示提交回调收到的内容；它不伪造模型回答，也不调用旧保存、冻结或求助接口。可复用实现位于正常应用模块，开发验收入口仅在开发模式存在。

## User Stories

1. 作为学生，我希望在普通课程文字中选中一段内容后看到“询问 Agent”，以便就地提问。
2. 作为学生，我希望在代码编辑器中得到同样的入口，以便不再寻找课程特有的求助按钮。
3. 作为学生，我希望点击入口打开对话并保留选中内容，以便继续写出自己的问题。
4. 作为学生，我希望对话打开时，新的有效选择能直接进入引用区，以便减少重复点击。
5. 作为学生，我希望选择内容本身不会发出问题，以便先组织自己的想法。
6. 作为学生，我希望引用区显示来源和当时选中的内容，以便确认 Agent 将收到什么。
7. 作为学生，我希望编辑原文后，已添加的引用仍保留原先内容，以便不改变已经表达的对象。
8. 作为学生，我希望删除不需要的引用，而原文保持不变，以便调整问题范围。
9. 作为学生，我希望焦点进入输入区或收起再打开对话时，问题草稿和引用仍在，以便连续思考。
10. 作为学生，我希望反复收到同一选区事件时不会出现重复引用，以便保持输入区简洁。
11. 作为学生，我希望能够引用来自不同位置的内容，并分别移除，以便对照提问。
12. 作为学生，我希望中文、换行和特殊字符被准确保留，以便代码和材料不被改写。
13. 作为学生，我希望键盘也能使用提问入口和移除操作，以便不依赖鼠标。
14. 作为学生，我希望在中文输入法组合输入时按 Enter 不会提前发送，以便完整输入问题。
15. 作为学生，我希望工具条和引用区在滚动、缩放及窄窗口中保持可见可操作，以便不遮挡关键内容。
16. 作为学生，我希望来源失效时得到明确反馈，以便不会误以为引用指向新的同名对象。
17. 作为接入开发者，我希望用来源适配器连接同一套组件，以便后续加入新的课程组件。
18. 作为接入开发者，我希望收到明确发送动作对应的问题与引用副本，以便由业务层决定同步与模型调用。
19. 作为开发者，我希望更换工作区身份能清理旧工作区的临时内容，以便引用不串到另一个学生或任务。

## Implementation Decisions

- 使用现有设计 token、图标、字体、动效和键盘交互习惯。工具条和引用区是可组合的展示组件，协调状态只管理本次前端草稿，不承担课程事实存储。
- 优先复用代码编辑器的原文选区捕获能力。适配器提供来源身份、可读来源名称、选中内容、局部定位信息以及工具条所需的位置；引用语义不依赖某个课程名称、冻结快照或模型服务。
- 普通文本适配只接受已登记来源容器内部的非空选区；不捕获输入区、其他页面、密码输入或组件之外的选择。代码适配保留原文语义，不把编辑器显示投影冒充原文。
- 选区工具条只在有效选择且对话关闭时显示。打开对话是前端动作，选区进入引用区后不自动发送。工具条获得焦点不能使待引用的内容丢失。
- 引用保存当时内容的不可变副本。相同来源、范围和内容的重复通知不重复添加；来源内容变化后的选择可以作为新引用。已添加引用不随原文变化静默更新。
- 引用支持独立移除；移除后，失焦或无变化的选区通知不应重新添加，新的明确选择可以重新加入。多处引用按加入顺序呈现。
- 对话开合保留当前工作区的问题与引用。显式工作区身份变化清理该范围的临时状态。首版不承诺刷新恢复、跨设备同步或服务端持久化。
- 发送回调获得本次问题与引用的副本；在调用方确认接受前保留草稿，失败时允许继续编辑。开发验收页只显示“已交给示例接收器”的收据，不模拟智能回答。
- 对引用的来源定位使用调用方提供的能力；无法定位时提示当前不可用，不按路径猜测其他对象。非文本对象的最终协议留给工作区研究。
- 引用组件可与未来输入框组合；不修改现有个人模型配置、模型协议或旧求助 API。开发验收页位于独立路由，正式构建不包含其入口与样例。

## Testing Decisions

- 主要测试切入点是浏览器中挂载真实组件、普通文本来源和真实代码编辑器的开发验收页。通过用户选取、点击、输入、键盘和可见回调收据验证行为，不直接调用内部状态更新来代替操作。
- 沿用项目现有 Playwright 浏览器验收方式，使用本机独立端口；对本次组件行为建立少量高价值场景，不把旧手动冻结流程写成新验收要求。
- 覆盖对话关闭与打开两条路径、重复选择、移除后不复活、多处引用、收起后保留草稿、工作区切换隔离和来源变化后保留原始内容。
- 覆盖中文与换行、代码原文选择、输入法组合输入、键盘使用、滚动定位、窄窗口和减少动效。
- 观察网络副作用：选择、添加和移除不发送业务请求，不触发模型调用、保存、冻结或运行。
- 对原文映射、去重等仅在浏览器难以清楚表达的边界补充纯函数测试；不测试 React 内部状态名称或无意义的 DOM 实现细节。
- 执行学生端类型检查、构建及相关既有编辑器回归；确认正式构建不包含开发验收样例。

## Out of Scope

- 实时同步、自动保存重构、最终引用持久化格式和模型上下文组装。
- 替换现有真实课程的保存、冻结、运行、求助或提交流程。
- 波形、板信号、任意画布、外部页面和隔离 iframe 的完整选择协议。
- Agent runtime、模型 provider、插件 SDK 和完整课程组件发布机制。
- 教学效果证明和整条课程流程验收。

## Further Notes

本规范来自负责人已确认的两种选区交互及本轮明确实施授权。它落实已知前端行为，为后续接入提供组件，不提前关闭[工作区交互与状态：自动保存、选区引用、执行依据和提交](https://github.com/paher-din/XunJie/issues/116)。工程检查、浏览器验收和教学效果分别报告。
