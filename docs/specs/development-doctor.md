# 只读开发环境自检与复现记录

状态：已授权实施的开发工具范围。日期：2026-10-23。

## Problem Statement

团队需要比较成员之间的代码、依赖、运行环境和配置条件，才能复现同一个问题。共享云服务解决了部分差异，但不等于大家运行相同代码或拥有相同本地条件。现有检查分散，有的只验证单个 Node 版本，有的绑定某台设备，缺少一份可分享、不会携带凭据的当前环境报告。

## Solution

提供可从任意目录调用的只读 CLI。它定位指定仓库，汇总代码 commit、修改状态、平台与运行时、工程声明的 Node 要求、依赖安装与锁文件信息，并可对明确指定的应用配置检查必要字段及引用文件是否存在。提供人类可读和结构化输出，以及一份可复制填写的复现记录模板。

默认不联网、不安装、不启动服务、不连接数据库、不读取密钥内容，也不修改被检查仓库。配置必须由调用者显式指定，报告只输出必要的检查状态和公开工程元数据。工具运行成功与当前环境满足目标工程要求分别表达。

## User Stories

1. 作为开发者，我希望用一个命令查看当前代码 commit 和分支，以便确认复现使用的代码。
2. 作为开发者，我希望知道工作区是否有未提交或未跟踪改动，以便识别代码差异。
3. 作为开发者，我希望从仓库外指定检查目标，以便在多个工作树之间使用同一工具。
4. 作为开发者，我希望知道操作系统、架构和当前 Node 版本，以便比较执行条件。
5. 作为开发者，我希望看到工程声明的 Node 版本要求及匹配结果，以便选择合适的运行时。
6. 作为开发者，我希望了解各工程依赖是否安装、是否与锁文件的直接依赖相符，以便区分代码问题与安装问题。
7. 作为开发者，我希望报告包含锁文件的稳定指纹，以便与同事判断依赖基线是否一致。
8. 作为开发者，我希望可以明确指定应用配置进行检查，以便知道缺少的是哪类条件。
9. 作为开发者，我希望配置报告不包含地址、账号、密钥或其他配置值，以便安全分享诊断结果。
10. 作为开发者，我希望密钥、数据库和证书路径只做必要存在性检查，以便诊断不会读取或修改其中内容。
11. 作为开发者，我希望不提供配置时得到“未检查”，以便不把未执行的检查当成通过。
12. 作为开发者，我希望缺失 Git、无效仓库或损坏配置得到清楚的错误与退出码，以便不误判成功。
13. 作为开发者，我希望既能阅读终端摘要，也能获得稳定的 JSON 输出，以便保留和比较结果。
14. 作为开发者，我希望工具在 Windows 和 macOS 都不依赖特定 shell 命令解析，以便跨平台使用。
15. 作为开发者，我希望工具执行后文件、配置和运行服务保持原状，以便放心在工作目录使用。
16. 作为问题报告者，我希望有包含输入、操作步骤、预期与实际结果的模板，以便别人能复现问题。
17. 作为问题报告者，我希望明确填写数据/schema/seed 和配置基线，而不是让工具编造版本，以便知道哪些条件还未知。
18. 作为维护者，我希望帮助信息说明每项检查能证明什么、不能证明什么，以便报告不被当作完整上线验收。

## Implementation Decisions

- CLI 使用 Node 标准库，不新增项目运行依赖、不执行包安装脚本。实现可从 Node 24 系列及更高版本运行；它报告目标工程要求，不要求工具自身必须使用被测工程的精确版本。
- 提供帮助、指定仓库、结构化输出、显式配置检查和复现模板输出。默认将结果写到标准输出，模板同样输出到标准输出；文件保存由用户或调用方重定向完成。
- Git 信息只调用只读命令，子进程使用参数数组和 shell:false。报告 commit、分支、是否 detached 及改动数量，不输出文件内容、远端 URL、私人目录或可疑原始错误文本。
- 工程检查读取受版本管理的包清单、Node 版本声明和锁文件。区分已声明版本、实际进程版本、未安装、缺包及直接依赖版本差异；无足够信息时标为 unknown，不宣称整个依赖树或 native addon 可运行。
- 对锁文件计算稳定摘要；已安装包只读取必要的包名与版本元数据。不要执行被检查仓库提供的任意脚本。
- 配置检查仅处理显式给出的本地 JSON。以现有应用配置的必要条件为依据，检查结构和字段是否存在、节点配置是否一致，以及声明的本地文件是否存在或可读；不将示例配置当真实配置通过，不读取被引用的密钥或数据库内容，不测试网络端点。
- 配置值一律不进入报告，字段名称采取白名单，未知字段只报告数量。路径、JSON 解析错误、Git 错误和子进程异常必须经过安全整理，不能把原始配置片段或输入参数反射出来。配置内容不参与公开哈希。
- 输出使用明确的 pass、warn、fail、not-checked 状态及稳定的检查标识。JSON 有报告版本；文本和 JSON 表达同一检查结果。
- 退出码固定为：0 表示检查完成且无失败；1 表示检查完成但存在不满足条件；2 表示命令参数、目标或检查过程错误导致报告不完整。警告或未指定的可选检查不单独导致失败。
- 复现模板包含代码与依赖基线、可公开描述的配置版本、数据/schema/seed 版本、最小输入、步骤、预期、实际及重现次数。不得自动复制学生作品、配置值或个人设备资料。
- 工具不扫描用户主目录或 SSH/云账号配置，不自动选择云服务器，也不调整现有环境。通用使用说明入仓库，个人连接资料继续留在本机。

## Testing Decisions

- 主要测试切入点为真实 CLI 子进程，使用隔离的临时仓库、包清单和合成配置；核对标准输出、JSON、退出码以及被检查目录在运行前后的状态。
- 覆盖干净与有改动仓库、分离 HEAD、仓库外调用、带空格路径、运行时匹配与不匹配、依赖缺失和直接版本差异。
- 覆盖未指定配置、合法合成配置、缺少必要字段、示例占位符、损坏 JSON、缺少被引用文件和互斥节点配置错误。
- 以运行时生成的显眼测试秘密验证文本、JSON 和错误路径均不泄露配置值、个人路径、认证 URL 或原始 JSON 片段；不在测试文件中放真实或仿真 token。
- 验证配置和被引用文件内容不被修改、工具不创建缓存或锁文件、不读取秘密文件内容、不发出网络请求；测试结束删除临时目录。
- 测试以行为与输出契约为中心，不锁定内部函数拆分或完整终端排版。对真实当前工作树执行一次只读检查，核对结果与实际环境一致。
- 跨平台命令构造与路径逻辑需要覆盖；本机测试不能替代实际 Windows 验收，未运行的平台明确记录未验证。

## Out of Scope

- 安装或升级依赖、自动修复、服务启停、云资源操作和网络连通探测。
- 数据库读取、seed/reset、迁移、备份恢复及环境隔离实现。
- 凭据管理、个人云管理文档和生产配置发布。
- 完整依赖树审计、原生模块兼容认证、课程编译器或教学效果验收。
- 决定最终产品部署、存储或支持操作系统范围。
