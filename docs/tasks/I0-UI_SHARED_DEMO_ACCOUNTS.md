## 明确批准与范围

负责人要求开发阶段只保留一个可登录教师账号与一个学生账号，两者课程、任务、作品和反馈真正互通；教师侧补多个虚拟学生、班级和课程用于演示；提供教师/学生统一登录页，登录后进入对应页面。此批准覆盖必要原页面、原接口消费和受控合成数据整理，不把演示结果当真人学习证据。

已读 PRD §4.1–4.3/§5/§8、MVP_SPEC §2/M-01/M-02/M-03/M-09/M-10、TECH_DESIGN §9–10、DESIGN 颜色/字阶与原页面，现有教师工作台及客户端契约。适用 PRD-01/02/08/09/10、M-01/02/03/09/10、AC-02/04/10/12。产品基线只读，汇总待授权维护者。

可写：原身份/课程/分配的数据建立工具与必要直接调用方、学生/教师登录入口、已有课程和教师演示展示、相称验证、本任务与清单。保留原ID、原已确认作品和权限；不初始化第二套团队业务数据库，不分发真实连接信息或密码到Git。

## 实施方案与验收

- 保留统一学生账号及一位现有教师，受控配置 allowedLoginUserIds 仅允许这两个原身份；其他历史会话撤销，登录与Session恢复均校验名单。虚拟用户保持active课程成员以出现在原教师名单，但白名单外不能登录；不增加users字段。历史归属、原登录名和密码hash保留。
- 优先复用既有课程成员关系、活动蓝图、发布和分配接口。教师对两个课程均具真实权限；学生从同一服务读取分配，不能用前端别名或静态卡片冒充。
- 现有模型没有独立班级表和班级写API。本批复用课程实例与真实成员关系：两学科各两个教学班，课程显示名含班级；不新增表或LMS。保留现有两个课程ID，追加另外两个课程实例与六位虚拟学生。
- 统一页提供角色选择；Session与课程角色由后端认证决定，选项不能授予教师权限。保留原深链、过期重登、真实退出和账号草稿隔离。
- 数据修改前一致备份，以幂等方式整理；敏感登录资料只写本地私下操作手册。

验收：两账号真实登录/角色错配/退出；教师创建或发布真实任务→同一学生首页出现→学生进入保存→教师读取同一作品；虚拟名单和演示数据来源可辨；停用账号不能登录；课程/作品历史保持。本批工程结果已按下方实测完成；未执行的真人/模型验收不预记通过。

## 2026-10-15 学生课程范围修正

负责人看到统一学生首页同时出现两个教学班，明确要求学生只保留一套课程。本轮沿用 PRD §5、MVP_SPEC M-10、TECH_DESIGN §9–10 及上述原账号整理授权，适用 PRD-02/10、M-03/10、AC-02/10。

范围：统一学生保留原教学班的 C 与 HDL 两门课程；仅停用其新增教学班的两条成员关系。教师四个课程实例、六位虚拟成员、原课程/分配/作品/运行/反馈及身份均保留。只改原演示准备/发布工具及相称测试、本记录与清单；不改页面或鉴权，不新增 schema，不更改受保护文档，不公开连接资料。

实施先做共享库一致备份，核对目标关系和进行中执行，再在一个事务中更正两条关系。若目标仍有执行或 HDL 会话，先沿原停用流程处理，不绕过停止语义。会话课程列表按原 active 成员关系实时读取，验收包含现有登录刷新后只见两门课程、教师仍有四门、原业务记录不变及完整性/外键检查。准备工具仅将统一学生加入原班，新增班只含虚拟成员；发布工具不再要求统一学生属于新增班，也不将未执行的学生 bootstrap 记为通过。旧发布回执保留，不以改写旧计划重放迁移归属。

现场结果：一致备份后，仅将目标两条成员关系置 inactive。锁内检查无进行中 Job、无活动 HDL 会话；41 表中另外 40 表的摘要、其他成员关系与 schema 均保持原值，完整性 ok、外键问题 0。原 8 个 Attempt、34 个 Job、1 条教师反馈保留，旧任务归属不迁移；学生不再具有新增班访问权，历史作品原记录保留。
