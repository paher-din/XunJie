# I0-UI：主仓库前端接入与 I0-A 准备规格

日期：2026-10-11。状态：`document-revised`（8 项审查发现已落实到规划，未实施）。父任务：[I0 #30](https://github.com/paher-din/XunJie/issues/30)。接入目录、设计同步办法与 Monaco 路线保持已确认。测试方法现已选定，安装/建库/具体 UI 操作与编码前置单列，不再把文档定稿标成全批可执行。来源和任务索引见[准备记录](I0_UI_PREPARATION.md)；具体实施约束见[客户端约束](I0_UI_CLIENT_CONTRACT.md)；术语见[任务用语](I0_UI_GLOSSARY.md)。

## Problem Statement

现有设计工作区能展示编辑器、版本、构建和波形，但正文、版本和部分操作仍为模拟，不能证明学生作品得到保存或执行。正式应用需要进入 XunJie 主仓库；设计仓库仍在迭代，整包重复覆盖会丢失业务接入改动。

主仓库已有 A1/A2/C2 接口工厂，但正常业务宿主、分配发现、首次恢复代际和持续运行交接尚不齐备。当前应先完成独立前端和已知契约的客户端准备，明确区分本机草稿、确认作品、固定快照与运行结果，使真实服务交接后能够继续接入。

## Solution

固定一个已提交设计版本，将独立前端导入主仓库；后续设计变化按来源差异选择性同步。沿用现有页面、导航和视觉结构，增加一条明确标为准备场景的 C/TextScope 工作区。学生可以编辑多文件、恢复本机草稿、主动确认保存、冻结快照、查看版本差异，以及发起固定快照运行并核对结果。

准备场景可由独立开发命令启动并实际操作，使用隔离合成身份、同一 HTTP 客户端与进程内 fixture authority；刷新后可读回确认状态。自动化也走该准备运行路径，故障只控制传输或有来源的响应。真实模式显式选择已有服务契约；初始化交接不齐时显示具体不可用条件，不能用模拟成功替代真实失败。原数字逻辑演示保留其演示身份，新增真实课程接入另行安排。

## User Stories

1. As a 前端接入成员, I want 在主仓库独立启动前端, so that 团队无需另一个本地设计 checkout。
2. As a 设计成员, I want 后续视觉提交按差异同步, so that 主仓库已有保存和运行改动得到保留。
3. As a 学生, I want 明确识别准备场景和真实分配, so that 模拟数据不会被误当作学习记录。
4. As a 学生, I want 继续查看现有数字逻辑演示, so that C 接入不会移除已有设计成果。
5. As a 学生, I want 读取固定活动版本及项目要求, so that 我知道当前作品对应哪一次分配。
6. As a 学生, I want 在专业编辑器编辑 C、头文件和测试文本, so that 我能开展实际多文件项目工作。
7. As a 学生, I want 切换文件保留各自的光标、滚动和撤销状态, so that 切换不会丢失上下文。
8. As a 学生, I want 使用中文输入、键盘选择、查找与撤销, so that 日常编辑无需依赖静态代码展示。
9. As a 学生, I want 新建项目内文本文件并看到路径和限额提示, so that 非法文件不会产生假成功。
10. As a 学生, I want 编辑正文保留原换行与 Unicode 内容, so that 确认版本和快照准确对应我写的代码。
11. As a 学生, I want 刷新或折叠工作区后恢复本机草稿, so that 未确认的工作仍可继续。
12. As a 学生, I want 区分本机草稿与确认保存, so that 我不会误认为自动本机持久化已上传作品。
13. As a 学生, I want 本机写入失败时看到准确状态, so that 我不会依赖不存在的草稿保护。
14. As a 学生, I want 主动确认保存所有选定变更, so that 输入和上传由我发起。
15. As a 学生, I want 保存等待中继续编辑, so that 到达的旧 ACK 不会覆盖新草稿。
16. As a 学生, I want 保存失败时保留完整草稿, so that 部分失败不会破坏作品。
17. As a 学生, I want 从已确认作品冻结可回取快照, so that 运行引用固定的多文件版本。
18. As a 学生, I want 断线时继续编辑并核对原保存请求, so that 重连不会重复创建文件或静默丢内容。
19. As a 学生, I want 多标签编辑冲突保留双方内容并让我选择, so that 较旧标签不能覆盖较新草稿。
20. As a 学生, I want 服务端版本冲突时比较本机和权威内容, so that 新操作基于我的明确决定。
21. As a 学生, I want 旧恢复代际被拒绝后重读并比较, so that 客户端不会自动伪造新请求。
22. As a 学生, I want 切换账号或 Attempt 后隔离草稿与迟到响应, so that 他人的作品不会进入当前工作区。
23. As a 学生, I want 在暂停或关闭采集时仍按契约保存已有文件正文, so that 保存不依赖过程证据采集。
24. As a 学生, I want 回收与恢复文件实例, so that 同名重建仍保留旧实例的历史。
25. As a 学生, I want 恢复路径冲突时保留两个实例, so that 恢复操作不会覆盖同名新文件。
26. As a 学生, I want 只读比较两个快照或草稿与确认版本, so that 差异展示不会偷偷修改作品。
27. As a 学生, I want 明确选择入口文件、测试文件及 TextScope 操作参数, so that 运行对应本次学习意图。
28. As a 学生, I want 查看运行快照与有来源的输入记录并识别不可回取的历史参数, so that 旧结果不会被误标为当前草稿或当前控件输入。
29. As a 学生, I want 区分作业状态、编译诊断、程序输出、课程检查和基础设施失败, so that 技术故障不会被解释为学习结论。
30. As a 学生, I want 请求取消并等待服务确认, so that 停止按钮不会虚假宣布执行已结束。
31. As a 学生, I want 结果未知时核原运行而不是自动重跑, so that 不会产生重复执行和用量。
32. As a 学生, I want 查看公开结果文件并在可回取时下载、比较两次运行, so that 能据具体结果修订而不把裁剪或缺失当成功。
33. As a 验收成员, I want 在真实浏览器复现正常及故障路径, so that 编辑器、持久化和请求行为有可回放证据。
34. As a 验收成员, I want 明确区分前端准备通过和真实产品验收, so that Mock 通过数不会替代 AC/NFR 或教学效果。

## Implementation Decisions

已确定：主仓库接入、固定提交导入与选择性设计同步、Monaco、I0-A 范围及保留数字逻辑。本次规划选定 Playwright 实际浏览器边界与可交互开发 fixture；实际依赖安装、新建库和缺失 UI 操作仍按准确授权推进，见客户端约束 P-01～P-04。这里定的是任务方案，不是已经完成实现或改写产品架构。

- 将固定 Design 提交的 `app/` 已跟踪子树导入 XunJie 的 `apps/student/`，保留独立前端工程与 lockfile；保留来源和许可说明。前后端独立构建，不引入 monorepo 工具、运行时目录链接或全量覆盖同步。来源工作副本的未提交改动不纳入导入。
- 编辑器采用 Monaco，在主仓库学生前端使用 `monaco-editor`，主要依据其多文件 model/view 与 diff API。浏览器测试使用开发依赖 `@playwright/test`；执行前核依赖授权、兼容与精确版本，不引入 editor wrapper、LSP 或新状态库。高亮不等于 C 编译检查。
- 编辑器 model 以模式、账号、Attempt、文件实例形成独立身份；未确认创建使用独立 clientFileKey，取得映射后保留草稿与视图状态。文件路径不充当身份，编辑器内部版本不充当 documentVersion。按生命周期正确复用和释放 model。
- 原文草稿是字节权威，Monaco 仅为 LF 显示投影。适配保存 BOM、逐段 EOL 与双向 UTF-16 offset 映射，编辑只改映射出的原范围；新增换行采用原文件首个 EOL（无则 LF），未改区域不变。undo/redo 恢复原文及元信息，不用 getValue 重建权威正文。对象范围按原快照和现有服务端行列规则生成，无法精确表达时显示不可用，不猜坐标。详细规则和精确版本技术验证见客户端约束 §4。
- 本机草稿及待确认命令使用全新 IndexedDB 存储，按模式、账号、Attempt 隔离。此项是新的浏览器 schema 提案，待具体范围批准后实施；不迁移或删除已有数据，不改服务端 schema。保存草稿采用事务检查本机修订，避免多标签最后写入覆盖；BroadcastChannel 只能用于通知，不能替代持久化冲突检查。
- 本机持久化只保护作品草稿与原请求，不把键盘过程、停顿、焦点或粘贴构造为学习证据；草稿保护状态须基于实际事务成功。布局重置、设置缓存清理不连带清空本批草稿。
- 准备模式有明确合成身份和固定 TextScope 材料，由独立开发命令启用 Vite fixture；真实与准备 base URL 显式分开，禁止隐式回退。fixture 确认头、快照与原回执在同一开发进程内可读写一致，重启换代际且提示重读；正式构建不带它。不能从设置昵称构造正式身份或把演示卡片改名冒充分配。
- 初始化客户端由首张任务负责：已有登录/Session/退出、获准分配/固定活动/可见资料读取；首次 Attempt 的原命令及回执由确认保存任务负责。分配入口可为 A 提供的授权引用，不预定新列表 API；缺登录 UI 时不另造页面。C 容器复用和文件/保存/冲突/运行缺口逐项见客户端约束 §7，未交付的业务控件先协调。
- 正式适配使用 Session、Assignment、固定 ActivityVersion、Attempt、受信 recoveryGeneration 与 runtimeProfileVersion。已有接口可做窄 HTTP 客户端及有来源的响应投影；服务端模块不直接打包到浏览器。分配发现、首次代际和正常 HTTPS 宿主等待交接，不发明接口或硬编码真实 ID。
- 所有变更由学生发起；写请求带当前 CSRF、受信代际和业务幂等键。冻结原命令的完整输入、clientId/clientSeq、预期版本、正文和键；业务重试只重发原请求，不将新草稿挂到旧键，未知不换键补做。权限与并发限制仍由服务端执行。
- sync 成功须逐层解包 HTTP 信封、命令回执与 result。确认头、创建映射、最新草稿关联和 outbox 确认在同一本机事务提交；失败全部回滚，保留原命令可核对。ACK 用冻结发送正文形成确认基线，不能覆盖较新草稿。clientId 不复用，clientSeq 事务预留只增不减，刷新重放保留原 clientId/seq；事务中断与两标签并发验收见客户端约束 §5。
- 快照基于已确认 workspaceRevision，由 POST 回执取得 ID/hash，再 GET 完整清单。仍有未确认草稿时明确标记版本差异，不把草稿偷偷塞进旧快照。对快照正文/清单不匹配、非法归属或缺项采取不可用状态。
- 当前 sync 会推进 attemptRevision，与 TECH §4.3 存在已记录差异；不单方修改规则。保存和快照之后，从获准 GET 重读权威 Attempt，再发 run/control；不计算 revision、不拿 workspaceRevision 替代。
- 暂停 Attempt 或分配时只允许已有 active 文件的 update，并服从实际返回；禁止创建/回收/恢复/运行。关闭采集不阻断允许的作品保存；不上传离线编辑过程补造证据。submitted 等终态按服务契约只读，GET/页面载入不自动开始学习。
- 当前上下文包含模式、身份、Attempt、单调 loadEpoch 与受信代际；所有 await 后核上下文，每次权威读取还核轮次。旧代际/旧加载的 ACK、GET 或 poll 不能改变当前确认头，旧回执只留隔离事实。冲突保留双方内容，由学生比较并发新命令；恢复不自动换代际/业务键。
- 文件回收是业务 lifecycle 操作；历史实例不硬删。恢复路径冲突不能覆盖同名新实例。比较界面沿用现有容器，快照、旧实例及比较源只读；学生明确应用修订才产生草稿变更。
- 运行请求绑定 snapshotId、entryFileId、参数 fileIds、runtimeProfileVersion、mode 和权威 expectedAttemptRevision。Core 使用 stats/find/top，Report 仅在固定活动支持时使用；不接收任意 shell、不在浏览器或应用宿主编译 C。
- Job/Run 可按已有 GET 做有界轮询，恢复核原 runId/jobId；不假设已存在 SSE。queued/running/cancelling/cancelled/stale/timed_out/outcome_unknown 等按服务状态展示；网络超时不伪装成执行终态，取消受理不等于取消确认，旧代际不自动重跑。
- 输出、编译/执行诊断、可信检查与结果文件分开呈现。GET Run 没有公开入口/输入；仅原请求已通过回执关联 runId 时显示“本机请求记录”，缺缓存则历史参数不可回取，不能取当前控件值或补 Mock 字段。check 只用公开 verdict/failureKind；产物的 redacted/unavailable/missing/incomplete 不当空成功。可回取产物只读，不自动写回作品。
- 导入后的准备模式禁止原设置入口实际请求外部模型供应商；I0-A 不调用真实教学模型。真实模式不能携带设计演示中的浏览器 provider 密钥。所需设置入口调整仅限明确能力可用性，不重做设置页。

## Testing Decisions

- 主测试边界选定为 Playwright 实际工作区：启动同一个可交互准备命令，操作 Monaco/文件/保存/运行，使用真实 IndexedDB、刷新和多标签；以可见正文、状态、对象归属和实际请求断言。依赖/建库未批准时对应实施 blocked，不能用 Node 内存替身或测试内假保存宣称通过。
- 保留已有 Vitest 规则测试；复用 C2 integration 中的回执、错误和对象样例核 wire。Mock 数据须有契约来源，不只验证客户端与自己写的替身一致。
- 必测反例：发送后继续编辑；ACK 各本机写入阶段中断后刷新重放；两标签命令身份不碰撞且保留双方文本；g2 重读后 g1 ACK 迟到；同身份同 Attempt 两次加载逆序；旧 poll 迟到；原文混合 EOL/CR/BOM/非 BMP 打开、编辑、undo/redo、保存与快照；缺历史参数及 check/产物裁剪。原有断线、恢复、暂停、同名重建、取消和未知反例保持。
- UTF-8 字节限额、原 EOL 与 UTF-16 范围转换允许最少纯函数反例；不按内部 hook 拆大量实现镜像测试。不以截图代替行为断言。
- 工程检查包含前端 typecheck、既有 test、build，以及独立浏览器准备检查。浏览器 fixture 检查 50 文件/1 MiB 边界；不把模拟拒绝当作后端限额、C1 隔离或 NFR 性能已通过。
- 每张 ticket 记录命令、版本、通过/失败/未执行、合成与真实范围。最小路径先交导入→编辑/草稿→确认/快照→一次 Core 运行；网络恢复、多标签冲突、文件历史、取消和运行比较分别增强，综合收口不成为每项真实接入的前置。全部通过只能声明准备范围；真实读取、保存、运行各按必要交接条件验收，原 AC/NFR 和 G0～G4 条件不变。

## Out of Scope

真实 I0-B 辅导消息、流式展示、Help/Action 回执与教学控制；新增数字逻辑执行、板卡、波形；另起 UI/导航或更换前端框架；后台宿主/分配发现/恢复登记/执行 worker 的实现；C 编译器或 LSP；教师页、提交/总结和正式全产品验收；受保护产品文档、分工、CI/CD、密钥、生产发布与数据迁移。
