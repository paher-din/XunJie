## 4. 集成核对顺序

### 4.1 数字逻辑增量

1. 收齐 P2 原预交付证据与确认；记录 DL-D01～05 仍缺的配置、契约、环境、模型/网络条件。

3. A/C 按批准方案交课程/权限/正常业务入口与真实 Build/Session 批次；先验证保存、版本因果、信号来源、四值状态、隔离/限额/停止，保留 C 回归。
4. B 接获准真实结果与版本化求助；UI 按实际模块分批接线，不等待 A4/A5/B3/C4 全部完成。
5. A 组织 DL-E2E，各成员按 DL-AC-01～09 留证；缺真实模型/实际 UI 时只登记已验证层次，不记真实 Demo 通过。

### 4.2 原反馈闭环

1. C4 固定提交，C2/C3 提供不可变作品、真实消息/帮助和覆盖引用。
2. B3 生成候选，A4 重查授权、引用/版本、Job/停止/租约/代际与 expectedStateRevision；原分析/接纳或拒绝原因与有效状态同事务保存。
3. 教师账号经 A4 明确确认/纠正/暂缓；新状态与 C3 epoch/相关旧动作失效同事务提交。已显示帮助保留历史并标明后续修订，不伪造真人教师判断。
4. A5 保存正式反馈并推进提交复核，允许个人修订或创建相关后续活动；C4 保留旧提交，学生显式消费许可才继续。
5. 新求助由 B2 读取同课程/适用目标的最新有效状态；无关历史不带入，撤回依据不能通过新 claimId/措辞/分析版本复活，迁移证据不足保持未知。

各成员先交模块证据，再按实际接口做服务端整链核对。工程教师账号和合成数据不计真人反馈、学习观察或教学收益。
