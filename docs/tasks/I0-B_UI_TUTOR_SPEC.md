## Problem Statement

学生已有可以编辑、确认作品与查看运行结果的前端准备工作区，但其辅导交互仍主要来自设计演示。学生无法从正常业务链核实一次求助的对象版本、实际教学内容、停止状态和回执，也无法用三个独立控制准确表达暂停尝试、暂停过程采集和关闭提醒。

直接沿用演示的逐字剧本、自动排队续发、停止后继续生成和重新生成覆盖旧消息，会违反正式辅导链的学生控制、先审核后展示与历史保留要求。只把模拟响应换成真实 URL 同样不足以完成接入。

## Solution

沿用已交付的工作区、对话容器、消息呈现、代码编辑器和结果区域，将求助、消息、回执、停止、返回与控制接入已有 B2/C3/Workspace 公共 HTTP 契约。每个切片都在同一个可交互准备场景中完成请求、响应、可见交互和必要浏览器反例，不建立第二套聊天、保存或后台服务。

先验证可独立交付的消息/回执和控制，再接显式求助及停止，随后分别接代码/选区与原运行求助、获准例子与返回。准备内容明确为合成，不调用供应商；真实接线按对应能力的交接条件进入。缺少对象关联、历史回取或正常入口时保留不可用与待交接状态，不用准备字段补出真实成功。

## User Stories

1. As a 学生, I want 看清当前活动允许的帮助及限制, so that 我能选择合适的求助方式。
2. As a 学生, I want 围绕项目直接提出文字问题, so that 空历史或尚无代码不会阻止求助。
3. As a 学生, I want 只在明确发送时发起求助, so that 打开页面和编辑不会自动调用模型。
4. As a 学生, I want 区分正在发送、已受理、排队、处理中和失败, so that 我知道问题是否已经接纳。
5. As a 学生, I want 发送失败或结果未知时保留问题与原请求, so that 我可以核对而不重复发起。
6. As a 学生, I want 选择已确认代码或其精确选区求助, so that 回答指向确切文件实例和快照。
7. As a 学生, I want 在发送前核对并更正所指对象, so that 我不会误问另一份作品。
8. As a 学生, I want 未确认草稿与快照不一致时先看到差异, so that 系统不会偷偷保存或引用错版本。
9. As a 学生, I want 围绕一次原运行及公开诊断提问, so that 求助保留该次运行的来源和故障类型。
10. As a 学生, I want 历史参数不可回取时仍能查看合法公开结果, so that 缺参数不会被伪造或阻断已有资料。
11. As a 学生, I want 求助后继续编辑时看到回答的原版本边界, so that 旧提示不会标到新代码上。
12. As a 学生, I want 获准教学正文及主要下一步一起呈现, so that 一轮支持后能自主接棒。
13. As a 学生, I want 看清可读来源、帮助条件和未解决项, so that 我能核查建议并理解未知。
14. As a 学生, I want 缺正文、引用不可见或来源未交接时看到准确说明, so that 空缺不会冒充完整回答。
15. As a 学生, I want 只接收经过业务检查的完整教学结果, so that 未审核 token 不会提前泄露答案。
16. As a 学生, I want 断线重连先同步当前控制再补取内容, so that 已失效动作不会复活。
17. As a 学生, I want 同一动作重复投递只呈现一次, so that 网络重试不会重复帮助。
18. As a 学生, I want 收到、实际展示和明确回应分别记录, so that 系统不会把投递当阅读或掌握。
19. As a 学生, I want 隐藏标签页或收起的消息不被登记为已展示, so that 展示事实可信。
20. As a 学生, I want 明确回应后才记录 acknowledged, so that 渲染、复制或普通点击不被猜成采纳。
21. As a 学生, I want 在生成中或已生成未展示时停止该次帮助, so that 迟到正文不能继续出现。
22. As a 学生, I want 看清停止请求与权威停止结果, so that 断线不会产生假停止。
23. As a 学生, I want 新求助显式替换旧求助, so that 一次尝试不会自动串行续发多个答案。
24. As a 学生, I want 停止和替换后保留已显示的历史事实, so that 重试不会覆盖原教学内容。
25. As a 学生, I want 看获准的类似例子后返回原文件和位置, so that 例子不会覆盖我的项目。
26. As a 学生, I want 例子与我的作品明确区分, so that 我自己决定怎样运用建议。
27. As a 学生, I want “我先试试”后继续自主操作, so that 系统不会自动继续生成、改代码或运行。
28. As a 学生, I want 分别设置尝试暂停、过程采集和里程碑提醒, so that 三种状态不被混为一谈。
29. As a 学生, I want 暂停采集时仍能显式保存和求助, so that 功能数据例外与覆盖空窗清楚可见。
30. As a 学生, I want 恢复采集只记录后续过程, so that 暂停期间不会被补造学习事件。
31. As a 学生, I want 关闭提醒仍能主动求助, so that 我能控制打扰而不失去帮助。
32. As a 学生, I want 教师暂停优先于个人恢复, so that 不能通过前端开关绕过活动限制。
33. As a 学生, I want 模型失败、预算耗尽和超时不影响获准保存, so that 我的作品可以继续保留。
34. As a 学生, I want 用键盘发送、停止、确认、查看例子并返回, so that 主要交互不用依赖鼠标。
35. As a 接入成员, I want 每张 ticket 都有完整可回放行为及来源记录, so that 准备结果可逐能力交接。
36. As a 验收成员, I want 准备、真实服务、实际模型、浏览器和真人证据分别报告, so that 部分工程通过不会替代正式验收。

## Implementation Decisions

以下为经Robert委托复核后定稿的前端方案；现有契约和已有决定继续有效。最小UI接线与拟写集已在规划范围内明确，D-01/D-02/D-03等未交接公共能力仍保留门禁。定稿不是已实现或已验收。

- 继续原前端分支与现有 React/Vite/Monaco 工程。复用实际工作区、对话面板与只读内容容器；仅增加本批必要业务 props、状态、对象引用及操作，不改变导航、布局和框架。
- 准备与真实模式共享窄 HTTP 客户端和领域状态；准备能力扩展已有开发 authority。正式构建不带开发控制端点、合成账号或模型替身，生产浏览器不直接请求供应商。
- 教学展示只消费 C3 已公开的事件分页及通过检查的正文；本批采用现有游标分页/有界轮询，不把技术基线中的 SSE 描述当作已实现流式入口。不模拟 token、思维链或假排队位置。
- 每次 await 核模式、Session、课程、Assignment、Attempt、loadEpoch、受信代际及读取轮次。事件页须先核 control，resyncRequired 时只接纳权威控制并重读；旧页不能推进游标或更新当前展示。hasMore 按页补取，serverSeq 不要求连续。
- 用 actionId/contentHash 对消息内容身份去重，用实际 eventId/serverSeq 和服务游标处理补取。只有正文、身份及本机待回执事实成功保留后才推进持久游标；存储失败保持可核对状态。metadata/outbox 复用既有存储，拟只加命名空间记录和兼容可选字段，不增加库版本、store 或索引，不迁移旧记录。
- 教学clientId按原标签通道隔离，刷新恢复原通道身份及其游标，不复用sync序号或把另一标签当原投递对象；新通道不能携旧游标跳过自己尚未取得的Delivery。存储丢失时按新通道处理，历史不可回取保留D-02，不用缓存或换clientId规避服务授权。
- received 只在目标客户端收到并核验该版本后产生；displayed 只在正文完成渲染、页面可见且消息本身处于可见展示区域时产生；acknowledged 只由明确确认/回应产生。回执复用原 action/hash/clientReceiptId/幂等键；缺回执保持未知，真实发生的迟到展示事实保留竞态原因。
- 求助按已有 question、expectedAttemptRevision、recoveryGeneration 和可选 ObjectRef 发送，不把课程、身份、政策、模型配置或本机命令元信息塞进 wire。命令先冻结和本机持久化，重试保留原正文与原键，当前 CSRF 仅内存取得。
- 明确区分输入中的问题、已接纳的学生问题、Job 状态与教学 Action。空画像不阻止项目求助；拒绝、超时、预算耗尽、依赖不可用和结果未知沿公共语义展示，客户端超时不自行宣判服务端终态。
- 同一 Attempt 的有效帮助与替换采用 B2 的现有规则。忙时再发送须明确表达替换意图；未发送草稿可以保留，但不自动排队续发。停止先在本地阻止迟到展示，再发原 Job 的持久取消；浏览器 abort 不代表停止完成。停止后再次求助是新的学生命令，不继续旧 Action。
- 已succeeded的教学Job取消后保留原终态，按权威stopRequested及invalidatedActionIds处理未展示内容，不一直等待status变cancelled；在途帮助按其实际停止/未知结果展示。已发生的displayed/acknowledged事实始终保留。
- 代码求助使用已回取校验的不可变快照、fileId/path/documentVersion/contentHash，选区先从 Monaco 显示投影映回原文，再按一基 UTF-16/起含终不含语义构造。不可精确表示时说明不可用，不猜位置或规范化作品。求助本身不自动确认新草稿或冻结新版本。
- 运行求助核当前 Attempt 的原 runId/snapshotId 和合法公开结果；缺本机请求记录不借当前运行控件补参数，环境故障与学生代码/课程判断分开。求助不触发重跑。
- Action 到原 Job/ObjectRef/版本的关联必须来自获准公开来源。现有事件 payload 没有这些完整依据；缺口确认前，不依据消息顺序、最近一次求助或内容匹配推断绑定，不在当前代码上定位旧建议。
- 已显示内容保存历史身份，不被“重新生成”覆盖。新页面、另一 clientId 或失效 Action 的历史正文若无法从当前公共来源回取，显示不可回取；本机缓存仅作原客户端历史，不能代表服务当前有效性或跨设备恢复通过。
- 复用现有只读正文/概念容器阅读教师批准的相邻例子或有来源的教学正文。没有专门例子 DTO 时不从自由文字补造结构化交互卡、可执行 HTML 或波形。
- 返回目标分开记录业务 ObjectRef 与本机文件视图状态。精确返回原实例/位置须核映射；已回收、同名重建、跨 Attempt 或版本已变时保留原引用并提示，不把位置改贴新实例。需要服务端恢复位置时只使用已有 position 控制，不因打开例子自动写学习状态。
- 三个控制采用原 attempts controls：pause/resume、capture 布尔值、reminders 布尔值；请求使用权威 Attempt revision，回执后重读。提醒默认关闭，采集暂停不改变主动求助，平台暂停优先，恢复不复活旧 Job。
- 帮助政策来自固定活动公开投影，限定检查还需可信当前检查状态；不能从 UI 模式、学生文字或本机设置推断。服务端继续鉴权和检查，不把禁用按钮当安全边界。
- 原规划不修改共享服务端契约。2026-10-13 Robert对[计划§10.3具体方案](I0-B_UI_TUTOR_PLAN.md#103-需要负责人确认的最小跨模块方案)追加授权后，本批限定补入已有事件的原 Action 关联、GET Attempt 的同事务限定检查投影、原 B2/C3 正常宿主/持久 worker组合与同一前端真实深链；不另建替代业务接口或 schema。历史读取复用已有公开路由。

## Testing Decisions

- 主测试接缝是现有 Web 工作区经同一 HTTP 客户端到同一开发 authority 的可见行为；复用 Playwright、真实 IndexedDB、刷新、多标签与故障注入。每张 ticket 自带最小成功链和风险反例，不等最终大收口才验行为。
- 合成响应逐字段追溯 B2/C3/Workspace schema 和原集成样例；不能给 fixture 增加真实响应中不存在的 Job/ObjectRef/政策字段来伪造闭环。缺失字段也作为不可用反例。
- 展示回执在真实浏览器检查 DOM 渲染、文档可见性和消息可见区域；覆盖隐藏页、收起面板、重复渲染、StrictMode、重复投递、丢 ACK、刷新、另一标签与明确回应。不能调用回执函数冒充实际 displayed。
- 状态/停止覆盖模型前、生成完成未展示、本地停止后旧分页到达、新求助替换、旧 poll、换账号/Attempt/代际、重连、已显示后失效；校验请求事实与可见内容，不只断言内部状态。
- 对象覆盖原快照与新草稿差异、BOM/CRLF/裸 CR/非 BMP 坐标、回收同名重建、旧运行/公开诊断缺项；只在已有高层边界难覆盖时加少量纯函数反例。
- 控制覆盖三开关互不替代、采集暂停仍保存/显式求助、恢复不回填、提醒关闭不阻止求助、教师暂停不可绕过、限定帮助拒绝与模型故障不阻断保存。
- 每票跑必要前端 typecheck、相关 Vitest、build 和对应浏览器 spec；有新失败或未解疑点才扩大。最终组合核保留的作品链与数字逻辑演示，准备通过不复算原 AC/NFR 全项通过。
- 真正的 B2/C3 HTTP 集成使用成员已有工厂与合成验证方式；UI 不因写规格自行建库或装配新宿主。真实内容/已准历史材料的浏览器回放与新供应商请求分开，新增请求需新许可。

上述测试接缝已按Robert委托复核定稿；规划交付时实际业务/浏览器测试均未执行，后续实际结果另记批次计划。附件逐项条件的核对与定稿理由见批次计划§8.2。
