## 2. 共同输入与可信来源提案

模型只接收 `modelContext`；以下运行元数据由服务端从 A 的授权和 C 的持久记录构造，模型不能回传身份/版本来覆盖它们。

| 字段 | 来源与校验 | 适用范围 |
| --- | --- | --- |
| actor / authorizedScope | A 的 ActorContext、当前会话/成员/资源授权；用途不可由模型扩大 | 全部任务，课程与角色逐次校验 |
| jobId / receiptId / kind / purpose | C 的已接纳 Job/命令，固定 scope 与用途 | teacher_generate、student_help、candidate_analysis |
| acceptedAt / deadlineAt / callCount | C/调用协调层持久记录；每轮总等待从接受开始 | 包含排队、工具循环、传输重试和一次修复 |
| leaseToken / recoveryGeneration | C 的有效租约及 A/C 恢复边界 | 完成/保存时重新核对，不是模型输出字段 |
| modelConfigVersion / promptVersion / schemaVersion / analysisVersion | B 的批准配置引用；实际模型 ID、价格口径及结构化模式固定 | 无配置时仅合成测试，不冒充供应商已接入 |
| expectedStateRevision / decisionEpoch | A 当前有效学习状态、C 对应 Attempt 决策上下文 | 学生辅导与候选；空状态为 revision=0，不补历史 |
| inputRefs / assistanceRefs / coverageRefs | A/C 解析的获准原始引用、实际帮助及覆盖区间 | 存在、归属、固定版本/正文/hash 与来源均核验 |
| objectRef / activityVersionId / policyVersion | C 确认作品/结果及 A 固定活动/政策 | 学生任务；teacher_generate 不借用学生 Attempt |

资源引用的处理分两类：学生使用 TECH_DESIGN §4.1 的 ObjectRef；教师设计采用 A 授权的 `resourceVersionId/paragraphId/contentHash/visibility` 和 `blueprintId/baseRevision`，不为资料引用伪造学生 attemptId。教师引用的具体外层命名由 A 会审，本稿不修改公共 ObjectRef 联合类型。

输入正文（资料、学生消息、源码、工具输出）都是不可信数据，不能成为系统政策或工具权限。过滤在检索和供应商请求前完成；身份凭据、其他学生信息、未授权私有资产不进入模型。教师专属资料仅在 A 明确批准 teacher_design 用途时可用，不能混入 student_help；输出提案仍须由 A 做角色投影/发布前核验。

`resultHash` 由服务端对持久保存的已校验结果正文原始 UTF-8 JSON 字节计算 SHA-256，不 trim 或转换换行，不采信模型自报摘要。结果同时绑定 jobId/kind、固定输入和配置版本；同结果重试复用保存的正文与摘要，不能重新序列化后伪称原结果。返回原 ID 前仍检查当前权限，不通过幂等命中绕过授权或失效守卫。

## 3. 教师生成与局部提案

### 3.1 输入与输出形状

输入：可信教师/课程范围、需求文本、已知目标与先备/资源/时间约束、获准资料段落；`mode=candidates/blueprint/patch/rubric_trial`。patch 须带 blueprintId/baseRevision 和目标字段，缺关键条件返回 `needs_input`，不要求教师预先上传完整机器配置。

模型产出形状如下；公共 ID 和信封元数据由服务端附加，关联 ID 由 A 校验或分配：

| mode | body 必需字段 | B 校验 / A 保存 |
| --- | --- | --- |
| candidates | candidates（1～3项）；每项问题/受众/作品/路线空间、三条能力线目标建议、约束/未知、resourceRefs | 数量/结构/引用；目标与内容供教师审阅，非验证效果。A/design 保存候选 |
| blueprint | problem、audience、artifact、routes、goals、milestones、resources、helpPolicy、checkpoints、rubric、goalEvidenceLinks、unresolved | 核心目标均有观察安排；不捏造证据。A/design 保存草案，教师选择/编辑 |
| patch | changes（字段及建议值）、rationale、resourceRefs、affectedLinks、unresolved | 目标字段在允许编辑集合中，建议绑定 baseRevision；A 保存提案，不覆盖主草稿 |
| rubric_trial | criterionComments、ambiguities、suggestedChanges、sampleRefs、unresolved | 只记录指定样例试评建议；教师决定量规修订，不自动生成正式评价 |

教师提案信封：`jobId/courseId/blueprintId或null/baseRevision/inputRefs/版本集合/resultKind/body/resultHash`。同 `(jobId,resultHash)` 保存重试返回同 proposalId；同 Job 异结果冲突。A 返回 `stored_proposal + proposalId + baseRevision + applicability=current/stale`，不把建议保存等同采用。

### 3.2 并发、失败与边界

人工编辑从 r3 变 r4 时，r3 的模型提案可保留为过期建议，不能自动 PATCH r4；教师采用仍走 A 的 expectedRevision/CAS 命令。取消/超时/恢复代际失效时只归档已产生事实，不新建可采用建议。资源越权、结构不合或引用不可回取分别返回 §6 的拒绝，不改主草稿。

B 没有发布活动、分配学生、保存正式反馈或执行作品的工具。教师生成的教学质量、目标/量规关系需真人课程审阅；结构通过不构成内容正确。模板中的私有资产必须由 A 的角色投影隔离，不能靠“模型未主动输出答案”代替授权。

## 4. 学生辅导

输入沿用 TECH §6.1：学生显式问题/意图、已确认对象、获准课程段落、固定活动/帮助政策、相关有效状态及反证、自述/正式反馈、实际帮助与覆盖。无历史可继续；代码尚未确认则先同步，不能拿本机草稿冒充上传证据；project/resource/run 求助不强迫选代码。

body 为 `actionType/content/rationale/expectedStudentAction/evidenceIds/resourceRefs/assistanceContext/unresolved`；actionType 使用 TECH §6.1 已有集合。证据 ID 须存在且适用，不仅检查 JSON 或 hash。content 是实际教学原文，rationale 是简短可审阅理由，不保存模型内部思维链。

完成信封附可信 `jobId/scope/ObjectRef/expectedStateRevision/decisionEpoch/policyVersion/恢复及租约/版本集合/resultHash`。C 在持久守卫通过后保存 Message/TeachingAction，返回 `queued_for_delivery + messageId/actionId/contentHash`；发送只记发送尝试。客户端收到/展示/明确确认分别回执；缺回执保持未知，不从下次编辑推断阅读或采纳。

普通“要完整答案”请求可以在允许的帮助入口转为支架；已在限定检查中禁用的入口则前置拒绝、供应商调用为零。两者不是同一个测试分支。相邻例子保留返回对象，不覆盖原作；帮助后等待学生，不自动修改、运行或提交。

## 5. 候选分析、反馈草稿与接纳

输入：获准 Job/purpose、当前课程/学生/尝试及活动版本、预期状态/epoch、固定作品/运行/检查/消息/解释引用、帮助事实/缺展示证据、coverage、有效状态/反证/撤回约束。用途至少区分 `explicit_analysis/passive_analysis`；具体触发点与 purpose 名称待 A/C 会审，不能由模型启用采集。

body 的 claims 每项含 `competencyId/competencyVersion/domain/scope/statement/evidenceIds/counterEvidenceIds/assistanceStatus/state/validity/unresolved`，状态/帮助/有效性使用 TECH §4.2 集合；另可有 `feedbackDraft`，固定 submissionId 或相关输入引用，明确 kind=draft。无证据允许 insufficient/unknown，不能伪造观察、掌握百分比或正式判断。

候选信封：`jobId/courseId/studentId/attemptId/activityVersionId/expectedStateRevision/decisionEpoch/inputRefs/assistanceRefs/coverageRefs/collectionPurpose/政策及模型提示分析版本/恢复代际与租约/resultHash/body`。可信字段来自原 Job/A/C，不来自模型的自报身份；仅候选语义字段由模型产生。

接纳提案分工：B 结构/引用/政策初检 → A/review 通过同一短事务核当前权限、Job 持久状态/停止标记、用途开关、scope/引用/撤回约束及 CAS → C 保存输入/分析原文和接纳或拒绝原因 → 成功才由 A 追加有效 LearnerStateRevision。事务外调用模型，C 不另开提交；A 的状态更新失败时整个接纳交易回滚，不双写头版本。

成功返回 `accepted_candidate + analysisId + candidateIds + newStateRevision`；已成功同结果返回原 IDs/revision，不重复生效。过期、已取消、证据越权或 CAS 冲突返回明确拒绝及可见引用；B 不能把旧结果改贴新 revision。教师先纠正则旧候选拒绝，候选先接纳则旧教师表单冲突；被明确撤回的相同主张不能换 ID/措辞/分析版本复活。原始事实、模型候选、教师决定始终分开。

暂停采集停止新/在途被动分析；恢复后旧 cancelled/stale Job 仍不接纳。显式求助的必要功能数据仍保存，是否附带分析由获准 purpose 决定；空窗不填“无帮助”，已观察到的帮助仍保留。环境失败不是知识错误，学生“我会了”只是自述，课程检查通过不是独立掌握。

## 6. 正常、拒绝、失败与返回提案

统一返回形状建议为 `outcome/refIds/errorCode/reason/requestId/retryAdvice`；reason 不含越权正文、内部路径或凭据。A 汇总实际字段，C 提供持久记录，不是已存在 SDK。

| outcome / 原因 | 业务效果与恢复 |
| --- | --- |
| stored_proposal / queued_for_delivery / accepted_candidate | 分别表示建议保存、教学内容待投递、候选已接纳；均不表示教师采纳/学生阅读/正式评价 |
| needs_input | 缺必要条件或引用正文；返回获准范围的缺口，现有作品仍可保存，不编造上下文 |
| rejected / unauthorized、invalid_reference、invalid_schema、policy_blocked | 401/403/422 由 A 统一；禁用入口无模型调用，非法候选不写有效状态 |
| stale / version_conflict、withdrawn_basis、recovery_required | 409 或内部 stale 完成；重读当前上下文后显式新请求，不换键重放未知动作 |
| cancelled / stopped | 不新建替代 Job；禁止该 Job 迟到动作及重连投递，保留已生成/已展示/已计费用事实 |
| timed_out | 从接受含队列达到45秒时终结；迟到输出只归档，不投递、不接纳，不因重启重置时限 |
| unavailable / budget_exhausted | 503/429；保留问题、作品、人工入口，系统降级提示不冒充模型教学内容 |

`cancelled/stale/timed_out` 等终态输出不得因通知/供应商取消失败而重新接纳。显式停止一个已完成生成但未展示的教学 Job，须同时持久停止其未展示 Action；不只看 Job 是否 succeeded。这里采纳 A0 的按用途停止提案，C0 的“已完成返回”须共同细化到 Job/Action，不能由 B 单方宣布接口已支持。

## 7. 时限、调用次数、版本与费用

每轮最多3次供应商生成请求，工具循环、一次格式/政策修复、可计费重试共用计数。建议适配层关闭隐式 SDK 重试，由可观测调度层统一预算；选用不同 SDK 时先核其实际重试语义。修复最多一次，不因换 worker 重置 acceptedAt/callCount/deadline。排队/准备/调用/校验共用45秒上限，末次请求只获得剩余时限。

取消不等于供应商没有执行/收费。C 记录每次开始/结束/错误/是否修复、实际或 unknown 用量及价格/模型配置、延迟；模型 reasoning 用量按供应商 usage 计，不能只按可见答案计。原请求 outcome_unknown 时不偷偷重发或退回已保留额度；预算不足先阻止新的调用，既有保存/人工复核继续。

完成时同时核租约/恢复代际、Job/Action 持久停止、相关状态/epoch、对象及政策版本、用途许可；不能仅检查调用前版本。无关提醒/采集开关变化不机械使主动帮助失效，文件变化通过对象版本检查，完成/投递/候选接纳各阶段均要守卫。具体接缝待 A/C 会审，真实故障验证未执行。

模型/配置切换显式新 modelConfigVersion、数据范围复核及回归；无自动跨模型/供应商/地域降级。默认仅在课程授权材料内检索，不启用供应商联网、任意URL抓取、代码执行、shell、浏览器控制或写文件工具；如将来确需其他检索，先评审数据流/费用/权限再授权。
