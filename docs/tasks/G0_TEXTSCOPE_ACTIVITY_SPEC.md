## 2. 数据与技术约束

- 基础版本处理普通 ASCII 文本，使用 LF 换行；不要求二进制、Unicode 中文分词、正则或复杂文档解析。
- 单词是 `[A-Za-z0-9]+` 的非空连续序列；其他标点和空白是分隔符。词频统一小写，检索输出保留原文大小写。
- 空文件为 0 行；有内容但末尾无换行符的最后一行计为一行。
- 可用 C 标准库，包括 stdio/stdlib/string/ctype，允许 qsort；词语识别、计数和数据组织由学生实现。
- 不调用 grep/sort/wc 等外部工具代替核心功能；不要求 GUI、数据库、网络服务或并发处理。
- 词频数据结构至少使用一种自引用结构，如链表、二叉搜索树或链式哈希节点。学生选择并说明理由、插入/查找复杂度，不以复杂算法本身作为优胜指标。
- 同一文件读取和单词识别逻辑应复用，避免各命令重复实现。

## 3. 四类命令与共同要求

| 命令 | 输入与行为 | 输出要求 |
| --- | --- | --- |
| `textscope stats article.txt` | 支持一个或多个输入文件，统计字节/行/单词 | 每文件结果及全部成功读取文件的汇总 |
| `textscope find memory article.txt` | 多文件完整单词匹配，默认 ASCII 字母不区分大小写；memory 匹配 Memory，不匹配 memories | `文件名:行号:原文行`；同一行多次命中仅输出一次 |
| `textscope top -n 10 article.txt` | 合并所有输入文件的词频，不分别给互不相关的表 | 次数降序；并列按小写单词字典序升序，输出前 N 项 |
| `textscope report -o report.txt article.txt` | 合并分析并写指定报告文件 | 文件列表、各文件统计、总字节/行/单词、不同词数、前 10 名词频；不是只打印终端 |

所有命令都支持多个输入文件。报告当前不足 10 种词时全部列出。词频集合不能创建重复逻辑词条；长行超过初始缓冲区仍应正确处理。

| 错误或结果 | 负责人规定的行为 |
| --- | --- |
| 未知命令、缺少必要参数 | 输出用法，退出码 2 |
| 文件不存在/不可读、输出不能创建、读取/运行时错误、内存分配失败 | 错误写 stderr，退出码 1，可靠释放已有资源 |
| 所有请求完全成功 | 退出码 0 |
| 一部分输入文件失败 | 继续处理其他有效输入，最终非零退出，并明确结果覆盖了哪些文件 |
| 空文件、连续分隔符、超长行 | 合法边界，正确处理，不以崩溃结束 |

## 4. 六阶段交付

| 阶段 | 学生预计投入 | 核心任务与可核验产物 | 验收与教材 |
| --- | --- | --- | --- |
| Stage 1 需求/接口 | 3 小时 | 简要需求、命令行接口、模块关系图、至少 5 个功能测试场景；列错误输入 | 能解释命令分发；第 3/4/5 章 |
| Stage 2 读取/统计 | 6 小时 | 单文件扩到多文件，字节/行/词计数、EOF、动态长行、关闭文件/释放缓冲；stats 可运行 | 空文件、末尾无 LF、超过 4096 字节的行、多文件汇总、访问失败；第 1/4/5/7 章 |
| Stage 3 识别/检索 | 6 小时 | 字符扫描、单词开始/结束、大小写归一化、完整词匹配、行号和多文件；find 可运行 | 解释完整词与子串、行边界；第 2/3/4/5 章 |
| Stage 4 词频/排序 | 8 小时 | 自引用结构的插入/查找/计数、未知数量的动态内存、可排序集合、前 N、完整释放；top 可运行 | 不重复词条，增长可分配，并列排序可预测，无明显泄漏/越界；解释结构与复杂度；第 4/5/6/7 章 |
| Stage 5 报告/集成 | 5 小时 | 报告输出、统一错误、多源文件/头文件、必要函数声明，控制全局变量依赖；四类命令可运行 | 模块协作、数据传递、错误处理；第 4/5/6/7 章 |
| Stage 6 测试/交付 | 7 小时 | 正常/边界/异常测试、编译器警告、内存检查、README、演示、设计总结、个人答辩 | 完整交付；Linux/WSL 增加第 8 章低级 I/O 小任务 |

Linux/WSL 小任务：用 open/read/close 实现低级读取，比较标准 I/O 的字节计数；处理分块、部分读取、失败。不重写整个文本分析系统。

## 6. 负责人提供的统一验收数据

两个文件均 ASCII/LF，最后一行带 LF。下列代码块的每行正文就是文件数据，末尾 LF 不省略。

`a.txt`：

```text
C is fun.
C is fast.
Memory matters.
```

`b.txt`：

```text
C and memory.
```

测试 A：`textscope stats a.txt b.txt`。

| 文件 | 行数 | 单词数 | 字节数 |
| --- | --- | --- | --- |
| a.txt | 3 | 8 | 37 |
| b.txt | 1 | 3 | 14 |
| 合计 | 4 | 11 | 51 |

测试 B：`textscope find memory a.txt b.txt`。

```text
a.txt:3:Memory matters.
b.txt:1:C and memory.
```

测试 C：`textscope top -n 5 a.txt b.txt`；单词与次数间展示空白，具体机器验收格式见补充提案。

```text
c       3
is      2
memory  2
and     1
fast    1
```

测试 D：`textscope report -o result.txt a.txt b.txt`。result.txt 至少包含上述统计、不同单词数 7、全部 7 个词的排序结果：c(3)、is(2)、memory(2)、and(1)、fast(1)、fun(1)、matters(1)。

学生补充空文件、重复词、仅空白、超长行、不存在文件等测试。示例预期须独立重算，不能以学生打印 passed 或进程退出 0 判断课程通过。

## 8. Web 学生空间中的活动适配

### 8.1 主项目和相关后续任务

负责人已确认首个活动为 TextScope Core：学生在 Web 工作区实现 stats/find/top，沿用候选中清楚可验证的 ASCII/LF、完整词、大小写、并列排序、多文件和错误覆盖规则。相关后续活动为 TextScope Report：教师复核 Core 后，学生基于有效反馈在新活动/尝试中复用已有逻辑，增加报告文件生成和产物核查。活动划分已确认，具体 TS-P 行为、目标和帮助衔接仍待批准；不强迫一个活动一次覆盖全部功能。

负责人已明确试点先备为函数、数组和指针基础，结构体/动态内存作为项目中训练的候选目标，实际教学支架仍由教师确认。词频存储允许动态数组、链表、BST 或哈希等合理路线，比较选择依据与测试，不强制自引用结构。原稿“学完整本 K&R”、25～40 小时、六阶段固定课时和五维评分只作参考，不作为 MVP 的学生入场/验收门槛。第 8 章 POSIX 低级 I/O 作为拓展候选，不成为首版额外必交任务。

### 8.2 实际学生操作与版本

1. 教师从教材和本参考题材与 Agent 共同形成蓝图，确认目标、公开练习数据、检查与帮助政策后分配固定活动。
2. 学生从实际 Web UI 进入自己的 Attempt，在工作区新建/编辑 C 和头文件、创建或导入教师提供的 ASCII 测试文本；保存状态区分本机草稿与服务器确认版本。
3. 学生显式发起运行，提交固定源码快照与课程批准的操作/参数；例如选择 stats 或 find、指定快照中的数据文件和查询词。学生不需要安装 GCC、WSL、容器或打开宿主终端。
4. 后台固定编译/执行配置把操作映射为受控可执行文件和参数数组，在独立 Linux 作业环境执行；Web UI 显示同一快照的结果/错误。运行和可信课程检查是不同动作。
5. 就地求助绑定代码/结果对象，Agent 给出建议后交还学生。学生继续修改、比较版本/结果、补充解释和测试，再主动提交固定快照。
6. 教师在本应用复核作品、帮助条件、三条能力线与未知，决定反馈/纠正和相关后续活动。学生仍从 Web 学生空间进入 Report 新尝试，不切换到本地软件项目流程。

具体页面、控件和参数/文件产物呈现采用 UI 成员实际交付。后台记录必需操作和接入缺口，不另做替代页面。实际 UI 最终需要支持课程运行参数、只读文件产物和解释/反馈等业务能力；尚未审阅交付，不断言入口已经存在。

### 8.3 教学与评价

三条能力线分别记录：C 语言的实现/解释/边界表现；项目中的结构选择/复杂度比较/测试与修订；人机协同中的提问分工、核查/调整或拒绝建议及理由。原稿评分权重不直接采用；按作品明确检查和三条能力线的少量具体表现组织形成性反馈，正式课程量规由教师确认，不把 AI 使用量或采纳率加成/扣分。

原稿线下答辩/现场修改适配为 Web 工作区中的短解释、设计取舍复盘或教师确认的小范围变式，保留帮助条件和未知；首版不新增语音、视频或外部答辩流程。提交物为源码快照、测试数据/运行/可信检查引用、必要解释和文档，不要求上传本地编译出的可执行文件。

## 9. 待确认的精确行为补充

| 编号 | 缺失点 | 最小建议 |
| --- | --- | --- |
| TS-P01 | stats/report 的机器核对格式未固定 | stats 每成功文件 `path<TAB>lines<TAB>words<TAB>bytes`，末行 `TOTAL` 同列；top 接受单词/次数间一个或多个 ASCII 空白，按固定顺序核对；report 使用文件清单/同列统计/TOTAL/UNIQUE/有序 TOP 部分，忽略非语义空白，不能忽略数值/覆盖范围 |
| TS-P02 | find 参数/无匹配、N 取值、命令解析 | 查询词必须是一个非空 `[A-Za-z0-9]+` 单词；无匹配为成功空输出/退出 0。N 为可表示的正整数；N 超过不同词数输出全部。未知选项/溢出/无输入返回 2；带 - 前缀的路径通过 `--` 分隔，不吞成选项 |
| TS-P03 | 输入失败与读取中断的汇总 | 未完整读取的文件标失败，不计入成功汇总/词频；find 如已输出部分行仍在 stderr 标覆盖不完整、退出 1。内存失败/计数溢出不能发布看似完整的报告 |
| TS-P04 | report 覆盖输入/已有输出 | 拒绝输出与输入同目标；默认拒绝覆盖已有输出，错误写 stderr/退出 1。全部可读文件分析结束后才创建报告；写失败返回 1。学生只需实现项目约定，平台另外保证只读输入和独立临时输出区 |
| TS-P05 | 内存失败的课程验证 | 在批准的测试配置中做可重现分配故障/检查错误返回；纯 OOM/工具掉线为环境或资源不完整，不记知识错。不强制为正式作品增加未请求的通用分配框架 |
| TS-P06 | Web 运行需要参数，Report 需要文件产物 | C 提供课程约束的参数输入和结果引用，服务端从快照解析文件，固定程序/参数数组执行。未知命令/缺参由课程批准错误样例验证，不开放任意 shell。C1 终止后受限回取文本产物，C2 保存来源/范围；只读查看，不自动回写作品。见 G0-C15 |
