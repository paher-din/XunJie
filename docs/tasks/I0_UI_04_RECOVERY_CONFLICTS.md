## Acceptance criteria

- [ ] 断线编辑/刷新仍有原文草稿；未发草稿、在途未知命令、已确认正文分开，不把超时当拒绝/成功。
- [ ] ACK 丢失后核或重发原完整业务输入，键/seq/代际/正文不变；新编辑不能挂旧键。重连不自动发送新业务操作。
- [ ] 多标签抢原命令 lease 不导致新命令，重复重放仍是同键同正文；原命令已确认时停止重发，当前 head 需重读。
- [ ] RECOVERY_REQUIRED 停旧重试，重读受信上下文；保持草稿并提示比较，不换代际/业务键续写。VERSION_CONFLICT 转 04A 的明确选择，未交付时保留正文且阻止自动覆盖。
- [ ] 复用 03 的 loadEpoch/代际守卫；账号/模式/Attempt 切换后旧重连结果不回灌。暂停/终态依权威状态，不补传编辑过程。
- [ ] 在普通 dev:prep 和实际浏览器测试复现丢 ACK→继续编辑→刷新→原请求重放，检查请求身份/数量、同 fileId 和正文保留；旧代际/存储失败也保留事实。
- [ ] 跑相应工程及浏览器检查，记录准备范围；真实恢复没有执行就保持未执行。
