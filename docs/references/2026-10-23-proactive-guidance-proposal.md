# 跨课程主动引导：学生选择、反馈适应与体验验证

整票结论与后续架构、重构验收交接见[连续教学决议](https://github.com/paher-din/XunJie/issues/118#issuecomment-6364486548)。

一手依据及适用限制见[主动引导调查](2026-10-23-proactive-guidance-research.md)、[无扰检测原始研究](2026-10-23-unobtrusive-guidance-evidence.md)和[开源实现核查](2026-10-23-unobtrusive-guidance-implementations.md)。HAX 支持区分局部反馈与全局控制、谨慎改变行为；Help Tutor 的求助行为改进未直接带来已检出的额外学科增益。这些来源支持分别考察体验、行为与学习，不能证明循阶采用本方案后必然有效。

## 已确认的方向

- 面向实际课程的多种学习活动；数字逻辑只是开发、演示和验证样例。活动可以没有代码、运行步骤或唯一标准答案。
- 教师提供材料、项目要求与已有目标，Agent 协助形成目标、评价依据和帮助策略，教师确认后使用；不要求教师编写完整教学脚本。
- 默认提供有依据、简短、可忽略的轻度主动帮助；学生正常推进时保持安静，明确希望自己尝试时尊重其选择。
- 增加学生对主动帮助的选择，并根据真实反馈优化主动性和实际使用体验。
- 已确认三档设置、全局默认与课程覆盖、当前活动暂停，算法不自动换档或解除暂停；已确认可选反馈与少量活动结束询问。
- 已确认无扰检测首版路线：复用正常活动证据，以课程进展依据和可解释规则形成帮助候选，再控制投递时机；先回放与观察候选，再做少量真实活动验证，有可靠标签和结果数据后才评估更复杂的模型。

## 已确认的学生选择：三个清楚的档位

| 选项 | 学生可以预期的行为 |
| --- | --- |
| 仅在我提问时 | 不主动发起教学提示；学生仍可随时提问，已请求操作的结果照常返回 |
| 适时提醒（默认） | 有具体、相关的困难或遗漏时给简短提示；正常推进时安静，不因一次停留就追问 |
| 更多引导 | 在合适的活动转折处，更主动地建议下一步、检查理解或提供补学；仍可忽略，不连续催答 |

另提供“先让我自己试试”：暂停当前活动的主动提示，学生可主动恢复；刷新或返回同一活动不自动撤销暂停。开始另一活动时采用所选档位。具体入口在后续界面方案中确定，不在这里决定布局或视觉样式。

全局设置保存学生的一般意愿，并允许当前课程覆盖。适应算法只在当前选择允许的范围内调整时机、频率与方式，不暗中改档，也不跨过暂停。显式选择优先于推测偏好。课程帮助策略继续约束能给什么帮助；“更多引导”不等于获得更完整答案或允许代改作品。

跨课程只复用明确的通用设置。某课程中学到的提醒时机、内容偏好与困难判断保留其课程和活动语境，不能自动套用到其他课程。学生可以修改设置、纠正偏好或重置学到的帮助偏好，而无需清除学习作品和真实过程记录。

## 反馈要能说明问题，又不能成为额外作业

已确认提供可选的简短反馈入口，不要求每次帮助都评分，区分“有帮助”“没解决”“现在不需要”“太打断”；其中“没解决”建议可进一步自愿说明内容不相关、看不懂或仍有困难。少量活动结束时的体验询问用于发现没有主动反馈的情况，不在每条提示后追加问卷。已确认以正常活动的无扰检测为基础，保留少量自愿反馈用于校准。

| 观察或反馈 | 本次应怎样处理 | 不能据此推出什么 |
| --- | --- | --- |
| 明确说“先自己试试”或切到仅提问 | 立即停止本次自主提示；已生成但尚未展示的提示重新检查是否还能投递 | 学生已经会了，或以后都不需要帮助 |
| 太打断 | 停止追问，抑制当前情境中相似提示，降低随后同类主动干预 | 内容必然错误、学生缺乏学习意愿 |
| 现在不需要 | 不再催促该提示，保留主动求助入口，等待新的相关情况 | 永久不需要这一概念的帮助 |
| 没解决 | 保留“问题尚未解决”；在学生愿意继续时改变解释或验证方式，不能只增加同类提示次数 | 应该提高全局提醒频率 |
| 有帮助 | 记录该帮助内容及情境得到肯定，等待后续独立表现 | 应立即更频繁提醒，或该知识已经掌握 |
| 关闭、未回应或没有点击 | 只记录发生的操作；同一提示不反复催促 | 反感、不理解、故意忽略或满意 |
| 之后有独立进展 | 记录与该活动相关的行为和依据，作为可能有用的线索 | 这次提示导致了进展，或任务成功就是掌握 |

反馈必须关联具体帮助及当时的活动、实际呈现和依据。系统知道“展示过”仍不等于学生注意到、读完或理解。后台页面、投递失败、内容过期、活动已切换时，没有回应不计为负反馈；证据不明时保留未知。

## 无扰式检测：从正常活动形成有限、可修正的判断

**已确认的首版路线：采用正常活动的语义事件、可解释规则与课程进展依据，进行困难候选检测和提示时机控制；先验证误报和打扰，再决定是否引入学习模型。** 原始研究不支持把通用日志直接变成可靠的满意度、帮助收益或掌握判断。路线确认不代表效果已验证。

本轮调查将“无扰”落实为：学生无需为了让系统判断而额外答题、打分或执行特定操作，优先复用学习过程中自然产生的作品、工具结果、资料使用和对话记录。少量自愿反馈仍用于校准系统不知道的情况。检测与主动提示是不同动作，自动发现某种情况不代表必须打断学生。

分开形成四种输出，每种都可以是未知：

| 要判断什么 | 可用的正常活动线索 | 判断的用途与边界 |
| --- | --- | --- |
| 现在是否适合提示 | 页面与目标内容是否可见、是否正在输入或操作、是否已有待回应帮助、学生的档位与暂停 | 先排除不适合投递的时机；页面可见不是学生正在注意 |
| 是否可能需要帮助 | 同类问题反复出现、相应作品一直没有相关修订、目标相关操作持续没有进展；也观察学生是否在尝试不同方案 | 形成“可能持续受阻”的候选；多次失败可能是有意义的探索，不能只计次数 |
| 帮助后发生了什么 | 实际展示后，学生是否进行了与建议相关的修改、检查或解释，原问题是否继续出现，是否再次求助 | 记录后续变化与可能关联；不直接写成满意度或帮助的因果效果 |
| 对学习目标有哪些证据 | 学生自己的解释、作品与验证、独立新情形表现及获得的帮助 | 根据课程目标形成有限的学习判断；后台观察和自动检查不能直接代表掌握 |

同一信号不跨层复用成确定结论：点击材料只证明打开了材料，持续编辑只证明在操作，关闭提示只证明收起了界面。低置信度候选可以让系统继续观察或安静等待，不必为了消除每个未知向学生提问。

隐式信号先用于当前情境中的等待、提示优先级和内容选择；例如学生已经自行推进，就取消原本准备出现的帮助。它们不能自动变成长期满意度标签。即使某学生从不打分，系统仍能依据真实活动减少错误时机与重复提示；但对其满意度、帮助是否造成进步等问题，仍需保留不知道的部分。

### 原始研究能支持到哪里

| 方法与依据 | 已有研究说明什么 | 对循阶的建议 |
| --- | --- | --- |
| 操作边界检测与延后投递：[Iqbal & Bailey, 2008](https://interruptions.net/literature/Iqbal-CHI08.pdf) | 编程与绘图的小样本实验中，在任务断点投递通知降低了挫败和反应时间；没有判断学习需要 | 通用层先识别输入、操作完成和页面状态，减少错误时机；到达边界本身不触发帮助 |
| 持续受阻与有益坚持：[Kai et al., 2018](https://learninganalytics.upenn.edu/ryanbaker/210-Article%20Text-1526-1-18-20180624_V7.pdf)及[勘误](https://learninganalytics.upenn.edu/ryanbaker/JEDM-Erratum-2018-v1.pdf) | 数学练习中组合错误、提示和间隔等特征；按学生隔离验证的 AUC 为 0.636，不是 63.6% 的分类准确率；原学生—技能划分结果更高 | 可以借鉴多信号窗口，不能移植成跨课程通用检测器；训练前先有与活动相符的标签和独立验证 |
| 困难标签与教学策略的关系：[Fancsali et al., 2020](https://files.eric.ed.gov/fulltext/ED606472.pdf) | 固定机会数、连续答对次数与系统掌握/停止策略可能产生相互矛盾的分类 | 不预设“失败几次就是无效坚持”；检查策略变化、局部进展及课程目标，保护学生探索 |
| 隐式反馈去偏：[Joachims et al., 2017](https://www.cs.cornell.edu/people/tj/publications/joachims_etal_17a.pdf) | 在有条件的观察模型下纠正搜索点击的位置偏差；并非教学干预效果试验 | 展示、回应与后续变化分别保存；有可靠概率和覆盖才考虑去偏估计，不能靠点击推导满意度或因果收益 |

因此，首版困难检测不建议直接训练一个统一的“困惑／满意”黑盒分数。可解释规则也会误判，但可以把触发依据、反证、未知与最终动作逐项核对，形成后续模型真正需要的标注材料。

浏览器的 [Page Visibility API](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)与 [Intersection Observer](https://developer.mozilla.org/en-US/docs/Web/API/Intersection_Observer_API)提供页面状态和几何相交信息。结合本地可见性检查，可以用于排除未展示情形；将其用于“学生已经看过或理解”的判断没有依据。后台定时器还可能被节流，不能用墙钟时长直接计算有效学习时间。

### 首版接入路线

1. 沿用已有工作区与过程记录边界，合并正常语义事件，保留时间、活动、对象、版本、来源、发起者及缺失区间。高频输入只形成有用的局部状态，不逐键调用模型，也不要求学生为检测额外操作。
2. 通用层处理呈现时机、设置、暂停、重复提示和过期依据；课程/工具能力解释具体进展。代码任务可提供错误类别和测试变化，报告任务可提供目标相关的论据、结构与解释变化；没有可靠解释器时保留未知，不制造统一对错分数。
3. 用可解释的事件窗口与规则形成持续困难、已有进展、帮助后变化等候选，保留支持和反对依据。必要时由模型对一段有限的作品变化与课程要求做有来源的解释，模型输出仍是推断，不充当真实标签。
4. 投递前遵守已确认的学生档位、暂停与课程帮助策略。时机不合适则延后，学生自行推进或目标变了则失效；同一问题不反复弹出。
5. 把隐式观察作为带不确定性的弱证据，与自愿反馈、实际独立表现及后续人工核对结合。无回应不补成正负反馈，明确选择不被推断覆盖；未展示、页面离开、观测窗口不足等情况保留未知。

需要通过回放和真实使用验证的不是“能否算出一个分数”，而是错误触发是否足够少、漏掉了哪些困难、不同课程中判断是否可靠、检测本身的延迟和资源开销，以及学生是否实际觉得更少被打断。

按已确认的分阶段路线推进：先补齐事件归属、观测缺失、设置和真实呈现记录，用已定义的反例回放；再让检测器只记录候选及依据，核对它是否把有益探索当成受阻；之后在少量真实活动中验证轻提示的时机与负担。只有明确标签与足够数据出现后，才比较规则与浅树／逻辑回归；只有可靠结果和选择概率出现后，才评估 bandit。不同阶段是否继续由实际证据决定，不按模型复杂度升级。

若以后引入 bandit，先按课程策略和学生设置过滤候选动作，再选择动作并记录实际概率；真正呈现前再次检查当前状态。取消、未展示、尚无结果和观测不足分别记录，不能统一填成零奖励。策略版本、候选动作、实际动作与结果窗口应可追溯；同一历史情境完全没有某动作的记录时，不能通过补造概率来估计其效果。

### 用事件轨迹检查误判

以下是设计反例，不是实际学生数据或运行结果：

| 已观察的事件顺序 | 应有判断与动作 |
| --- | --- |
| 多次失败，但每次修改都检验了新的假设，失败范围也在缩小 | 有探索或局部进展的依据，不能只按失败次数判为受阻；适时提醒档下优先等待 |
| 同类问题在相关修改后持续存在，未见针对该问题的新尝试；学生结束当前输入 | 可以产生需要帮助的候选，核对课程目标、设置和当前作品后给可忽略的局部提示；仍不宣称知道学生情绪 |
| 提示未实际展示，学生随后修好了原问题 | 记录学生进展；不能把修复算成这次帮助的正反馈 |
| 提示已展示，学生作了相关修改，但同时收到教师帮助 | 记录多来源帮助及随后变化；归因不明，不能只给 Agent 记功 |
| 页面离开后很久没有操作，返回时出现新作品 | 未观察区间保持未知；不计为长时间受阻，也不猜测其间是否独立完成 |
| 课程没有可用的进展评价能力，学生一直在编辑报告 | 可以观察编辑与呈现时机；内容是否改善保持未知，不以字数增加代替论证质量 |
| 学生暂停当前活动，后台检测仍产生受阻候选 | 暂停继续有效，不投递自主提示；学生主动求助时按当前问题回应 |

后续验证应对学生、任务和时间分开留出数据，避免把同一学生同一活动的邻近事件同时当训练与验证。分别检查误报、漏报、未知覆盖率和概率是否可靠；样本少时只报告场景结果，不输出看似精确的通用准确率。帮助后变化的因果收益需要另行比较，不能用检测器的分类准确率替代。

## 首版反馈算法：明确边界内的渐进调整

首版采用可检查的规则、带语境的近期观察与反馈统计。隐式观察与显式反馈保留不同来源和可靠性，不把行为直接转换成用户评分。调整对象是是否介入、何时出现、内容与呈现方式，允许选择安静等待。先通过真实使用找到可测的帮助效果，再决定是否需要更复杂的学习策略；目前没有足够产品反馈来标定一个可靠的统一奖励分数。

一次决策依次完成：

1. **读取实际情况**：当前课程、目标、作品与近期操作，学生明确设置和暂停状态，课程帮助策略，已有待回应引导及相关反馈。学生主动提问优先进入回应路径，不被自主提醒的节流规则阻挡。
2. **检查是否允许且有必要介入**：仅提问、暂停、同一问题刚拒绝、已有待回应提示、依据失效时选择等待。输入或操作中暂缓非必要打断。一次空闲、点击或工具故障本身不构成“学生不会”的证据；工具故障需要按实际故障处理。
3. **提出最小有用帮助**：引用当前具体困难，优先给一个可采取的下一步；依课程需要选择问题、解释、示例、材料或工具观察。避免把预测—运行—比较当作所有活动的固定过程。
4. **检查个人反馈**：在相同或相近课程活动情境中，分别维护内容是否有用、时机是否合适、是否造成打断的近期观察。明确设置和拒绝立即生效；多次一致反馈才支持稳定的偏好调整，单次好评不提高频率。样本少或相互矛盾时保持保守默认，不把跨情境平均值当成个体事实。
5. **实际呈现前再检查**：学生可能已修改作品、改变目标或设置；不投递已无关的旧提示。记录采用的策略及理由，等待实际反馈与后续行为，不因为模型生成成功就更新体验判断。
6. **更新适应状态**：负面时机反馈先降低同类打断；内容反馈优先改变相关性、解释方式或帮助深度。更多引导需要重复的正面依据且仍在学生选择范围内；未回应不累积成好评或差评。近期反馈可逐渐替代旧推断，保留纠正与恢复默认的入口。

统计项按可观察的实际反馈更新：内容的正负反馈与时机的正负反馈分别计数，样本量及未知量同时保留。是否达到稳定调整所需的样本量、历史衰减窗口与提示间隔，通过试用标定并随策略版本记录；本阶段不编造已验证的阈值或频率。显式暂停和选择的效力不取决于统计阈值。

同一次反馈重传或修改不重复累计，旧活动的迟到反馈仍归属原活动，不改变学生后来明确作出的设置。需要减弱历史影响的是推测偏好，不是学生的显式选择。可以用一句可理解的理由说明当前为何减少或改变提示，并允许学生纠正，不让学生调算法参数。

课程策略、学生设置、推测偏好、学习证据和画像判断保持不同语义。“少提示”是帮助方式选择；“尚不能解释某个概念”需要独立的课程证据。算法不会通过修改学生画像来提高自身的有用率。

## 个人适应与整体改进分开验证

个人适应服务于当前学生，及时尊重其选择并在相近情境中改进帮助。整体改进用真实使用记录找出共同问题，例如提示重复、出现太晚、解释不相关、等待太长或反馈入口本身造成负担，然后比较新的规则或策略版本。

整体分析至少区分课程/任务类型、学生所选档位、初始困难与是否实际呈现。不能把高难度学生更常求助解释为某策略更差，也不能让多数课程的行为覆盖少数课程需要。整体数据不把其他学生的能力判断写进个人画像；默认策略更新保留学生选择及课程限制。

同时检查逐人体验分布，避免少数频繁互动者贡献大量好评而掩盖其他学生的打扰。任务未完成、离开或没有反馈的记录不能静默排除后再宣称效果改善。

| 观察维度 | 具体指标或材料 | 解释边界 |
| --- | --- | --- |
| 体验与控制 | 已回应反馈中的有用/打断情况、反馈参与比例、重复提示、拒绝后再次催促、暂停实际生效、学生访谈 | 没反馈的人保持未知；选择安静是有效偏好，不算产品失败 |
| 问题是否得到帮助 | 学生确认是否解决、后续有意义的独立操作、同类阻碍是否持续；对已有明确阻碍记录恢复进展所需的有效活动时间 | 不把所有点击、Agent 自动执行或退出页面当进展；进展相关性不证明因果 |
| 学习与自主性 | 按课程目标观察解释、独立完成、迁移运用和必要的后续复查，保留获得了哪些帮助 | 不跨学科汇总一个“掌握分”；满意度、任务完成和知识掌握分开 |
| 交付体验 | 帮助是否到达正确活动、是否在相关时刻显示、等待及失效情况、反馈操作成本 | 技术成功不等于教学有用 |

“有用率”等反馈统计必须同时展示样本数、参与比例和未知量；反馈分母为实际回应者，不能用少数好评代表所有展示。主动帮助量、点击率、回复率和停留时长用于诊断，不单独作为优化目标。优先减少无用打断，在独立推进与课程学习表现没有变差的前提下改善帮助效果；不能只优化让学生更快得到成品。

验证顺序建议为：先观察少量真实学生使用，发现可修复的问题；再比较版本，并在条件允许时用有对照的试用核对改善。访谈和观察要覆盖选择安静、经常跳过、初学与熟练的学生。离线回放能检查错误触发、重复与设置生效，不能证明学生体验提高；不同版本的反馈率直接比较也不能排除学生与任务差异。比较方法、样本和阈值随试用设计确定，当前不执行自动在线实验。

## 跨课程与失败场景

| 场景 | 预期行为 |
| --- | --- |
| 数字逻辑反复产生进位错误 | 依据真实输入、结果与当前作品给出局部解释；遵守该活动不改代码的规则 |
| 报告论证没有说明结论依据 | 结合课程要求提示补充依据或比较解释；没有编译与自动对错结果也能持续引导 |
| 学生正在阅读材料，停留较久 | 不单凭时长判定困难或增加提醒；保留学生自己提问的能力 |
| 学生反馈提示正确但很打断 | 保留内容有效的反馈，调整出现时机和频率，不把两种评价抵消成一个分数 |
| 学生选择更多引导但课程限制代做 | 更主动解释和提出步骤，仍不越过该课程的帮助范围 |
| 学生切到仅提问时，旧提示尚在生成 | 旧提示在投递前被当前设置拦截，已请求的回答或操作结果仍可正常返回 |
| 学生夸奖帮助，随后仍无法独立解释 | 帮助体验可为正；知识判断仍保留证据不足或困难 |
| 同一学生在不同课偏好不同 | 尊重课程覆盖；不因一课的反馈改变另一课的掌握判断或偷偷提高提醒 |
| 提示生成后学生换了目标或已自行解决 | 旧提示取消或失效；重新依据当前目标决定是否继续 |

报告等非数字逻辑情形是设计反例，尚未选为已接入、已实测的第二课程。实际课程验收需要相应教师材料、任务与学生试用，不能由反例表代替。
