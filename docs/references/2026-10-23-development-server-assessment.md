# 开发协作服务器：配置与运行状态核查

核查时间：2026-10-23 02:22—02:30（Asia/Shanghai）。面向 Robert 确认的 **2–5 人同时开发**。本文件记录当时的实测快照和工程判断，不表示已通过五人并发验收。

## 结论

当前服务器适合继续承担共享应用、数据基线目录和轻量成员管理。已采集时段内资源充足、业务健康；新增协作能力需要优先处理 **3 Mbps 公网出口**和**云端构建占用内存**。建议大文件由私有对象存储直接交付，构建移到 CI，个人前后端与执行节点仍留在开发者设备。

本轮未升级实例、创建付费存储、修改安全组或系统服务配置，也未停止业务。详细接入与运行策略见[成员接入与云端运行](../development-access-operations.md)。

## 连接观察

首轮本机 SSH 连接超时，云助手在线；随后同一 SSH 别名重试成功，能够完成只读复核。安全组查询显示允许 IPv4 TCP 22，服务端 SSH 处于运行状态。当前证据不足以定位首次超时发生在哪一段网络，不能将其断言为服务器故障或已根治的网络问题。

新工具需要区分网络暂时失败、身份被撤销、主机身份不匹配和服务不健康：网络失败可退避重连，其他情况不能无限重试。当前[连接脚本](../../tools/i0-cloud/ssh-common.ps1)有 SSH 保活和超时配置，但[页面入口](../../tools/i0-cloud/connect.ps1)是一次前台进程，不提供断开后的监督重启。

## 对实施的具体影响

1. **文件传输改为对象存储直达。** ECS 处理成员授权、包元数据和短期访问凭证，客户端直接上传/下载对象；SFTP 可保留为小包过渡路径。包的内容摘要与本地缓存减少重复传输。对象存储尚未创建，也未产生这项新资源配置。
2. **构建逐步移出共享业务宿主。** 当前 1600 MiB 的构建上限已接近系统可用物理内存量；本轮没有取得实际构建的内存峰值，不能把上限当实测值，也不能凭猜测直接调低后声称构建仍可用。目标是 CI 产生匹配 Linux、架构和 Node 版本的产物，云端只校验、备份、安装和切换。
3. **先加准入与可观测性，再确定资源上限。** 为业务、成员管理与维护任务分开设置资源预算；并发模型调用、打包和导入应有队列。2–5 人是本轮容量设计输入，尚非已验证容量。
4. **建立有边界的保留策略。** 当前磁盘并不紧张；实施工具后只清理工具拥有的失败临时文件、可再取缓存和不再引用的旧发布。业务数据、仍被引用的基线与唯一备份不能按普通缓存清理。
5. **减少重复静态资源传输。** 当前[静态文件处理器](../../apps/teaching/server/app/i0-static.ts)同步读取整个文件，在该处理器内未设置压缩协商和缓存策略。可在构建时生成压缩产物，并为带内容摘要的资源设置长期缓存、入口 HTML 做版本校验；需要配套浏览器与发布回退验证。

建议参数、成员权限和验收流程由[运行策略](../development-access-operations.md)统一维护。本轮未进行负载压测、真实模型并发、编译/仿真或浏览器端到端验收；这些不能由低负载快照替代。

## 机制依据

- [systemd 资源控制](https://www.freedesktop.org/software/systemd/man/255/systemd.resource-control.html)：`MemoryHigh` 用于主要内存控制，`MemoryMax` 作为最后限制；CPU 权重与配额作用不同。
- [OSS 预签名上传](https://www.alibabacloud.com/help/en/oss/user-guide/upload-files-using-presigned-urls)与[预签名下载](https://www.alibabacloud.com/help/en/oss/developer-reference/python-download-using-a-presigned-url)：可对私有对象授予有时限的操作权限，文件传输不需经过应用服务器。
- [云助手结果查询](https://www.alibabacloud.com/help/en/ecs/developer-reference/api-ecs-2014-05-26-describeinvocationresults)：提交执行请求并不等于执行成功，本轮已读取实际执行状态、退出码和输出。
