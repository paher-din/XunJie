# SystemVerilog ALU 课后活动设计与验收场景

日期：2026-10-23。依据负责人本轮讨论选择整理，供后续交互、运行与教学设计引用。[数字逻辑与部件设计：首条学习活动与验收目标](https://github.com/paher-din/XunJie/issues/113#issuecomment-6348000023) 已形成决议并关闭，最终决定以该评论为准；本文是配套场景说明，不表示活动已经实现或通过验收。

## 已确认的设计依据

- 活动面向课后项目学习。相关概念已经在课上接触，学生可能遗忘，需要在项目中补学；不能只按年级判断起点。
- 从真实课程实验改编，以 ALU 为载体；完整活动预算为 50–70 分钟，实际时长需要学生试用验证。
- 主线是**设计并验证 ALU 行为**，允许使用 `+` 等内置运算符；全加器推导放到扩展。
- 语言是 **SystemVerilog**。学生文件与后续起始工程使用 `.sv`，示例与运行工具按此核对。
- 前置概念按前三节理论设定，范围、原始资料与补学页码见 [课程资料索引](../../course_matrial/README.md)。
- 主线采用五种核心操作，减法留在扩展；向教师交付时允许保留失败与缺项。
- 本活动的 Agent **只解释，不修改学生代码**，包括学生主动请求代改的情形。

遵循地图中的既有方向：Agent 可以主动观察、诊断并做课程允许的验证；学生作品自动保存，提交是向教师交付；任务完成与知识掌握分别判断。作品修改还受课程帮助策略限制，本活动采用上述只解释策略。运行安排由教师设计，尽量本地，具体执行器不在本活动票中预选。

## 学生面对的学习问题

> 设计一个 4 位 ALU，让同一组输入在不同控制选择下得到正确的逻辑或算术结果。你不仅需要让它运行，还要选出能检验设计的输入，解释结果与进位，并用实验检查自己的判断。

以四项可观察能力组织活动：读懂操作要求并实现行为；处理固定宽度结果与进位；选取有目的的验证用例；根据预测与实际结果解释或修改设计。语法与工具使用提供必要支持，作品由学生编写和修改。

## 主线范围与行为约定

保留 4 位无符号 `A`、`B`，输出 4 位 `F` 和 1 位 `Cout`，沿用原题的 `M`、`S[1:0]`、`Cin` 作为控制与输入。以下将已选定的五种核心操作具体化，并补全原题中本活动需要的输出约定。

| M | S | 行为 | F | Cout |
| --- | --- | --- | --- | --- |
| 0 | 00 | 按位 NOT | A 的 4 位按位取反 | 0 |
| 0 | 01 | 按位 AND | A AND B | 0 |
| 0 | 10 | 按位 OR | A OR B | 0 |
| 0 | 11 | 按位 XOR | A XOR B | 0 |
| 1 | 00 | 无符号加法 | `A + B + Cin` 的低 4 位 | 完整和的第 5 位 |
| 1 | 01、10、11 | 本版保留的控制组合 | 0 | 0 |

逻辑操作忽略 `Cin`；NOT 还忽略 `B`。有效输入取 0/1，稳定采样时输出应为确定值。所有约定直接向学生公开，不能用未说明的行为作隐藏判分标准。

学生完成运算选择、操作行为和位宽处理，可以使用 `logic`、连续赋值或 `always_comb` 等适合组合逻辑的 SystemVerilog 写法。起始工程提供端口骨架、运行入口、用例输入和观察结果的能力；学生不必从零写 testbench。若展示数码管或虚拟板，显示与接线由起始工程提供。

减法、有符号标志位、动态扫描显示设计和手工全加器推导不计入主线。后续扩展减法时需单独确定控制编码、输入范围及借位约定，不直接照搬旧 PPT 的另一套接口。

## 交付与学习证据

向教师交付三部分：

1. **SystemVerilog 作品**：学生完成的 `.sv` 内容及对应验证状态。
2. **两条有目的的自选用例**：保留输入、运行前预测、实际结果，以及为什么选这条用例。至少一条涉及进位或边界，另一条能区分容易混淆的操作。学生可重新选取，工具提供输入方式，不预填答案。
3. **简短解释**：解释一条结果；若预测与结果不符，说明如何定位、修改或仍存在哪个疑问。没有出错的学生说明用例能发现哪种错误，不人为制造失败。

活动末尾建议再给一个相近的新输入，请学生先预测结果并说明理由，再自行决定是否运行检查，用于观察迁移理解。该记录与完成度分别呈现；不以 Agent 的一次判断替代教师评价，也不把获得帮助自动记为能力不足。

允许提交未完成作品。提交时明确显示“验证通过”“仍有失败”或“修改后待验证”，保留已有证据与当前困难；缺少预测等记录时呈现缺项，不能补造“学生原先就知道”的证据。后台验证与 Agent 生成的回答不能记作学生独立预测。

自动检查负责覆盖约定行为，学生的两条用例负责展示选择和解释过程。全部自动检查通过只支持功能正确性结论，不能单独证明掌握。

## 可自由往返的完整活动

以下是时间分配建议，不做成锁定顺序的步骤向导。学生可先运行、回查概念、编辑或提问；只有真实发生在运行前的回答才记为预测。

| 活动 | 参考预算 | 学生行动与支持 |
| --- | --- | --- |
| 进入与理解 | 5 分钟 | 看到任务、控制表和可运行的起始工程；IP 简短介绍目标，学生可直接开始，也可查询接口 |
| 设计与编辑 | 20 分钟 | 编写 SystemVerilog 行为；选区“询问 Agent”携带代码或材料引用，并保留自由提问 |
| 预测与实验 | 15 分钟 | 自选输入、记录预测、运行并比较；检查进位边界和操作差异，按需要反复修改 |
| 解释与交付 | 10 分钟 | 整理两条用例和简短解释，尝试新输入，向教师交付；也可带着未解决问题提交 |
| 穿插补学 | 10 分钟 | 回查理论或语法，借助短卡片或交互示意理解，再返回当前工作位置 |

总计约 60 分钟，50–70 分钟作为初始设计区间。学习中的回查、求助和修正计入活动时间；工具安装与运行环境应提前准备。若实际试用大部分时间消耗在环境问题上，应调整起始工程，不能把它解释为学习困难。

## Agent 帮助边界：只解释，不修改代码

解释、定位问题、推荐验证方法和概念示意均可用于帮助学生；学生代码由学生编写和修改。该策略对主动帮助和学生直接要求代改同样生效。

- 主动帮助基于具体证据，例如同一失败再次出现、预测与结果冲突、代码中的位宽问题；先说明观察到什么，并提出一个可执行的下一步。仅停留时间长不能推出“不理解”。
- 学生忘记概念时，提供相关页码、短解释或可操作的示意。例如用 5 位和拆分 `F/Cout`，并清楚区分教学示意和实际仿真结果。
- 学生主动求助时可以解释其代码、指出相关位置，或用简短的概念例子帮助理解；解释不必机械地经历固定轮数。不得写入学生的 SystemVerilog 文件或自写测试代码，也不提供可一键应用的代改补丁。
- 学生直接要求“替我改”或索要整份实现时，仍以观察到的问题、原因和验证方法来回应，让学生完成修改；不交付整份可直接提交的 ALU 答案。概念例子与讲解卡片不记作学生作品或学生独立回答。
- 被忽略或关闭的同一提示不反复弹出；学生可以继续编辑、运行、提问和提交。后续出现新的相关证据时才再次提供有针对性的帮助。

IP 用于发出简短且可忽略的引导与反馈；对话承接解释和追问；卡片用于局部概念操作与预测；编辑器、结果视图和必要时的波形用于真实实验。主界面只呈现学生完成学习所需的信息，不预选面板数量、固定布局或内部架构。

## 用具体学生情形检验设计

| 情形 | 应当发生的支持与反馈 | 必须保留的判断边界 |
| --- | --- | --- |
| 正常推进 | 学生自行实现、选例、解释并交付；IP 在有信息可补充时出现 | 不要求学生先完成一轮固定问答才能编辑 |
| 反复出现进位错误 | Agent 引用当前失败输入与相关代码，帮助比较低 4 位与完整和；学生重试后显示新结果 | 不直接断言遗忘补码，不把旧运行当作新代码的证据 |
| 忘记概念 | 从当前卡点打开短解释或材料片段，完成小预测后返回原位置 | 补学不是额外考试，不强制重读完整课件 |
| 主动求助或索要答案 | 引用选区解释原因、定位问题并建议验证方法；需要时给概念示意 | 不代写整份答案，帮助来源与学生回答有区别 |
| 学生直接要求代改 | 解释如何判断与修正，让学生实际编辑后重新验证 | 请求代改不放宽本课程策略；Agent 不写学生代码、不应用补丁 |
| 忽略提示 | 学生继续操作；同一提示收起，已有对话仍可查阅 | 不反复打断，不因未回应降低画像判断 |
| 中途离开后返回 | 恢复作品、输入、用例和相关讨论，并指出上次待解决的问题 | 代码已改但未重跑时明确待验证，不展示过期“通过”状态 |
| 仍有失败时提交 | 可以把当前作品、失败和问题交给教师，后续修改不覆盖这次交付 | 提交成功不等于任务通过，更不等于知识掌握 |
| 编译工具或运行环境失败 | 明确是环境或执行故障，保留作品并提供恢复入口 | 不把工具失败归因于学生概念错误 |

## 验收设计

| 层次 | 建议的验收依据 | 当前状态 |
| --- | --- | --- |
| 工程行为 | SystemVerilog 运行链可用；按公开行为表检查全部二值输入组合；有效输入的稳定输出正确；编辑、自动保存、重新运行、返回和教师提交所指内容一致；主动帮助和学生请求代改均不能触发 Agent 修改学生代码；故障状态不混成概念判断 | 未实现、未执行 |
| 浏览器体验 | 真实走通上表情形；能编辑和运行、使用选区引用、补学后返回、忽略提示、中断恢复、提交未完成作品；IP、对话、教学卡片与实际运行结果互相对应；无强制问答阻断 | 未执行 |
| 教学效果 | 由接触过前置概念的真实学生试用；逐人记录有效活动时间、卡点、帮助程度、用例选择、解释和新输入预测；检查 50–70 分钟是否可行、是否能区分功能完成与理解 | 未试用，不能据草案宣称有效 |

工程验收可利用本问题有限的输入空间：`A`、`B` 各 16 种，`M/S` 共 8 种，`Cin` 2 种，共 4096 组。此处定义验证目标，不预选模拟器、执行位置或测试实现；穷举通过仍不替代教学效果证据。

试用若显示多数时间被重复语法修复、环境操作或长说明占用，应调整起始支持与活动范围；若代码运行成功却解释和新输入预测薄弱，应调整活动中的验证与引导。具体教学达标阈值需结合试用对象与数据确定，不用自动测试通过率替代。

每位试用学生至少分别记录：是否实现约定行为；是否能解释一条边界用例和一条操作区别；是否能对相近的新输入作出有理由的预测，以及当时获得了什么帮助。出现失败、缺项或尚不能判断时保留原样。以上是观察依据，不是自动画像标签或提交门槛。

## 已收束的取舍与后续交接

1. 五种核心操作、减法扩展；起始工程提供运行与显示支持，保留完整的验证和解释过程。
2. SystemVerilog 作品、两条自选用例与简短解释构成交付内容；允许带失败或缺项提交给教师。
3. Agent 只解释，不修改学生代码；“请求或采纳后局部修改”的先前建议已被负责人选择替代。

运行工具与实验生命周期交给执行议题；自动保存、选区、结果对应和教师交付交给工作区议题；解释策略、提示忽略、补学与证据判断交给连续教学议题。它们已有对应地图主题，本活动不另建重复议题，也不预选 Agent 内核或组件结构。

实际实现、运行验证和学生试用属于后续工作。活动设计议题的决议或关闭不表示这些验证已经完成。
