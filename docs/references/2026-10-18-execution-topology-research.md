# 执行位置与课程工具运行的研究

研究日期：2026-10-18。状态：技术研究；已根据本轮 Q7/Q8 修正架构建议。
核验方式：官方文档及相关项目配置只读检查；未安装、编译或运行实测。
目的：说明教师设计本地优先运行方案时的能力边界，以及教师通过 Agent 制作工具的接入条件。

## 结论与最小分层（架构建议）

三层可以共用任务契约，但执行能力不能假定相同。
教师生成的工具可由学生端统一装载；执行位置由教师设计的课程运行方案约束，平台依据实际设备在方案内匹配。

| 层 | 适合范围 | 成立条件 |
| --- | --- | --- |
| 浏览器 / WASM | 交互演示、计算器、数据变换、受限 C 练习 | 运行时可移植，输入与资源有界 |
| 本地执行节点 | 原生 C 编译运行、HDL 编译仿真 | 安装组件、工具链及实际隔离环境 |
| 远端执行节点 | 本地确实无法满足的环境、设备或资源需求 | 教师明确配置适用路径，具备远端容量、隔离与结果回传 |

“本地执行”不自动意味着离线可用或源码不出机。
“本地 / 远端可组合”不表示学生选择节点，也不要求每个工具同时具备两种实现。
尚未安装组件不等于本地无法支持；应先检查是否能完成课程要求的环境准备。

## 来源事实与推论

### 1. 浏览器执行有 API 边界

**事实：** Emscripten 的浏览器环境以虚拟文件系统承接 C/C++ 文件操作，
不能直接读取用户磁盘；网络调用受浏览器异步 API 约束。
来源：[Emscripten API Limitations](https://emscripten.org/docs/porting/guidelines/api_limitations.html)。

**建议：** 浏览器层先限定为标准输入输出、虚拟文件和计算型任务。
执行已编译 WASM 与在浏览器编译学生源码必须分别验收。
若要求编译也在浏览器完成，还需交付可用的编译器、链接器及运行库。
**未知：** 本项目所需 C 特性、工具链下载体积、冷启动与内存表现。

### 2. Worker 不构成完整的不可信代码沙箱

**事实：** Worker 不能直接操作 DOM，但仍可使用网络、WebSocket 和 IndexedDB；
宿主可通过 terminate 停止 Worker。
来源：[MDN：Using Web Workers](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers)。

**推论：** 移到 Worker 主要解决后台计算和停止任务，不能据此承诺权限隔离。
**建议：** 生成代码与应用身份、存储分开，限制桥接和 WASM 导入能力；
另设时间、内存和输出预算。不能把任意生成的 JS 放进同源 Worker 即发布。

### 3. HDL 需要完整仿真链

**事实：** Icarus 将 HDL 编译为 vvp 输入；VPI 是由本机编译器生成、
由 vvp 加载的原生模块。
来源：[Icarus Verilog：Using VPI](https://steveicarus.github.io/iverilog/usage/vpi.html)。

**推论：** 若沿用 Icarus/VPI，浏览器方案需移植编译器、仿真器及桥接，
不能直接复用原生二进制。
**未知：** 所需 SystemVerilog 语义、波形输出及交互性能能否在 WASM 路径满足。
**建议：** 暂将原生 C/HDL 作为本地或远端执行器能力；浏览器路径独立验证。

### 4. 浏览器直连 localhost 有额外部署条件

**事实：** Chrome 官方说明自 142 引入 Local Network Access 权限，
覆盖公网网页访问本地网络和 loopback；申请权限要求安全上下文。
文档同时说明部分本地请求有混合内容例外，不能概括为“HTTPS 一律不能访问 HTTP 本地服务”。
来源：[Chrome：Local Network Access](https://developer.chrome.com/blog/local-network-access)。

**建议：** 直连仍需处理跨源访问、服务发现、配对鉴权及来源校验。
浏览器权限允许连接，不应被当作执行本机命令的授权。
**未知：** 目标浏览器版本、学校策略及跨平台安装条件；本次未做兼容矩阵。

### 5. 容器隔离取决于配置

**事实：** namespaces、cgroups、capabilities 分别参与隔离、资源限制和权限控制；
默认能力与挂载配置可能隔离不足，容器管理接口具有较大宿主权限。
来源：[Docker Engine security](https://docs.docker.com/engine/security/)。

**建议：** 本地伴随进程负责接任务，执行交给操作系统沙箱、容器或虚拟机。
桌面壳与普通子进程不自动提供隔离；编译和运行均需受限，不向页面开放宿主 shell。
本地隔离方案及其额外安装依赖，需要按目标操作系统确定。

## 连接拓扑的取舍（架构建议）

| 方式 | 收益 | 代价 / 条件 |
| --- | --- | --- |
| 网页直连本地服务 | 可直接交互；能组成全本地部署 | 处理跨源、LNA、端口、鉴权与浏览器差异 |
| 本地节点主动连后端 | 网页只访问后端；不要求网页访问本地监听端口 | 后端中转任务与结果；需配对、断线恢复 |

为避免云端成为每次本地实验的必经路径，首条活动优先验证网页到本机组件的直接通道；
本机节点到应用服务的连接承担 Agent 命令、记录同步与恢复。它们是两条传输路径，不是两套命令语义。
若联调暂用后端中转，必须记录网络等待与断线限制；仅本地计算不证明交互低延迟。
节点凭据绑定学生与设备，执行器只接受已登记能力及任务范围。
本地手动命令先持久绑定实际输入和命令身份，再执行并异步上传记录；云端判断和教师提交等待相关同步。
如要求完整断网教学，需另有本地服务与资源方案，不能依赖云端中转。
如果要求源码不出机，还必须明确任务传输和工作区同步的数据边界。

教师配置的远端路径可复用执行器契约，运行隔离任务并返回日志、波形及产物。
它用于本地无法满足的能力，增加网络等待、运维及并发成本；不作为安装失败或暂时失联时的自动兜底。
相同接口不保证结果等价：工具链版本、目标架构和执行限制仍需记录。
任务启动后保持原节点、代际和输入归属；结果未知先查询，不跨节点自动重跑。

## 工具包与执行器分离（架构建议）

教师借助 Agent 生成工具包：界面、计算逻辑、资源、输入输出 schema 与状态事件。
工具包声明所需能力，例如 C 编译运行、HDL 仿真、文件读写范围与资源预算。
声明只是需求，不自动授予权限，也不携带任意宿主命令。

宿主依据已发布的课程运行方案、实际设备能力、课程权限和版本匹配实现。
即使本地与远端都符合包声明，也由课程方案决定路径，学生端保持统一操作和结果格式。
已有执行器支持的代码可直接复用该执行路径；新运行时或宿主能力才需扩展执行器。
这能支持教师制作课程工具，但不能让任意生成代码自动获得跨平台可移植性。
课程工具和教学产物共用工作区 SDK 的状态、选区与事件桥接，临时卡片不必经过完整工具发布流程。

## 本轮决定与实施验证

Q7 已明确：教师在设计课程时确定运行方案，本地优先，只有本地不能满足时才配置远端。
原先“学生选择本机组件或远端节点”的建议已撤销。Q8 已委托工程判断，不再等待整体选型确认。
决定见 [ADR 0001](../adr/0001-teacher-owned-course-execution-plan.md)。

实施时需验证目标系统与学校设备安装条件、浏览器/WASM 覆盖范围、组件配对与直连、工具链更新和实际隔离。
已有运行时支持的工具可独立分发；全新系统依赖或运行时要经过平台执行器扩展，不能由生成包任意安装。
本轮优先满足计算与交互本地；源码不出机与完整离线教学尚未设为要求。
