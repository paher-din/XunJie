# 本地优先执行：体验要求、执行契约与验证草案

日期：2026-10-23。所属议题：[本地优先执行：设备支持、课程运行方案与实验生命周期](https://github.com/paher-din/XunJie/issues/114)。

状态：本轮产品要求与工程建议，等待负责人确认整体理解后收束。产品要求来自负责人的实际答复，技术建议依据本轮原生与浏览器小样本；本文不是 resolution，也不是生产验收。已决议的 [SystemVerilog ALU 活动](https://github.com/paher-din/XunJie/issues/113#issuecomment-6348000023) 是输入。

## 本轮已明确

1. 首批正式验收目标为 Windows 11 x64 与 Apple Silicon Mac，使用桌面 Chrome/Edge。这是目标范围，不是已经通过的支持声明；具体 OS、浏览器版本随验收记录固定。
2. 允许安装组件，但产品应自动完成下载、安装、依赖配置、检测和更新，减少学生的繁琐流程。不能把环境搭建步骤转交给学生；负责人没有硬性排除某种底层技术，也没有同意将手工配置 WSL/Docker 作为默认准备方式。
3. 自由实验时改输入就更新实际结果；需要保留预测用例时，先写预测，再点一次“运行并比较”。编译、装载等内部步骤由系统处理。
4. 继续遵循既有原则：教师设计运行方案，本地优先，仅本地确实不能满足时使用课程明确配置的远端路径；学生不选择节点。安装准备在 50–70 分钟活动预算之前完成。

## 技术建议：首条 ALU 在浏览器本地执行

采用 **Web Worker 内的 Icarus/WASM** 作为首条 ALU 的工程方向。预处理、编译、实际仿真与 VCD 生成均在学生浏览器完成；工具链随课程工具自动加载并缓存。首次准备与更新由平台完成，本活动不默认要求安装本机组件、WSL、Docker 或 FPGA 开发环境。

浏览器内的界面与 Worker 直接交换有界任务和结果；自由实验的输入反馈不经过应用服务器，也不需要浏览器连接 localhost。应用服务负责课程、保存/同步、Agent 和教师交付所需记录。此选择解决首条活动的通信路径，不表示已经选定所有未来课程的本机组件协议。

教师发布的课程运行方案引用固定的工具与执行环境版本，平台在进入前检查 Worker/WASM 能力、资源加载和课程自检。新发布版本先验证，已开始的运行保留原版本。第一版 ALU 默认只有已验证的浏览器路径；若某设备确实不能满足，只有教师方案预先包含适用的远端路径才可使用。缺文件、加载失败、未完成权限与结果未知分别处理，不统称为“本地不支持”。

本机组件保留为确需原生能力时的扩展方向，并遵守已确认的自动准备要求。它不成为首条 ALU 的默认安装包，也不因浏览器一次运行失败而自动接管。未来课程若确需本机组件，其直连/中转、安装、隔离和平台支持需随该能力验证；现有 SSH/VM 链不成为默认产品要求。

### 替代路线与取舍

| 路线 | 本轮判断 |
| --- | --- |
| Icarus/WASM + Worker | 优先方向：有实际源码编译、四态输出、VCD、停止/恢复与编译复用证据，最符合减少准备操作的要求 |
| 原生 Icarus + 自动本机组件 | 可行备选：Mac CLI 小样本成功，但新增安装、更新、连接和隔离工作；首条活动尚没有必须承担这些成本的能力缺口 |
| Verilator/Clang WASM | 暂不优先：增加 C++ 编译链；已调查实现主要采用二态语义，不能用正常二值输出证明学生没有产生 X |
| 默认服务端编译/仿真 | 本轮不选：本地小样本已显示能力可行，尚无必须增加远端执行资源与网络往返的依据 |
| 直接沿用现有 VM/容器与 VPI 会话 | 本轮不选：单次有界执行已覆盖主线，旧接线、2800 组验证与持续会话不是新活动需求 |

VeriSim 是能力与性能的实验来源，不作为已经可直接发布的二进制依赖。它的公开产物仍输出 `system.vpi` 动态加载诊断；删除模块声明会导致系统任务不可用，不能靠删除配置或过滤错误文本解决。移植补丁和完整固定构建链也尚未取得。实际交付须重建可追溯的 Icarus/WASM 包、修正系统模块初始化，固定编译选项，并重新运行同一组探针。若这一步失败，必须回来重评路线，不能把本研究通过写成运行包已就绪。

## 学生操作与环境准备候选

进入活动前自动检测课程所需能力。浏览器路径满足要求则直接就绪；确需本机组件时，提供一次明确的准备入口，识别系统与架构，下载安装匹配包、完成配对、执行小型自检，再返回原工作位置。保留系统要求的确认，产品处理其余安装细节。

日常进入不要求再次启动终端、填写端口、选择模拟器、切换节点或重装依赖。组件更新先验证并保留可恢复版本；正在运行的实验继续使用原环境，新环境在下次运行前检查兼容性。更新失败保留作品和可用旧环境，不以未确认的新环境继续给出结果。

环境检测至少区分：

| 情况 | 平台处理 |
| --- | --- |
| 已就绪 | 进入活动 |
| 尚未准备、组件未运行或可修复的版本不匹配 | 自动准备或修复，说明进度与失败原因 |
| 系统确认或浏览器连接权限尚未完成 | 就地解释并给一次操作入口；不能据此断言设备不支持 |
| 设备、组织策略或资源条件确实不满足 | 依据教师已发布方案提供允许的替代路径，否则提供明确的准备/教师协助入口 |
| 组件失联但实验结果尚未查明 | 查询原运行，不把失联伪装成安装缺失或直接重跑 |

资源下限与确切版本范围需要在实际目标机器上测得；当前不凭开发机速度宣布最低内存、下载体积或安装耗时。

## 首条 ALU 的运行方式候选

主线 ALU 是组合逻辑。优先比较“复用编译结果、按需有界运行”的实现，不要求学生维持一场持续的虚拟板会话。底层可以为降低等待复用进程或 Worker；界面和课程契约不依赖某个常驻进程一直存活。

作品稳定后自动准备当前代码的编译结果；自由实验的输入更新合并短时间内的连续操作，并只显示最新输入与对应作品的结果。编译失败时保留代码位置与诊断，旧结果明确属于上次作品，不显示成新输入的结果。波形来自实际执行，不能用教学示意代替。

预测用例进入独立的“预测—运行—比较”过程。该用例的实际结果在运行前不显示，相关结果视图暂停自动反馈，运行时绑定预测、输入和当时的作品；已看过自由实验结果不能被补记成运行前的独立预测。学生仍可选择直接查看结果，记录真实发生的行为与缺项，不加提交门槛。两种操作共享同一实际仿真能力。

Agent 可以进行课程允许的验证，但使用自己的运行身份与明确输入，不抢占或覆盖学生正在观察的结果，也不把后台验证记录当成学生预测。完整提示和教学证据策略交给相应连续教学议题。

## 最小执行契约候选

这里给出行为契约，不预选 API 名称或持久化结构。与自动保存、作品引用及提交的完整衔接交给[工作区交互与状态：自动保存、选区引用、执行依据和提交](https://github.com/paher-din/XunJie/issues/116)。

| 内容 | 要保持的约束 |
| --- | --- |
| 运行身份 | 每次实验有稳定身份、发起者、课程/任务/学生范围；重复投递同一请求不重复执行，同一身份不能更换输入 |
| 执行依据 | 绑定实际作品内容、工具/运行方案/模拟器/验证器版本、编译配置、实验输入；由系统完成，不要求学生手工保存快照 |
| 编译复用 | 只有源文件、依赖、配置和工具链一致时才能复用产物；作品变化不能沿用旧“通过”状态 |
| 执行位置 | 运行开始后固定实际执行器与其启动实例；重连先找回原运行，不在另一位置默默重跑 |
| 返回结果 | 返回运行身份、实际依据、结果/诊断/波形、完成或失败原因；工作区与 Agent 都能判断结果属于哪次作品与输入 |
| 结果时序 | 同一运行的事件可去重并排序；晚到结果不覆盖新运行结果，旧结果仍可追溯 |
| 停止与取消 | “请求停止”与“确认停止”分开；确认进程/Worker 已终止才报告已取消，正常完成和停止竞态保留真实终态 |
| 超时与失联 | 有限执行设置时限及输出预算；失联表示尚未拿到可信终态，不等于失败或已停止；查询与恢复沿原身份进行 |
| 同步 | 本地结果先与其依据一起保存，再同步；应用服务上的 Agent 与教师提交只能引用已经收到的对应记录 |
| 失败分类 | 代码编译错误、行为不符、输入无效、工具/环境失败、取消与结果未知分别记录，环境故障不能归因于学习困难 |

首条活动无需承诺刷新或关闭页面后继续长时间运行。已保存作品、用例和结果应能恢复；执行进程是否存活通过查询确认。完整离线教学、源码绝不上云和对本机结果的防篡改证明不在当前范围。

## 本机已取得的最小证据

复现入口：[probe-alu-iverilog.py](../../tools/research/probe-alu-iverilog.py)。结果：[Icarus 小样本记录](2026-10-23-alu-iverilog-probe-results.json)。

```sh
python3 tools/research/probe-alu-iverilog.py --output docs/references/2026-10-23-alu-iverilog-probe-results.json
```

脚本需要已有 `iverilog` 与 `vvp`，不会安装工具。源码、testbench、工具版本、参数和结果摘要随记录保存，临时编译产物与波形自动清理。

| 验证 | 结果 |
| --- | --- |
| 当前 Apple Silicon Mac，Icarus 13.0，`logic`、`always_comb`、`case`、定宽加法 | 编译并运行成功，无诊断 |
| 新行为表全部 4096 组输入 | 零不符；独立 Python oracle 比对 |
| 故意漏掉进位的负对照 | 检出 256 组错误 |
| 保留控制组合故意输出 X | 检出 1536 组未知输出，未被强制变成 0 |
| VCD | 产生约 176 KB 波形，检查定义段与最终时间戳；尚未经过波形查看器验收 |
| 外部超时停止直接子进程 | 250 ms 时限后确认直接子进程已退出；不等于已验证产品取消或完整进程树清理 |

一次本机样本的正确模型编译约 12 ms，仿真与输出约 16 ms。这只是已安装工具的 CLI 测量，不含首次下载、打包、浏览器渲染、同步与通信，不能作为跨设备延迟承诺。

现有旧代码的 ALU 验证契约是 2800 组采样、1296 组排除（`apps/teaching/contracts/runner/alu.ts`）；新活动要求全部 4096 组，不能直接沿用旧检查通过作为新活动验收。

## 固定 WASM 的浏览器证据

[独立上游调查](2026-10-23-systemverilog-local-execution-research.md) 给出候选与来源；主线程进一步使用 VeriSim commit `dc391801af44ec8e99fcdc12c12a3d9a47a5758b` 的六个固定文件，校验各文件 SHA-256 后从临时 loopback 服务加载。六文件合计 2,994,577 bytes，不含应用页面，亦不代表压缩下载量或内存。

复现入口：[serve-alu-wasm-probe.py](../../tools/research/serve-alu-wasm-probe.py) 与 [探针页面](../../tools/research/alu-wasm-probe.html)。

```sh
python3 tools/research/serve-alu-wasm-probe.py --output docs/references/2026-10-23-alu-wasm-probe-results.json
```

命令启动临时 HTTP 服务；在待测浏览器打开 `http://127.0.0.1:8754/`，结果会写入指定 JSON。Ctrl-C 停止并清理临时文件。此命令是研究复现入口，不是面向学生的安装流程。HTML 仅为实验报告页，不是产品界面。

已在同一 Apple Silicon Mac 上运行 [Codex 内嵌 Chromium 155](2026-10-23-alu-wasm-iab-probe-results.json) 和 [真实 Chrome 155](2026-10-23-alu-wasm-probe-results.json)。两次均通过六个功能探针；运行包诊断单独保留，不能视为整个交付通过。

| 检查 | 真实 Chrome 样本 |
| --- | --- |
| 4096 组、进位错误负对照、X 负对照 | 分别零不符、256 组错误、1536 组 X；规范化逐行结果的 SHA-256 与原生 Icarus 完全一致 |
| VCD | 完整输入探针产生约 190 KB，并包含最终时间戳；本探针不包含产品波形查看器 |
| 首次完整链 | 工具文件从 loopback 加载约 75 ms，预处理约 29 ms，编译约 51 ms，仿真与输出约 126 ms；不含公网首次下载 |
| 复用编译产物、改变输入 | 三组新的输入通过 `+CASE` 传入，得到正确输出；含新运行时初始化约 2.7–4.2 ms，恢复阶段为 10.4–13.9 ms；不含最终产品渲染与事件传输 |
| 无限推进、零时间死循环 | 外层 250 ms 定时停止 Worker，观察到约 428/369 ms 后结束；说明定时器会延迟，不能承诺恰好在 250 ms 停止 |
| 停止后恢复 | 新 Worker 重新编译、4096 组验证和单输入执行成功 |
| 原始运行包诊断 | 保留 `Failed to open 'system.vpi'` / `dynamic linking not enabled`，仍是待修正项 |

本地证据说明约 86 秒的滚动演示页记录不是足以否定 WASM 计算能力的证据；本次没有进一步分离那个演示的网络、初始化与页面开销，不能断言其慢的具体原因。上述只是少量样本，不是冷启动标准测试、p95 或整个课程的性能承诺。

## 实施与验收尚未完成的内容

- 可复现的 WASM 移植构建、系统模块诊断修正、固定 Icarus 版本与编译选项；不承诺完整 SystemVerilog，明确课程支持的写法与未支持特性的诊断。
- Windows 11 x64 与 Apple Silicon 的实际 Chrome/Edge 矩阵；未测试平台只作为验收目标。公网首次资源准备、缓存与更新失败恢复另测。
- 产品中的连续输入、代码变化、X/Z、未驱动或遗漏赋值、事件顺序、刷新/断线/恢复、Agent 与学生并发，以及晚到结果分别取证；不能用探针页面替代工作区集成。
- 编译/仿真的外部时间与输出/内存预算，Worker 可见能力与文件导入边界。Worker 本身不等于完整权限隔离，WASM 工具链仅获得明确的文件和宿主接口。
- 如果将来启用本机组件，再验证其自动准备、实际执行隔离与通信；Chrome 的 [Local Network Access 文档](https://developer.chrome.com/blog/local-network-access/)涉及本地连接权限，不以历史行为推断目标版本兼容性。

工程证据、浏览器体验和教学效果分别记录。目前已完成 Mac CLI 与两种 Mac Chromium 环境的有界小样本；实际产品集成、跨平台矩阵和学生试用均未完成。
