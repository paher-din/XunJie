# Agent 新消息、过程展示与自主学习设计

日期：2026-10-27。对应[总体架构与复用取舍](https://github.com/paher-din/XunJie/issues/119)。依据负责人本轮三项答复：默认 steering、设置中可改为排队；需要工具调用、思考摘要和状态显示，具体程度结合学习场景；个人空间可直接自主学习，无需先建课程。产品要求已确认，以下工程与交互设计已纳入[最终决议](https://github.com/paher-din/XunJie/issues/119#issuecomment-6443526782)；尚未实现或完成课堂验收。

## 新消息：默认引导，设置可改为排队

设置位于个人的 Agent 交互偏好，默认“引导当前任务”，另一项为“本轮结束后处理”。它与主动引导档位、模型选择分别控制不同事情。输入区在忙碌时显示当前发送方式；不要求学生选择内部 Run。设置改变只影响之后发送的消息，已接收消息保留当时的处理方式。

“一轮”是一次学生请求及其模型、工具、等待和交付的完整处理，不是一次模型 API 请求，也不是一次工具调用。

- **引导：** 消息立即进入当前请求的持久输入记录，在最近可用边界纳入当前任务；补充、纠正和转向都保留在同一逻辑运行中，不因语义分类自动再开一个并行 Run。明确新建对话/任务才建立独立运行。预算不因追加消息自动清零。
- **排队：** 消息立即可靠保存，但不改变当前轮的目标。当前轮正常交付结束后，按接收顺序逐条作为新一轮处理；每条消息保留发送时的引用和作品依据，不能用轮到它时的最新作品偷偷替换。
- **停止：** 独立控制，立即停止新派发并请求中断可取消的模型/工具。已发生效果保留；队列暂停并留在界面，学生可继续或移除。失败、预算耗尽也暂停自动推进，避免无人处理的失败接着触发后续工作。
- **回应 Agent 的提问：** 在对应交互卡中作答直接恢复等待，不经过普通排队。输入区在等待学生时提供“回答当前问题”；仍可明确选择“另发消息”。避免排队设置导致当前轮永远等不到回答。

等待学生时选择“另发消息”，仍按该消息的 steering/queue 方式处理。steering 唤醒同一 Run；原问题尚未收到回应时，将其 Wait 记为被新输入取代，卡片标明已暂缓并关闭旧回应入口。后续仍需要这个问题时创建新的等待身份。与引导同时到达的旧回答按接收顺序裁决：先已接受的回答保留为事实，后到且已失效的回答保存为未用于当前问题，并允许学生明确作为补充发送，不推进旧 Wait 或复活旧方向。queue 则不改变当前问题与等待。

失败、取消或硬期限终止时，异常收尾同时结算全部尚未消费输入：queue 和 steering 均保留为可见的暂停项，显示未处理原因，不能挂在终态 Run 上悄然遗失。学生继续时，终态运行不复活；创建关联后继 Run，带入选定补充、原引用及已核实效果，重新按预算规则开始，不重放旧操作。若原 Run 只是非终态暂停，则满足原恢复条件后继续同一 Run。

### 引导究竟何时生效

普通请求不能修改已经发往模型的上下文。“立即”首先指可靠接收和可见反馈；模型采纳发生在下一次可续接的推理请求。比较依据见[DeepSeek Harness 与 Pi 调度研究](2026-10-27-agent-steering-research.md)。循阶采用以下边界：

上游普通 steering 实际等模型及完整工具批次结束，不会跳过尚未派发工具。循阶在自有 RunDriver 中增加派发前检查，是本项目的工程选择，**不是声称上游已经这样做**：学生说“先别运行，先解释”时，尚未开始的旧实验应能停住。代价是自行维护配对结果、派发竞争和恢复检查；实施验收须覆盖这些边界。

| 新消息到达时 | 接收后做什么 | 学生看到什么 |
| --- | --- | --- |
| 尚未发起下一次模型请求 | 将待处理引导按接收顺序加入该请求上下文 | 已收到 → 正在根据补充继续 |
| 模型正在思考、生成文字或生成工具参数 | 保留本次调用直到完整响应；不只等 thinking 块结束，也不默认取消重开。响应完成后、任何新工具派发和最终交付之前检查引导 | 已收到，等待本次生成结束后调整；已经显示的旧片段保留，但不能继续标为有效的最终答案 |
| 工具意图已生成、尚未派发 | 不执行基于旧输入产生的未派发调用；为原 tool-call 写入“因新输入未执行”的配对结果，再纳入引导重新判断 | 未执行：已收到你的调整。不是“运行失败”或“取消成功” |
| 同步工具已开始执行 | 不把输入塞进正在执行的调用；收齐已派发调用的结果，停止后续未派发调用，再进入下一次模型请求 | 当前操作仍在执行；补充已收到。并行批次中已启动的调用也按实际结果收束 |
| 长任务已返回接收回执，Run 正在等待结果 | 引导可唤醒 Run；以已接受但未完成的真实回执继续推理，不等实验数分钟完成。原作业按其真实状态继续跟踪 | 等待实验结果 → 正在处理你的补充；实验另标“仍在运行” |
| 即将结束本轮 | 与接收新输入在同一运行序列中裁决。已先接收的引导必须处理后才可完成；完成已经提交后收到的消息成为下一轮 | 不丢消息、不产生两个同时声称为当前回复的答案 |

“停止新工具派发”与“接收引导”共享同一有序状态：工具若在消息被接收前已取得有效派发身份，就按已开始处理；在其后则不得绕过引导检查。不能仅在生成前查一次内存队列。原生 tool-call/result 配对完整后才能续接；已派发调用不能伪造 skipped 结果。

多条引导按实际接收顺序进入下一步；后来的纠正可改变先前目标，但历史记录不删除。尚未消费的消息可编辑或移除，编辑产生修订；消费与编辑按同一版本条件裁决，来不及时作为新补充，不能改写已发给模型的文本。队列提供条数、预览、编辑、移除和“改为引导”；后者沿既定引导边界处理，不等于强行中止操作。

当前已显示的旧回复标明已被后续补充调整，未交付的旧最终内容不作为新答案发布。晚到实验结果仍保存事实；新的回答是否引用它，要核对其输入和本次问题，不能让结果自动覆盖新方向。模型切换、长等待、恢复和未知效果仍遵守[总体运行设计](2026-10-27-overall-architecture-proposal.md)。

## 过程展示：保留信息，按学习用途展开

默认在本轮回答上方显示一条当前状态、一段简短过程说明和紧凑工具记录。完整回复与学生可操作的学习内容保持主要层级。IP 在工作区只给当前短状态或需要学生回应的入口；展开过程在对话中进行，不把工具日志连续播成气泡，不抢焦点、切面板或强行滚动作品。

| 信息 | 默认显示 | 展开后显示 | 不进入普通学生过程面板 |
| --- | --- | --- | --- |
| 状态 | 正在查看资料、正在生成、实验运行中、等你回答、等待服务、已中断、结果待核对；使用真实状态和实际经过时间 | 等待对象、可读原因、可用动作；失败直接说明能否继续 | 无依据的进度百分比、预计剩余时间；把所有等待都叫“思考中” |
| 工具调用 | 可读动作名、对象、实际状态，例如“读取本次波形 · 完成”“运行当前用例 · 尚未执行”；重复的独立读取可合并为一行但保留条数 | 有意义的参数、固定作品/资料来源、实际结果与获准原件入口。编译错误、输入值、波形和检索出处按课程对象呈现 | 凭据、系统指令、内部 Run/trace ID、原生协议 JSON、无关日志；开发排障走独立调试包 |
| 思考摘要 | 端点确实提供可展示摘要时，显示“思考摘要”的简短预览与折叠入口；完成后自动保持紧凑，不关闭学生正在查看的内容 | 与问题相关、符合本次帮助范围的可读摘要；不透明块无正文就不提供虚假的展开 | 原样 raw reasoning、签名或假称为完整思维过程的文字 |
| 过程说明 | 在开始、依据变化、遇到障碍或需要学生动作时，给一两句面向学生的目标与方法，如“先核对这次输入，再比较两种溢出判断” | 学生可要求解释方法、证据与不确定性；这是教学说明，与供应商摘要分别标注 | 每个 token、轮询和自动重试各产生一条消息；将计划陈述写成工具已完成 |
| 待处理消息 | 引导显示“已收到，尚未采纳/已纳入本轮”，排队显示条数与下条摘要 | 原文、发送时引用及尚可执行的编辑/移除操作 | 将“服务已接收”当作“模型已经理解”，或只凭灰色文字区分两者 |

**思考摘要的来源要讲清。** [OpenCode / Claude Code 研究](2026-10-27-agent-progress-display-research.md)表明，折叠显示与是否拿得到可读摘要是两件事。Anthropic 当前官方 API 将可读 thinking 明确描述为摘要；DeepSeek 的 `reasoning_content` 则是其推理输出，不能改个标签就说它是相同摘要。[Anthropic Thinking](https://platform.claude.com/docs/en/build-with-claude/thinking#how-thinking-works)、[DeepSeek Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)

每条模型路线分别记录其能力。只有 raw reasoning 的路线默认不展示原文；模型可在正常面向用户的输出中提供有界的“过程说明”，说明其方法与下一步，无需为每个工具额外调用一次模型生成摘要。路线没有摘要时不造一个空折叠块；学生主动查询时如实说明该模型未提供。原生推理与签名仍按续接要求保存和回传，UI 截断或摘要绝不改写原生记录。

**教学限制同样适用于过程。** 在允许完整解释的自主学习中，可展开合适的原生摘要；在只允许提示、要求先预测的活动里，原生摘要若不能可靠保证符合帮助范围，就只显示面向学生的过程说明，不能通过“默认折叠”规避该范围。工具结果也只暴露学生可访问的反馈，不增加教师私有答案入口。

### 不同学习情境中的默认程度

| 情境 | 采用的展示 | 为什么 |
| --- | --- | --- |
| 阅读资料、询问概念 | 一条查阅记录、简短说明、回答里的来源；连续读取按材料合并 | 能核对出处，不被工具细节打断阅读 |
| ALU 结果不符、编译失败 | 当前失败及关联的输入/结果直接可见，打开工具条目看输出、波形或错误位置 | 失败本身是学习材料；“工具执行完成”和“用例通过”分别表达 |
| 学生要先自己预测 | 给出下一项观察或问题，明确“等你回答”；隐藏会提前揭示解法的推理原文 | 保留学生实践机会，等答复不伪装忙碌 |
| 长实验或外部服务等待 | 显示等待对象和实际状态；允许继续问概念、追加引导或停止 | 实验与对话能够分别推进，不用假进度维持活跃感 |
| 新消息纠正当前方向 | 显示接收与采纳两个阶段；旧结果可查，当前说明随已采纳目标变化 | 让学生看得出控制是否生效 |

视觉沿用 [DESIGN.md](../../DESIGN.md)：系统正文 15px，次级说明 13px，辅助标注 12px；使用现有浅/深色 token、32px 控件与 8px 控件圆角、偶数间距。状态裸排，只有操作用按钮；颜色只辅助语义。每项可用键盘展开，减少动效时保留状态文本。此设计补充整体 Agent 对话，不把[已授权的 IP 展示组件](../specs/guidance-presentation.md)扩张成调度或事件权威。

## 自主学习：活动可以没有课程

个人空间中，学生直接输入问题或选择资料即可开始；目标可以从首条问题形成，不增加建课、教学配置或额外问卷。沿用 Learning Activity、Workspace、作品、引用、Agent 与持久运行；课程绑定为可选值，不创建一份伪造 CoursePack 来满足字段要求。

无课程时，由平台的学习助手职责、学生当下目标与明确偏好组成指令。默认能阅读选定资料、检索已连接的个人资料、给解释和练习、生成可检查的学习内容；课程专属实验工具不会凭空出现。个人扩展按实际连接和可用能力装配，普通学习无需配置 MCP/Skill。需要运行环境而本机未具备时明确缺项，先提供仍可完成的资料与解释工作，不自行假设学校资源可用。

自主学习沿用已定的轻度主动默认、自己尝试/暂停与反馈规则；没有教师帮助策略时，按学生请求提供讲解、练习或完整解释，不强制套用某门课的预测流程。作品修改、外部发送仍按学生意图与实际能力处理，不因“无课程”而变成无限制后台执行。

长期记录按活动及学生明确延续的学习目标组织；同一目标可跨会话继续。无课程不等于所有个人聊天共享一份学科能力判断，主题之间仅复用明确通用偏好；推断仍保留依据与可纠正性。材料、活动和结果属于个人空间，不自动进入学校教师视图。今后加入课程，应建立明确的课程活动与材料引用，不能静默重归属个人学习记录。

## 验证范围

本轮研究只核实公开官方文档、固定版本源码与有限无模型探针；本文件是工程设计。完整工具能力表和请求走查见[能力与质量契约](2026-10-27-agent-capabilities-design.md#具体能力表与课程组件映射)。课堂帮助程度、不同端点的实际摘要、目标浏览器和生产持久恢复仍需实施验证；本次不把竞品功能存在当作教学效果证据。

本轮已完成 11 个上游局部无模型探针；独立设计走查发现并补齐了“学生等待被新引导替代”和“异常终态中的未消费输入”两个边界。[对话交互示意](prototypes/2026-10-27-agent-process-preview.html)可直接用浏览器打开，已检查摘要/工具展开、引导接收与采纳、设置仅影响后续消息、排队在完整轮结束后开始，以及无课程自主学习。示意使用合成内容，没有真实 Agent 后端；未做生产 UI、设备矩阵或课堂验证。10 个相关 Markdown 的 182 个本地目标、25 个标题锚点与代码围栏检查通过，`git diff --check` 通过；临时研究源码和预览服务已清理，研究及示意源码保留在仓库。
