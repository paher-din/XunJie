# 连续教学：活动恢复、学习证据与画像纠正

日期：2026-10-23。状态：学生查看与纠正画像、教师持续摘要和提交交付边界已确认；活动恢复与证据模型按这些产品要求形成工程设计，尚未实现。服务于[跨课程连续教学：主动引导、活动进展、学习证据与学生画像](https://github.com/paher-din/XunJie/issues/118)。已确认的主动性控制与无扰检测首版路线见[主动引导方案](2026-10-23-proactive-guidance-proposal.md)，学生画像边界见[确认记录](https://github.com/paher-din/XunJie/issues/118#issuecomment-6364293339)。本文件确定教学语义，不预选存储或运行框架。

完整决定、来源与交接范围以[连续教学决议](https://github.com/paher-din/XunJie/issues/118#issuecomment-6364486548)为准；本文是其详细设计附件。

## 活动要记住目标与依据，而非只保存聊天

一个项目任务可以包含多个有目标的学习活动：理解要求、预测、实验、比较、解释或修改作品。它们可由课程安排，也可在学习中根据实际需要形成；平台不强制固定顺序。以下活动模型属于工程设计：依据连续学习、学生控制、课程差异和可追溯证据的已确认要求，确定跨次运行需要保存的语义，不把模型会话或某门课的固定步骤作为活动的权威状态。

| 需要记住什么 | 为什么需要 |
| --- | --- |
| 所属课程、任务、课程要求版本和当前学习目标 | 返回会话后知道在解决什么，区分学生改变方向与教师更改要求 |
| 当前作品及已引用的版本、实际工具结果 | 旧问题与提示可以核对是否仍然相关，不用聊天摘要代替作品事实 |
| 已尝试的方法、得到的证据、仍存在的疑问 | 保留分支与探索，不把重复调用模型当成新学习活动 |
| 正在等待谁或什么，以及实际处理状态 | 等学生解释、等工具结果和环境故障有不同处理方式；一次模型调用结束不等于活动结束 |
| 已提供的帮助、实际呈现、学生回应与主动性选择 | 避免重问、重复提示和返回后丢失暂停；区分学生表现与获得的帮助 |
| 目标调整、暂缓或结束的原因及前后关联 | 可以回到旧目标，不把切换任务解释为不会或放弃 |

活动的进行、暂缓与结束，等待事项，以及目标是否达成分别表达。作品完成、向教师提交、活动结束与知识掌握是不同事实。即使活动结束，相关学习判断仍可能是证据不足。

学生返回时恢复已有目标和状态；有必要时提供一条可忽略的进度说明，允许继续、换方向或暂时结束。只在恢复方向确有歧义时询问，不要求每次回来先回答确认题。旧提示依据失效则取消；尚未查明的工具结果先核实，不因恢复会话自动重复执行。学生只更改当前探索方向时，课程正式要求仍保持原意。

恢复也遵守主动性设置：仅提问或当前活动已暂停时，恢复事实状态，不自动发起新的教学提示；学生主动提问仍正常回应。跨次返回时保留活动身份与暂停范围，不能通过创建一个同内容的新活动绕过暂停。

| 新发生的事情 | 状态怎样变化 | 后续怎样继续 |
| --- | --- | --- |
| 学生回答或修改作品 | 为当前目标增加新观察，保留对应版本和帮助情况 | 根据新依据判断下一步，已解决的问题不再重复追问 |
| 等待中的工具完成 | 更新该等待事项并关联实际输入与结果 | 检查结果是否仍适用；模型调用或工具成功本身不结束学习活动 |
| 工具或环境失败 | 记录实际失败及未获得的学习观察 | 处理故障，不把失败写成学生概念掌握不足 |
| 学生忽略或拒绝一次提示 | 记录该次呈现和回应，不推断永久偏好 | 停止催促，保留活动；明确暂停时才进入相应暂停规则 |
| 学生转向新的问题或子目标 | 保留旧目标、未解事项和关联，新目标成为当前上下文 | 不强迫回到旧步骤；是否回来由实际学习需要决定 |
| 学生结束活动或向教师提交 | 分别记录活动结束或交付事实 | 不自动把证据不足改成掌握，也不清除仍有价值的探索记录 |

## 观察、评价与画像分别表达

| 层次 | 应保存什么 | 示例与边界 |
| --- | --- | --- |
| 事实观察 | 具体作品、解释、操作或工具结果，及时间、版本、来源与发起者 | 学生写出了某段解释、Agent 运行了一次检查；分别保留，不互相代替 |
| 评价依据 | 对应课程目标或量规、所用标准、关联观察及缺失信息 | 这段解释缺少哪个必要关系；不能只因模型说“很好”就认定达标 |
| 阶段性判断 | 有限范围内的学习认识、支持与反对证据、帮助情况、不确定性及修正历史 | “尚无独立解释进位关系的证据”，比“学生不会进位”更准确 |

同一结果可支持不同强度的判断。通过检查可说明该版本满足已检查条件；有帮助后的正确解释与新的独立解释应区分；保持或迁移需要相应新情境证据。证据缺失、冲突或过期时保留未知或待复核，不强行合成一个掌握分。

已有的同课跨任务积累与跨课通用偏好边界继续有效。某次受阻和提示被忽略不形成稳定人格、动机或态度标签。

## 已确认：学生查看和纠正画像

学生能查看与当前学习有关的简明能力判断、主要依据及不确定性，并能指出“不准确”或补充说明和证据。原始记录与后续解释分开保留：提出异议不改写历史事实，但异议必须能改变系统后续如何使用这项推断。

记录异议及依据，将被争议的推断标记为待复核；Agent 核对相关作品、帮助与新证据后更新或撤销判断，保留变更理由。复核期间不再把被争议的推断作为确定事实推动同类补学；仍可依据当前新事实提供帮助。教师作出的正式评价另有归属，Agent 的画像修正不自动改写正式评价。

纠正流程的工程落实：提交异议本身不以完成额外测试为前置条件；学生可以直接指出已有说明、补充背景或附上新证据。复核后提供简明结果和理由，仍有分歧时保留分歧及依据，不要求学生先认同 Agent 才能继续学习。具体入口与呈现方式在界面设计中确定。

## 已确认：持续摘要与提交交付

教师可以持续查看本课程的进展摘要、可能的困难、阶段性判断及必要依据，争议判断明确标注待复核或已修正。需要时可追溯相关作品与支持判断的对话片段；这些材料服务于当前课程教学，不自动扩展为跨课程画像或完整教师分析系统。

学生提交时，围绕本次任务固定交付：作品版本、课程目标对应的关键过程证据、获得的帮助、已核对的表现，以及仍不确定或存在争议的判断。教师可以追溯依据并作最终评价。后续编辑不静默替换已交付内容；后续判断修正通过关联的新记录体现，不能改写“当时交付了什么”。

持续摘要与固定交付的工程边界如下：

| 内容 | 如何变化 | 教师应如何理解 |
| --- | --- | --- |
| 进行中摘要 | 随已收集的新事实更新，保留更新时间、主要依据和观察缺口 | 用于及时支持，不构成正式成绩；没有新记录不等于学生没有学习 |
| 已提交材料 | 固定当次作品、证据及判断版本；后续修正另行关联 | 是当次交付的记录，不跟随后续编辑悄悄变化 |
| 学生画像判断 | 新证据、异议及复核可以更新，保留变化理由 | 看见当前认识，也能追溯过去依据与分歧 |
| 教师正式评价 | 由教师评价流程管理 | Agent 推断或学生异议不自动改写正式评价 |

帮助偏好与学科表现分开，选择安静或拒绝某次提示不作为能力差的证据。原有记录收集状态与主动提示档位保持不同语义；摘要只能使用实际获得的记录。具体教师入口、访问实现和审阅流程由后续工程落实，本票确定必要的共享内容与语义。

## 平台复用与课程差异

| 平台负责 | 课程、任务或工具提供 |
| --- | --- |
| 活动身份、目标关联、等待与恢复、学生主动性设置 | 实际目标、材料、任务要求、允许的帮助程度与可用能力 |
| 记录来源、版本、发起者、呈现、回应、缺失与修正关系 | 编辑、实验、论证等操作的含义，以及哪些变化有助于判断进展 |
| 观察、评价依据、学习判断的分层及争议处理 | 目标和量规对应的判断依据；何时具备充分证据，何时只能保持未知 |
| 候选引导的时机控制、失效检查和反馈归属 | 问题、解释、示范、验证等具体教学方法和活动限制 |
| 进行中摘要与固定提交的共享契约 | 本课程需要交付的成果类型及评价要求 |

教师与 Agent 协作形成课程输入，由教师确认。材料已有要求时优先复用，Agent 辅助补齐；无法自动确定进展或评价含义时保留未知并指出具体缺口，不要求教师预写完整教学脚本，也不把任意工具的点击解释成学习证据。

## 用活动检查这些语义

以下均为设计验收场景，不是已经发生的学生记录或通过的运行测试。

| 场景 | 应有行为 |
| --- | --- |
| 学生修改 ALU 后离开，返回时先前运行已完成 | 恢复原目标并核对结果绑定的输入；若作品又变了，不能将旧通过结果当成当前作品已通过 |
| 学生中途从验证实现转去理解某个概念 | 关联新的学习目标，保留原探索；不要求完成一条固定步骤链后才能转向 |
| 学生写报告时补充了论据，但没有运行或对错结果 | 依据课程目标与文本证据评价变化，不制造编译步骤或用字数当质量 |
| 学生纠正“尚不能解释某概念”的判断并指出已有说明 | 查看实际说明及其版本，修正或说明仍缺少的依据，保留异议和复核结果 |
| Agent 提供示范后工具检查通过 | 记录示范与真实结果；学生是否能独立应用该方法仍需其他证据 |
| 学生提交作品，但迁移运用的证据不足 | 教师收到作品与已有证据；任务交付成立，掌握判断仍保留有限范围和未知 |

数字逻辑是已有样例，报告在这里仅是反例。实际跨课程验收还需选定另一门真实课程、任务与评价材料，不能把反例表当作课程已接入或教学效果已验证。

### 完整活动的设计走查

以首条数字逻辑样例中一次进位问题为例：学生先表达预期，随后自主修改和运行；系统记录预期、学生作品、真实输入与结果，以及已经获得的帮助。若多次尝试仍有局部进展，保持观察；持续出现同类困难且时机合适时，按学生选择与该活动只解释不代改的规则给局部提示。学生之后的解释、修改和新情形表现形成新证据，不能把 Agent 的验证算作学生独立完成。中断返回时恢复原目标与暂停选择，核对迟到结果是否对应当前作品。提交时固定作品和关键证据；教师持续摘要可以继续更新，学生也可以纠正不准确的画像判断。

对于报告论证任务的设计反例，同一机制围绕问题、主张、论据和解释组织活动。进展由课程评价依据和作品变化支持，不要求代码或运行；无法可靠判断论证质量时保持未知。上述两条都是设计走查，未运行产品流程。

| 验证层次 | 应检查什么 | 本轮状态 |
| --- | --- | --- |
| 工程检查 | 活动恢复、依据归属、设置和暂停生效、投递失效、异议复核、摘要与提交版本区分 | 已形成语义与反例；未实现和执行运行测试 |

| 教学与体验效果 | 不同真实课程中误报、漏报、主观打扰、独立进展及目标对应的表现 | 未进行；第二课程待定 |
