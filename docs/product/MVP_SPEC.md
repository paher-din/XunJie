# MVP_SPEC：第一版可用教学闭环

版本：0.2 · 初稿依据：2026-10-04 · 本次修订：2026-10-06（Asia/Shanghai）  
状态：基于已确认产品方向的首版实施建议；功能和验收尚未执行。  
上游：[PRD](PRD.md) · 下游：[TECH_DESIGN](TECH_DESIGN.md)

## 1. 首版交付定义

**交付一个可供真实教师与学生使用的独立 Web 应用：教师从资料设计并分配项目，学生围绕自己的代码获得帮助并完成作品，教师能够复核具体表现、给出反馈，并让有效修订进入后续学习。**

首版完成一条纵向链路。教师端不能只有手工配置上传，学生端不能只有泛化聊天，分析端不能只有日志列表。日常辅导可以自动进行，作品操作与教学决定各有明确责任人。

### 1.1 工作范围

| 维度 | 首版基线 | 状态 |
| --- | --- | --- |
| 承载 | 独立 Web 应用，桌面浏览器优先 | 用户已确认 |
| 教学 | CS 课程、个人项目、一位教师与少量真实学生 | 用户已确认 |
| Web UI | 由团队成员负责具体设计与前端实现，本工作项基于其交付对接 | 2026-10-06 用户确认 |
| 规模 | 1 门课程、1 个主项目、1 个相关后续任务；建议 3–5 名真实学生 | 本文建议，用于流程试点 |
| 运行 | 只支持首发课程的一种语言、预装工具链和批准资源 | 本文建议；具体语言待 D-01 |
| 使用形式 | 邀请制私有试点；支持跨会话恢复 | 本文建议 |
| 能力目标 | 三条能力线各选择少量具体目标，作品质量另列 | 遵循 PRD |
| 帮助入口 | 学生主动求助为主；可选的里程碑提醒默认关闭 | 本文建议 |
| 评价 | 形成性反馈和教师确认的课程评价，不自动写入正式成绩系统 | 本文建议 |

后续任务用于检查历史状态与教师反馈能否被正确带入新任务，不要求学生重复同一道题。项目题材、时长和难度由教师决定；已有检索项目仅作候选，不导入旧模拟画像。

### 1.2 明确不做

不做团队实时共编、同伴评价、完整 LMS/题库、自动成绩发布、公开注册、公共插件市场、第二学科工作区、手机完整编程体验、语音/三维、开放网页自动生成教学场景、模型微调、BKT/深度知识追踪、在线强化学习。

课程资料首版支持粘贴文本和 UTF-8 TXT/Markdown，保留标题与段落引用；PDF/扫描件、自动网络抓取和通用文档解析延后。代码执行不支持任意依赖安装、任意终端、网络服务或学生自定义运行命令。

不建设模拟教师/学生来演示产品价值。开发使用隔离测试数据验证软件行为，真实试点检查教学体验，两者分别报告。

## 2. 角色任务与 Web UI 接入边界

Web UI 正由团队成员制作，页面划分、导航、布局、视觉样式、控件文案和前端技术栈均以其交付为准。本节只约定各角色需要完成的业务任务，不指定页面数量或组件形式；本轮没有审阅该 UI，也不将其标记为已完成或已验收。

| 角色与任务 | 必须支持的业务结果 | 对接所需信息 |
| --- | --- | --- |
| 教师设计与分配 | 从资料起草、修改、检查、预览并分配项目 | 目标/任务/支持/评价关系、局部差异、影响范围和版本 |
| 教师了解进展与审阅 | 找到学生尝试，查看依据并确认、纠正、暂缓或反馈 | 进展、自述、作品、实际帮助、反证/未知与待处理事项 |
| 教师改进后续教学 | 允许修订、创建新版本或相关后续任务 | 教师决定、有效学习状态、活动版本及关联 |
| 学生开始与实践 | 理解任务、恢复进度、自主编辑/运行、求助并返回原任务 | 项目要求、允许帮助、对象版本、保存/运行/记录状态 |
| 学生查看反馈与继续 | 查阅具体表现和教师建议、提出异议、继续修订或进入后续任务 | 证据引用、反馈版本、修订许可和恢复位置 |

接入时将上述任务与实际 UI 中的操作逐项对应，补齐数据、状态和接口；键盘可达、状态可辨认和恢复可靠等基本可用性要求仍需验收。目标设备与视口跟随团队 UI 的交付范围确定，本文件不再指定固定布局或像素尺寸。

维护者仅负责预置账号、批准运行镜像、配置限额和导出/恢复，不新增一套复杂运维后台；其身份不能代替教师作正式教学判断。

## 3. 首版能力规格

### M-01 教师与 Agent 共同设计

输入为课程资料、学生基础、时间与资源约束，以及教师已有目标。允许从少量信息开始，缺少关键条件时集中提示补充。

Agent 生成 1–3 个项目候选，教师选中后形成一个共享蓝图：真实问题/受众、产物、选择空间、三条能力线目标、里程碑、资源、帮助政策、必要检查点和量规。每个核心目标关联至少一种可观察表现，不能只标“已覆盖”。

支持字段级直接编辑和局部 AI 建议。AI 建议显示差异、依据与受影响项，教师决定采用；重新生成不得覆盖期间发生的人工编辑。至少支持用一个教师认可的样例试评量规、记录歧义并修订。

### M-02 检查、角色预览和分配版本

发布前检查分三类：

- 阻断项：必需字段/引用缺失、目标无观察安排、资源越权、运行环境未就绪、规则版本缺失。
- 设计疑点：任务意义、难度、时间、可接受解法和量规歧义，由教师说明处理方式。
- 待验证项：学习效果、估计工作量等，保留标记，不能显示成已验证事实。

提供学生、辅导 Agent、教师/验证器三种视图预览。教师确认后产生不可变活动版本，再分配给指定学生。学生不获得私有答案或验证资产；辅导 Agent 默认也不获得这些资产。

已开始的尝试固定原活动、量规、政策、资料和运行配置版本。教师改动产生新版本，默认只用于新尝试；若原活动存在必须停止的问题，教师先暂停相应活动并说明后续安排，不静默替换学生正在使用的要求。

### M-03 学生项目工作区

支持项目说明、资料阅读、项目文件访问与编辑、学生新建/回收文本文件、保存、运行、查看结果和两个版本/运行的比较。文件导航与编辑器的具体呈现以团队 UI 交付为准，已有 Monaco 能力作为可复用输入。首版限制为 50 个项目文本文件、源码合计 1 MiB，不处理任意大型仓库。

学生能区分本机未同步草稿、服务器已确认版本及运行所用版本。未保存到传统磁盘文件也可形成服务器确认的源码快照；Agent 和执行器只使用明确确认过的版本。刷新恢复确认成果，本机未同步草稿单独提示，不冒充已上传证据。

学生自主选择路线，可保存简短计划或正在探索的问题；不是开工前的强制表单。代码修改、文件管理、执行和提交由学生发起。类似例子不能覆盖学生项目。

### M-04 就地帮助与学生接棒

求助携带学生问题、目标对象/选区和可核对的版本；学生可更正指向。应支持以下求助意图，具体入口与文案采用团队 UI 的方案，可通过开放文字表达，不要求每种意图对应一个按钮：

| 求助意图举例 | 典型支持 | 接棒点 |
| --- | --- | --- |
| 帮我找到起点 | 澄清目标、比较路线、提出可选下一步 | 学生选择并动手 |
| 检查这一步 | 围绕当前实现/结果指出需要核查之处 | 学生检查或试验 |
| 给一点提示 | 指向相关条件或概念 | 学生继续推理 |
| 解释/看类似例子 | 概念说明或教师批准的相邻例子 | 学生返回原对象，尝试运用 |
| 帮我核查/比较 | 找依据、设计反例、比较方案限制 | 学生作出取舍 |

帮助政策默认保护当前任务的关键思考步骤，允许概念解释与相邻示例；不提供整份可直接提交的答案。教师可收紧某检查点的帮助，MVP 不提供一键放开“代做整个项目”的模式。

每轮只交付一个主要教学目的，可以有充分解释；随后等待学生。学生能追加帮助、停止生成、暂缓辅导、继续自主操作和返回原任务。Agent 不自动改代码或运行程序。

默认不主动插话。学生开启里程碑提醒后，仅对明确提交的里程碑提供一次可忽略的回顾邀请；不按停顿、焦点、粘贴或逐次失败猜测心理状态。关闭主动提示取消待投递提醒，主动求助继续可用。

### M-05 教学消息、自然记录与覆盖说明

应用保存本系统内实际教学内容、学生主动消息、来源对象和政策版本。区分生成、投递、界面展示和学生确认；缺回执保持未知，不用模型自报代替。

过程采集只针对当前项目，能暂停/恢复并记录覆盖空窗。暂停后停止新增逐次编辑过程及被动分析；为完成显式保存、求助、运行、提交而必要的作品/消息/结果仍保存，切换采集状态时须明确说明这一范围。恢复后只采集后续数据，不补造空窗事件。

原始观察、模型候选和教师判断分层保存。原始记录可追溯，引用包含版本和帮助条件；同一次尝试的多次编辑/运行不重复算作独立能力证据。

### M-06 最小可纠正学习状态

只保存课程内相关状态：学生自述的目标/约束、当前任务、三条能力线的候选表现、反证与未知、已提供帮助及后续反应。

能力状态使用“证据不足”“受助条件下有支持”“限定检查条件下有支持”“证据冲突”等描述，不输出掌握百分比。每条主张都有目标、范围、原始引用、帮助条件和分析版本。没有观察不是失败，工具环境故障不计为知识错误。

学生可修改自己的自述、对推断提出异议；教师确认/纠正推断。学生一句“我会了”和教师无依据的赞同都不能生成不存在的学习证据。

日常候选提取和支持选择无需逐条等待教师审批。正式评价、重要冲突和异议进入教师处理；相关主张在争议期间标记，避免继续据其作强适应。

### M-07 提交、课程检查与反馈

提交固定一个作品快照。自然产生的解释、方案取舍和核查记录优先复用；仅对课程明确要求的目标补充短解释、预测或变式检查。

学生显式发起运行得到运行结果，发起课程检查得到指定规则下的验证结果；两种行为及结果应可区分，控件形式与文案由团队 UI 确定。限定帮助检查显示帮助政策，并在系统内关闭不允许的辅导；不声称阻止外部帮助。

结果分别显示作品表现、三条能力线、实际帮助及未知。Agent 可起草反馈，教师决定正式评价。程序退出码 0、学生自行打印的 passed 或语言环境 smoke 验证均不等于课程验收。

### M-08 教师审阅、纠正与教学行动

教师能够围绕一次学生尝试查看结论、具体表现、帮助条件、反证/未知和可选下一步，并追溯作品与消息原文；信息组织采用团队 UI 方案。支持确认、纠正、暂缓和反馈；变更带理由与引用，不覆盖历史。

纠正必须更新有效状态、撤销依赖旧结论的待投递动作，并影响后续上下文。并发打开的旧复核表单不能覆盖新判断。

教师可给资源/拓展建议、允许修订，或基于发现的问题复制出下一版项目蓝图。作品、目标和量规变更作用于新版本；针对个人的状态纠正与课程设计修改分开操作。

### M-09 后续任务与恢复

至少支持一个教师确认的相关后续任务。新尝试读取同一课程、适用目标范围内的有效状态；无关历史不带入，已撤回主张不继续使用，缺少迁移证据时保持未知。

会话中断后恢复活动版本、作品、最近运行、待处理问题、分支返回位置及有效教师反馈。无需依赖一个模型进程一直运行。相同请求重试不重复提交、运行或展示同一提示。

### M-10 最小访问与运行保障

具有真实的教师/学生登录和课程成员校验，不能靠前端角色按钮或请求参数扮演教师。学生仅能访问自己的尝试，教师仅能审阅自己负责的课程。

学生代码在独立执行环境中按固定快照运行，不能读取应用密钥、其他学生作品或私有答案。运行有时间、内存、进程和输出限额；不暴露应用服务器终端。

支持课程/个人范围导出，包含原始引用、帮助、判断版本与覆盖缺口。试点前明确保留期限和处理负责人；MVP 不做自动永久删除任务，实际删除仍须遵守工作空间授权要求。

## 4. 状态与操作规则

| 对象/状态 | 用户可以做什么 | 系统行为 |
| --- | --- | --- |
| 活动草稿 | 教师编辑、接受局部建议、预览 | 草稿有 revision；冲突要求重读 |
| 已确认活动版本 | 教师分配、复制新版本、暂停使用 | 内容不可原地修改 |
| 尝试 ready / active | 学生开始、编辑、运行、求助、提交 | 固定活动版本，执行课程帮助政策 |
| 尝试 paused | 查看和保存现有草稿；本人恢复 | 停止新辅导/运行投递；进行中的动作取消或归档，结果不冒充当前状态 |
| 尝试 submitted | 查看提交与反馈 | 提交快照固定；不能继续改写该快照 |
| 尝试 reviewed | 查看教师反馈、按许可重开修订或进入后续任务 | 重开保留旧提交，新提交生成新版本 |
| 过程采集暂停 | 继续自主工作，显式保存/求助/运行/提交 | 功能数据仍保存；停止逐次过程采集和被动分析，保留空窗 |
| 模型/执行器不可用 | 保存、浏览既有材料、查看故障和重试 | 不编造辅导、运行结果或能力结论 |

暂停尝试、暂停过程采集、关闭主动提示是三个独立控制。平台活动暂停优先于个人恢复；模型不能解除任何暂停或扩大帮助政策。

## 5. 非功能验收基线

以下为拟定工程目标，不是当前实测结果。采用同一台登记配置的测试服务器、10 个活跃会话、每会话约每 2 秒一个编辑同步批次；保存/API 至少采样 100 次，模型求助至少采样 30 次，报告 p50/p95、错误和超时数。

| ID | 目标 | 首版判据 |
| --- | --- | --- |
| NFR-01 | 编辑与保存 | 编辑不等待模型；本地可见保存状态；正常网络下保存确认 p95 ≤ 1 秒，已确认版本刷新/重启后不丢失 |
| NFR-02 | 辅导响应 | 接收/排队状态 ≤ 1 秒；非排队求助完整可展示结果 p95 目标 ≤ 20 秒；含排队与修复的总等待 45 秒上限，超时明确结束 |
| NFR-03 | 运行限额 | 每次固定快照；编译 ≤ 30 秒、执行 ≤ 10 秒；每作业 1 CPU、512 MiB、64 进程、128 MiB 临时空间、总输出 64 KiB；最多 2 个并发作业 |
| NFR-04 | 边界与可靠性 | 跨学生/课程访问、教师越权、私有资料泄露、旧版本覆盖、重复副作用的确定性用例全部通过 |
| NFR-05 | 可用性与恢复 | 主要桌面流程可用键盘完成；刷新/断网/重连能区分确认版本与本机草稿，不静默覆盖冲突 |
| NFR-06 | 成本与可观测性 | 每轮/尝试记录模型与重试用量、延迟、失败、运行资源及配置版本；预算耗尽降级，保存与人工复核仍可用 |

单轮教学最多 3 次模型调用（含格式/政策修复），不逐编辑事件调用模型。美元/人民币预算由 D-02 冻结；未设实际预算不进入付费真人试点。目标未达时记录瓶颈并缩小负载或修订方案，不能通过关闭检查宣称达标。

## 6. 验收场景

所有工程验收使用新建的隔离测试项目，不操作正在学习的 student-ide 会话。真人项由实际用户完成，自动化不能冒充人类批准或教学反馈。

涉及浏览器的验收在团队交付的 Web UI 上进行，以业务行为、数据和状态是否正确为准，不以匹配本文件的页面或布局为通过条件。接入前可以先验证服务端契约；完整浏览器验收须等待实际 UI 可用。

| ID | 场景与操作 | 通过条件 | 验收方式 |
| --- | --- | --- | --- |
| AC-01 | 教师提供材料，接受草案后修改目标/里程碑 | 人工改动保留；受影响量规/检查点被提示；可修正后形成有效版本 | 自动流程 + 教师审阅内容 |
| AC-02 | 学生/辅导端尝试读取教师私有资料，修改已发布版本 | 服务端拒绝；前端载荷/模型上下文无私有资产；活动只能另建版本 | 自动权限/契约测试 |
| AC-03 | 编辑未同步、已同步后刷新；两个标签页冲突；文件回收 | 已确认内容恢复；未同步内容单列；冲突不覆盖；历史引用仍可解释 | 浏览器自动化 |
| AC-04 | 编辑过程中运行/求助，随后继续改代码 | 结果与旧快照绑定；提示不误指新行号；展示前识别过时对象 | 集成 + 浏览器自动化 |
| AC-05 | 学生求一点提示、类似例子，然后停止或“我先试试” | 帮助满足政策；原作保留且可返回；不连发后续答案；提醒可取消 | 自动取消检查 + 教师抽查语义 |
| AC-06 | 重复发送请求/回执，断线后重连 | 只产生一次业务动作；生成/投递/展示区分；无回执保持未知 | 故障注入/幂等测试 |
| AC-07 | 无历史、缺消息、采集空窗、工具故障和矛盾证据 | 可继续求助；无伪造证据；环境失败不记知识错；冲突保留 | 记录/状态契约测试 |
| AC-08 | 教师纠正，旧页面再次提交；纠正时有提示/分析在生成 | 旧写入冲突；新状态与依赖失效一并保存；过期结果不生效 | 并发集成测试 |
| AC-09 | 提交后教师反馈，学生进入相关后续任务 | 新尝试引用新任务版本及有效状态，旧错误不再是依据 | 端到端 + 实际反馈复核 |
| AC-10 | 运行超时、过量输出、路径逃逸、访问网络/他人数据 | 限额生效；访问被拒；故障类型明确；应用数据与服务仍可用 | 专用隔离环境安全验收 |
| AC-11 | 暂停采集后编辑、保存、显式求助，再恢复 | 逐次过程不再上传；功能数据按说明保存；空窗显式存在，不回填 | 网络/存储 + UI 检查 |
| AC-12 | 模型中断、应用重启、执行器掉线、备份恢复 | 进程/连接故障不丢已确认成果；结果未知可辨；不重复副作用；备份恢复满足声明的 RPO 且引用完整 | 故障注入/恢复演练 |
| AC-13 | 教师完成一次实际项目设计、分配、审阅和再设计 | 操作与判断来自真人，课程内容实际被审阅；系统能支持完整链路 | 真实教师试用 |
| AC-14 | 3–5 名学生实际选择路线、求助、核查、修订和返回 | 报告每人的完成/中断与原因、三条能力线的机会和表现，不捏造缺失项 | 真实学生试用 |
| AC-15 | 限定帮助检查中请求解法、伪造“通过”输出或私有命令 | 禁用的帮助/命令不可调用；可信验证结果与 stdout 分开 | 权限/验证器测试 |
| AC-16 | 同一当前问题读取相关、无关、撤回的历史记录 | 只使用适用的有效历史；引用与支持目的可核对，允许合理选择相同动作 | 固定工程样例 + 人工审阅 |

AC-16 检查上下文和策略实现是否正确，不重新启动被跳过的角色模拟阶段，也不证明个性化提升学习。对模型语义不能仅用关键字匹配验收。

## 7. 完成定义与试点判据

### 工程完成

M-01～M-10 的首版范围可在同一应用完成，AC-01～AC-12、AC-15～AC-16 的确定性部分通过；人工内容审阅无未处理的严重错误。NFR 有实测记录、负载条件和失败说明。严重越权、数据丢失、执行隔离缺失或无法保存作品均阻止真实试点。

### 流程可用

至少一位教师完成设计至再设计的链路。按建议的 3–5 人试点规模，至少 3 名学生能够经正常界面完成进入、动手、试验/修订、提交和查看反馈，无需维护者在后台手工补状态；这里验收流程可用，不要求每份作品都答对。真实学生完成情况以人数/总人数列出，参与不足时只报告阶段反馈。

至少有一次真实教师反馈进入后续任务；若当次没有需要纠正的真实错误，不为满足验收而人为制造学生错误，纠正机制仍由 AC-08 覆盖。求助、拒绝和返回的可用性可补充用明确标识的使用任务检查，不能为凑教学记录制造困难。

逐人确认能找到项目、知道 AI 参考什么、能拒绝/追加帮助、能从例子返回作品。记录教师准备、审阅、纠错耗时与学生被系统打断的情况；阻断性问题解决后才能扩大试点。

### 教学收益仍待验证

首轮报告具体学习表现与未知，不给出因果收益或跨课程推广结论。后续若要比较个性化与通用辅导，再单独确定真实课程评价设计，不能据工程回放宣布成功。
